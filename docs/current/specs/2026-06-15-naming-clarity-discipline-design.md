# 設計: AIの言葉遣いの明確性規範（Theme C-B）

- **Date**: 2026-06-15
- **Status**: Draft
- **Scope**: Theme C のうち問題B（AIの言葉遣い）のみ。問題A（プロジェクト固有用語集の仕組み）は別サイクル
- **関連ADR**: ADR-0022（スコープ限定＋アプローチA採用）

## 1. 背景・問題

ハンドオフ等の成果物ドキュメントや対話の中で、AI がプロジェクト固有の用語や、その場限りで定義のない略号・記号的呼称を使い、後から見返した際に正確な意味をつかみ損ねるというフィードバックがあった（`docs/conversation_log.md` 206-208行目）。

具体例:

- 「Aモード」「Bプラン」のように、文章だけでは意味が推測できない略号
- ブレスト中の「Primary では入れず、Secondary 検証へ降格すべき」のような、その場限りで定義のない記号的呼称

このフィードバックには2つの問題が含まれていた:

- **問題A（成果物の用語）**: プロジェクト固有のドメイン用語を一元管理する用語集（ユビキタス言語）の仕組みが無い。
- **問題B（AIの即興用語）**: AI がその場限りの意味不明な略号・記号的呼称を使い、説明的でない。

本サブプロジェクトは**問題Bのみ**を扱う。問題Aは置き場・作成タイミング・管理スキルの設計を要し規模が大きいため、別サイクルに送る（ADR-0022）。

## 2. 目的

- AI が対話・成果物ドキュメントで使う用語を、前提知識なしに意味が推測できる説明的な表現にする。
- これまで個人メモリに依存していた規範を、リポジトリ共有のガイドラインへ昇格させ、全コントリビューターに適用する。

## 3. 既存原則との対応（原則は変更しない）

本規範は**原則3（コンテキストの明示的管理）**の系として位置づける。読み手（人間・次セッションのAI）が前提に頼らず理解できるようにする、という明示性の延長である。

新しい関心事は導入しないため `docs/principles.md` は変更しない。実装は Layer 2（`.github/copilot-instructions.md`）に限定する。Skill 化は常時適用の単純な規範には過剰（YAGNI）なため行わない。

## 4. 変更内容

### 4.1 copilot-instructions.md への規範追加

`.github/copilot-instructions.md` の「AI駆動開発ガイドライン > コンテキスト管理」セクションに、以下2点の行動規範を追加する:

1. 対話・成果物ドキュメント（ハンドオフ/仕様書/ADR等）で用語を使うときは、文章だけを読んで意味が推測できる説明的な表現を用いること。「Aモード」「Primary/Secondary」のような、その場限りで定義のない略号・記号的呼称は使わないこと。
2. 初出のプロジェクト固有用語には簡潔な説明を添えること。

### 4.2 テンプレート同期

`.github/copilot-instructions.md` は template 対象（`template.manifest` に記載）のため、変更後に `scripts/sync-template.ps1` を実行して `template/` 配下へ同期する。

## 5. スコープ外

- 問題A（プロジェクト固有用語集の仕組み）の設計・実装。別サイクルで扱う。
- `docs/principles.md`（Layer 1）の変更。
- 新規 Skill の作成。

## 6. 完了基準

- `.github/copilot-instructions.md` のコンテキスト管理セクションに規範2点が追加されている。
- `template/` 配下の copilot-instructions.md が同期されている。
- ADR-0022 が Accepted に昇格している。
