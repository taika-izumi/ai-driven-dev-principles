## 1. Issue-0009 対策: 即ドラフト作成・コミット遅延（ADR-0030)

### 規範の内容

- ADR ドラフトの「作成」（ファイル作成＋インデックス更新）は、従来どおり意思決定を検出した瞬間に行う
- 「コミット」は関連論点が収束したチェックポイントまで遅延してよい:
  - brainstorming 中に作成したドラフト → 設計承認時
  - それ以外 → ユーザーがその決定の確定を確認した時
  - 関連論点が既に収束していれば従来どおり即コミットしてよい
- 未コミットの間、ドラフトは関連論点の進展に応じて書き直し自由（書き直しは想定された更新であり手戻りではない）
- コミット漏れ対策: `start-work` の Phase 2 Post とセッション終了処理で、未コミットの ADR ドラフトがないか確認する

### 変更ファイル

1. `skills/decision-log/SKILL.md`
   - 「ADR作成手順」の手順4（コミット）を「コミットのタイミング」規定に書き換える（上記チェックポイント表を含める）
   - 「ユーザーへの確認」の前後に、収束前は書き直し自由である旨を追記する
2. `CLAUDE.md`「意思決定の即時記録（継続適用）」
   - フロー「検出 → 即ドラフト作成 → ユーザー承認 → 元のスキルへ復帰」に、コミットは論点収束後でよい旨の1行を補足する
3. `skills/start-work/SKILL.md`
   - 「重要な前提: 継続的ADR検出ルール」の引用文言を CLAUDE.md 側の更新と整合させる
   - Phase 2 Post とセッション終了処理に「未コミット ADR ドラフトの確認」を1行追加する

## 2. Issue-0010 対策: 再発の一次記録を issue「検討状況」へ一元化（ADR-0031)

### 規範の内容

- 既存 open 課題の再発・進展を検出したら、検出したその場で該当 issue ファイルの「検討状況」セクションに1行追記する
  - 形式: `YYYY-MM-DD: 事象の要約（必要なら詳細への参照）`
- retrospective では既存 open 課題の再発を新規起票しない。振り返りファイルで言及する場合は Issue-NNNN への参照を付け、一次記録は issue 側とする

### 変更ファイル

1. `docs/overview/folder-structure.md` §7
   - §7.3（ライフサイクル）に再発・進展の記録ルールを追記する
   - §7.4（フォーマット）の「検討状況」の説明に再発ログの形式を追記する
2. `skills/retrospective/SKILL.md`
   - 課題起票手順（Phase 2）に「既存 open 課題の再発は新規起票せず、該当 issue の検討状況へ追記済みであることを確認する（未追記ならその場で追記する）」旨を追加する

## 3. Issue-0011 対策: エージェント実行可能性チェックの定式化（ADR-0032)

### 規範の内容

- 規範・ルール・ADR（特に撤去基準・発動条件・適用条件などの判定条件）を起草するときは、「その判定条件・動作を、実行主体であるエージェントが実際に観測・実行できるか」を確認する
- エージェントが観測できない状態（例: 他モデルの利用状況、ユーザー画面上の事象、セッション横断の利用履歴）を判定条件にせず、観測可能な事実（例: ユーザーの明示指示、ファイル・設定の存在、コマンド出力）で書く
- エージェントが判定できない場合は「ユーザーが判断し指示した時点」のように判断主体をユーザーへ明示的に移す

### 変更ファイル

1. `skills/decision-log/SKILL.md` — 記述規律（ADR-0019 の注記ブロック付近）に実行可能性チェックを1項追加する
2. `CONTRIBUTING.md` — 「ADRを記録するとき」の記述規律に1行、「CLAUDE.md を更新するとき」の注意事項に1行追加する
