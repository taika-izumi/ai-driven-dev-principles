## 背景・動機

ガイドラインは 2 つの経路で他プロジェクトへ届く。

| 経路 | 生成 | 配布先での姿 |
|---|---|---|
| プラグイン `ai-driven-dev-principles` | （従来）なし。リポジトリをそのまま配信 | `skills/` がスキルとしてロードされる |
| テンプレート `template/` | `scripts/sync-template.ps1` | 配布先プロジェクトの初期ファイル一式になる |

配布物には、本リポジトリの文脈でしか意味を持たない参照が含まれている。当初は決定記録番号の**番号衝突**（配布先では `ADR-0080` がその配布先自身の記録を指す）だけを問題と捉えていたが、走査により同じ性質の参照が 5 種類あることが分かった。判定基準を「**配布先の読み手が解決できるか**」に統一し、5 種類すべてを対象とする（ADR-0081）。

| 種別 | 配布先での解決可能性 |
|---|---|
| 無修飾の決定記録番号・課題番号 | 解決できるが別の記録を指す（衝突） |
| `<repo>#` 修飾済みの実参照 | 衝突しないが、参照先リポジトリが配布されず開けない |
| worklog エントリ id | 中央ストアはリポジトリ外・配布対象外のため原理的に解決不能 |
| プロジェクト名 | 配布先に無関係な私的プロジェクト名 |

これらは配布先のためではなく**保守者のため**に置かれている。ADR-0073 は「規範項目には根拠と観測世代を添え、実測にもとづく退役経路を持たせる」ことを義務づけており、根拠は将来の見直し（単一プロジェクト由来から複数プロジェクト由来への更新など）の材料として累積する。したがって**ソースからは除かず、配布物からのみ除く**。

**除去するのは識別子であり、根拠の散文は残す。**「10 タスク中 7 回ずれた」「根拠 8 件全件が単一プロジェクト由来のため拘束的規範ではなく適用例」「世代: claude-opus-4-7〜claude-opus-5」といった記述は、配布先で規範の拘束力と適用範囲を判断する材料になるため保持する。

問題はプラグイン経路に変換ステップが無いことである。とくに `skills/session-handoff/SKILL.md` のハンドオフ書式テンプレート内にある識別子は、配布先プロジェクトの実ファイル（`docs/working/handoff/<branch>.md`）へ複写される。

## 全体アーキテクチャ

### 機能ブロック一覧

| # | ブロック | 責務 | 主な対象ファイル |
|---|---|---|---|
| 01 | 出所識別子の記法規約 | 配布対象ソースにおける識別子の書き方（R1〜R5）を定義し、拡張フローへ執行点を配線する | `CONTRIBUTING.md`、`skills/extend-guidelines/SKILL.md` |
| 02 | 配布物生成器 | 配布対象ソースから識別子を除去した配布物を生成し、規約違反を検出したらエラーで停止する。生成物の陳腐化も検出する | `scripts/build-dist.ps1`、`scripts/lib/strip-provenance.ps1`（いずれも新規） |
| 03 | template 同期への変換組み込み | `template/` の生成にも同じ判定と変換を適用する | `scripts/sync-template.ps1` |
| 04 | プラグイン配布構造 | 生成物をプラグインのルートとして配布する構造を定義し、成立性を実機で検証する | `.claude-plugin/marketplace.json`、`.claude-plugin/plugin.json`、`dist/.claude-plugin/plugin.json`、`README.md` |
| 05 | ソースの規約適合化 | 既存の規約違反 38 行を規約適合形へ書き換える | `skills/` 8 ファイル、`docs/records/retrospectives/README.md`、`docs/overview/folder-structure.md` |

### ブロック間関係

```
01 規約（契約）
 ├─→ 02 生成器（契約の実装かつ検査主体）
 │    ├─→ 03 template 同期への組み込み
 │    └─→ 04 プラグイン配布構造
 └─→ 05 移行
```

依存は一方向で循環しない。01 が契約を定め、02 がそれを実装・執行する。03 と 04 は 02 の適用先、05 は既存ソースを契約へ合わせる作業である。

**実装順序の制約**: 05（移行）は 03 より先に完了させる。順序を逆にすると `sync-template.ps1` が規約違反を検出して非ゼロ終了する。04 の構造判定（A / B）は他ブロックのパス表記に影響するため、04 の「役割名とパスの対応表」を先に確定させる。

## 主要な処理フロー

### フロー 1: 配布物の生成

1. 保守者が配布対象ソースを編集する
2. `scripts/build-dist.ps1` を実行する
3. 生成器が配布対象ソースを走査し、記法規約 R1〜R5 への適合を判定する
4. 規約違反を検出した場合、違反箇所（ファイル・行・違反した規約 ID・内容）を出力して**非ゼロ終了する**。配布物は変更しない
5. 適合していれば識別子を除去した配布物を `dist/` へ書き出す

### フロー 2: 陳腐化の検出

1. `scripts/build-dist.ps1 -Check` および `scripts/sync-template.ps1 -Check` を実行する
2. 各生成器がソースから配布物を再生成し、既存の生成物と比較する
3. (a) ソース由来の全ファイルが生成物側に存在して内容が一致し、(b) 生成物側にソース由来でないファイルが無い、の 2 条件を満たさなければ非ゼロ終了する

この検査が塞ぐのは**ディスク上の生成物の陳腐化**である。セッションへ供給されるスキル本文の陳腐化は別の失敗様式であり、`/plugin marketplace update` の実行と「起動して返った本文と実ファイルの突合」に依存する（Issue-0044）。両者を混同しない。

### フロー 3: ガイドライン拡張時

1. `extend-guidelines` から始まる拡張作業で、配布対象ソースを編集する
2. コミット前に `scripts/build-dist.ps1` と `scripts/sync-template.ps1` を実行する（`CONTRIBUTING.md` の執行点）
3. 規約違反があれば修正してから再実行する。迂回路は用意しない

## 設計上の主要な意思決定

| ADR | 決定 |
|---|---|
| ADR-0081 | 配布物から除くのは「配布先で解決できない参照」であり、決定記録番号に限らない |
| ADR-0082 | 保守者向けの根拠注記はソースに残し、注記を除去した生成物を配布する |
| ADR-0083 | 配布対象ソースの出所識別子は位置で規約化し、生成器が規約適合の検査を兼ねる |

前提となる既存決定: ADR-0015 / ADR-0016（スキルはプラグイン配信対象とし template から除外）/ ADR-0027（テンプレート初期セットの基準）/ ADR-0033（LF 固定書き出し）/ ADR-0039（環境・ツール設定による構造的解決を規範追加より優先）/ ADR-0055（プラグインの再読み込みはユーザーへ依頼）/ ADR-0068（クロスリポジトリの課題参照）/ ADR-0073（規範項目に根拠と観測世代を添える）

ADR-0027 は「インデックス行のみ除去し、説明文は保持する」と定めている。本設計は保持された説明文からも出所識別子を除去するため、ADR-0027 の Decision の適用範囲が変わる。ADR-0027 へ部分修正の注記を追加する（ステータスは Accepted のまま。`decision-log` の台帳監査における「部分修正あり（本体現役・状態変更なし）」の扱い）。

ADR-0068 は本リポジトリ内の記述について `<repo>#` 修飾を定め、既存記述への遡及適用をしないと決めている。本 spec は配布物について遡及適用する。適用対象が異なるため矛盾しないが、同一リポジトリ内に遡及方針の異なる 2 つの判断が並ぶ。

## スコープ外（YAGNI）

- **`template/CLAUDE.md` のプラグイン名 `ai-driven-dev-principles` とインストール元リポジトリ `taika-izumi/ai-driven-dev-principles`** — 配布先が環境を準備するために必要な情報であり、本リポジトリ固有であること自体が正しい（ADR-0081）
- **書式例・プレースホルダ** — `ADR-NNNN` / `Issue-NNNN` / `<repo>#Issue-NNNN` のように実在を指さない表記、および中立名を使ったサンプル値。配布先が使う型そのものであるため保持する（ADR-0081）
- **`docs/` 配下の参照** — 配布対象ではない。プラグインキャッシュへ物理的に複製されるが、スキルとしてロードされず配布先の作業指示にならない（ADR-0081）
- **空インデックス生成で除去される行** — `sync-template.ps1` が `docs/records/retrospectives/README.md` 等のデータ行を落とすため、配布物に届かない（ADR-0081）
- **スクリプトファイルのテストフィクスチャとコード** — `.py` / `.ps1` は機械判定の対象をコメント行のみとする。架空データ（`X-2026-01-01-01` 等）を規約で縛らないため。**ただし docstring と利用者へ表示するメッセージはスコープ内**（散文であり配布先の読み手が読むテキストのため。機械判定が届かないので書き手が守る。検査の自動化は Issue-0070）
- **`docs/overview/folder-structure.md:153` の散文中の他リポジトリ名** — 「無修飾の表記が実際に衝突した例: LoopForAlpha の `flow/0034` …」の記述。種別 1〜5 のいずれにも当たらず生成器が除去しないため、意図的に残置する。同ファイル 149 行の記法例はプレースホルダ化する（ブロック 05）
- **旧型式 spec 残り 6 本の整理** — Issue-0008 の担当範囲
- **git フックによる自動実行** — 執行点は `CONTRIBUTING.md` の手順に置く。フックの導入は Issue-0020 の対策設計と合わせて別途判断する

## 完了基準

1. `scripts/build-dist.ps1` が存在し、規約適合時に `dist/` を生成し、規約違反時に違反箇所と違反した規約 ID を出力して非ゼロ終了する
2. `scripts/build-dist.ps1 -Check` と `scripts/sync-template.ps1 -Check` が、**両生成物それぞれについて**生成漏れのある状態で非ゼロ終了する
3. 配布対象ソース 10 ファイル 38 行の規約違反が解消し、両生成器がエラーなく通る
4. 生成された配布物に**実在を指す出所識別子**が 0 件である（`dist/` と `template/` の両方。判定式は `02` が定める正規表現による）
5. プラグイン配布構造が実機で成立する（`/plugin marketplace update` 後にスキルがロードされる）。構造 A が不成立の場合は構造 B へ切り替えたうえで同条件を満たす
6. `CONTRIBUTING.md` に記法規約と執行点が記載され、既存 4 シナリオのチェックリストへ規約適合の確認項目が 1 行ずつ（計 4 行）追加され、`skills/extend-guidelines/SKILL.md` から参照されている
7. `docs/records/decisions/0027-template-seed-criteria.md` に本 spec による部分修正の注記があり、Status は Accepted のまま維持されている

（`2026-04-13-template-folder-and-sync-design.md` への一行追記は本 spec 執筆時点で完了済みのため、完了基準ではなく前提条件とする。）

## 過剰適合点検（ADR-0079）

| 観点 | 判定 | 根拠 |
|------|------|------|
| 出所の偏り | 問題なし | 根拠は本リポジトリ単一（Issue-0067、実測 172 行、worklog `MakeAiInstructions-2026-08-07-13` / `-14`）、モデル世代 2（claude-opus-5 / claude-fable-5）。単一プロジェクト由来だが、**本規約の適用範囲も本リポジトリに閉じる**（`CONTRIBUTING.md` は `template.manifest` に無く配布されない。規約が拘束するのは配布物を生成する本リポジトリの作業のみ）。単一プロジェクトの教訓を他プロジェクトへ課す構図にならない |
| システム種別依存性 | 問題なし | 本規約は「文書をプラグイン／テンプレートとして配布するリポジトリ」に固有の運用規約であり、配布先の開発対象システムの種別・技術スタック・テスト文化に依存しない。前提が崩れるプロジェクトには適用されない（そもそも配布物を生成しない） |
| AIモデル/ツール依存性 | **要是正 → 根拠と世代＋退役経路** | ツール依存はブロック 04（プラグイン機構の `source` 解決）に限局し、既存の配布体制が既にその上に立っているため新たな依存を増やしていない。**引用元のゲート脱落の点検**（Issue-0066 の型）: ADR-0068 のゲート「修飾は跨いだときだけ要る」は無条件化しておらず、別軸の条件（配布対象ソースであること）を新設して ADR-0081 で軸の違いを明示した。一方 **ADR-0073 の「根拠と観測世代を添える」義務は、配布物では一部の行で満たせなくなることが実測で判明した**（`subagent-dispatch` の 9 行へ変換を適用したところ、根拠列が完全に空になる行が 1・出所が消える行が 2）。是正として、当該行の根拠を散文で補ってから変換する（ブロック 05）。補った散文は参照先 Issue の実体（根拠件数・出所プロジェクト数・モデル世代分布）から書き起こし、変換後も ADR-0073 の要求を満たす形にする |
| 退役経路 | 定義済み | 生成体制を廃止する判断（ユーザーが配布をやめる、または識別子の配布を許容すると判断した時点）で本規約は不要になる。判断主体はユーザー。加えて、生成器が長期にわたり規約違反を検出せず、かつ新規違反の delta が中央ストアへ現れない場合、規約の簡素化をユーザーへ提案する |
