# 02: 配布物生成器

## 対象ファイル

- `scripts/build-dist.ps1`（新規） — 生成器の本体
- `scripts/lib/strip-provenance.ps1`（新規） — 判定と変換のロジック。ブロック 03（`sync-template.ps1`）と共有する

## 責務

配布対象ソースを走査し、記法規約（ブロック 01）への適合を判定する。適合していれば出所識別子を除去した配布物を生成し、違反していれば違反箇所と違反した規約 ID を出力して非ゼロ終了する。生成物がソースから再生成した結果と一致するかも判定する。

## インターフェース

```
scripts/build-dist.ps1 [-Check]
```

| モード | 動作 | 終了コード |
|---|---|---|
| 既定（引数なし） | 規約を判定し、適合していれば `dist/` を再生成する | 0 = 生成成功 / 1 = 規約違反（`dist/` は変更しない） |
| `-Check` | 規約を判定し、ソースから再生成した内容と既存 `dist/` を比較する。書き込みはしない | 0 = 一致 / 1 = 規約違反または不一致 |

`-Check` の一致判定は次の 2 条件をともに満たすこととする。

1. ソース由来の全ファイルが `dist/` に存在し、内容が一致する
2. `dist/` にソース由来でないファイルが存在しない（ソース側の削除・改名の取りこぼしを検出するため）

### 共有ライブラリのインターフェース

`scripts/lib/strip-provenance.ps1` は次の 2 関数を公開する。

| 関数 | 入力 | 出力 |
|---|---|---|
| `Test-ProvenanceConvention` | ファイル内容（文字列）、ファイルパス（診断用） | 違反の配列（行番号・違反した規約 ID・内容） |
| `Remove-ProvenanceNotation` | ファイル内容（文字列） | 出所識別子を除去した内容（文字列） |

## サブ機能 / 内部構成

### 1. 走査対象の決定

計 25 ファイル。

- `skills/` 配下の全ファイル（18）
- `template.manifest` に記載されたファイル（4。ブロック 03 が使用）
- 空インデックス生成対象 3 ファイル（判定は空インデックス化後の内容。ブロック 03 が生成した結果を判定に回す）

### 2. 判定に用いる正規表現

規約の解釈が実装ごとにぶれないよう、判定式を spec に固定する。

| 用途 | 正規表現 |
|---|---|
| 出所識別子（種別 1〜3） | `(?<![A-Za-z0-9])(?:[A-Za-z][A-Za-z0-9]*#)?(?:ADR\|Issue)-\d{4}` |
| 出所識別子（種別 4: worklog id） | `(?<![A-Za-z0-9])(?:[A-Za-z][A-Za-z0-9]*)?-20\d\d-\d\d-\d\d(?:-\d\d)?`（プロジェクト名を省いた省略形を含む） |
| 出所識別子（種別 5: 出所注記） | `（出所[:：][^）]*）`（全角コロンも受ける） |
| 出所リスト行 | `^\s*[-*]\s*(?:[A-Za-z][A-Za-z0-9]*#)?(?:ADR\|Issue)-\d{4}(?:\s*[/〜]\s*\d{4})*\s*[:：]` |
| 中立名（種別 4 のプレースホルダ判別） | `^(?:X\|Proj\|<project>)$` をプロジェクト名部に適用 |

種別 1〜3 は 4 桁の数字を要求することでプレースホルダ（`ADR-NNNN` 等）が自動的に対象外になる。種別 4 は日付部に 4 桁の年を含むためこの規則が使えず、プロジェクト名部が中立名の許可リストに一致するもの（`X-2026-01-01-01` 等）を対象外とする。

### 3. 判定順序

順序を規約の一部として固定する（実装が判定順を推測しないため）。

1. プレースホルダ（種別 1〜3 は 4 桁の数字を持たない表記、種別 4 は中立名のもの）は対象外として素通しする
2. コードフェンス内に出所識別子があれば **R4 違反**として記録する
3. 出所リスト行（上記の正規表現に一致する行）は**削除対象**とする
4. 行頭がリスト記号＋識別子でありながらコロン形でない行は **R3 違反**として記録する
5. **種別 5（`（出所[:：]…）`）は、括弧そのものを識別子として除去対象とする。** ステップ 6 の括弧内判定では、種別 5 の括弧に囲まれた識別子も内側扱いとする
6. 行内の残る識別子がすべて全角括弧の内側にあれば**除去対象**とする
7. 括弧の外に識別子が残る行は **R2 違反**として記録する

`.py` / `.ps1` ファイルはコメント行のみを上記に掛ける。

### 4. 変換

| 対象 | 処理 |
|---|---|
| 出所リスト行 | 行ごと削除する。削除の結果その節にリスト項目が 1 つも残らなければ、見出し行と直前の空行も削除する |
| `（出所: …）` | 括弧を中身ごと削除する |
| 括弧内の識別子 | トークンと隣接する区切り（`。`／`、`／`・`／`/`／`〜`／空白／`項目N`）とともに除去する。括弧の中身が空になれば括弧ごと削除する |
| コードフェンス内 | 変換しない（R4 により識別子は存在しない） |

### 5. `dist/` の構成と書き出し

`dist/` は生成のたびに完全削除して作り直す（冪等性・クリーン性）。**したがって `dist/` 配下のすべてのファイルを生成器が書き出す責務を負う。**

| 出力 | 生成元 |
|---|---|
| `dist/skills/**` | `skills/**` を変換したもの |
| `dist/.claude-plugin/plugin.json` | リポジトリ直下の `.claude-plugin/plugin.json` をそのまま複写する |

`plugin.json` を生成器の責務に含めないと、2 回目の実行でプラグイン定義が失われ、`/plugin marketplace update` 時に全スキルが消える。

書き出しは改行 LF 固定・UTF-8（BOM なし）で行う（ADR-0033 の規律）。

### 6. 自己検査

生成後、`dist/` 配下に**実在を指す出所識別子**が 1 件も残っていないことを確認する。残っていれば変換規則の欠陥として非ゼロ終了する。

**検査は判定と同じ適用範囲・同じプレースホルダ判別を用いる**（`.py` / `.ps1` はコメント行のみ、中立名の種別 4 は対象外）。この限定が無いと、配布物に含まれる `dist/skills/worklog-extract/scripts/check-store-health.py` のテストフィクスチャ（コード行の `X-2026-01-01-01` 等）を検出して必ず非ゼロ終了する。

## このブロック固有の制約・前提

- **迂回路を用意しない。** 規約違反を無視して生成を続けるオプション（`-Force` 等）は設けない。迂回できると規約が空文化する
- **`dist/` は git 管理下に置く。** `template/` と同じ運用。生成物をコミットすることで、配布先は追加のビルドなしに利用できる
- 実装言語は PowerShell とする（既存スクリプト 2 本と揃える。実行環境の前提を増やさない）
- **本ブロックが塞ぐのはディスク上の生成物の陳腐化のみ。** セッションへ供給されるスキル本文の陳腐化は別の失敗様式であり、`/plugin marketplace update` の実行と本文の突合に依存する（Issue-0044）

## 関連 ADR

- ADR-0082: 保守者向けの根拠注記はソースに残し、注記を除去した生成物を配布する
- ADR-0083: 配布対象ソースの出所識別子は位置で規約化し、生成器が規約適合の検査を兼ねる
- ADR-0033: 生成物は LF 固定で書き出す
- ADR-0054: 検査は silent tolerance をせず、検出したら報告して停止する
