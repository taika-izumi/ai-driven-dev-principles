# 04: プラグイン配布構造

## 対象ファイル

- `.claude-plugin/marketplace.json` — プラグイン本体の位置を変更し、検証用エントリを追加する
- `.claude-plugin/plugin.json` — 構造 A では複写元として残す（下記「plugin.json の帰結」）
- `dist/.claude-plugin/plugin.json`（新規・生成物） — ブロック 02 が複写して生成する
- `README.md` — インストール手順に変更が生じる場合のみ

## 責務

ブロック 02 が生成した配布物をプラグインのルートとして配信する構造を定義し、その構造が実機で成立することを検証する。

## 役割名とパスの対応

他ブロックは次の**役割名**で参照する。構造 A / B のどちらを採るかで実パスが変わるため、対応表は本ブロックが持つ。

同一パスが 2 つの役割を兼ねると読み替えが一意にならないため、役割は 4 つに分ける。

| 役割名 | 構造 A | 構造 B |
|---|---|---|
| 開発用ソースディレクトリ | `skills/` | `skills-src/` |
| 生成スキルディレクトリ | `dist/skills/` | `skills/` |
| プラグインルート | `dist/` | リポジトリ直下 |
| プラグイン定義の複写 | 必要（`dist/.claude-plugin/plugin.json` を生成） | 不要（リポジトリ直下のものがそのまま使われる） |

**構造が確定するまで、他ブロックの記述は役割名で読む。** 構造 A を前提に書かれた実パスは、構造 B を採る場合に本表で読み替える。読み替え対象は次のとおり。

- `01` の適用範囲（開発用ソースディレクトリ）
- `02` の走査対象（開発用ソースディレクトリ）
- `02` §5「`dist/` の構成と書き出し」（生成スキルディレクトリ／プラグインルート／プラグイン定義の複写の要否）
- `02` の `-Check` の比較先（プラグインルート）
- `05` の対象ファイル表（開発用ソースディレクトリ）
- `00-overview.md` の完了基準 4（プラグインルート）

構造の確定は実装の最初のタスクで行う。

## 配布構造

第一候補は構造 A である。

```
skills/                           開発用ソース（人が編集する。識別子あり）
dist/
  .claude-plugin/plugin.json      生成物（リポジトリ直下から複写）
  skills/                         生成物（識別子なし）
.claude-plugin/marketplace.json   本番エントリの source を "./dist" にする
```

配布物が `dist/` に限られ、`docs/` や `CONTRIBUTING.md` は配布先へ複製されない。

構造 A は「マーケットプレイスの `source` にサブディレクトリを指定できる」という**未検証の前提**の上に立つ。前提が成立しない場合は構造 B へ切り替える。

```
skills-src/                       開発用ソース（人が編集する。識別子あり）
skills/                           生成物（識別子なし。プラグインが読む場所は不変）
.claude-plugin/marketplace.json   変更しない
```

構造 B はプラグイン設定に依存しないため未検証の前提を持たないが、`skills/` が生成物になり、`skills-src/` も物理的には配布され続ける（スキルとしてロードされないため実害はない）。

## plugin.json の帰結

構造 A では、リポジトリ直下の `.claude-plugin/plugin.json` はプラグインルートの定義ではなくなる。**削除せず、生成物側の複写元として残す。** ブロック 02 が `dist/.claude-plugin/plugin.json` へ複写するため、プラグインのメタデータ（`name` / `version` / `description` 等）の編集は引き続きリポジトリ直下のファイルに対して行う。

構造 B ではリポジトリ直下がプラグインルートのまま変わらないため、複写は不要になる。

## 成立性の検証手順

**本番のマーケットプレイスエントリを検証に使わない。** 検証用に別名のエントリを追加し、そこで確認する。

```json
"plugins": [
  { "name": "ai-driven-dev-principles",        "source": "./dist" },
  { "name": "ai-driven-dev-principles-probe",  "source": "./dist" }
]
```

手順:

1. `dist/.claude-plugin/plugin.json` と `dist/skills/` に最小構成（スキル 1 本）を用意する
2. `marketplace.json` へ検証用エントリ `ai-driven-dev-principles-probe` を追加する
3. `/plugin marketplace update` と検証用プラグインのインストールをユーザーへ依頼する（エージェントからは実行できない）
4. 検証用プラグインのスキルが `Skill` ツールから起動でき、ベースディレクトリが `dist/skills/<name>` を指すことを確認する
5. 成立すれば本番エントリの `source` を `./dist` へ変更する。不成立なら構造 B へ切り替える
6. 検証用エントリを削除する

判定条件は観測可能な事実（スキルが起動するか、ベースディレクトリがどこか）で書かれている（ADR-0032）。

**本番エントリを最小構成で上書きしてはならない理由**: `CLAUDE.md` は当該プラグインのスキル群を作業の前提条件として宣言している。本番エントリを最小構成に差し替えると、`start-work` / `decision-log` / `session-handoff` を含む 17 本が当セッションから失われる。供給はセッション冒頭または直近の update 時点のスナップショットで固定されるため（Issue-0044）、復旧にはユーザーによる再 update が必要で、エージェントからは実行できない。

## 本リポジトリ自身への影響

どちらの構造でも、本リポジトリのセッションは**生成版（識別子なし）のスキルをロードする**。これは受け入れる（ADR-0082）。

- スキルを**改定する**ときは対象ファイルを直接読むため、識別子は参照できる
- スキルを**実行する**ときに必要なのは手順であり、識別子ではない
- 「生成物が古いまま実行される」危険はブロック 02 の `-Check` で塞ぐ（ディスク上の陳腐化に限る）

## 環境の実測（2026-08-07）

設計の前提であり、本サイクルで変更する対象ではない。

- マーケットプレイス登録は `{"source": "directory", "path": "D:\\Dev\\002_AiDev\\MakeAiInstructions"}` で、リポジトリディレクトリそのものを指す
- プラグインキャッシュにはプラグインルートの完全コピーが置かれる（現行のルートはリポジトリ直下のため 743KB）
- 本リポジトリのセッションでは、スキルは repo 直下から読まれている

## このブロック固有の制約・前提

- **プラグインのバージョン**: `plugin.json` の `version` は現状 `0.1.0` で据え置く。バージョニング方針の見直しは本サイクルのスコープ外
- **`/plugin marketplace update` はエージェントから実行できない。** 検証ステップではユーザーへ依頼する
