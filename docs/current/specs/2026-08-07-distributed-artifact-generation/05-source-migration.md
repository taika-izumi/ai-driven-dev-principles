## 責務

既存の配布対象ソースを記法規約へ適合させる。適合後は生成器がエラーなく通り、以降の違反混入は生成の失敗として検出される。

## 書き換えの型

### R3 違反（出所リスト行の括弧形 → コロン形）14 行

```
違反: - ADR-0044（記録ゲート・スキル1/2 責務境界・scope 暫定タグ）
適合: - ADR-0044: 記録ゲート・スキル1/2 責務境界・scope 暫定タグ
```

括弧内にコロンが含まれる場合は、内側のコロンを避けて書き直す。

```
違反: - ADR-0048/0049/0051（読み側互換: model 材料・v 版数判別・friction 読み替え）
適合: - ADR-0048/0049/0051: 読み側互換（model 材料・v 版数判別・friction 読み替え）
```

`skills/retrospective/SKILL.md:53` は行頭の形が出所リスト行と同じでありながら中身が手順文であるため、コロン形にせず本文として書き直す。

```
違反: - ADR-0006（意思決定の継続検出ルール）は本スキル中も常時適用される。…
適合: - 意思決定の継続検出ルール（ADR-0006）は本スキル中も常時適用される。…
```

### R2 違反（本文中の識別子 → 括弧内へ移す）16 行

意味を保ったまま語順を変える。括弧の中身が主語・目的語になっている場合は、それを本文へ出して識別子を括弧へ入れる。

```
違反: - 出力ファイルは ADR-0011（時系列追記型）に従い、一度書いたら原則上書き禁止
適合: - 出力ファイルは時系列追記型（ADR-0011）に従い、一度書いたら原則上書き禁止
```

表のセル内で識別子がセル冒頭にある場合（`subagent-dispatch` の根拠列）は、散文を主文として前に出し、識別子を末尾の括弧へ集める。

```
違反: | … | Issue-0033 項目2。原則4（不可逆操作前の人間関与）の委譲先への伝播 |
適合: | … | 原則4（不可逆操作前の人間関与）の委譲先への伝播（Issue-0033 項目2） |

違反: | … | `LoopForAlpha-2026-07-22-09`（黙って従えば品質が下がる指示が 2 回）、`-2026-08-01-03` / … |
適合: | … | 黙って従えば品質が下がる指示が 2 回、…（出所: LoopForAlpha-2026-07-22-09 / -2026-08-01-03 / -2026-08-03-02） |
```

同一行の 2 件目以降が省略形（`-2026-08-01-03`）で書かれている場合も種別 4 の識別子であり、あわせて括弧内へ移す。`subagent-dispatch/SKILL.md:35` に 2 件ある。

プロジェクト名が散文中にある場合は `（出所: …）` へ移す。

```
違反: 根拠 8 件全件が単一プロジェクト（LoopForAlpha）のテスト運用出所のため、…
適合: 根拠 8 件全件が単一プロジェクトのテスト運用出所のため、…（出所: LoopForAlpha）
```

### R5 違反（書式例に実在の識別子・実在の固有名を使っている）2 箇所

```
違反: - 書式: `<repo>#Issue-NNNN`（例: `LoopForAlpha#Issue-0069`）
適合: - 書式: `<repo>#Issue-NNNN`（例: `OtherProject#Issue-NNNN`）

違反: { "MakeAiInstructions": { "path": "D:/Dev/002_AiDev/MakeAiInstructions", "lastSeen": "…" } }
適合: { "X": { "path": "/path/to/X", "lastSeen": "…" } }
```

R5 の対象は識別子 5 種に限らない。**書式例に置いた実在のプロジェクト名・実在の絶対パスも配布先では解決できない**ため中立名にする（`store-format.md` の `projects.json` 例は、同ファイル内の台帳レコード例が `X` へ中立化されたのに実名のまま残り、同じ `project` の手本が 2 通りに割れていた）。

R5 は位置規約ではないため生成器が違反として検出できない。**機械検査に頼らず、コードフェンス内のサンプル値を全数目視すること**（2026-08-08 の実測では、`docs/overview/folder-structure.md:149` の 1 件だけを拾って `store-format.md` の 1 件を取り逃がした）。配布物側のフェンスを列挙して 1 巡する。

## 根拠が消える行への散文の補完

変換後に根拠列が空になる、または出所が読み取れなくなる行が `subagent-dispatch/SKILL.md` に 3 行ある（変換をシミュレートして確認済み。50 行目は根拠列が完全に空、36・37 行目は原則からの演繹だけが残る）。ADR-0073 が要求する「根拠と観測世代」を配布物でも満たすため、これらの行には散文を補う。

```
違反: | 長時間かつ書き込みを伴う作業を委譲するとき | … | Issue-0033 項目4 |
適合: | 長時間かつ書き込みを伴う作業を委譲するとき | … | 本項目を含むクラスタ（中央ストア 10 件）由来。全件が単一プロジェクト出所。世代: claude-opus-4-7〜claude-opus-5[1m]（出所: Issue-0033 項目4 / LoopForAlpha） |
```

補完に使う数値・世代分布は、参照先 Issue の「根拠エントリ」節の実データから書き起こす。推測で書かない。件数はクラスタ単位の統計であり項目単独の根拠数ではないため、そう読める書き方にする（Issue-0033 は後日 2 つ目のクラスタを合流しており、初回クラスタの 10 件と和集合 13 件が併存する）。

## このブロック固有の制約・前提

- **規範の内容を変えない。** 表の制約列・手順文など規範本体の文言は変更しない。本ブロックが変えるのは識別子の位置と、根拠列の散文である
- **根拠列への散文の補完のみ例外とする。** 補完は参照先 Issue の実体から書き起こす場合に限り許し、補完内容はユーザー確認を経る。これは新しい情報の追加であり、純粋な語順変更ではないため
- **`template/` 配下は直接編集しない。** 生成物であり、ソースは `docs/records/retrospectives/README.md` である
- ブロック 03（`sync-template.ps1` への変換組み込み）より先に完了させる。順序を逆にすると同期が非ゼロ終了する
- スクリプトファイルのテストフィクスチャとコードは規約の適用対象外であり、本ブロックでも変更しない。**ただし docstring と利用者へ表示するメッセージは対象**（散文であり配布先の読み手が読むテキストのため。機械判定が届かないので目視で確認する。検査の自動化は Issue-0070）

## 検証

1. `scripts/build-dist.ps1` と `scripts/sync-template.ps1` が違反 0 件で完走する
2. 生成物の差分を確認し、書式例（`folder-structure.md` の課題ファイルひな形、`<repo>#` の記法例、`store-format.md` の台帳レコード例）が壊れていないことを見る
3. `skills/session-handoff/SKILL.md` のハンドオフ書式テンプレートから識別子が消えても、`review=` の記入規則が読み取れる
4. `subagent-dispatch/SKILL.md` の根拠列 9 行すべてが、変換後も**出所**を伝える内容になっている。観測世代については補完対象 3 行（36・37・50）で確認する

観測世代は、ソース時点で 9 行中 2 行（35・46）にしか書かれていない。本サイクルの変換はこの状態を悪化させないことを条件とし、既存の記載欠落（38・47・48・49）の解消は扱わない（ADR-0073 の充足度の問題であり、本サイクルが作った欠陥ではない）。
