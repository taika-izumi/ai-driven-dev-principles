# handoff 肥大化制御 — 全体像

- **Date**: 2026-08-13
- **対象課題**: Issue-0078 / Issue-0079 / Issue-0080 / Issue-0081
- **関連 ADR**: ADR-0086（正本移設の標準）/ ADR-0087（剪定・移設の発火体系）/ ADR-0088（節別記載規範）。部分修正: ADR-0075
- **構成**: 本ファイル（全体像・役割分担・過剰適合点検）/ `01-relocation-standard.md`（移設標準）/ `02-volume-norms.md`（定量規範・トリガー）

## 1. 背景と目的

配布先プロジェクト LoopForAlpha でハンドオフファイルの肥大化（99KB / 増加約 10KB/日）が実測された。肥大化防止策（ADR-0074/0075/0076/0077）は展開・実行されていたが、**策の設計が増加側を制御していない**ことが原因調査（2026-08-13、Issue-0078〜0081 起票）で判明した。

本設計は 4 課題への対策パッケージである。設計原則は「**情報を削らず、置き場を直す**」（ユーザー制約: ハンドオフの簡略化しすぎで引継ぎ後の作業精度を落とさない）。

| 課題 | 内容 | 対策（担当 ADR） |
|---|---|---|
| Issue-0079 | 「正本が handoff のみ」の保護が無上限 | 種類別対応表と finalize 移設工程（ADR-0086） |
| Issue-0078 | リセット間隔×増加速度が防止策の射程外 | サイズ実測トリガー＋cycle-reset 発火点一般化（ADR-0087） |
| Issue-0080 | 消化記録 1 行の長さ・内容規範がない | 1 行の内容限定・目安 200 字（ADR-0088） |
| Issue-0081 | 自由記述部の分量規範がない | 節別の分量・形式規範＋圧縮記録の残置禁止（ADR-0088） |

## 2. 役割分担の原則（配置定義とスキル手順）

本設計の基盤となる責務境界（ADR-0086 決定 1）:

| 責務 | 正本 | 配布経路との対応 |
|---|---|---|
| 情報分類と配置先の定義（What/Where） | `docs/overview/folder-structure.md`（「配置判断の唯一の参照元」） | template 配布 = プロジェクト初期に複製され、以後プロジェクトの所有物。フォルダ調整の受け皿 |
| 情報を移動する契機と手順（When/How） | スキル（session-handoff 等） | プラグイン配布 = 中央改定が全プロジェクトへ届く。手順改善はガイドライン側の責務 |

スキルは移設先を **5 分類の分類名**で参照し、具体パス・分類定義を再定義しない（デフォルトパスの併記は可）。folder-structure.md の削除・一本化は不採用（理由は ADR-0086 の Considered Alternatives 3）。

## 4. 完了基準

1. session-handoff スキルに移設標準・トリガー・節別規範が記載され、`build-dist.ps1` / `sync-template.ps1` の検査が全て通過する
2. 配布物（`dist/skills/session-handoff/SKILL.md`）の目視で、機械判定の届かない 5 型（半角括弧・識別子同居・実在固有名・自己参照・表示文字列）の違反がない
3. folder-structure.md の配置表に移設先の行が実在する
4. ADR-0086/0087/0088 が Accepted へ昇格し、Issue-0078〜0081 が close される

## 過剰適合点検（ADR-0079）

| 観点 | 判定 | 根拠 |
|------|------|------|
| 出所の偏り | 問題なし | 根拠は Issue-0078〜0081（LoopForAlpha 実測、2026-08-13）と Issue-0049（同じく LoopForAlpha、closed）で、出所は実質 1 プロジェクト・課題 5 件。単一出所の偏りは、数値（サイズ目安 20KB・行 200 字等）をすべて**デフォルト値（プロジェクト調整可・調整値優先）に降格**し、対応表の移設先を分類名参照（プロジェクトの folder-structure が解決）とすることで是正済み。手順（移設・トリガー・節別限定）は情報の置き場と量の一般問題でありプロジェクト固有性がない |
| システム種別依存性 | 問題なし | handoff 運用は開発対象システムの種別・技術スタックに依存しない。「数週間の長期サイクル」という運用形態が実測の背景にあるが、サイズトリガーはサイクル長と無関係に機能するため、短サイクル運用でも害がない（発火しないだけ） |
| AI モデル/ツール依存性 | 問題なし | 発動条件はファイルサイズ実測と操作契機（read/finalize/cycle-reset）で、いずれもモデル・ツール非依存にエージェントが観測・実行できる。特定モデルの挙動を前提とする規範を含まない |
| 退役経路 | 定義済み | サイズトリガーが長期にわたり未発火（肥大が構造的に再発しない）で、同型の delta が中央ストアへ現れない場合、トリガー・節別規範の簡素化・退役を候補としてユーザーへ提案する。判断はユーザーが行う（ADR-0087/0088 の Consequences に記載） |
