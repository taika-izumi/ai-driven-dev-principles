# handoff 肥大化制御 — 正本移設の標準（ADR-0086）

## 1. 種類別対応表

`session-handoff` スキルの規範として次の対応表を置く。移設先は 5 分類の**分類名**で書き、具体パスはプロジェクトの `folder-structure.md` が解決する（標準パスは参考として併記する）。

| 情報の種類 | 正本の置き場 | handoff に残すもの |
|---|---|---|
| 進行中タスクの状態・残り | handoff（唯一 handoff が正本でよい） | そのまま |
| 教訓・技術知見（テスト設計の穴・検査の落とし穴など、サイクルを跨いで再利用するもの） | 参照知識（標準: `docs/reference/`） | 参照＋1 行要約 |
| 未解決の論点・要対応事項 | 課題（標準: `docs/working/issues/`） | Issue 番号の参照 |
| 今サイクル限りの一時的な注意・ブロッカー | handoff「既知のブロッカー・懸念」（分量目安内） | 1 件 1〜2 行 |
| レビュー結果・検査の詳細 | 計画・監査記録・課題等の正本 | 消化記録 1 行（参照のみ） |

判別の指針: 「次のサイクルでも使うか?」が Yes なら参照知識へ、「誰かが対応すべき未解決事項か?」が Yes なら課題へ、「今サイクルの作業状態か?」が Yes なら handoff に残す。

## 2. finalize の移設工程

finalize の手順を「**(0) 移設 → (1) 基準付き圧縮 → (2) 次アクション整備 → …**」の順に再構成する。移設工程 (0) の内容:

1. handoff を走査し、対応表の「参照知識」「課題」行に該当する記述（handoff が正本になっているもの）を特定する
2. 特定した記述ごとに、正本を外部へ作成または追記する:
   - 教訓・知見 → 参照知識のドキュメントへ追記（該当ドキュメントがなければ新設。種別サブフォルダはオンデマンド作成の運用規約に従う）
   - 未解決事項 → 課題として起票（既存課題に一般形があれば「検討状況」へ追記）
3. handoff 側の記述を「参照＋1 行要約」へ置換する
4. 移設は「情報の削減」ではなく「正本の引っ越し」である。移設先で情報が減っていないことを確認してから handoff 側を置換する

平時（サイズ目安内）の finalize では、移設は「対応表に該当する記述を見つけたら行う」でよい。サイズ目安超過時（`02-volume-norms.md`）は移設工程を必須実施する。

## 3. ADR-0075 の部分修正

「圧縮しないもの＝正本が handoff 以外にないもの」の保護規定は維持する。ただしこの保護は**移設工程とセット**で運用する: 正本が handoff にしかない状態を圧縮で保護し続けるのではなく、移設で正本を外へ作り、保護対象から外していく。ADR-0075 は Accepted のまま、Consequences に部分修正を追記する。
