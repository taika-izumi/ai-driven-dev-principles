# handoff 肥大化制御 — 正本移設の標準（ADR-0086）

## 1. 種類別対応表

`session-handoff` スキルの規範として次の対応表を置く。移設先は 5 分類の**分類名**で書き、標準パスを括弧で併記する（具体パスの解決はプロジェクトの `folder-structure.md`。ADR-0089）。

| 情報の種類 | 正本の置き場 | handoff に残すもの |
|---|---|---|
| 進行中タスクの状態・残り | handoff（進行中の作業。唯一 handoff が正本でよい） | そのまま（節別規範の分量内） |
| 教訓のうち、スキル化・ルール化に有用な delta 型（AI の挙動と必要だったことの差分） | worklog 中央ストア（記録経路は worklog-record） | 記録済みなら削除してよい（worklog が消費装置を持つため参照も不要） |
| 教訓のうち、プロジェクト固有の参照知識（次サイクルの作業者が読む運用ノウハウ・既知の落とし穴） | 参照知識（標準: `docs/reference/`） | 「関連ドキュメント」節に正本ドキュメント単位で参照 1 行 |
| 未解決の論点・要対応事項 | 課題＝進行中の作業（標準: `docs/working/issues/`） | Issue 番号の参照 |
| 今サイクル限りの一時的な注意・ブロッカー | handoff「既知のブロッカー・懸念」 | 1 件 200 字以内 |
| レビュー結果・検査の詳細 | 計画・課題・記録類の正本（進行中の作業または追跡型の記録） | 消化記録 1 行（参照のみ） |

判別の指針: 「AI の挙動改善に使う差分か?」→ worklog、「次サイクルの人間・AI が読み返す知識か?」→ 参照知識、「誰かが対応すべき未解決事項か?」→ 課題、「今サイクルの作業状態か?」→ handoff に残す。

## 2. 独立手順「移設」

移設は操作（read/update/finalize/cycle-reset）から独立した名前付き手順としてスキルに定義し、次の 3 箇所から参照する: **(a)** finalize の圧縮前段（必須工程）、**(b)** read でサイズ超過を提案しユーザーが受諾した時（その場で実行）、**(c)** cycle-reset の申し送り現役性点検の前段（教訓型を落とす前に移設する）。

手順:

1. handoff を走査し、対応表の worklog / 参照知識 / 課題行に該当する記述（handoff が正本になっているもの）を特定する
2. 移設対象の一覧（何をどこへ移すか）をユーザーへサマリー提示する（複数ファイル変更の中リスク対応）
3. 正本を外部へ作成または追記する:
   - delta 型の教訓 → worklog-record の記録経路へ（既に記録済みならこのステップは不要）
   - 参照知識 → 該当ドキュメントへ追記（なければ新設。**初回は置き場のディレクトリと索引 README を作成し**、以後ドキュメント追加時に索引へ行を足す）
   - 未解決事項 → 課題として起票（**インデックスへの 1 行追加と通し採番を含む**。既存課題に一般形があれば「検討状況」へ追記。system/flow の分岐はプロジェクトの課題管理規約に従う）
4. handoff 側の記述を対応表の「handoff に残すもの」へ置換する。参照知識への参照は「関連ドキュメント」節に**正本ドキュメント単位で 1 行**（項目単位に並べない。cycle-reset では正本側の索引に載っているものは handoff から落としてよい）
5. 移設は「情報の削減」ではなく「正本の引っ越し」である。移設先で情報が減っていないことを確認してから handoff 側を置換する
6. **移設で作成・更新した正本ファイルを、handoff と同じコミットに含める**（finalize のコミット手順を拡張。正本が git 履歴に入らないまま handoff が参照だけになる状態を防ぐ）

## 3. finalize の手順再構成と「圧縮しないもの」の改稿

finalize の手順を次の 7 段に再構成する（現行 5 段との対応を括弧で示す）:

1. サイズ実測（新設。`02-volume-norms.md` §1）
2. update と同様の更新（現行 1）
3. 移設（新設。本ファイル §2。サイズ超過時は必須、平時は該当記述を見つけたら実施）
4. 基準付き圧縮（現行 2）
5. 「次セッション開始時のアクション」整備（現行 3）
6. Status 更新（現行 4）
7. コミット（現行 5。**移設先の正本ファイルを add 対象に含める**）

「圧縮しないもの」規定（現行 finalize 手順 2 内）へ次の趣旨の文を追加する: 「正本が handoff 以外にないもの」の保護は、**移設で正本を外へ作るまでの暫定**である。移設手順の対応表に該当する記述は、保護を理由に移設をスキップしない。

## 4. ADR-0075 の部分修正

「圧縮しないもの＝正本が handoff 以外にないもの」の規定は維持するが、保護は移設手順とセットで運用する。ADR-0075 は Accepted のまま、Consequences に部分修正を追記する（既存の ADR-0080 由来の注記とは対象条項が異なり両立する）。

## 5. folder-structure.md への変更

配置表（「6. 代表的なドキュメント種別の配置表」）の既存行を拡張する（新規行は追加しない。同一配置先の行が並ぶ重複を避けるため）:

- 変更前: `| 技術調査・検証メモ | docs/reference/ |`
- 変更後: `| 技術調査・検証メモ、セッション跨ぎに再利用する教訓・作業知見 | docs/reference/ |`

## 6. SKILL.md へ写すときの記法

session-handoff は配布対象ソースである。本 spec の表・規範文を SKILL.md へ写すときは記法規約に従うこと: 出所識別子は全角括弧に単独で置く（説明語と同居させない）、実在プロジェクト名（実測の出所など）は書かない（必要なら出所注記の形にする）、根拠の実測値は ADR 側を正本とし SKILL.md には規範文のみを書く。
