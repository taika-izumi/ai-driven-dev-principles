# handoff 肥大化制御 — 定量規範とトリガー（ADR-0087 / ADR-0088）

数値はすべて**デフォルト値**である。プロジェクトが調整する場合は自プロジェクトの CLAUDE.md に調整値を明記し、スキルはそれを優先する。字数は全角換算の文字数。

## 1. サイズ実測トリガー（ADR-0087）

- **実測位置**: read は対象ファイルの**存在確認の直後**、finalize は**手順冒頭**（手順 1）
- **実測手段**: シェルで行う（専用スクリプトは設けない）。例: PowerShell `(Get-Item <path>).Length`、POSIX `wc -c < <path>`。単位は 1KB = 1000 バイト
- **目安値（デフォルト）**: **40KB**。根拠: cycle-reset 直後のクリーンな実測（23KB / 15.3KB）に、実測された 1 サイクル分の健全な増分（約 8.6KB）を積み、プロジェクト差の余裕を持たせた水準。ガイドライン配信元リポジトリの handoff 全 20 ファイル（最大 23.9KB）への試算で発火 0 件＝健全なファイルをすべて許容し、実測された肥大（97〜99KB）は確実に捕捉する。異常増加（実測級の 10KB/日）の再発時はリセット後 2 週間前後で発火する。節別規範が守られる平時は発火しない
- **read 時に超過**: ハンドオフ要約の提示に移設・剪定の提案を添える。ユーザーが受諾したら、独立手順「移設」（`01-relocation-standard.md` §2）を**その場で実行する**
- **finalize 時に超過**: 移設を必須実施する。移設候補がなく、基準付き圧縮を再適用しても超過が解けない場合は、目安値の調整をユーザーへ提起する

## 2. cycle-reset の扱い（ADR-0087）

当初案の「発火点を作業単位完了時へ一般化」は**撤回**した（発火ゲートは呼び出し元 retrospective にあり文言変更が無効。仮に retrospective を経ず発火させると worklog 総ざらいの情報源と `review=` 保持を壊す。ADR-0087 の Considered Alternatives 3）。呼び出し関係の一般化は Issue-0050 の検討へ委ね、サイクル内の実効制御はサイズトリガーが担う。

本節（cycle-reset の扱い）に由来する session-handoff 側の変更は次の 2 点のみ（サイズトリガー由来の変更は §1、移設まわりの変更は `01-relocation-standard.md` が定める）:

1. cycle-reset 手順 2（申し送りの現役性点検）の**前段に移設判定を追加**する（教訓型の申し送りを、落とす前に対応表で移設する。`01-relocation-standard.md` §2 (c)）
2. 「本サイクル」の定義を「現 feature ブランチの作業単位（cycle-reset まで）」から「**前回 cycle-reset から次の cycle-reset までの作業単位**」へ改める（master 直接開発では feature ブランチが存在せず保持範囲が定義不能になるため。`skills/session-handoff/SKILL.md` と `skills/start-work/SKILL.md` の該当文言を同語彙へ揃える）

## 3. 節別の記載規範（ADR-0088）

session-handoff のフォーマット節・update 手順に以下を明記する。

| 節・要素 | 規範 |
|---|---|
| 消化記録の 1 行 | 現行形式の必須要素（日付・マイルストーン名（確定点ラベル含む）・`ADR=` / `worklog=` / `review=` の各フィールド・なし/棄却時の理由）は**維持**。各フィールド値は「判定結果＋安定識別子＋正本への参照」に限定。1 行 200 字以内。詳細は正本側へ |
| タイトル（見出し 1 行） | 作業名のみ。進捗・状態・参照は Status / Current Phase / 本文の各節へ |
| 次セッション開始時のアクション | 3 項目・各 200 字以内。詳細は参照で書く |
| 「要点のみ」と称する抜粋（全節共通） | 1 項目 200 字以内。必ず正本への参照を伴う |
| 既知のブロッカー・懸念 | 1 件 200 字以内。教訓型に膨らんだものは移設対象 |
| **列挙外の節への既定規則** | 個別の定めがない節（完了済みタスク・未着手のタスク・作業の目的・背景・重要な意思決定の履歴など）も 1 項目 200 字以内を既定とし、超える内容は対応表に従って正本へ移して参照に置き換える。ただし handoff が正本の記述（進行中タスクの状態・残り）は移設対象外とし、200 字超過時は項目を分割する（項目数は制約しないため） |
| 圧縮・削除の実施記録 | handoff に残さない（受け皿は git 履歴のみ。ADR-0074 との整合を明文化） |

update 手順に「詳細を書きたくなったら正本へ書き、行には参照を書く」の分岐を明記する。項目の**数**は制約しない（作業量に比例するため）。項目数の増加による肥大は、既定規則の移設とサイズトリガーの二段構えで受け止める。

## 4. 逸脱の検出

節別規範の機械検査は設けない（handoff は自由記述文書であり、検査機構の導入・配布コストが便益に見合わない）。逸脱の累積はサイズトリガーの発火時にまとめて検出・是正される。
