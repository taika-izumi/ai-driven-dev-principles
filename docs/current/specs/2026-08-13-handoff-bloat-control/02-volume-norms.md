# handoff 肥大化制御 — 定量規範とトリガー（ADR-0087 / ADR-0088）

数値はすべて**デフォルト値**である。プロジェクトが調整する場合は自プロジェクトの指示文書（CLAUDE.md 等）に調整値を明記し、それを優先する。

## 1. サイズ実測トリガー（ADR-0087）

- **実測**: read / finalize の手順冒頭で handoff ファイルのサイズをシェルコマンドで実測する（専用スクリプトは設けない）
- **目安値（デフォルト）**: 20KB。根拠は LoopForAlpha 実測（健全時 6.9KB・肥大時 99KB・cycle-reset 直後 23KB）から「1 サイクル分の正常な蓄積を許容しつつ肥大の初期に発火する」水準
- **read 時に超過**: ハンドオフ要約の提示に移設・剪定の提案を添える（実施はユーザー判断）
- **finalize 時に超過**: 移設工程（`01-relocation-standard.md`）を必須実施する。移設候補がなく、基準付き圧縮を再適用しても超過が解けない場合は、目安値の調整をユーザーへ提起する

## 2. cycle-reset 発火点の一般化（ADR-0087）

session-handoff の cycle-reset の発火点記述を「サブプロジェクトの master マージ後」から「**作業単位（サブプロジェクト・段階）の完了時**」へ改める。master 直接開発など、マージという節目を持たない運用でも段階完了時に発火できるようにする。retrospective の起動粒度（サブプロジェクト単位）と呼び出し関係（retrospective の仕上げから呼ばれる）は変えない。

## 3. 節別の記載規範（ADR-0088）

session-handoff のフォーマット節・update 手順に以下を明記する。

| 節・要素 | 規範 |
|---|---|
| 消化記録の 1 行 | 「判定結果＋安定識別子（ADR 番号 / worklog id / Issue 番号 / コミットハッシュ）＋正本への参照」に限定。目安 200 字。詳細は正本側へ |
| タイトル（見出し 1 行） | 作業名のみ。進捗・状態・参照は Status / Current Phase / 本文の各節へ |
| 次セッション開始時のアクション | 3 項目・各 1〜2 行。詳細は参照で書く |
| 「要点のみ」と称する抜粋 | 1 項目 1〜2 行。必ず正本への参照を伴う |
| 既知のブロッカー・懸念 | 1 件 1〜2 行。教訓型に膨らんだものは移設対象 |
| 圧縮・削除の実施記録 | handoff に残さない（受け皿は git 履歴のみ。ADR-0074 との整合を明文化） |

update 手順に「詳細を書きたくなったら正本へ書き、行には参照を書く」の分岐を明記する。

## 4. 逸脱の検出

節別規範の機械検査は設けない（handoff は自由記述文書であり、検査機構の導入・配布コストが便益に見合わない）。逸脱の累積はサイズトリガーの発火時にまとめて検出・是正される（二段構え: 書く時点の規範＋サイズの安全網）。
