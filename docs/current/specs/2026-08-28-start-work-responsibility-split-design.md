## 背景・目的

start-work スキルの責務過多の指摘を分析し、妥当と判定した（2026-08-28 実測）。`skills/start-work/SKILL.md` は 34,676 バイトで全 13 スキル中最大。バイト実測で本文の約 49% を「確定前レビューの提示規則」、約 12% を「完了処理のマージ方式確認」が占め、オーケストレーション以外のドメイン規範の正本 2 つが本文の約 6 割を構成する。start-work は毎セッション冒頭で全文読み込まれるため、確定点に到達しないセッションでもこの分のコンテキスト費用が発生する。

本改修は、この 2 節を責務の所有者へ移設し（ADR-0116）、start-work をオーケストレーションとポインタに絞る。**便益は確定点に到達しないセッションに限る**: 確定点に到達するセッションでは start-work 残留分＋pre-finalization-review の合計が現行の start-work 単体を約 10KB 上回る（正味増）。この増加は、毎セッション費用の削減と正本帰属の正常化の対価として受容する。スコープは start-work の分割に限定し、SKILL.md サイズ・分割の一般規範は扱わない（ADR-0115）。

## 設計 3: 責務境界の明文化

1. **start-work 本文への境界宣言**（「いつ使うか」直後、2〜3 行）: 「start-work が正本として持つのはオーケストレーション（フェーズ構造・次手ナビゲーション・節目の前後で行う共通処理の接続の記述・セッション終了処理）のみ。ドメイン規範の正本は所有スキルへ、所有スキルが無いものは `references/` 配下へ置き、本文には発火点のポインタのみを書く」
2. **pre-finalization-review 本文への管轄宣言**（1〜2 行）: 「確定点の定義・提示・推奨順位・反復・停止判定・実施方式の正本は本スキル」
3. **CONTRIBUTING.md の start-work シナリオ**: 既存チェックリスト項目「フェーズの責務分離が崩れていないか」を「フェーズの責務分離が崩れていないか（ドメイン規範の正本を本文へ持ち込んでいないか。正本は所有スキルまたは references へ）」に文言拡張する。新規チェックリスト項目（新規観点）は追加しない

**新設の評価可能性（ADR-0102）の扱い**: 境界宣言・管轄宣言は拘束的な文の新規追加（＝新設）にあたるため、ADR-0116 に「既存工程の文言拡張で足りないかの比較」「期待検出量」「向き付きの廃止の条件」を記載済み（点検ブロックは本 spec 側にあるため、ADR へ直接記載する型）。チェックリスト側は既存項目の文言拡張であり新設を発生させない。

置き場の判断根拠: スキル拡張の全経路で必ず読まれるのは CONTRIBUTING.md（extend-guidelines 手順 1・3）。extend-guidelines スキル本体は判定基準の正本を CONTRIBUTING に置く薄いゲートウェイ設計であり、そこへ規範本文を書くと本改修が解消する構造と同型になる。worklog-skillify の references は worklog 経路限定で通常改定では発火しない。superpowers:writing-skills は外部プラグインで改変不可。

## 設計 4: 検証・執行手順

### 移設の同一性検証（条文複写禁止の担保）

   - (ii) 操作分化に伴う節見出し・導入文
