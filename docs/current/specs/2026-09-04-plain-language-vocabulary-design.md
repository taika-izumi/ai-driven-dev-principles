# 規範文書の語彙を平易表現規約へ適合させる 設計書

- **Date**: 2026-09-04
- **Status**: Draft（brainstorming の設計承認済み。確定前レビュー未実施）
- **関連 ADR**: ADR-0123（本設計の決定）・ADR-0022（平易表現規約の導入。据え置き）・ADR-0057（実行後処理の記録の導入。識別子改名の部分修正対象）・ADR-0079（過剰適合点検。表の行名改名の部分修正対象）・ADR-0121（SKILL.md サイズ警告。検査の型の先例）
- **関連 Issue**: Issue-0119（本設計の対象課題）・Issue-0043（意思決定要求の用語提示。隣接・open 維持）・LoopForAlpha#Issue-0131（配布先文書側の同型。配布先が所有）

## 背景・目的

`AGENTS.md`「コンテキスト管理」は「文章だけを読んで意味が推測できる説明的な表現を用い、その場限りで定義のない略号・記号的呼称は使わない」と定める（ADR-0022）。ところが配信スキル自身の文面がこの条件を満たさない語と記号的ラベルを多用し、AI がそれを写して配布先の対話・成果物へ伝播している（Issue-0119。配布先 LoopForAlpha の 8 セッション観測から申し送り）。

配布先の観測で固まった知見:

- 規約より読み込んだ文書の語彙のほうが強い。出所を直さない限り頻度は下がらない
- 「専門用語を避けよ」型の禁止指示は括弧説明を誘発し、語の置き換えより 1 桁大きいトークン増を毎回起こす
- 語彙の供給源はサイクルの局面ごとに入れ替わる。合計回数だけで優先度を決めてはいけない
- 記号的ラベルの供給源は 2 系統から 4 系統へ増えた。放置すると再流入する
- 配布先は配信物由来語を成果物の構造名（表の列名・節見出し）として定着させる。識別子の改名は移行を伴う

本設計は、**出所である規範文書の語彙を直す**ことを主対策とし、再流入を自動検査で検知する。配布先向けの新しい規則は追加しない（変数を 1 つずつ変え、効果を配布先の観測で切り分けるため）。

## 設計 1: 射程の定義

対象とする「平易でない語」を 3 型で定める。判定条件は配布先が示した 2 条件（(1) 一般的に認知されていない、または一般的な意味で使っていない (2) 同程度の文字数の一般的な語に置き換え可能）を引き継ぐ。

| 型 | 定義 | 対策 |
|---|---|---|
| 型 1: 語自体型 | 語そのものが業界外で通じない、または誤用（例: 突合・消し込み・母数・裁定） | 同長の一般語へ置き換える |
| 型 2: 目的語省略型 | 語は一般的だが、何に対する動作かを示す目的語がガイドライン固有で、それを省いて使っている（例: 「昇格」「退役」を裸で使う） | 識別子（見出し・行名・フィールド名・ラベル）には目的語を埋め込む。文中は意味が取れない箇所に限って目的語を添える |
| 記号的ラベル | 定義箇所以外では意味が推測できない英字・番号のラベル（例: `A 群`・`採用基準 (i)`・`観点 4`・`spec 確定点 (a)`） | 定義箇所で名前を与え、参照箇所は名前（必要なら番号を併記）で書く |

**射程外**:

- システム開発の現場で使いうる語（写経・委譲・起票・縮退・発火・閾値・ゲート・棚卸し など）。判定はユーザーの主観に依存するため、境界の語は本文書の表で個別に確定する
- 同長の一般語で置き換えると意味が変わる固有概念語（正本・確定点・移設 など）。「正本」は「唯一の定義元で他所は参照のみ」という重複禁止の規律を担うため据え置く
- 英字キー（`ADR=` `worklog=` `review=` `cyclecheck=`）。機械可読の書式
- LLM の言語的な癖として出る語（申し送りの対象外規定を引き継ぐ）

**対象文書**: AI が作業時に読み込む規範・案内文書 = 配布対象ソース（`skills/` 配下・`template.manifest` の 6 ファイル）＋ `CONTRIBUTING.md`・`README.md`・`docs/reference/`。記録型・作業中文書（`docs/records/`・`docs/working/`）は追記型規約と参照時にしか読まれない性質から対象外。`AGENTS.md` の条項の文面は据え置く（`突合` 1 語の置き換えを除く）。

## 設計 3: 規約の置き場と自動検査

### 3-1. `CONTRIBUTING.md` の新節「全シナリオ共通: 規範文書の語彙」

既存の共通節と同じ構成（適用対象・背景・規約・執行点・退役規範）で置く。

- 適用対象: 設計 1 の対象文書
- 規約: 設計 1 の 3 型と対策、判定条件 2 点、射程外の 4 種
- 検査対象の設計原則: 自動検査のテーブルに入れる文字列は「置き換え後に残っていたら構文的に誤りと言えるもの」（型 1 の語・旧識別子・固有の並びを持つラベル型）に限る。文脈の判定を要する語（型 2 の文中の裸の使用、単独の英字括弧）は入れない
- テーブル運用の規律: 警告が出たら置き換えるか、理由つきで許可リストへ登録する。正当な用法が繰り返し出るようになった語はテーブルから外す
- 型 2 の文中の裸の使用は「Skill を新規作成・改定するとき」のチェックリスト項目と確定前レビューで受ける（自動化しない）
- 執行点: 既存の執行点 4 手順の中で `check-vocabulary.ps1` が自動実行される。追加手順なし
- 退役規範: 警告の発火が長期にわたり 0 件で、かつ配布先から語彙起因の課題・worklog delta が中央ストアへ現れない状態が観測されたら、本規範と検査の簡素化・退役を候補としてユーザーへ提案する（サイズ警告の退役規範と同型）

### 3-2. 構成要素と責務

| 構成要素 | 場所 | 責務 |
|---|---|---|
| 規則の定義 | `CONTRIBUTING.md` 新節 | 規範の唯一の置き場。テーブルへ行を足す・外す・許可リストへ登録する判断基準 |
| 置き換え表・ラベル型・旧識別子・許可リストのデータ | `scripts/vocabulary-rules.json`（新規） | データの唯一の置き場。配布物には含まれない（`scripts/` は template にも dist にも入らない） |
| 検査の実行 | `scripts/check-vocabulary.ps1`（新規） | 規則ファイルを読み、対象文書を走査して `Write-Warning` を出す。単体実行可 |
| 呼び出し | `build-dist.ps1`・`sync-template.ps1` の末尾 | 既存の執行点 4 手順の中で自動実行。`check-claude-md-size.ps1` の先例と同型 |

### 3-3. 規則ファイルの構造

```json
{
  "targets": ["skills/**/*.md", "CONTRIBUTING.md", "README.md", "docs/reference/*.md", "@template.manifest"],
  "words": [
    { "pattern": "突合", "replacement": "照合", "legitimate": "なし", "note": "..." },
    { "pattern": "前置(?!き)", "replacement": "前に付ける / 接頭辞", "legitimate": "「前置き」は除外条件で対応済み" },
    { "pattern": "母数", "replacement": "対象の総数", "legitimate": "母集団の特性値の意味。許可リストへ" }
  ],
  "labels": [
    { "pattern": "[AB] ?群", "replacement": "常時項目 / 条件項目" },
    { "pattern": "spec ?確定点 ?\\([abc]\\)", "replacement": "spec 確定点（機能ブロック型 / 設計文書型 / ADR 兼用型）" },
    { "pattern": "観点 ?[1-5](?!（)", "replacement": "観点 N（名前）の形で名前を併記" }
  ],
  "identifiers": [
    { "old": "Post ラッパー消化記録", "new": "実行後処理の記録" },
    { "old": "B群判定:", "new": "条件項目判定:" },
    { "old": "逸脱突合:", "new": "逸脱照合:" },
    { "old": "退役経路", "new": "規範の退役条件" }
  ],
  "allow": [
    { "file": "skills/session-handoff/references/op-read.md", "pattern": "Post ラッパー消化記録", "count": 1, "reason": "旧見出しの互換読み取り" }
  ]
}
```

- `targets` の `@template.manifest` は、検査スクリプトが `template.manifest` を読んで対象ファイルへ展開する指定（manifest とリストの二重管理を避ける）
- `words` / `labels` / `identifiers` の各行は「置き換え先」と「正当な用法の例」を持ち、警告文に出す（読んだ人が誤検知かどうかをその場で判断できるようにする）
- `allow` は「ファイル ＋ 正規表現 ＋ 許容回数 ＋ 理由」。そのファイル内の出現回数が許容回数を**超えた分だけ**警告する。ファイル単位の除外・行番号指定は採らない（前者は新しい使用が見えなくなり、後者は編集で行がずれるたびに更新が要る）。同じファイルで 1 件消えて 1 件増えると素通りする残余は、非ブロック検査のリスクとして受容し確定前レビューで受ける

### 3-4. 検査スクリプトの挙動

- 対象文書を走査し、`words` / `labels` / `identifiers` の各パターンに一致した箇所を `allow` で差し引き、残りを `Write-Warning` で「ファイル:行 一致文字列 → 置き換え先（正当な用法の例）」の形で 1 件ずつ出す
- 非ブロック（exit 0）。ブロック化への昇格は、警告が無視されたまま配布された実測が出た時点で候補にする（判断はユーザー）
- 正規表現は UTF-8 の Unicode 文字列として扱う（PowerShell / .NET の落とし穴は `docs/reference/powershell-pitfalls.md` を参照して実装時に実測する）

## 設計 4: 識別子の改名と互換処理

| 識別子 | 旧 | 新 | 互換処理 |
|---|---|---|---|
| handoff の節見出し | Post ラッパー消化記録 | 実行後処理の記録 | `op-read` は新旧どちらの見出しでも節を見つけて欠落検査する。`op-update` / `op-finalize` / `op-cycle-reset` は旧見出しを見つけたら新見出しへ書き換える（本文無改変） |
| handoff のマイルストーン名 | spec 確定点 (a)/(b)/(c) | spec 確定点（機能ブロック型）/（設計文書型）/（ADR 兼用型） | `op-read` の欠落検査は「spec 確定点」「plan 確定点」の接頭だけで照合する（旧行も新行も同じ規則で通る） |
| 委譲プロンプトの判定行 | `B群判定:` | `条件項目判定:` | 一過性の行のため互換処理なし |
| タスク完了報告の行 | `逸脱突合:` | `逸脱照合:` | 計画ファイルへ書く `逸脱記録:` は据え置き。完了報告は一過性のため互換処理なし |
| 過剰適合点検の表の行名 | 退役経路 | 規範の退役条件 | 既存 ADR の点検ブロックは記録として据え置き。棚卸しの走査（見出し `過剰適合点検` の検索）には影響しない |

互換処理の退役条件（観測可能・向きつき）: 本リポジトリの `Status: in_progress` の handoff に旧見出しが 0 件で、かつ配布先から旧見出し起因の報告が 3 サイクル無い状態が観測されたら、旧見出しの認識行を外す。旧見出しの報告が 1 件でもあれば存置側。

配布先への周知は README には書かない（互換処理が自動で手作業が不要なため）。新旧対応表は ADR-0123 と `scripts/vocabulary-rules.json` の `identifiers` に置き、配布先はそれを参照する。

## 設計 5: Accepted 済み ADR への改訂記録の線引き（ADR-0108）

- **注記する**: 改名した識別子を決定本文が定めている ADR。「Post ラッパー消化記録」を定めた ADR-0057、`A 群 / B 群` を定めた ADR-0066 / 0070 / 0071、`spec 確定点 (a)(b)(c)` を定めた ADR、`逸脱突合:` を定めた ADR-0119、「退役経路」を定めた ADR-0079 など。注記は Consequences 内の部分修正注記（ADR-0122 サイクルと同じ形式）。件数は計画作成時に全数走査で確定する
- **注記しない**: 文中の語（突合・消化・母数 など）が本文に現れるだけの ADR。意味を変えない語の置き換えは決定の内容に影響しないため

## 設計 6: 実施手順の制約・検証・完了条件

### 6-1. 置き換えの実施手順

- 語ごとに全出現を列挙し、文脈を見て 1 件ずつ置き換える（一括置換はしない）。引用箇所・互換処理の行は許可リストへ登録する
- ラベルは定義箇所に名前を置いてから参照箇所を直す
- 各語の完了ごとに diff を取り、列挙外の差分がないことを確認する（ADR-0122 サイクルの検証と同型）

### 6-2. サイズ制約

- `retrospective/SKILL.md`（19,042B）と `pre-finalization-review/SKILL.md`（17,539B）は目安値 20,000B に近い。置き換え後に各 SKILL.md が目安値未満であることを完了条件に含める。超えた場合は ADR-0121 の判断（責務帰属型 → references 型 → 例外登録）へ進み、その判断を ADR-0123 に追記する
- `AGENTS.md` は `突合` 1 語の置き換えのみで、`check-claude-md-size.ps1` の計測に影響しない

### 6-3. 完了条件

1. `check-vocabulary.ps1` を実行し、警告 0 件（許可リスト分を除く）
2. 全 `skills/*/SKILL.md` が 20,000B 未満
3. 執行点 4 手順を通過（両生成器の `-Check` が exit 0）
4. 本リポジトリの handoff で旧見出しを持つ `in_progress` のファイルを `op-update` で 1 件更新し、新見出しへ移行することを実測
5. 改名した識別子を定めた Accepted 済み ADR への部分修正注記が全件済み
6. plugin version 0.1.19

### 6-4. 効果の観測と再評価の条件

- 配信元で観測できるのは「対象文書の該当語 0 件」まで。伝播の減少は配布先の観測に依存する
- 再評価の条件: 0.1.19 以降、配布先で 3 サイクル観測しても成果物由来の該当語の紛れ込みが減らない（配布先の課題または申し送りとして報告される）場合、`AGENTS.md` の射程明示を次サイクルの候補にする。減った場合は本課題の前提「出所を直せば頻度が下がる」が支持され、追加対策はしない
- 型 2 の対話での効果は本サイクルでは期待しない。固定文字列として写される識別子への効果は確実だが、対話の文は AI が自分の状態から生成するため複合形が保たれる保証がない。同じ観測で測る

## 過剰適合点検（ADR-0079）

| 観点 | 判定 | 根拠 |
|------|------|------|
| 出所の偏り | 問題なし | 根拠は配布先 LoopForAlpha 1 プロジェクトの 8 セッション観測（利用者が語の意味を尋ねた実例 2 件・記号的ラベルの供給源 4 系統・構造名への定着 2 件）と本リポジトリの文書実測（2026-09-04）。モデル世代は申し送り資料に明記なし。出所は単一プロジェクトだが、本拡張が配布先へ届ける変更は規範文書の語の置き換えのみで、配布先の AI に新しい行動規範を課さない。新設する規約（CONTRIBUTING 新節）と検査（`scripts/`）は本リポジトリの書き手向けで配布されない。`AGENTS.md` の条項は据え置く |
| システム種別依存性 | 問題なし | 特定のシステム種類・技術スタックの前提なし。引き写し箇所: (1) `AGENTS.md`「コンテキスト管理」の平易表現条項（引用元は無条件の命名基準でゲートなし。引き継ぎ判定: 落としていない） (2) 配布先が示した判定条件 2 点（引用元は語の判定基準でゲートなし。引き継ぎ判定: 落としていない） (3) ADR-0121 のサイズ警告の型（非ブロック・目安・例外テーブル。引用元のゲート「`skills/` 変更時の生成器実行」を執行点として引き継ぐ） |
| AIモデル/ツール依存性 | 問題なし | 前提「AI は読み込んだ文書の語彙を写す」は LLM 一般の性質で、より高性能なモデルの性能発揮を制限する方向には働かない（平易な語で書かれた文書は全モデルに読める）。検査スクリプトは PowerShell 依存だが既存生成器（`build-dist.ps1`・`sync-template.ps1`・`check-claude-md-size.ps1`）と同じ前提で、新しい依存を増やさない。引き写し箇所: 上記 (3) と同じ |
| 規範の退役条件 | 定義済み | 検査と規約: 警告の発火が 10 サイクル連続 0 件で、かつ配布先から語彙起因の課題・worklog delta が 0 件の状態が観測されたら退役側。発火あり、または課題ありなら存置側。判断はユーザー。互換処理: 設計 4 の退役条件。再評価: 設計 6-4 |
