# 各工程での適用

## 責務と対象ファイル

各工程の既存判断・検証へ、01の共通判定を接続する。判定の定義を各ファイルへ複写しない。

- `skills/start-work/references/plan-deviation-defaults.md`: 計画作成時の宣言と、実装中の妥当性・権限判定。
- `skills/pre-finalization-review/SKILL.md`、`references/review-procedure.md`、`references/iteration-norms.md`: 初回・反復の実施、指摘の採否、確定への接続。
- `skills/decision-log/references/adr-authoring.md`、`references/status-updates.md`: 委任による判断の記録・確定。
- `skills/subagent-dispatch/SKILL.md`: 委譲範囲と判断の根拠の伝達。

## 入出力

入力は01で特定した判断の分担、変更案、実体確認の結果。出力は採否・権限の判定と実施結果、または相談が必要な事項。記録方法と再開は03へ渡す。

## 計画と実装

新規計画を確定するときは、判断の分担の所在を参照し、委任された局所仕様の変更を計画の宣言欄の採用基準へ反映して照合する。具体的な変更を全て予測して列挙する必要はなく、対象領域・維持する要求・検証条件を示す。宣言欄が既定参照だけでも、その既定が委任された変更を扱えることを確認できる場合に限り足りる。合意の範囲内で詳細計画を作成・確定できる許可がある場合は、同じ設計への再承認を求めない。必要な計画検証は維持する。

実装中は既存の前提検査・型分類・採用基準を先に満たす。委任は妥当でない変更を採用する理由にはならない。基準外の変更・別の作業への拡大は、既存規範に従って課題へ分離または相談する。計画の採用基準自体を変更する必要がある場合は、計画確定時の合意と変更権限を照合する。事後的に許可範囲を広げない。

## レビュー

初回レビュー・再レビューの実施と方式選択も01の共通判定に含める。分担の提示で、後続の計画・レビュー・実装・記録にこの分担を使うことを説明し、工程別の許可を一つずつ取り直さない。レビュー判断が相談事項として留保されている場合は相談する。そうでなければ既存の必要性・方式・人数・停止条件の判断に従って実施し、検証を省略する権限を推定しない。

費用・回数等の限度が明示されている場合はそれを共通判定で適用する。指定がないこと自体を不足情報として停止したり、便宜的な数値上限を作ったりしない。既存の費用比較・停止判定・通算回数の分布外通知を用い、続行による便益と負担を判断する。分布外の値を自動打ち切りの予算へ読み替えない。具体的な影響が相談事項や明示限度へ到達する場合は相談し、委任範囲内の方式・採否判断は通知して進める。

指摘は一件ごとに前提と実証を確認する。全件採用でなくても委任範囲内なら採否を決める。見送り・縮小も共通判定で扱い、重要な保護を外す判断は相談する。既存の反復提示に必要な採否根拠・残る懸念は記録に残し、許可内では回答待ちを伴わない通知に置き換える。

既存レビューの対象に「変更が委任範囲を越えていないか」を含める。新しい独立レビュー工程は作らない。判定が覆った場合は03の差し戻しへ接続する。

## ADR

意思決定の検出・Proposed起票・根拠・既存ADRの改訂記録・Accepted昇格時の検査は維持する。採用可否と権限が確認できた判断は、許可の所在を添えて既存の確定チェックポイントで確定する。委任範囲の拡張そのものは委任を根拠に自動確定しない。

記録には「ユーザーの個別承認」または「委任に基づくAI判断」とその根拠を既存のContextまたはConsequencesへ短く書く。新しいStatusは設けない。ユーザーが既に回答した同じ設計判断を、ADRの体裁を整えたことだけを理由に再質問しない。再検討時は既存の終端ステータス規則を維持し、AcceptedからProposedへ戻さない。

## サブエージェント

委譲元が対象作業と必要な分担の抜粋・根拠の所在を渡す。委譲先は既存の実態優先の範囲で調整し、設計変更の候補・判定に迷う事項を委譲元へ報告する。委譲元が最終的な権限判定を行い、委譲先が許可を拡大しない。受け渡しでは既存環境の構造化形式を用い、専用の新しい通信基盤は作らない。

## 関連ADR
