# 実行管理

## 入出力と担当

入力は入力準備の `manifest.json` と各条件の作業コピー。出力は実行別の成果物、`events.jsonl`、`run.json`。実行管理者は作成セッションの外側で開始・期限・状態・終了を確認する。モデル自身に停止期限の強制を任せない。

`run.json` は `run_id`、`model_requested`、`models_observed`、`effort`、`condition`、`task`、`input_manifest_sha256`、`started_at`、`ended_at`、`active_wall_seconds`、`human_wait_seconds`、`status`、`stop_reason`、`child_processes`、`usage`、`artifact_hashes` を持つ。取得不能値はnullと理由を記す。認証トークンや実会話本文を転記しない。

## 起動前の成立条件

次の結果と証拠を `preflight.json` に保存する。各項目はpass/fail/unknownのいずれかと証拠パスを持つ。実行するモデルの経路について全項目passとなるまで当該モデルの本比較を起動しない。共通のCodex環境・保護・検査の証拠は再利用し、Solではモデル指定・指示の読み込み等のモデル依存部分を確認する。Claudeの失敗・未確認は過去記録へ保持し、今回の成立条件へ混ぜない。現在は準備完了までの指示に従い、起動許可を無効としている。本比較の実行指示を受けた時点で有効化する。既存の成功証拠は条件の変更がない限り再利用する。

| 項目 | 必要な証拠 |
|---|---|
| 認証 | 通常ユーザー環境のCodexがChatGPT契約による認証。APIキー経路へ切り替わっていない |
| 版とモデル | Codex CLIの版、要求ID・推論設定、起動結果の実モデル名。自動切り替えがあれば不一致として止める |
| 指示分離 | 起動時に読まれた設定・AGENTS・プラグイン・メモリと親子への継承を記録し、共通情報と意図した差だけである |
| 書き込み境界 | 許可内の無害なファイルは作成でき、許可外の保護確認用ファイルは親・子とも書き換えられない。作成・採点の双方で元リポジトリ・通常設定・共有Python環境への変更を許さない同じ境界を確認し、外側から実体を読み直す |
| 固定検査保護 | 作成側から検査原本・相手成果・原本プロジェクトへ変更できない |
| 停止 | 無害な親子プロセスを停止し、親だけの終了ではなく子の消滅も外側から確認する |
| 回収 | 実モデル名・親子の対応・利用量・開始終了・終了理由と固定成果物が回収できる。重複計数を排除できる |
| 検査の識別 | 固定検査が正常例を通し、未修正例・意図した不合格例を落とす |

認証・CLIヘルプの読み取り以外のモデル起動を含む事前確認も利用枠を消費するため、起動操作の承認対象に含める。準備・検査の経過時間を記録し、継続はADR-0169の必要性・進捗の条件に従う。CLIオプションの存在だけでは各項目をpassにしない。

起動前の提示にはモデル別の時間・利用量の見込みも含める。初期の時間見込みは各モデル4実行で40〜120分（題材の規模からの未実測の概算）、各モデルの作成側上限は120分。トークンと契約枠の消費量は事前不明で、最初の対比較の実測後に残りの見込みを更新する。請求額に換算しない。準備では、同じ試行で証拠が増えない、検証だけが増えて比較開始・評価へ近づかない場合は止め、原因と進め方を相談する。

Codexの認証はサンドボックス内で未ログイン、通常ユーザー権限ではChatGPTログイン済みという結果だった。認証を移し替えず、通常ユーザー側の公式実行経路と生成コマンドのサンドボックスを区別する。親のCLIに認証があっても、その子の権限が適切とは限らない。

試験条件の分離は通常の設定を変更せず、試験専用の設定とコピーで行う。公式の設定読み込み元制御を検証して採用する。採点原本の保護を成立させるために独自の常設隔離基盤を実装しない。制約を満たす公式経路が見つからなければfail/unknownのまま記録し、比較不能時の進路を相談する。

事前確認は完了。両モデルの共通スキル一覧、親子の内蔵編集と拒否、モデル・推論設定・利用量を確認した。Astra既存手順の子は同じ構成の過去成功記録を再利用し、公式入力のルート別名は実パスへ展開して照合した。停止時の取得不能値はnullと理由を保存し、完全回収と報告しない。取得不能を許容する既存の出力契約と、観測できた利用量を回収する処理の成立を区別する。

## 実行資料と採点接続

試験ルートのcontrol/launch-packet/openai-comparison-20260911.jsonに8実行・12段階を保存する。control/runtime/run-openai-comparison.ps1は準備完了・起動許可・依頼とmanifestのハッシュ・未終了の比較・再開の前提を確認し、各実行と全体の残時間を外側で計数する。起動後はcontrol/runtime/analyze-codex-preflight.ps1で子孫の公式記録を回収する。

採点はcontrol/runtime/grade-openai-comparison.ps1を使う。元のcontrolのdenyを保ち、停止済み成果物・固定検査を採点専用コピーへ複製する。採点コピーだけをwriteとし、原本・相手成果・通常設定・共有Pythonへ変更できない公式サンドボックス経路を使う。ROOTと固定依存の起動先だけをコピーに対応させ、機能の検査条件は変えない。採点コピーの改変に対する偽装耐性を保証しないことは仕様03の限界に含む。

## 時計・停止・再開

各実行の30分は、開始から終了までの稼働経過時間として子の並列動作を含む。中断・再開でリセットしない。人への相談中は親子を止め、回答待ちを別記する。確認済みの停止手段が使えなければ後続起動を止める。対象8実行の上限は240分。準備・採点の残作業はADR-0169の条件付き継続許可に従い、準備不備による試行も費用・時間から消さない。

終了状態は `completed`（作成側が終了、合格を意味しない）、`timeout`、`needs_user`、`blocked`、`failed`。作成側終了後に成果物を固定し、ハッシュと停止状態を記録してから採点する。タイムアウト・利用枠到達・認証失敗・条件混入・停止確認不能では、無承認の追加購入・リセット・別モデル再試行を行わない。

小機能第一段階で保存後に完全停止する。第二段階は同じ成果物と共通資料を新規セッションへ渡し、旧会話は渡さない。新規セッションの実行IDを同じrun_idへ対応付け、第一段階との時間・利用量を合算する。
