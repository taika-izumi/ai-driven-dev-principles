# 固定検査と比較結果

## 入出力

入力は停止済み作成セッションの固定成果物とrun.json。採点原本は作成側の書き込み範囲外で保持する。出力は `assessment.json` と比較表。必須項目は `run_id`、`artifact_sha256`、`checks`（id・pass/fail/unobserved・証拠）、`quality_pass`、`continuity`、`interventions`、`maintenance_burden`、`cost_breakdown`、`usage_limitations`。品質合格に必要な検査が未観測ならquality_passはtrueにしない。

検査対象コードのimportやCLI起動も生成コードの実行に当たる。採点原本へ書き込める管理者プロセスで対象を直接実行せず、原本を保護できる別プロセスの権限で実行する。固定検査そのものの保管と、対象コードの実行結果を信頼できる範囲は分けて記録し、任意コードに対する採点の偽装耐性を実測なしに主張しない。

元リポジトリ・通常設定・共有ツールを変更しない制約は採点にも適用し、共有Python本体と依存パッケージもその保護範囲に含む。読み取り専用で使える既存環境は再利用できる。Pythonを別の場所へ移すだけで保護成立とはせず、実際に使う権限でこの境界を確認する。

## 固定検査一覧

| ID | 共通の期待結果 |
|---|---|
| BUG-01 | Zと+09:00で同じ瞬間の日時を等しく扱い、有効な時刻を失わない |
| BUG-02 | タイムゾーンなし、無効文字列、Noneを時刻不明として扱う |
| BUG-03 | 有効・不明の混在する親ログでCLIが終了コード0、4CSVを生成し、全入力レコードの非時刻集計を維持 |
| BUG-04 | 子ログでも混在時刻で例外を起こさず、有効時刻と非時刻集計を維持 |
| BUG-05 | タイムゾーンなし・無効文字列・時刻キー欠落を各1件以上含む、全て時刻不明のセッションでfirst_ts・last_ts・wall_minutesが空欄、件数は保持 |
| FEATURE-01 | 指定なしの4CSVが固定開始版と同じ内容 |
| FEATURE-02 | 単一指定で当該セッションの親・子・人間ターン・スキル区間だけ出力し、各CSVで当該セッションのseqは1 |
| FEATURE-03 | 複数指定と重複指定が一意化され、従来の開始時刻順・同時刻ID順を維持。出力対象順にseqを1から振り、各CSVに存在する行のsession_id→seq対応が一致。該当種類の入力記録がないCSVには行を要求しない |

| COMMON-01 | 元入力が不変、会話本文の検査用文字列がCSVへ出ない、既存列が不変 |
| COMMON-02 | コピー直下をcwdとし、仕様01の固定依存を使うpytest起動経路で固定開始版の既存テストを省略せず実行し、成功・失敗・スキップ・エラー・実行件数を記録して元の失敗と後退を区別。0件実行や必要テストのスキップをpassにしない |

固定検査は公開した機能要件を具体化する。タイムゾーンなし値をUTC補完する、無効値のレコードを丸ごと捨てる、未知IDで成功して空出力にする、といった誤実装を不合格例に使う。正解実装・採点原本は作成者へ渡さない。現在の元コードの失敗と、検査自体の環境エラーを分ける。

個々の後退検査まで未修正例で失敗することは要求しない。検査一式で対象の不具合・未実装を識別する。FEATURE-02が失敗した成果物のFEATURE-04は前提未成立として未観測とし、argparseの未知オプション拒否だけを機能の成功に数えない。関数の検査は既存テストと同じパッケージ入口から読み、検査独自の単一ファイル読み込み方式で妥当な内部整理を失敗させない。

判断を伴う継続情報と介入分類は、実行管理者がモデル名・条件名を含まない採点用IDへ置き換えた資料で先に判定する。IDとrun_idの対応は管理側で保持し、判定後に結合する。成果物の意味や原本は改変せず、指示・様式などから条件を推測できる残存情報があれば限界として記録する。機械検査と実行管理ログ自体のrun_idを伏せる必要はない。

## 継続情報

小機能第二段階の開始報告を、共通依頼・manifest・第一段階の成果物と照合する。目的、許可範囲、開始版、未完了事項、検証結果の5項目ごとに一致・欠落・誤り・未観測を記録する。特定のhandoffやADR様式への準拠は加点しない。復元不能な事項を推測で補い実行した場合は、継続情報の欠落として残す。

## 利用量と介入

親・子・再開の実行IDを対応付け、提供元の出力から取れる入力・出力・キャッシュ利用量を記録する。親の合計に子が既に含まれる場合は二重加算しない。集約関係を確かめられなければ内訳と不明点を示す。契約全体の残量差やAPI価格換算を一実行の実請求額にしない。

人の介入は、必要な承認・仕様判断、不要な再確認、誤りの訂正に分ける。相手条件の情報や解法を教えず、共通依頼で解決する問いには同じ情報を返す。新しい仕様判断が必要なら片方だけ補わず、比較条件の変更として扱う。人の対応時間は観測できた分のみ記録する。

維持負担は追加ファイル・指示・設定・スキルの用途と今後の更新要否を両条件で記録する。費用は共通資料・検査準備・採点と、各方式の実行・導入・修正に分け、片方だけに必要な設定や手順の負担を当該方式へ対応付ける。別の計測基盤は作らず、既存ログ・差分・短い用途記録を用いる。件数の少なさだけで優劣を決めない。

## 結果と次の進路

各モデル内の対比較を先に行う。品質・許可範囲・継続情報を満たさない結果を、速さや安さで相殺しない。モデル裁量が条件を満たし手順の便益がなければ対象範囲の詳細化見送り、手順で欠落を防げれば限定支援、両方未達・不明なら原因確認または保留、手順で悪化すれば縮小候補を示す。自動的に通常利用の規範を変更しない。

固定検査の成功は、未測定の権限境界や長期運用の成立を意味しない。必要な検査が実行できなかった場合は結果を不明・未観測として残す。共通手順の採否にOpusの結果も必要であり、Codexだけの成功で省略しない。
