# プロジェクトの目的・方針を担当へ届ける仕様

## 読み方と全体目的

本ガイドラインは、必要品質・権限・継続情報を保ちながら、AI利用費用・時間・将来の維持変更負担を抑える。本機能は、担当が局所的な依頼だけを基準に判断することを防ぐため、現在のプロジェクト目的へ到達する経路を定める。根拠はADR-0130・0183、設計理由はADR-0190。

| ブロック | 仕様 | 責務 |
|---|---|---|
| 目的の定義・取得・変更 | [01-purpose-context.md](01-purpose-context.md) | 正本を特定し、参照した内容・確定状況・依頼との関係を扱う |
| 開始・再開・委譲への接続 | [02-workflow-integration.md](02-workflow-integration.md) | 01の結果を主担当・handoff・子・レビューへ届ける |
| 導入・更新・検証 | [03-distribution-and-validation.md](03-distribution-and-validation.md) | 各プロジェクトの目的を保持して共通手順を届け、判断と負担を確認する |

## 主要な流れと依存関係

利用側のプロジェクト指示・標準入口 → 01の正本取得 → 02の新規／再開・今回の依頼との照合 → 範囲内の作業または影響する判断の相談、という順序とする。委譲では02が01の参照結果を渡す。目的変更時は01の保存・未反映状態を02で引き継ぐ。

03は01・02の手順を配布し、利用側の設定・目的本文を保全する。01・02は配布更新や検査を毎回呼び出さない。各ブロック間の受け渡しは01の「参照結果」を共通にし、各スキルへ定義を複写しない。

## 範囲と完了条件

- 開始・再開・目的変更後・委譲で、目的の正本と参照内容を区別できる。既知目的を毎回再質問しない。
- 正本の未定義・読取不能・未反映の目的変更と、読み取り専用作業を扱い、草案を確定目的にせず、影響のない作業を一律停止しない。
- start-workで正本を確認できない場合は、整備をそのセッションの作業候補に含める。前回見送り後も次回は再提示するが、同一実行内で重複提示せず、着手を強制しない（ADR-0191）。
- 本プロジェクトの固有目的は配布せず、利用側の正本指定・固有指示を共通部更新で失わない。
- 03の判断例・参照・配布整合を確認し、未確認の環境や利用効果を明示する。ファイル存在や読了報告だけで行動面の合格としない。
- 継続判断の規範、全情報の検索基盤、自動注入サービス、全モデルの記憶保証、利用側への実導入・公開は含めない。全体目的は作業範囲・操作許可を拡張しない。

## 設計・検証の所在

ADR-0190が採用理由・代替案・導入後評価の正本。過剰適合点検は次節に置く。実装計画は `docs/working/plans/`、判断比較とレビュー結果は既存の実験・レビュー記録へ置く。本仕様は目的参照機能の全体仕様であり、既存スキル自体の全仕様は各現行仕様・スキルを参照する。

## 過剰適合点検（ADR-0079）

整備候補提示の追加についてはADR-0191の点検・評価可能性を参照する。根拠はユーザーの明示要件であり、特定モデルの失敗を一般化したものではない。既存の作業範囲・権限と主担当への限定を維持する。

| 観点 | 判定 | 根拠 |
|---|---|---|
| 出所の偏り | 要是正→入力の取得・受け渡し条件へ限定 | 直接材料はMakeAiInstructionsの1プロジェクト、主担当gpt-6-astraの1セッション。Sol/highの設計・実装レビューと、8題を現行・改修後で各1回の判断比較を実施。判断比較は有限の読解試験であり、実運用の効果を保証しない |
| システム種別依存性 | 問題なし | 特定製品・数式・固定の全欄記入を要求しない。引き写し箇所: folder-structureのゴール配置、ADR-0130の要求・概算、ADR-0185の承認済み限定の尊重を保持 |
| AIモデル/ツール依存性 | 問題なし | 特定モデルの記憶や任意ファイルの自動注入を仮定しない。引き写し箇所: decision-delegationの承認根拠と範囲、review-criteriaの原文・出所・閲覧不能時の受け渡し、外部送信の許可を保持 |
| 規範の廃止条件 | 定義済み | ADR-0190の導入後評価で判断の改善がなく重複読解・確認負担だけが確認された場合、該当する接続や必須記載の簡素化・撤回を提案する |
