# 目的の定義・取得・変更

## 対象ファイルと責務

- `skills/start-work/references/project-purpose.md`（新規）：本ブロックの共通手順。
- `docs/overview/project-purpose.md`（新規）：本ガイドラインプロジェクトの現在の目的。
- `docs/current/development-roadmap.md`：目的の正本を参照し、段階・次手を扱う。

プロジェクトの目的と、開発方法の品質・費用の共通基準を区別して併用する。目的本文には利用者・実現したい成果、良い成果の条件、判断の優先順位、重要な制約・方針を必要範囲で記載する。数式・固定の全欄記入・進捗の収載は要求しない。

## 正本の特定

1. 今回の作業が属するプロジェクトのルートを、明示されたプロジェクト指示・作業対象から特定する。指定がなければ作業対象のGitリポジトリルート、非Gitでは明示されたプロジェクト作業ディレクトリを使う。単なるコマンドの現在ディレクトリから推測しない。
2. 適用されるプロジェクト固有のAGENTS.mdに正本指定があれば使う。相対パスの既定は1のプロジェクトルート基準。別の基準が明示されている既存指定は、その基準を含めて解決する。下位AGENTS.mdの局所的な作業指示だけでプロジェクト全体の目的を置き換えない。別プロジェクトの目的が明示される場合は適用範囲を確認する。
3. 未指定なら `docs/overview/project-purpose.md` を標準入口とする。入口が参照だけの場合は指定先の必要な節まで読む。
4. 未定義ならREADME・overview・ロードマップなどの案内文書と、そこから参照される既存合意を調べる。現在の目的と今回の判断に必要な根拠を確認できた時点で探索を終える。全ADR・全履歴の一律読破はしない。判断に影響する矛盾・不明が残る場合だけ、その点を確認する。

明示先が不存在・読取不能なら、その事実と確認可能な既存根拠を分ける。別の資料を黙って正本に昇格しない。既存の適切な文書・節が使える場合は再利用し、標準入口と両方へ本文を複写しない。

## 参照結果と受け渡し

各スキルは次の情報を既存の入力・関連資料欄へ含める。新しい必須帳票や専用台帳は作らない。

- **所在・適用範囲**：対象プロジェクトのルート、正本のパス・必要な節。
- **参照した内容の根拠**：既存コミットとパス・節、または内容を保持した記録・必要な原文のいずれか。未コミットならその旨を添える。コミット済み版と作業ツリーの異なる本文を同じ版としない。全ファイルのハッシュ採取は要求しない。
- **確定状況と未反映事項**：確定した目的、草案、不明を区別する。正本未整備でも既存合意が確定している状態と、目的そのものが未確定な状態を混同しない。目的変更が未反映なら、新しい確定内容・合意根拠・反映先を示す。

参照内容の識別は入力の取り違えを防ぐためであり、目的変更や操作への承認を生成しない。承認基準の扱いは既存のdecision-delegation、目的変更の決定記録はdecision-logに従う。

## 開始後の再利用と目的変更

開始・再開では現在の正本を読み、handoffの前回参照内容と未反映事項、今回の明示指示・承認範囲を照合する。同一作業内では、参照内容が有効で変更の兆候がなければ再利用する。毎応答の全文再読・目的の唱和は不要。目的の明示変更や既知の正本差分がある場合、または根拠を参照できなくなった場合は再取得する。

目的変更が確定したら、権限内で正本と既存の決定記録を整合させ、反映後の実体を読み直してから、その内容を後続の依存判断・handoff・子へ渡す。両方の保存を一括で保証する仕組みは新設しない。途中で止まる場合は、未反映の新しい目的と合意根拠を既存handoff等へ保存し、更新完了と報告しない。未反映の変更が判明しているのに可読な旧正本を「最新」としない。

目的変更だけで作業範囲・操作許可が広がったとは扱わない。合意範囲の変化や根拠の不明が影響する判断だけを相談する。別主体による未知の変更を常時検知できるとは保証しない。

## 初期整備と読み取り専用の分岐

正本・所在案内の作成や更新は、今回の作業範囲と実効権限が許す場合だけ行う。読み取り専用のレビュー等では、確認済みの既存根拠を使い、未整備状態・候補の所在を報告して、独立して可能な作業を続ける。永続化のためだけに作業全体を止めたり、権限外の書込みを試したりしない。

新しい目的・優先順位・重要な解釈が必要ならAIが根拠つき草案を示し、その点の判断を求める。草案は確定目的として使わない。正本更新を保存できない場合は新しい確定内容と未反映状態を報告し、永続化できる担当へ渡す。これは永続化完了の代わりにはならない。
