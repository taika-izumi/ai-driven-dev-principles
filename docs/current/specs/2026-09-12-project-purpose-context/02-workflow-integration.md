# 開始・再開・委譲への接続

## 対象ファイルと責務

| 対象 | 接続内容 |

| skills/start-work/SKILL.md | 主担当・委譲された担当の適用範囲を定義し、主担当の新規・継続分岐より前に01を呼ぶ |
| skills/session-handoff/SKILL.md、references/op-read.md・op-create.md・op-update.md・op-cycle-reset.md | 参照結果の保存・再開・有効な所在の保持 |

手順・参照結果の定義は01の共通手順だけに置く。既存の必須手順・承認・実行保護を費用や目的だけで解除しない。

## 主担当の開始・再開

start-workは依存確認後、新規・継続の分岐より前に01の正本取得を行う。handoffの継続要約を提示する時点でも目的の参照結果を使えるようにする。その後は既存の継続確認・状況診断・次手の経路を維持する。

この全体フローの主体は、利用者からの作業を取りまとめる主担当とする。AGENTS.mdの「作業の起点」とstart-workの「いつ使うか」の無条件発火文を、この分担へ揃える。委譲されたタスクを受け持つ子は、「子とレビュー担当への受け渡し」の目的・担当範囲の確認を行い、主担当のPhase 0・1、handoff作成・更新、ADR作成を重複実行しない。

今回の依頼が全体目的のどの部分に寄与するか、承認済みの限定範囲を守るかを判断に用いる。目的の全項目を一つのタスクへ要求しない。矛盾や未確認は影響する判断と切り分け、読取りや承認済みの独立作業を一律停止しない。

AGENTS.mdの短い接続は、開始・再開と、目的の根拠を参照できなくなった場合を対象とする。セッション要約等のツール固有イベントの自動フックや記憶保証を新設しない。同じ作業中の有効な取得結果は再利用する。

## handoffの保存・再取得

関連ドキュメントへ01の所在・適用範囲・参照内容の根拠を置き、進行中タスクまたは既知の懸念へ未確定・未反映事項と影響を置く。既存の節を使い、目的本文全体を毎回複写しない。承認根拠の記録は既存の判断の分担の参照と共用できる。

readを単独で呼んだ場合も、継続要約や目的に依存する判断の前に01の結果を得る。start-workで同じ内容を取得済みなら再利用する。前回版の保存は履歴の識別に使い、次回の現在の目的をその版へ固定しない。

create/updateは正本未整備・未反映の変更も確定済みの目的と区別して保存する。finalizeはupdateを通じて同じ契約を適用する。cycle-resetは目的の有効な所在・未反映事項を消さず、完了作業の許可は次作業へ流用しない。

## 子とレビュー担当への受け渡し

委譲元は01の参照結果から、正本の所在・参照内容の根拠と担当に必要な原文を、担当範囲・実行条件とともに渡す。対象版の違いが判明していれば再取得して整合させる。子が実体を読めない場合は必要な原文と出所を渡し、親の要約を原文と称さない。外部送信の許可は別に守る。

子は目的と担当作業の関係を確認し、矛盾・変更候補は親へ報告する。目的の変更、担当外の実装、権限拡張、不要なstart-workや履歴全件調査を自律で始めない。

受け渡された目的・根拠が不足する場合も全体フローへ切り替えず、担当範囲・権限内で01の必要な特定・読取りだけを行うか、不足を親へ報告する。全体フローを主担当に限定することは、子の目的取得を免除するものではない。subagent-dispatchの入力と既存の担当外作業禁止をこの分担へ接続し、子向けの新しいスキル・起点工程は作らない。

独立レビューの既存入力に必要な全体目的・方針を01から供給する。必要な原文を省いたり、目的担当だけへ渡したりしない。追加のレビューや人数変更をこの接続だけで発火させない。
