# 導入・更新・検証

## 対象ファイルと責務

README.mdの導入・更新案内と、通常のdist・template生成物を扱う。template.manifestへプロジェクト固有の目的本文は追加しない。版更新は実装・必要なレビュー・検証後に、CONTRIBUTING.mdの配布規約に従う。新しい自動配布・移行スクリプトは作らない。

## 新規導入と既存プロジェクトの更新

新規導入では、既存資料から目的の正本を特定する。指定が必要ならプロジェクト固有のAGENTS.mdに所在を記載する。適切な文書がなければ01の初期整備へ進む。AIが既存合意から草案を作り、不足・矛盾・重要な解釈だけを利用者へ確認する。

既存プロジェクトでは、プラグイン更新で届くスキルと、利用側のAGENTS.mdへ統合する共通部を区別する。READMEに次の更新方法を示す。

1. 利用側の既存AGENTS.md・固有指示・目的正本の指定を確認し、変更前の内容をGitまたは退避コピーで保持する。参照される目的本文も保全対象とする。
2. 新しい共通の作業起点・コンテキスト規定だけを、利用側の既存指示と差分照合して統合する。テンプレートでAGENTS.md全体や目的本文を上書きしない。共通部と固有部の識別・意味が衝突する箇所は、黙って置換せず報告する。
3. 更新後に正本指定・固有指示が保持され、開始・再開の手順から正本の必要箇所へ到達できることを確認する。未統合の共通部や未確認の経路は導入完了に含めない。

これは利用側の更新案内であり、今回そのプロジェクトへの書込み・導入を実行するものではない。自動更新の有無や版の固定方法など、未確認のツール挙動を仮定しない。

start-work実行時に指定先・標準入口で正本を確認できない場合は、02に従い整備を作業候補へ含める。整備への着手は強制しない。

## 検証ケース

| ケース | 期待する判断・結果 |
|---|---|
| 新規開始、標準入口に目的あり | 正本を読み、その必要品質を破る安価な案を採らない |
| 再開、handoffが旧目的を要約 | 現在の正本と未反映変更の根拠を照合し、旧目的を無条件に使わない |
| 目的変更が正本へ反映済み／保存が途中で停止 | 前者は新しい合意を再承認させず使い、後者は新しい確定内容と未反映を保持し、更新完了としない |
| 別文書指定、サブディレクトリから開始 | プロジェクトルートと明示指定の基準で目的へ到達し、不要な別本文を作らない |
| 正本未整備だが既存目的は確定、read-only作業 | 確認できる根拠を使い、権限外の書込みや整備のためだけの停止をしない |
| 目的そのものが不明、または明示先が読取不能 | 草案・確定事項・不明を分け、影響する判断だけを相談する |
| 子へ限定した実装・read-onlyレビューを渡す | 同じ参照内容・必要な原文を使い、親のPhase 0・1やhandoff・ADR作成を重複しない。目的の不足は範囲内の読取りか親への報告で扱い、範囲を広げない |
| 利用側の固有正本指定を持つAGENTS共通部更新 | 指定・本文・固有指示を保持し、新しい参照経路を確認する。衝突を黙って上書きしない |

整備候補の提示は、以下の境界も確認する（ADR-0191）。

| 状態・経路 | 期待する提示 |
|---|---|
| 明示指定なし、標準入口で正本を確認できる | 整備候補を追加しない |
| 指定された別文書で正本を確認できる | 整備候補を追加しない |
| 正本なし、既存合意だけ確認できる | 新規・再開とも整備候補を含める |
| 正本なし、目的自体も未確定 | 整備候補を含め、不明が影響する判断だけ相談する |
| 指定先不存在／読取不能 | 理由を添え、参照先の確認・復旧を含む候補を提示する |
| read-only作業で正本未確認 | 候補を含めるが、権限外の保存や整備の強制をしない |
| 前回整備を見送り、次回start-workでも未確認 | 再提示する |
| 同一start-workのPhase 2ループ | 同じ候補を重複提示しない |

会話履歴を持たない担当が同じ目的・依頼で現行手順と変更案を使い、期待判断・不要な確認や再読・負担・未確認を比較できるよう、実装計画で入力と判定を具体化する。資料の存在・読了申告だけでは行動面の合格としない。既存の実行経路を再利用し、正常な読取りが成立しなければレビュー・評価不能と区別する。

静的確認では、共通手順への参照と受け渡し、仕様と実装対象の対応、プロジェクト固有本文の配布非混入、AGENTSのサイズ、生成後の意味・同期を確認する。build-dist・sync-templateの必要な生成と両Check、差分検査を行う。利用側更新は、固有指定を含む試験用コピーで保全と到達を確認し、実プロジェクトへ適用した証拠にしない。

小規模試験を全モデルへの保証にしない。追加モデル実行の具体的な対象・設定・送信範囲・上限を計画に記載し、既存の操作承認に従う。改修後最初の3件の開始・再開における利用効果と簡素化条件はADR-0190の既存記録による評価に従い、新しい恒久的な評価台帳は作らない。
