# ADR-0011: 振り返り出力の保管規約（時系列追記型）

- **Status**: Accepted（ADR-0021 で一部改定: 配置パスを `system/` `flow/` の2フォルダに分割）
- **Date**: 2026-05-01

## Context

ADR-0010 で導入する `retrospective` スキルの出力ファイルをどう保管するかを決める必要がある。本リポジトリには既に2つの保管規約が存在する:

- ADR / spec / handoff: ADR-0008 で「スナップショット規約」を採用（差分仕様書を作らず常に書き換え）
- plan: 1ファイル / サブプロジェクト、原則として完成後は触らない

retrospective は「過去のサイクルで何があったか」を後から振り返る学習素材としての価値を持つ。ADR-0008 のような上書き型を適用すると、過去の事象や当時の判断が消えてしまい、学習素材として機能しない。

## Decision

retrospective 出力は以下の規約で保管する:

1. **配置**: `docs/retrospectives/YYYY-MM-DD-<topic>.md`（YYYY-MM-DD は振り返り実施日、`<topic>` はサブプロジェクト識別子）
2. **粒度**: 1ファイル = 1サブプロジェクト
3. **編集ポリシー**: 一度書いたら原則上書き禁止。例外は typo / リンク切れ修正のみ。事象や判断の改変は禁止
4. **インデックス**: `docs/retrospectives/README.md` に時系列テーブルを置く。**行追加のみ**、過去行の編集は禁止（`docs/decisions/README.md` と同方針）

ADR-0008 のスナップショット規約は **適用しない**。両規約は対象が異なる:

| 対象 | 規約 | 理由 |
|---|---|---|
| ADR / spec / handoff | スナップショット（書き換え） | 「現在の正しい状態」を表す |
| retrospective | 時系列追記型（上書き禁止） | 「過去の事象の記録」を表す |

## Alternatives Considered

- **ADR-0008 と同じスナップショット規約を適用**: 上書きで履歴が消え、retrospective の本来の目的（学習素材）を損なう
- **1ファイルに全サブプロジェクトの retrospective を時系列追記**: ファイルが肥大化し、git diff やレビューが困難になる
- **`docs/handoff/` のサブディレクトリに含める**: handoff と responsibility が混ざり、原則2（関心の分離）に反する

## Consequences

- 振り返り内容に後から間違いが見つかっても基本的に修正できない。修正が必要な場合は次回 retrospective 内で「前回振り返りの訂正」として記述する
- 過去事例が永続的に参照可能になり、新規メンバーや次サイクルでの学習素材として活用できる
- インデックスと本体ファイルの両方に追記専用ルールが適用されるため、レビュー時もこのルールに従っているか確認する
