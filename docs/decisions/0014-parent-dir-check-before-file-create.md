# ADR-0014: 新規ファイル作成時は親ディレクトリ存在を先行確認する

- **Status**: Proposed
- **Date**: 2026-05-01

## Context

サブプロジェクトC の Task 4 で、`create` ツールで新規ファイル `skills/retrospective/SKILL.md` を作ろうとしたが親ディレクトリ無しで失敗し、1往復のロスが生じた。本リポジトリでは新規スキル / 新規ドキュメントの追加が高頻度で発生するため、同種の手戻りは今後も繰り返し発生する可能性が高い。

サブプロジェクトC の retrospective Improvement Drafts #2 として採用判定された。rubber-duck レビューの指摘 #3 を受け、特定ツール名（`create`）への依存を避け、一般ルールとして規約化する形にスコープを調整した。

## Considered Alternatives

1. **何もしない**: 各エージェントが踏むたびに対処する。学習コストが各サイクルで再発生する。
2. **`create` 固有のルールとして書く**: copilot-instructions.md に「`create` ツール使用前に親ディレクトリ確認」と明記する。将来 `create` ツールが廃止 / 仕様変更されたときに陳腐化する。
3. **一般ルールとして書く**（本案）: 「新規ファイル作成前に親ディレクトリ存在を確認し、無ければ先行作成する」を copilot-instructions.md の「タスク構造」または「ドキュメント運用」セクションに1文追加する。`create` 等は例示扱い。

## Decision

選択肢3を採用する。理由:

- 一般ルール化することで将来のツール変更にも耐える
- 1文追加というコスト極小
- 本サイクルで実害（1往復ロス）が発生済みで、優先度判断の根拠が明確

実装は次セッションで `start-work` から writing-plans に直行する軽量サイクルで進めて構わない（中規模変更ではないため brainstorming を省略してよい）。

## Consequences

- ＋ 新規ファイル作成時の手戻り再発を予防
- ＋ ガイドラインがツール非依存の抽象度を維持できる
- − copilot-instructions.md の「常時適用ルール」が1項増える（認知負荷の微増）
- − template に同期するため、本リポジトリ運用 + テンプレ受領プロジェクト両方の挙動に影響する
