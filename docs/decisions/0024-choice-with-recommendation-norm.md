# ADR-0024: ユーザーへの質問・意思決定要求時に選択肢と推奨を提示する規範を追加

- **Status**: Proposed
- **Date**: 2026-06-16

## Context

AIエージェントがユーザーに質問したり意思決定を求めたりするとき、選択肢を提示せず自由記述だけを求めると、ユーザーの回答コストが上がり、AIの推奨も伝わらない。意思決定の局面では「どんな選択肢があり、AIは何を推し、なぜそう推すのか」が明示されているほうが、ユーザーは速く正確に判断できる。

この規範をどの層に実装するかが論点だった。本リポジトリは3層構成（Layer 1 `docs/principles.md` = ツール非依存の普遍的原則、Layer 2 `CLAUDE.md` = エージェント向け行動指示、Layer 3 `skills/` = ワークフロー自動化）を採る。

加えて、本ガイドラインは GitHub Copilot CLI と Claude Code の双方で利用される。Copilot CLI には選択肢提示用の `ask_user` ツールがあり、Claude Code には同等の `AskUserQuestion` ツールがある。したがって規範は特定ツールに依存させず、ツール非依存の行動として記述する必要がある。

## Considered Alternatives

- **案A（採用）: Layer 2 `CLAUDE.md` に対話規範を追加し、Layer 1 原則4 に一文補足する。** 発動条件が「質問・意思決定のたび＝常時」かつ「数行で表現できる」ため、CONTRIBUTING の Skill 化判定表は明確に CLAUDE.md 側を指す。原則4「重要局面での人間の関与」に一文を補い、抽象（Layer 1）→具体（Layer 2）の勾配を保つ。
- **案B: 既存スキル（brainstorming, decision-log, pre-action-review, start-work 等）を個別改修する。** 質問・意思決定はスキル外のアドホックな対話でも発生するため漏れる。複数スキルに同じ規範が重複し、発動条件「常時」がスキル化の判定基準に反する。不採用。
- **案C: 新規スキルを作成する。** 本規範は手順・分岐・テンプレートを持たない単純な対話ルールで、判定表上すべて CLAUDE.md 側に倒れる。明確な YAGNI 違反。不採用。

## Decision

案Aを採用する。

1. `docs/principles.md` 原則4「重要局面での人間の関与」に「人間の判断を仰ぐ際は、可能な限り選択肢を提示し、推奨する選択肢とその理由を明示する」を一文追加する。
2. `CLAUDE.md`「メタ・ガイドライン」配下に新サブセクション「ユーザーへの質問と意思決定要求」を追加する。内容は次のとおり:
   - 質問・意思決定要求時は原則として選択肢を提示し、推奨する選択肢を「（推奨）」として先頭に置き、推奨理由を一言添える。
   - 構造化された質問ツール（Copilot CLI の `ask_user`、Claude Code の `AskUserQuestion` 等）が使える場合はそれを用い、無ければテキストで選択肢を列挙する。
   - 本質的に自由記述が必要な質問（選択肢を自然に列挙できないもの）に限り、例外として自由記述を許す。
3. 既存スキルは改修しない。CLAUDE.md の横断規範でカバーし、brainstorming 等は既に選択肢＋推奨を実践しているため。

## Consequences

- 良い影響: 全ツール（Copilot CLI / Claude Code / 将来ツール）で一貫して、選択肢＋推奨が提示される。ユーザーの判断コストが下がり、AIの推奨と理由が常に可視化される。原則4の具体化として勾配が保たれる。
- 良い影響: スキル個別改修を避けたため、規範の重複・記述漏れが生じない。
- 留意点: `CLAUDE.md` と `docs/principles.md` は template.manifest 対象のため、変更後に `scripts/sync-template.ps1` でテンプレート同期が必要。
- 留意点: 「原則として常に選択肢」とすると、本質的に自由記述が必要な質問で形式的・不自然な選択肢を作りかねない。例外条項でこれを回避する。
