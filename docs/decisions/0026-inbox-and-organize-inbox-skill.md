# ADR-0026: inbox フォルダと organize-inbox スキルによる情報分類の仕組みを導入する

- **Status**: Proposed
- **Date**: 2026-07-04

## Context

ADR-0025 で情報の5分類体系を導入するが、どんな固定分類でも100%の網羅は保証できず、ユーザーが「どこに置くか迷う」情報は必ず発生する。分類基準をユーザーが暗記しなければ機能しない体系は、AI駆動開発のガイドラインとして本末転倒である。

当初案は「迷ったら最寄りの分類に置き、分類基準への疑義として課題に1行起票する」というフォールバック規則だったが、ユーザーから「inbox フォルダを設け、分類判断そのものをAIエージェントに委ねる」仕組みが提案された。

## Considered Alternatives

1. **フォールバック規則のみ（迷ったら最寄りに置く＋疑義起票）** — 仕組みの追加が不要だが、ユーザーが分類基準を理解している必要があり、誤配置が起きやすい
2. **CLAUDE.md への指示のみ（スキルなし）** — 実装コスト最小だが、分類手順・ユーザー確認フローの一貫性が保証されにくい
3. **専用スキルのみ（ユーザー手動実行）** — 手順の一貫性は保てるが、実行を忘れると inbox に滞留し続ける
4. **専用スキル＋start-work 検知（提案のみ、強制なし）** — スキルで手順の一貫性を保ちつつ、セッション開始時に未分類ファイルを検知して実行を提案する

## Decision

案4を採用する。

- **inbox フォルダ**を新フォルダ構成に設ける。ユーザーは分類に迷った情報（またはとりあえず放り込みたい情報）を inbox に置く
- **organize-inbox スキル**（名称は実装時に確定）を新設する。inbox 内の各ファイルを ADR-0025 の分類基準に照らして分類し、曖昧な場合は選択肢＋推奨（ADR-0024 の規範）でユーザーに確認した上で、適切な場所へ移動しインデックスを更新する
- **start-work の状況診断（Phase 1）に inbox 検知を追加**する。ディレクトリ一覧の取得1回で未分類ファイルの有無を確認し、あれば organize-inbox の実行をユーザーに提案する（強制はしない）

start-work への組み込みコストが懸念されたが、検知はディレクトリ一覧1回＋スキル定義への数行の追記であり、分類処理（ファイル内容の読み込み）のコストは実行を選んだ時に初めて発生するため、影響は誤差範囲と評価した。

## Consequences

- ユーザーは分類基準を覚えなくても情報を確実に体系へ載せられる。分類判断がAIエージェントの責務として明確になる
- inbox 滞留は start-work 起動のたびに検知されるため、拾い漏れが構造的に防がれる
- 新スキルの作成・README スキル一覧の更新・start-work の修正が必要になる
- 大きなファイルや大量のファイルが inbox に置かれた場合のトークン消費対策（分類判断に必要な部分だけ読む、件数提示と確認）は organize-inbox スキル側の設計で担保する
