# このプロジェクトの目的・判断方針

## 実現したいこと

AIエージェントと協働する各種システム開発で、利用者が満足できる品質の成果物を作り、保守・拡張を続けられるようにする。そのための原則・行動指示・スキルを整備し、利用するプロジェクトへ配布する。

必要な品質、判断理由を追跡できる記録、変更しやすい構造を維持し、人の判断を必要な箇所へ集中させながら、AI利用費用・所要時間・将来の維持変更の負担を抑える。成果につながらない方針への固執による時間・トークンの浪費も改善対象とする。

## 良い成果と判断の優先順位

ここでの「目的関数」は、何を満たし、その下で何を抑えるかという判断の優先順位を指す。品質と費用を単一の点数に換算するものではない。

- 利用者の要求と必要品質を満たすことを前提に、現在と将来の負担を比較する。機能テストの成功だけで品質全体を満たしたとせず、短期の速度で品質・権限・継続情報の不足を相殺しない。
- 通常は手元の情報で概算し、判断を左右する不明点だけを確認する。見積もりのためだけに測定・帳票・確認会話を増やさず、成果物に必要な検証は行う。
- 品質の上積みに利用者の価値があれば考慮する。人間の関与量自体を独立した最適化目標とせず、新たに必要な作業は説明し、その負担を理由にAIだけで機能を見送らない。
- 規範や工程の追加だけを改善とせず、既存手順の適用・簡素化・縮小も比較する。追加の読解・確認・実行・維持負担に見合う便益があるかを見る。

## 適用方針と制約

特定のシステム種別や最も高性能なモデルだけを前提にしない。利用予定のモデル・実行基盤でも必要な品質を満たせることを目指し、確認した版・範囲・未確認を区別する。少数の成功・失敗を全モデルや将来の保守性へ一般化しない。

開発対象システム自身の目的は、そのプロジェクトの要求から定める。本書の開発方法に関する判断基準で製品固有の目的を置き換えず、合意した範囲・操作権限・必要な保護を維持する。目的・方針を変更するときは、確定した内容を本書へ反映し、理由と合意は決定記録に残す。
