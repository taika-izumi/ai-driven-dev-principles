# ADR-0003: テンプレートフォルダとマニフェスト同期方式の採用

- **Status**: Accepted
- **Date**: 2026-04-13

## Context

新プロジェクトへの転用に4つの手作業（フォルダコピー2回、フォルダ作成1回、ADRインデックスのコピーとエントリ削除）が必要で、手順が煩雑だった。また、ガイドラインの変更がテンプレートに反映されず陳腐化するリスクがあった。

## Considered Alternatives

### テンプレートの形態

1. **GitHub Template Repository として別リポジトリに分離する** — メンテナンスが二重管理になり、本体との同期が困難
2. **リポジトリ内に `template/` フォルダを設ける** — 本体と同一リポジトリで管理でき、同期スクリプトで自動反映が可能

### 同期メカニズム

1. **スクリプト単体（対象ファイルをスクリプト内にハードコード）** — 新スキル追加時にスクリプト本体の編集が必要で変更箇所が分散する
2. **マニフェスト＋スクリプト（対象ファイルを外部定義）** — 対象ファイルの追加・削除がマニフェスト編集のみで完結し、スクリプトは汎用のまま維持できる
3. **Skill駆動（AIエージェントが都度判断して同期）** — 判断の再現性が低く、実行結果の一貫性を保証できない

### 同期方式

1. **差分同期（変更ファイルのみ更新）** — マニフェストから削除されたファイルの残骸が残るリスクがある
2. **完全同期（削除→再構築）** — 常にクリーンな状態を保証でき、冪等性を確保できる

## Decision

- リポジトリ内 `template/` フォルダ方式を採用する（形態: 選択肢2）
- マニフェスト＋スクリプト方式を採用する（メカニズム: 選択肢2）
- 完全同期方式を採用する（同期方式: 選択肢2）

## Consequences

- 新プロジェクトへの転用が `template/` のコピー1回で完結する（4手順→2手順）
- `template.manifest` が対象ファイルの単一ソースとなり、スキル追加時の変更箇所が明確になる
- ガイドライン変更時に `sync-template.ps1` を実行することで、テンプレートの陳腐化を防止できる
- 完全同期のため、マニフェストから除外したファイルの残骸が残らない
- 同期スクリプトの実行をユーザーが忘れる可能性がある（`extend-guidelines` スキルとCONTRIBUTING.mdで案内して対策）
