# ADR-0029: 質問ツールの表示特性への対処規範をモデル条件付きで追加

- **Status**: Proposed
- **Date**: 2026-07-05

## Context

選択肢提示規範（ADR-0024）に従い構造化質問ツール（Claude Code の AskUserQuestion 等）を使うと、同一ターンに書いた説明テキストがユーザーに表示されず、説明の欠落した状態で選択を求める形になる事象が確認されている（Issue-0004。2サイクル連続で再発: 2026-07-05 の brainstorming 中に設計相談の前置き説明が非表示のまま質問され、説明の再要求が発生した）。ADR-0024 はツールの表示特性への対処を定めておらず、現状の回避はセッション環境のメモリ頼みでガイドラインとしては未解決だった。

一方、この事象は利用中のモデル（またはモデル×ツールの組み合わせ）の特性に依存している可能性がある。将来モデルを変更すると事象が発生しなくなる可能性が十分あり、その場合この対処指示は不要になる。したがって規範は「事象が確認された環境でのみ適用」とし、不要になった時点で撤去できる形にする必要がある。

## Considered Alternatives

- **案A（採用）: 「質問の自己完結」＋「説明が必要な場合のテキストフォールバック」の2本立てを、事象が確認されたモデルに限定して適用する。** 再発した事象（説明欠落・再質問）を両方カバーし、ツール非依存の表現で書ける。事象が発生しないモデルでは構造化ツールの利便性を制限しない。撤去基準を定めることで規範の陳腐化を防ぐ。
- **案A'（無条件適用）: 同じ2本立てをモデルを問わず常時適用する。** 事象が発生しないモデルでも構造化ツールの使い方を不必要に制限し、モデル更新後に規範が形骸化する。不採用。
- **案B: 「質問の自己完結」のみを規定する。** シンプルだが、選択肢の説明欄に収まらない長い前提説明・比較が必要なケースを救えない。不採用。
- **案C: 構造化ツールの利用をやめ、常にテキスト選択肢に回帰する。** 確実だが、ADR-0024 が採用した構造化ツールの利点（誤答防止・回答コスト減）を失う。過剰対応で不採用。

## Decision

案Aを採用する。`CLAUDE.md`「ユーザーへの質問と意思決定要求」セクションに、以下の内容の項目を追加する。

1. **適用条件**: 「構造化質問ツールと同一ターンに書いた説明テキストがユーザーに表示されない」事象が確認されているモデルで動作している場合にのみ、以下の対処に従う。事象が未確認のモデルでは、事象の発生を確認するまでこの対処には従わない。
   - 事象確認済みのモデル: Claude Fable 5（Claude Code の AskUserQuestion で再現。2026-06〜2026-07 に複数回確認）
   - 新たなモデルで同事象を確認した場合、確認済みリストに追記する
2. **対処内容**:
   - 構造化質問ツールを使う場合、質問文と各選択肢の説明だけで意思決定に必要な情報が完結するようにする（同一ターンの先行テキストに依存しない「自己完結」）
   - 選択の前提として長い説明や案の比較が必要な場合は、構造化ツールを使わず、説明＋番号付き選択肢をテキストのみのターンで提示する
3. **撤去基準**: 事象が発生しないモデルの利用が常態化し、確認済みモデルを日常的に使わなくなった時点で、本項目を `CLAUDE.md` から削除し、本ADRを Deprecated に更新する。

実装位置は Layer 2（`CLAUDE.md`）のみとする。Layer 1（`docs/overview/principles.md` 原則4）は既に「選択肢＋推奨の提示」を抽象度高く定めており、ツール表示特性への対処は Layer 1 の抽象度に合わないため変更しない。スキル個別改修も行わない（ADR-0024 と同じ判断: 発動条件が「質問のたび＝常時」であり CLAUDE.md の横断規範が適切）。

## Consequences

- 良い影響: 事象が確認された環境で、説明の欠落した質問・説明の再要求という往復コストが規範レベルで防止される（これまではセッション環境のメモリ頼みだった）。
- 良い影響: モデル条件と撤去基準を明記したことで、モデル更新後に不要な制約が残り続けることを防げる。
- 留意点: `CLAUDE.md` は template.manifest 対象のため、変更後に `scripts/sync-template.ps1` の実行が必要。
- 留意点: 「事象が未確認のモデルでは従わない」ため、新モデルへの切替直後に事象が再発する可能性がある。再発を確認したら確認済みリストへの追記で対応する。
