# ADR-0030: ADR ドラフトは即時作成・コミットは論点収束チェックポイントまで遅延可能とする

- **Status**: Accepted
- **Date**: 2026-07-05

## Context

意思決定の継続検出ルール（ADR-0006）は「検出した瞬間にドラフト作成」を定め、`decision-log` スキルの手順はドラフト作成からインデックス更新・コミットまでを一続きに実行させる。一方で ADR 記述規律（ADR-0019)は「承認（Accepted 昇格）」を決定確定チェックポイントまで遅延させた。この非対称により、「起票・コミットは即時、承認は遅延」という状態になっていた。

実運用では、brainstorming 中の1つの決定の直後に関連論点で前提が覆ることが多く、ADR-0028 の起草時には「選択肢決定直後の即コミット」がユーザーの未解消の懸念と衝突してコミット中断・ADR 書き直しの手戻りが発生した（Issue-0009。起票元: retrospectives/flow/2026-07-05-retrospective-issue-integration.md 課題#1）。原因は、規範に「ドラフト作成」と「コミット」の区別、および関連論点の収束確認が含まれていないことである。

本対策サイクルでは、対策の深さとして「既存原則（即時検出・即時ドラフト作成）を維持した最小限の規範追記」をユーザーが選択した（プロセス再設計案は変更範囲・影響の大きさから不採用）。

## Considered Alternatives

- **案A（採用）: 即ドラフト作成・コミット遅延。** 検出時のドラフト作成（ファイル作成＋インデックス更新）は維持し、コミットのみ関連論点の収束チェックポイントまで遅延可能とする。即時記録の利点（コンテキスト喪失前に検討経緯を記録する。ADR-0006 の趣旨）を保ちつつ、手戻りの実体である「未収束段階でのコミット→中断→書き直し」を防ぐ。ADR-0019 の遅延昇格と対称的で一貫する。
- **案B: 起票自体を遅延。** 検出時は ADR 候補としてメモ（handoff 等）に残すだけにし、ドラフト作成を論点収束後にまとめて行う。手戻りは最小化されるが、即時記録の利点が失われ、ADR-0006 の趣旨（コンテキスト喪失前の記録）から離れる。不採用。
- **案C: 現状維持。** 手戻りが構造的に再発し続ける。不採用。

## Decision

案Aを採用する。

1. **ドラフト作成は即時のまま**: 意思決定を検出した瞬間に ADR ファイルの作成とインデックス更新を行う（ADR-0006 は変更しない）。
2. **コミットは収束チェックポイントまで遅延可能**: ADR のコミットは、関連論点が収束したチェックポイントで行う。目安は ADR-0019 の昇格チェックポイントと同じ考え方に従う:
   - brainstorming 中に作成したドラフト → 設計承認時
   - それ以外 → ユーザーがその決定の確定を確認した時
   - 関連論点が既に収束している場合は、従来どおり即コミットしてよい
3. **収束までドラフトは書き直し自由**: 未コミットの間、関連論点の進展に応じてドラフトを自由に書き直してよい（書き直しは手戻りではなく想定された更新と位置づける）。
4. **反映先**: `skills/decision-log/SKILL.md`（手順のコミット規定と承認プロンプト前後の記述）、`CLAUDE.md`「意思決定の即時記録（継続適用）」（1行補足）、`skills/start-work/SKILL.md`（ルール再宣言部の文言整合）。

## Consequences

- 良い影響: brainstorming 中の連鎖的な決定でも、コミット中断・書き直しの手戻りが規範レベルで防止される。「作成は即時・コミットと承認は収束後」という一貫したモデルになる。
- 留意点: コミット漏れのリスクが生じる。ADR-0019 の昇格漏れ対策と同様に、`start-work` Phase 2 Post とセッション終了処理で未コミットドラフトの確認を促すことで補う。
- 留意点: `CLAUDE.md` は template.manifest 対象のため変更後に `scripts/sync-template.ps1` の実行が必要。skills/ の変更はプラグイン更新（`/plugin marketplace update ai-driven-dev-principles`）まで利用者に反映されない。
- **部分修正（ADR-0105）**: 決定 4 の反映先（CLAUDE.md 即時記録節・start-work 冒頭ブロック）のコミット遅延の定義列挙は decision-log への参照に置換された（コミット遅延の規範本体は decision-log 側で現役）
