# ADR-0033: sync-template.ps1 の生成ファイルは LF 改行で書き出す

- **Status**: Accepted
- **Date**: 2026-07-05

## Context

sync-template.ps1 の空インデックス生成（ADR-0027）は `[System.IO.File]::WriteAllLines` を使っており、改行コードが実行環境の既定値（Windows では CRLF、Linux/macOS では LF）になる。リポジトリのコミット済み内容は LF 正規化されているため、Windows で実行するたびにワークツリーの生成ファイルが CRLF となり、`git status` に内容差分のない「見かけの modified」が表示される（Issue-0002。再発2回記録済み）。

調査（2026-07-05）で以下を確認した:

- index 側の対象3ファイルはすべて LF のみ（CR 0 バイト）
- スクリプト実行後のワークツリーはすべて CRLF
- clean フィルタ適用後の内容は index と完全一致（`git diff` は空）だが、`git status` は modified を表示する
- `Copy-Item` で単純コピーするファイルは LF ソースをそのままコピーするため無害。生成系の書き出しのみが原因

## Considered Alternatives

1. **スクリプト側で LF を明示して書き出す（採用）**: 生成部を「行を `"`n"` で連結 + 末尾改行 + `WriteAllText`」に変更する。数行の修正で、どの OS で実行しても同一バイト列になり、スクリプトタイトルどおりの決定性が得られる。
2. **.gitattributes で `* text=auto` などのリポジトリ全体正規化を導入する**: 見かけの差分は消えるが、ワークツリーのバイト列は実行 OS 依存のまま残り「非決定性」の根本は解消しない。また全ファイルの正規化状態変更による一時的な差分ノイズ（血流域が広い変更）を伴う。本課題の範囲を超えるため不採用。将来、貢献者環境の autocrlf 差異が問題化した時点で別途検討する。
3. **現状の運用回避（実行後に `git restore`）を継続する**: 手作業ノイズが同期のたびに発生し続ける。Issue-0002 が問題視している状態そのものであり不採用。

## Decision

案1を採用する。sync-template.ps1 の空インデックス生成の書き出しを、エンコーディング（UTF-8 BOM なし）に加えて改行コード（LF、末尾改行あり）も明示する方式に変更する。これによりスクリプトの出力は実行環境に依存せず、コミット済み内容とバイト一致する。

## Consequences

- 良い影響: template 同期のたびに発生していた改行のみの見かけ差分と `git restore` による回避作業が不要になる。スクリプト出力がクロスプラットフォームで決定的になる。
- 悪い影響・制約: 今後 sync-template.ps1 に生成系の書き出しを追加する場合、同じ方式（LF 明示）に揃える必要がある。リポジトリ全体の改行正規化ポリシー（.gitattributes）は未導入のままであり、貢献者環境の autocrlf 設定差異への防御は本 ADR の範囲外。
