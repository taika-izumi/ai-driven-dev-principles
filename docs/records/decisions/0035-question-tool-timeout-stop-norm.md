# ADR-0035: 構造化質問ツールのタイムアウト時は一律で停止・待機する規範を追加

- **Status**: Accepted
- **Date**: 2026-07-05

## Context

構造化質問ツール（Claude Code の AskUserQuestion、GitHub Copilot CLI の `ask_user` 等）は、無応答が一定時間続くとタイムアウトし、エージェントに「ベストジャッジで進めてよい」という状態を返す。この結果、ユーザー不在時に人間の確認プロセスが実質スキップされ、不可逆操作（merge、削除、外部書き込み等）が確認なく実行されうる。操作の重要度に応じてエージェントがどこまで自走してよいか・どこで待機すべきかの基準がガイドラインになかった（Issue-0012）。

この事象は複数サイクルで再発しており、直近では Issue-0013 対策サイクルでも、可逆作業を best judgment で進め不可逆な master merge の手前で停止する運用で凌いだが、基準は未定義のままだった。

既存の規範状況:
- CLAUDE.md「不可逆操作」節にリスクスケーリング（低=確認不要 / 中=サマリー / 高=承認必須）が定義済み。
- CLAUDE.md「ユーザーへの質問と意思決定要求」節に選択肢＋推奨の提示規範（ADR-0024）と表示特性への対処（ADR-0029）が集約済み。
- 原則4（人間の関与）に「エージェントが行き詰まった場合のフォールバック（撤退条件）を定義する」が既にある。

しかし、質問がタイムアウトした場合の振る舞いはどこにも規定されていなかった。

## Considered Alternatives

### 骨子（タイムアウト時のデフォルト挙動）

- **案A（採用）: 一律で停止・待機。** 構造化質問ツールを起動した時点で「人間の判断が必要」とエージェント自身が判断している。ならば回答が得られない以上、リスクの大小・可逆性に関わらず勝手に前進しないのが原則4に最も忠実。
- **案B: リスク階層で分岐**（低=自走継続 / 中=可逆範囲のみ進める / 高=停止）。質問を出しておきながら一部を自走で進めるのは「判断が必要」という自己判断と矛盾する。不採用。
- **案C: 一律で自走継続**（ツール既定動作の追認）。課題を実質的に解決しない。不採用。

### 実装層

- **案A（採用）: CLAUDE.md「ユーザーへの質問と意思決定要求」節に本体を追加し、原則4に一文補足。** タイムアウトは質問ツール起因の事象であり、ADR-0024/0029 と同居させると質問関連規範が一箇所に集約される。原則4の既存「撤退条件を定義する」に論理接続できる。
- **案B: CLAUDE.md「不可逆操作」節に追加。** 今回の停止は不可逆操作に限らず一律適用のため、不可逆操作節では適用範囲がずれる。不採用。
- **案C: 新規スキル化。** 規範は数行で表現でき手順・分岐・テンプレートを持たない。YAGNI 違反。ADR-0024/0029 も CLAUDE.md 横断規範を選択済み。不採用。

### 停止のタイミング

- **採用: 破損・中途半端な状態を残さない区切りまで整えてから停止。** 書きかけのファイルを壊れた状態で放置する方がかえって危険で再開も難しい。「一律停止」の主眼は"新たに前進しない"ことであり、"今の状態を安全に確定する"のは前進ではない。
- **代替: タイムアウト検知の瞬間に即停止。** 中途半端なファイル状態を残すリスクがある。不採用。

### スコープ

- **自律性を高めるモード: スコープ外。** 本ガイドラインは安全側の一律停止で固定し、自律性を上げたいケースは別機能／別リポジトリの関心として切り出す。将来この線引きが蒸し返されないよう記録する。
- **Issue-0005（選択UIの誤操作が即確定）との統合 vs 分離: 分離を選択。** 解の性質が異なる（本件=タイムアウト時の"振る舞い"の規範、Issue-0005=選択UIをやめてテキスト提示する"ツール選択"の規範であり、ADR-0024 の改定を伴う）。関心が別で、混ぜると責務が分かれる（原則2）。共通テーマ（質問ツール経由の意思決定の信頼性）は関連リンクで保持する。

## Decision

案A（一律停止・待機）を、実装層 案A（質問節＋原則4一文）で採用する。

1. `CLAUDE.md`「ユーザーへの質問と意思決定要求」節に、以下の規範を追加する:
   - 構造化質問ツールが無応答でタイムアウトし、エージェントに「ベストジャッジでの続行」を促す状態になった場合、操作のリスク・可逆性を問わず、それ以上作業を進めずに停止し、ユーザーの応答を待つ。
   - 進行中の可逆作業がある場合は、ファイルを破損・中途半端な状態で残さない区切りまで整えてから停止する。新たな判断を要するステップや不可逆操作には進まない。
   - 停止時は「何を待って停止したか」「再開に必要な回答・判断は何か」を明示して報告する。
   - ユーザーの応答を得るまで次のステップへ進まない。
   - （適用範囲）低リスクで確認不要な作業ではそもそも質問ツールを使わないため、本規範が発動するのは、人間の判断を要するとエージェント自身が判断して質問を出した局面に限られる。
2. `docs/overview/principles.md` 原則4「重要局面での人間の関与」の「エージェントが行き詰まった場合のフォールバック（撤退条件）を定義する」に接続する形で、「人間の判断を仰いだが得られないまま自動的な続行を促される状況では、リスクの大小に関わらず停止を既定の撤退とする」趣旨の一文を追加する。
3. 表現は固有ツール名を避けて一般化し（「構造化質問ツールが無応答でタイムアウトし…」）、挙動の異なるツールでも「回答を得られないまま続行を迫られる状況」として読めるようにする。
4. 自律性を高めるモードは本ガイドラインでは扱わない（別機能／別リポジトリの関心）。
5. Issue-0005（選択UIのテキスト化）は本件から分離し、次サイクルで扱う。

判定条件の観測可能性（ADR-0032）: 「無応答でタイムアウトし、ベストジャッジでの続行を促す状態になった」は、ツールがタイムアウト応答を返すというエージェントが観測できる事実であり、判定可能。

## Consequences

- 良い影響: ユーザー不在時に不可逆操作が確認なく実行される構造的リスクを、規範レベルで塞ぐ。原則4の抽象的な「撤退条件」が、質問ツールのタイムアウトという具体的局面で明確化される。
- 良い影響: 実装層を CLAUDE.md「質問と意思決定要求」節に集約したため、質問関連規範（ADR-0024/0029 と本件）が一箇所にまとまる。
- 良い影響: モデル非依存（タイムアウトはツールの一般的挙動）のため、ADR-0029 のようなモデル条件付けは不要で、規範がシンプルになる。
- 留意点: 一律停止のため、ユーザーが短時間離席しただけでも可逆作業が止まり、効率が落ちる場合がある。自律性を上げたいケースは別レイヤーの関心として意図的に切り出した（本ADRのスコープ外）。
- 留意点: `CLAUDE.md` と `docs/overview/principles.md` は template.manifest 対象のため、変更後に `scripts/sync-template.ps1` の実行が必要。
- 留意点: Issue-0012 は本ADRの実装完了・Accepted 昇格時に close する。Issue-0005 は分離済みで、次サイクルの申し送りに記録する。
