# ADR-0038: ツール適用結果はリスク比例で実体の読み直しにより独立確認する規範を追加

- **Status**: Accepted
- **Date**: 2026-07-05

## Context

エージェントが編集ツールの適用結果を、戻り値とは独立した観測で確認せずに「既遂」とみなして後続の記録・判断を積み上げると、記録と実体が乖離する（Issue-0016）。実例として、Edit が「成功」表示だったにもかかわらず実際にはファイル未変更で、後続の振り返り記録が実体と食い違った事象が観測されている（Opus モデルで複数回。Bash 実行自体をせず結果を捏造するケースも報告あり）。

対策方向（read-back verification をリスク比例・git 非依存で導入）は Issue-0016 起票時にユーザー合意済みで、実装層と発動条件の確定が本サイクルの論点だった。Issue-0014 対策サイクルでも実践例（renormalize 後の `git ls-files --eol` 確認、使い捨てファイルでの実機検証）が積み上がっていた。

## Considered Alternatives

配置層について:

1. **CLAUDE.md「検証」節のみ** — Layer 2（エージェント行動指示）に1箇条追記。Layer 1 の原則5 は既に「各ステップの出力を確認してから次のステップに進む」と抽象レベルでカバーしており、本規範はその具体化にあたる。ADR-0034（plan 検証整合）と同じ扱い
2. **CLAUDE.md + 原則5 にも1行** — 普遍性を主張できるが、原則5 の既存記述と重複感がある
3. **原則のみ** — エージェントが毎セッション読むのは CLAUDE.md のため、行動変容の効果が薄い

発動条件について: 全編集への一律適用は過剰であり、リスク比例で限定する（Issue-0016 検討状況の合意を踏襲）。

## Decision

案1を採用し、`CLAUDE.md`「検証」節に以下の趣旨の1箇条を追加する:

> 変更の適用結果に後続の判断・記録が依存する場合、および複数の変更を節目（コミット・保存・送信・デプロイ等）で確定する直前は、ツールの戻り値ではなく実体の読み直し（Read/grep 等）で変更内容を確認すること

- 発動条件は「後続依存」と「節目直前」の2つに限定する（リスク比例。全編集への一律適用はしない）
- 確認手段・節目の表現は git 非依存の一般語とする（VCS を使わないプロジェクトにも適用可能）
- Layer 1（原則5）は改定しない（既存の抽象記述の具体化であるため）

## Consequences

- ツール戻り値と実体の乖離（適用漏れ・捏造）が、後続の記録・判断へ波及する前に捕捉されるようになる
- 発動条件を2つに限定したため、低リスクな単発編集のオーバーヘッドは発生しない
- CLAUDE.md の変更は template 経由で配布先プロジェクトにも展開される（`scripts/sync-template.ps1` の実行が必要）
- 規範は「確認すること」の行動指示であり、確認の粒度（全文 Read か対象行 grep か）はタスクのリスクに応じたエージェント判断に残る
