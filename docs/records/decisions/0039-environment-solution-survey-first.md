# ADR-0039: 課題対策手順に環境・ツール設定による構造的解決の先行調査ステップを追加する

- **Status**: Proposed
- **Date**: 2026-07-05

## Context

課題対策の brainstorming で、規範・運用ルールの設計に入る前に「環境/ツール設定で構造的に塞げないか」を調査するチェック観点が定式化されておらず、ユーザーの深掘り提案がなければ、より単純で根本的な解（環境設定）を見逃して複雑な規範を導入するところだった（Issue-0017。実例: Issue-0005 対策で「重要判断の定義」という複雑な規範案まで進んだ後、環境変数 `CLAUDE_CODE_DISABLE_MOUSE_CLICKS` による根本解決が判明し方針転換した = ADR-0036）。

直後の Issue-0014 対策サイクルは環境・設定による構造的解決（`.gitattributes` 1行）そのものであり、この観点の有効性を裏付ける実例になった。

なお本サイクルの設計議論で、ユーザーから「CLAUDE.md は配布先全プロジェクトに影響する常時指示のため、安易な規模拡大を防止したい」という方針が示された（この懸念自体は Issue-0018 として別途起票）。

## Considered Alternatives

1. **CLAUDE.md + CONTRIBUTING.md の両方** — 汎用規範として配布先にも届くが、CLAUDE.md の常時指示が増える。本課題の放置リスクは低く（発動局面が対策設計時に限られ、設計承認という人間レビューの砦が必ず挟まる）、常時指示化の対価に見合わない
2. **CONTRIBUTING.md のみ** — 起票元事例の直接の発生箇所（本リポジトリの課題対策フロー）に調査ステップを定式化する。配布先プロジェクトには届かないが、本リポジトリでの価値の大半を確保でき、CLAUDE.md を拡大しない
3. **CLAUDE.md のみ** — 発生箇所の手順に現れず、かつ常時指示も増える。両案の短所を併せ持つ

## Decision

案2を採用し、`CONTRIBUTING.md`「振り返りで抽出された課題に対策するとき」の手順に、対策方針の検討前の調査ステップを1行追加する（規範・運用ルールの追加より構造的解決を優先する旨。ADR-0036 の事例を参照として付す）。

`CLAUDE.md` は変更しない。判断根拠:

- 本課題の放置リスクは低い（発動局面が限定的で、見逃しても設計承認の人間レビューで補足されうる。実例もユーザー指摘で好転した）
- CLAUDE.md は template 経由で配布先全プロジェクトに影響する常時指示であり、リスクの低い課題のために拡大しない（規模拡大の抑制方針）

## Consequences

- 本リポジトリの課題対策フローでは、対策方針の検討前に環境・ツール設定による構造的解決の調査が手順として発動する
- 配布先プロジェクトの対策検討には本観点は配布されない。配布先で同種の見逃しが問題化した場合は、その時点で CLAUDE.md への昇格を再検討する（Issue-0018 の肥大化監視の仕組みと合わせて判断）
- CONTRIBUTING.md の手順番号が1つ繰り下がる（既存参照への影響は本リポジトリ内のみ）
- CLAUDE.md を変更しないため、この決定単独では template 同期は不要（同サイクルの ADR-0038 による CLAUDE.md 変更で同期は実施される）
