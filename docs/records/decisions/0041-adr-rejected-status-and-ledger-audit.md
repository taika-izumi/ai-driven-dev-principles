# ADR-0041: コミット済み Proposed ADR の不採用経路（Rejected）を定義しステータス体系を完成させる

- **Status**: Proposed
- **Date**: 2026-07-07

## Context

Issue-0019 への対策。`decision-log` スキルには Accepted 後の破棄・置換手順（`Deprecated` / `Superseded by ADR-XXXX`）が定義されている一方、**コミット済みの Proposed ADR を「不採用」で終える経路が未定義**だった。現行の「却下」手順はファイルとインデックスエントリの削除を指示しており、コミット前のドラフトにのみ適切で、コミット済み ADR に適用すると「なぜ採用しなかったか」の記録が消え、原則1（追跡可能性）と矛盾する。また `start-work` の Post チェックは Proposed の昇格漏れのみを見ており、不採用方向の見直しを促すトリガーがなかった。

一般的な ADR 運用（MADR 等の標準テンプレート）では、不採用の提案は削除せず `Rejected` ステータスで残すのが通例である（同じ案が再浮上したときの再検討コストを下げる）。

対策方針の検討に先立ち、環境・ツール設定による構造的解決を調査した（ADR-0039）。本課題の核心（語彙・手順の不在）は定義の問題であり、環境設定や自動検査では代替できない。

なお、本課題の検討中に「Superseded の置換対象を現実的なコストで特定する手順」と「台帳全体のステータス監査」という隣接論点が浮上した。これらは別の問いに答える独立の決定として ADR-0042 に分離した。

## Considered Alternatives

1. **語彙・手順の定義＋見直しトリガーの対称化（採用）**: `decision-log` に Rejected を定義し、`start-work` の Post チェックを不採用方向にも対称化する
2. **語彙定義のみ（トリガーは触らない）**: Issue-0019 が明示する「不採用方向の見直しトリガーの不在」が未解決のまま残るため見送り
3. **何もしない（削除運用の継続）**: コミット済み ADR の削除は追跡可能性（原則1）と矛盾するため見送り

## Decision

### 1. ステータス体系の完成（`skills/decision-log/SKILL.md`）

4つの終端ステータスの意味境界を明文化する:

| ステータス | 意味 | 遷移元 |
|-----------|------|--------|
| Accepted | 承認され現役 | Proposed |
| Rejected（新設） | 承認前に不採用が確定 | Proposed |
| Deprecated | 承認後に廃止（置換先なし） | Accepted |
| Superseded by ADR-XXXX | 承認後に新 ADR で置換 | Accepted |

Rejected の手順: Status を `Rejected` に更新し、不採用の理由を Consequences に追記し、インデックスも更新してコミットする。ファイルは削除しない。

### 2. 却下分岐の分割（`skills/decision-log/SKILL.md`「ユーザーへの確認」）

却下の扱いを2つに分割する: **未コミットのドラフトは現行どおりファイル削除**、**コミット済みは Rejected 化**とし、削除手順のコミット済み ADR への適用を禁止する。

### 3. 不採用方向の見直しトリガー（`skills/start-work/SKILL.md`）

Post チェックの「Proposed の昇格漏れ確認」を対称化し、議論の結果不採用が確定した Proposed を Rejected へ更新する確認を同じチェックポイントに含める。

### 4. 変更しないもの

`CLAUDE.md` は変更しない（手順はすべて Layer 3 スキルに収まる。ADR-0040 の肥大化ガバナンスに従い常時指示を増やさない）。

## Consequences

- ＋ 4つの終端ステータスが揃い、コミット済み Proposed ADR を追跡可能性を保ったまま不採用で終えられる
- ＋ 不採用の理由が Consequences に残るため、同じ案が再浮上したときの再検討コストが下がる
- ＋ 昇格・不採用の両方向が同じチェックポイントで見直されるため、Proposed の長期滞留が減る
- − 終端ステータスが増えることで、使い分けの判断が必要になる（意味境界表で緩和する）
