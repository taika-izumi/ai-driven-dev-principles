# ADR-0042: Superseded の置換対象は変更箇所起点で特定し、網羅は台帳監査を保険とする

- **Status**: Proposed
- **Date**: 2026-07-07

## Context

Issue-0019 の対策検討中（ADR-0041 の設計議論）に浮上した論点。`Deprecated` / `Superseded by ADR-XXXX` は `decision-log` に定義済みだが適用実績がゼロで、「一度承認した ADR を Superseded に変更する仕組み」が現実的なコストで回るかが未検証だった。

具体的な懸念はユーザーから提起された: 新規 ADR を起票したとき、それによって Superseded になる既存 ADR の存在を把握していなければステータスを変更できない。これを愚直に実行すると起票のたびに既存 ADR の全件調査が必要になり、台帳の成長とともにコストが膨張する。

また、台帳全体（40件）のステータス正確性は一度も監査されておらず、実質置換済みの Accepted ADR が眠っている可能性がある（境界例: ADR-0015/0017、ADR-0016/0023、ADR-0003/0027、ADR-0010/0021）。

## Considered Alternatives

### 置換対象の特定方法

1. **起票時に既存 ADR を全件調査**: 網羅的だが、コストが台帳の成長とともに膨張するため見送り
2. **変更箇所起点の特定（採用）**: 置換が起きるのは既存の決定を変更している場面であり、エージェントはそれを起票時に自覚している（`decision-log` の既存の強トリガー「既存の判断の変更」）。よって問題は「変更中の決定の導入元 ADR 番号を安く特定すること」に縮約でき、全件走査は不要

### 網羅性の担保

1. **滞留検出スクリプトの新設（機械化）**: Proposed の滞留や相互参照の矛盾を機械的に警告する。現状の台帳はインデックスを見れば一目で分かる規模であり、滞留日数等の閾値にも根拠が薄く、メンテナンスコストが先行して YAGNI に反するため見送り。取りこぼしが実際に累積した時点で課題起票する（Issue-0018 と同じ「困った時点で起票」方針）
2. **定期監査（Nサイクルごと・日数閾値）**: 閾値の根拠が薄く空振りコストが先行するため見送り
3. **ユーザー指示＋矛盾発見をトリガーとする随時監査（採用）**: 観測可能な事実のみで構成される（ADR-0032）

## Decision

### 1. 置換対象の特定ステップ（`skills/decision-log/SKILL.md`）

ADR 作成手順の採番ステップ（インデックスの README テーブルを開くタイミング）に「この決定が変更・置換する既存決定の特定」を追加する:

- 一次経路: 変更対象ファイルが引用している ADR 番号を確認する
- 二次経路: 採番時に開いているインデックスのタイトルを同一トピックで走査する
- 置換対象が見つかったら、新 ADR の作成と同時に旧 ADR を `Superseded by ADR-XXXX` へ更新する

起票時の特定は網羅保証を追わない。コストを O(変更箇所) に抑え、取りこぼしは台帳監査（下記2）を保険とするトレードオフを明示的に選ぶ。

### 2. 台帳監査の定義（`CONTRIBUTING.md`「ADRを記録するとき」へ小節追加）

- **発動条件**: ① ユーザーが監査を指示した時点、または ② エージェントが作業中に台帳の矛盾（引用先 ADR と実態の不一致等）を具体的に発見し、監査を提案してユーザーが承認した時点
- **手順**: 全 ADR を「現役 / 部分修正あり（本体現役・状態変更なし）/ 実質置換（Superseded 化）/ 廃止（Deprecated 化）」で判定し、状態変更は `decision-log` の手順で記録する

### 3. 変更しないもの

新規スクリプトは作らない。`CLAUDE.md` は変更しない（ADR-0040 の肥大化ガバナンスに従う）。

## Consequences

- ＋ Superseded の適用が「変更箇所起点の特定手順」として実行可能になり、起票時コストが台帳の成長で膨張しない
- ＋ 台帳監査により、実質置換済みの Accepted ADR の取りこぼしを回収する経路が定義される
- − 起票時の特定は網羅保証を持たない。間接的な置換（ファイルを共有しない決定の前提を暗黙に無効化するケース）は監査まで検出されない
- − 台帳監査に定期トリガーがないため、ユーザー指示か矛盾発見がない限り実施されない。取りこぼしが実際に累積した場合は、滞留検出の機械化を課題として起票する
