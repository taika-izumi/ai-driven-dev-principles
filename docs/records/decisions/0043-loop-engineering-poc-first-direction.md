# ADR-0043: ループエンジニアリング環境は実証先行で構築し、現行体系は対話モード専用として無変更維持する

- **Status**: Accepted
- **Date**: 2026-07-08

## Context

ユーザーは「ゴール（完了の定義）を与えると、AI が作業→確認→修正のループを自律反復して達成する」環境（ループエンジニアリング）の実現を目指している。その入り口として、現行メタ・ガイドラインの現在地分析を実施した（2026-07-08 セッション）。分析の結論:

- Layer 1（5原則）は前文のリスクスケーリング（低リスクには高い自律性）により自律ループと互換。書き換え不要の見込み
- Layer 2（CLAUDE.md）/ Layer 3（スキル群）は人間同席の対話セッションを前提に具体化されており、ループとは前提が異なる（例: ADR-0035 の「応答がなければ停止・待機」はループの自律続行と正面衝突する。ADR-0024/0029/0036 の質問系規範も同様に対話前提）
- ループに必須で現行体系に無い要素は6点: 完了条件（DoD）の機械判定可能な記述様式、検証オラクル整備の規範、事前定義された権限境界、ループ制御（反復・コスト上限、振動検出、撤退条件）、事後監査プロトコル、実行基盤
- 現行体系の人間ゲート群は、ループ環境で機械的に置換すべき要求仕様のカタログとして資産価値を持つ（承認→権限境界、質問→DoD形式化、確認→検証オラクル、振り返り対話→テレメトリ＋事後レビュー）
- 人間判断が中心のプロジェクトでは現行ガイドラインを今後も使い続けるため、現行体系をループ対応に改修する動機がない

最初の適用先は新規のトレード戦略検討・バックテストプロジェクト（実行基盤: Claude Code、ゴール粒度はタスク単位から探索型へ段階拡大、現行の対話型ガイドラインと併用）と決まっている。

## Considered Alternatives

1. **実証先行・抽出先は本リポジトリ内2プロファイル構成を第一仮説として予約（採用）** — 今決められることだけを決め、受け皿の確定は実証後へ遅延する
2. **別リポジトリ新設を今決める** — 本リポジトリとの分離は最初から完全だが、実証前に構造を確定してしまい「実証先行」と矛盾する。Layer 1 の共有設計が二重管理になる。また検討中に発見した実行時干渉の論点（後述）は配布元の場所を分けても解決しないため、利点が心理的な分離の安心感に縮む
3. **現行体系へ直接ループ規範を追加する** — 対話規範とループ規範を同一 CLAUDE.md に同居させると条件分岐だらけになり、ADR-0040 の肥大化ガバナンスと衝突する。不採用
4. **本リポジトリ内の長期ブランチで検討を進める** — 自然言語文書は、マージ時に行の競合が起きなくても意味の矛盾が残り得るが、それを検出する仕組み（コードにおけるテスト相当）がない。また ADR の連番採番・台帳・issue インデックスは「アクティブなブランチは常に1本・短命・即マージ」の直列運用を前提としており、長期並行ブランチはこの前提を壊す。さらに本リポジトリには実行可能な検証オラクルがなく実証ができない。不採用（従来通りの短命 feature ブランチ運用は本決定の影響を受けない）

## Decision

案1を採用し、以下の3点を決定した:

1. 現行ガイドライン体系は**対話モード専用として無変更で現役継続**する（ループ対応の改修は行わない）
2. ループエンジニアリング環境は**新規トレード戦略プロジェクト内で実証先行**で構築する（本リポジトリには当面何も追加しない）
3. 実証後に汎用部分を抽出する際の受け皿は「**本リポジトリ内の2プロファイル構成**」を第一仮説とする。2プロファイル構成とは、Layer 1（5原則）を共有し、Layer 2/3 を対話プロファイル（現行資産そのまま）とループプロファイル（新規）にファイル・起動単位で分離する構成であり、1ファイル内のモード条件分岐は行わない。ただし**受け皿の確定は実証後**とし、実証結果次第で別リポジトリ案へ転換することを明示的に許容する

選定理由: 実証なしに書くループ規範は推測の産物になり書き直しリスクが高い（行動規範より構造的・実証的解決を優先する ADR-0039 と同じ思想）。また、対話規範の自動読み込みやスキル可視範囲といった実行時干渉の論点は配布元の場所に依存しないため、受け皿の決定は実証で判断材料が揃ってからで遅くない。

## Consequences

- 本リポジトリはループエンジニアリング関連の変更から当面隔離される（本 ADR とハンドオフ記載のみ）
- PoC で検証すべき項目（対話規範の読み込み干渉、スキル・プラグイン可視範囲のモード単位制御、汎用化候補の学びを記録する規律）はハンドオフ（`docs/working/handoff/master.md`）に記録し、トレード戦略プロジェクト側で扱う。本リポジトリの issue には起票しない（本リポジトリの課題ではないため）
- 実証で有効性が確認できるまで、2プロファイル構成の設計・実装は開始しない
- 汎用部分の抽出サイクルを開始する際は、本 ADR と実証の学びを入力として brainstorming からやり直す
