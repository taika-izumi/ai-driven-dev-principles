# ADR-0053: worklog の記録単位は「同一 context の delta 束」とし、節目のテーマ単位で複数記録を許す

- **Status**: Accepted
- **Date**: 2026-07-17

## Context

worklog-record は「1 呼び出し = 1 エントリ」と読める記述だが明示規範がなく、節目で複数の delta 候補があるとどれを記録するか毎回迷い、記録の粒度がブレると後段 worklog-extract のクラスタリング入力の粒度が揃わず抽出精度に影響する（Issue-0023。初回スモークテスト時に実際に迷いが発生した）。

## Considered Alternatives

- **厳格 1 件＋優先順位規範**: 節目ごと最大 1 エントリとし選択基準を明文化する。記録コスト最小だが、選に漏れた delta は永久に失われ、優先順位判断という新たな迷いどころを作る
- **原則 1 件・例外複数可**: 「重要なら複数可」は「重要」の判断が毎回発生し、粒度のブレが解消されない

## Decision

記録単位を定義で固定する: **1 エントリ = 同一 context（作業テーマ）を共有する delta の束**。

- 同一作業内の複数の躓きは `friction[]`（ADR-0051）に列挙する
- 節目に独立した作業テーマの delta が複数あれば、**テーマごとに複数エントリを記録してよい**
- 「どれを捨てるか」の優先順位判断は行わない（判断自体を不要にする）。ノイズ抑制は既存の記録ゲート（delta の存在。ADR-0044）が担う

## Consequences

- 良い影響: 記録粒度が context 単位で揃い、クラスタリング入力が安定する。優先順位判断の迷いが構造的に消える
- コスト・留意: 節目あたりの記録件数が増えうる（記録ゲートを通過した delta のみなので実害は限定的と見込む）。エントリの膨張が実害化した場合は件数上限の目安を再検討する
- Issue-0023 は本 ADR で close する
