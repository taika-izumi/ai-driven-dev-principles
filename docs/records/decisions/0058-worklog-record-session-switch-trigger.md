# ADR-0058: worklog-record の発火契機にセッション切り替え直前を追加する

- **Status**: Proposed
- **Date**: 2026-08-01

## Context

`worklog-record` の発火契機は ADR-0047 により「スキルの完了 / plan の1タスク完了 / 重要な分岐の通過」の3つに限定されている。いずれも**作業の節目**を条件としている。

しかし、節目でない時点でセッションを切り替える局面が実運用で発生する。中央ストア `LoopForAlpha-2026-07-19-07` は、コンテキスト使用率が逼迫し利用者がセッション終了を指示した場面を記録しており、`friction` に次のとおり記載されている。

> 記録契機が「作業の節目」に限定されており、コンテキスト逼迫によるセッション切り替えが独立した発火契機として定義されていない（節目でなくても切替直前は記録すべき局面がある）

このとき利用者は「キリのよいタイミングではないかもしれないが、セッションを切り替えると正確な作業の情報を引き継げない可能性があるので、今作業記録を残しておくこと」と指示している。セッションが切り替われば delta を保持している文脈は失われるため、節目かどうかに関わらず切り替え直前は記録の最終機会になる。

Issue-0037 の失敗モード3 として整理された。

## Considered Alternatives

- **A: 発火契機に「セッション切り替え直前」を追加する** — `skills/worklog-record/SKILL.md` のマイルストーン契機一覧へ1項目追加し、`start-work` のセッション終了処理にも worklog-record のステップを置く。現在このステップは終了処理に存在しない（retrospective 提案・ADR ドラフトのコミット・handoff finalize の3つのみ）
- **B: `session-handoff` の finalize 操作に記録を内包させる** — 発火契機の定義は変えず、finalize が worklog-record を呼ぶ形にする。契機の一覧が増えないが、handoff の確定と作業記録という別責務が1操作に混ざる（原則2）
- **C: 対処しない** — 利用者が都度指示する現状を維持する。実際に指示によって復旧しているが、記録の有無が人間の注意に依存し続ける

## Decision

選択肢 A を採用する。`worklog-record` の発火契機に「**セッション切り替え・コンテキスト逼迫による中断の直前（節目かどうかを問わない）**」を追加し、`start-work` のセッション終了処理へ worklog-record のステップを明示的に置く。

発火の判定は既存の記録ゲート（ADR-0044）をそのまま用いる。契機が増えるだけで、delta が存在しなければ記録しない点は変わらない。

判定条件は、エージェントが観測できる事実に限る（ADR-0032）: 利用者によるセッション終了・切り替えの明示指示、または `start-work` のセッション終了処理への到達。コンテキスト残量そのものを判定条件にはしない。

## Consequences

- **良い影響**: セッションが切り替わる前の最終機会で delta が回収される。切り替え後は文脈が失われるため、この契機の欠落は delta の恒久的な喪失を意味していた。`session-handoff` finalize と対になる形で終了処理が揃う
- **コスト・留意**: 発火契機が1つ増えるため、記録ゲートの判定回数が増える（大半は棄却されるため実記録の増加は限定的）。`skills/worklog-record/SKILL.md` と `skills/start-work/SKILL.md` の改定が必要でプラグイン更新を伴う（ADR-0055）
- ADR-0047 の配線（Post ラッパーからの発火）は維持する。本決定はそこへ契機を追加するものであり置換ではない
- 本決定は既存2スキルの挙動変更を伴う。実装完了・検証後に Accepted へ昇格する（ADR-0019）
