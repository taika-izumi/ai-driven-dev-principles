# ADR-0059: ADR の粒度は「後から探しに来るときの問い」で決め、文章量は基準にしない

- **Status**: Accepted
- **Date**: 2026-08-03

## Context

`decision-log` の ADR 作成手順には「1つの ADR に収める決定の単位」を判定する観点がない。このため「1サイクル=1ADR」の慣性で複数の独立した決定を束ねやすい。

実害は2回観測されている。

- 本リポジトリ: ADR-0041 の初版に独立した決定3件と実行計画を束ねて起票し、ユーザーレビューで分割となった（2026-07-07、Issue-0022 の起票元）
- LoopForAlpha: 議論の往復のたびに Proposed のままの ADR へ決定を追記し続け、1本に決定が9件まで肥大した。ユーザー指摘は「1ファイルに複数の意思決定が混在しており、後から『あの意思決定はどのファイルをみればわかるんだっけ』と迷ってしまう」というもので、対処は「後から探しに来るときの問い」を単位とした4本への再分割だった（2026-07-19、中央ストア `LoopForAlpha-2026-07-19-02`）

課題の核心は「決定を何件まで入れてよいか」ではなく、**1件と数える単位そのものが未定義**である点にある。単位が未定義だと、粒度の規範を書いても「1決定」の数え方で再び揺れる。

## Considered Alternatives

- **決定の件数を数える（1決定=1ADR を字義通り運用）**: Issue-0022 のタイトルどおりで単純だが、「1決定」の数え方自体が曖昧なため、起票時の慣性に負けやすい。実例の LoopForAlpha でも、追記のたびに「これは同じ決定の詳細化だ」と解釈されて肥大した
- **独立して Superseded / Rejected になりうるかで切る**: 台帳のライフサイクル視点で、ADR-0041 を分割した本来の理由（大型 ADR の部分置換が台帳のステータス管理を悪化させる）に直結する。ただし将来の置換可能性という予測を要求するため、起票時点では判定が安定しない
- **文章量の上限で判定する**: 計測を機械化でき（`scripts/check-claude-md-size.ps1` に先例がある）、判定に解釈が入らない。しかし実測が指標としての成立を否定した（下記）
- **「後から探しに来るときの問い」が1つに収まるかで切る（採用）**: 検索者視点の失敗（どのファイルを見ればよいか分からない）に直結し、実際にユーザーが再分割で用いた単位。決定の件数を数えず、将来予測も不要なため、起票時点で判定できる

### 文章量が指標として成立しない実測

- 肥大していた LoopForAlpha の ADR-0034 は 5,545文字。分割後の4本は 3,757 / 3,324 / 4,044 / 2,793文字で、**合計 13,918文字と元の約2.5倍に増えた**（各 ADR が単独で成立するよう Context・検討した選択肢・帰結をそれぞれ持つため）。分割は総文章量を減らさない
- LoopForAlpha の ADR 99本は中央値 2,523 / 最大 7,558文字で、**肥大していた 5,545文字より大きい正常な ADR が複数ある**（上位5本は 5,254 / 5,677 / 6,247 / 6,615 / 7,558）。本リポジトリの 58本も中央値 1,689 / 最大 5,912文字
- したがって閾値をどこに引いても、見逃し（肥大 ADR が正常な大型 ADR より小さい）と誤検出（正常な大型 ADR への警告）が同時に発生する

## Decision

ADR を分ける単位は「**後から探しに来るときの問い**」とする。1つの ADR は、将来その決定を探しに来る人が立てる問い1つに答えるものとし、問いが2つ以上に割れるなら ADR を分ける。

タイトルはその問いへの答えとして読めるように書く。タイトルが答えていない決定が本文にあるなら、それは別の問いに属する決定であり、分割の対象とする。

**文章量（文字数・行数）は粒度の基準にしない**。上限値も目安値も設けず、計測スクリプトによる警告も導入しない。長い ADR であることは分割の理由にならず、問いが1つに収まっているかだけを見る。

## Consequences

- 起票時に「この ADR はどんな問いで探されるか」を1回考えるだけで判定でき、決定の件数を数える必要がない
- タイトルと本文の乖離が分割の外形的な兆候になるため、肥大の検出をタイトル突合で行える
- 文章量という機械判定可能な指標を採らないため、粒度の判定は最後まで意味的な判断に依存する。機械化による取りこぼし防止は期待できない
- 分割すると総文章量はむしろ増える。粒度を保つことの利益は文章量の削減ではなく、探索時に正しいファイルへ到達できることに限られる
- 問いの立て方には幅があるため、判定が一意には定まらない。粗く立てれば大型 ADR を正当化でき、細かく立てれば ADR が増えすぎる。この幅は運用の中で事例を積んで狭める
- 既存の ADR を遡って再分割することはしない（本 ADR は起票時の判定軸であり、過去 ADR の監査基準ではない）
