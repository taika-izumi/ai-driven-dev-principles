# ADR-0062: 今サイクルは worklog パイプラインの疎通を優先し、構造観察型の取り込みは次サイクルへ送る

- **Status**: Accepted
- **Date**: 2026-08-05

## Context

ADR-0061 で「配布先の flow 課題は delta 型を worklog 経路へ委ねる」と決めた結果、**その経路が実際に流れることが前提条件**になった。2026-08-05 に中央ストアを実測したところ、経路は止まっていた。

- 中央ストアは 120 エントリ（LoopForAlpha 106 / MakeAiInstructions 14）、処理済み台帳は 18 行。**前回走査（2026-07-31）以降の 23 件が未処理**
- 台帳の `adopted` 4 件のうち 3 件（Issue-0033 / 0034 / 0015）が open のまま。以後 3 サイクル（retrospective 役割再定義 → Post ラッパー可視化 → ADR 粒度）が別テーマで回り、**出口である `worklog-skillify` は一度も起動していない**
- `LoopForAlpha/log.jsonl` の CR は、Issue-0050 起票時（2026-07-27）の 3 行から**現在 5 行へ増えている**。書き側の契約違反が累積している
- `worklog-extract` 手順 2 が定める健全性検査（BOM・CRLF・非 UTF-8 を検出して報告・停止）は、その CR=5 を素通りする状態にある。**規範として書かれた検査が一度も発火を確かめられていない**

最後の点は、LoopForAlpha-0084（検出器自身の検出力が確かめられず「常に 0 件を返す検査」が生まれる）が主張する事象そのものが、本リポジトリのスキル内で成立していることを意味する。

## Considered Alternatives

1. **検証の検出力（LoopForAlpha-0084 / 0069 / 0054 / 0034）を新規テーマとして設計する** — 当初の推奨案。実害は最も大きいが、ADR-0061 の検証で一般形が既に Issue-0033 / 0034 と中央ストアの在庫エントリに存在すると判明したため、新規設計は重複になる
2. **構造観察型（クラスタ C）を先に片付ける** — 手で運ぶしかないため確実に進むが、worklog 経路が止まったまま未処理エントリが積み増す。ADR-0061 が前提とする経路の不通を放置することになる
3. **worklog パイプラインの疎通を先に通す** — 採用

## Decision

今サイクルのスコープと順序を次のとおりとする。構造観察型（クラスタ C）の取り込みは次サイクルへ送る。

| Task | 内容 | 対応する課題 |
|---|---|---|
| 0 | 配布先からの申し送り経路・クロスリポジトリ参照形式・close トリガーを規範化する | Issue-0040 / Issue-0041 |
| 1 | 中央ストアの書き側契約の矛盾を解消し、読み側の健全性検出手段を具体化して発火を実測する | LoopForAlpha-0050 / Issue-0032 |
| 2 | `worklog-extract` を再走査する（未処理 23 件 + `deferred` 14 件の再浮上判定） | — |
| 3 | `worklog-skillify` で採用済み候補を成果物化する | Issue-0033 / Issue-0034 |
| 4 | LoopForAlpha 側 flow 課題の close 判定と一括処理を行う | ADR-0061 の適用 |

順序の根拠:

- **Task 1 は Task 2 に先行する。** 健全性検査が機能しない状態で走査しても、走査結果を信用できない。CR=5 の素通りが実例である
- **Task 0 は Task 4 の判断根拠であり、かつ Task 3 の記録先を決める。** また `docs/overview/folder-structure.md` は `sync-template.ps1` の同期対象であるため、Issue-0040（`CONTRIBUTING.md` の同期指示が現行構成と矛盾）が実際の前提条件になる

## Consequences

- **滞留が解消し、以後 delta 型の申し送りが自動で流れる状態になる。** ADR-0061 が成立する前提が満たされる
- **取り込み作業そのものが Task 0 で定める規範の初回適用になる。** 規範を書いて終わりにせず、同一サイクル内で実行可能性が検証される
- **Task 1 は「検査が発火することを実測する」形を取るため、LoopForAlpha-0084 の対処の先行実例になる。** 0084 自体は Task 2 の走査で正規に上がってくる
- **クラスタ C の解消が 1 サイクル遅れる。** LoopForAlpha のハンドオフは 573 行・約 77KB に達しており、本リポジトリの `master.md` も 100 行超で同型の兆候がある。遅延の間に肥大は進む
- **Task 数 5 で中規模のサイクルになる。** LoopForAlpha-0042（サイクル規模の当初見積もり誤差が繰り返し発生する。規模再見積もりのチェックポイントが無い）が未対処であるため、膨張しても気づく仕組みが無い状態で着手することになる
