# ADR-0068: 他リポジトリの課題は `<repo>#Issue-NNNN` で修飾して参照する

- **Status**: Accepted
- **Date**: 2026-08-05

## Context

課題番号は**リポジトリ内で一意**に採番される（`docs/overview/folder-structure.md` 7.2「採番は両フォルダ通しの連番 — インデックス全体の最大番号+1。Issue-NNNN の参照がプロジェクト内で一意になる」）。この一意性はリポジトリ内で閉じており、**リポジトリをまたぐと同じ番号が別の課題を指す**。

ガイドラインは配布物であり、配布先（LoopForAlpha 等）の課題を本リポジトリの記録から参照する場面が常時発生する。ADR-0061 で配布先の flow 課題を取り込む経路を定めたことで、この参照は例外ではなく定常的な操作になった。

**衝突は既に起きている。** LoopForAlpha の `flow/0034`（編集ツールが不可視文字のエスケープ表記を生の文字へ正規化する）と、本リポジトリの `flow/0034`（計画・仕様など非コード成果物の確定前に実証を課した独立レビューを挟む工程がない）は、番号が同じで内容の異なる別課題である。無修飾の `Issue-0034` はどちらとも読める。

worklog 台帳（`~/.ai-dev-worklog/processed.jsonl`）の `ref` フィールドにも同じ穴がある。2026-07-31 の走査で記録された値は `docs/working/issues/flow/0034-independent-review-with-proof-for-non-code-artifacts.md` というリポジトリ修飾のない相対パスで、どちらのリポジトリを指すかは slug を読まなければ判別できない。中央ストアは全プロジェクト共有であるため、この曖昧さは構造的に発生する。

## Considered Alternatives

1. **配布先の課題番号をガイドライン repo 側でも引き継ぐ** — 参照の衝突は解決するが、採番規則（リポジトリ内の通し連番）を壊す。配布先が 2 つ以上になると番号空間が競合して成立しない
2. **参照は常にファイルパスで書く** — 一意ではあるが冗長で、slug が変わると壊れる。文中での可読性も落ちる
3. **リポジトリ名で修飾する** — 採用

## Decision

- **他リポジトリの課題を参照するときは、必ずリポジトリ名で修飾する。** 書式は `<repo>#Issue-NNNN`（例: `LoopForAlpha#Issue-0069`）
- **同一リポジトリ内の参照は従来どおり `Issue-NNNN` でよい。** 修飾は跨いだときだけ要る
- **worklog 台帳の `ref` フィールドにもリポジトリ名を含める**（例: `MakeAiInstructions:docs/working/issues/flow/0034-....md`）。中央ストアは全プロジェクト共有のため、パスだけでは出所が決まらない
- **既存の記述には遡及適用しない。** 過去の無修飾参照はそのまま残す

規範の本体は `docs/overview/folder-structure.md` 7.4.1 に置く（template 同期対象であるため配布先へも届く）。

## Consequences

- **番号の衝突が読み手の推測に委ねられなくなる。** 現に衝突している 1 組（両リポジトリの `flow/0034`）は、修飾さえあれば区別できる
- **採番規則を変えずに済む。** 配布先が増えても番号空間の設計は不要で、修飾の追加だけで対応できる
- **既存の記述に遡及しないため、移行期は無修飾の参照が残る。** 読み手は文脈で判断する必要がある。既存文書の一括書き換えを避ける代わりに、この曖昧さを受け入れた
- **機械検査はない。** 無修飾のまま他リポジトリを指す記述が混入しても検出されない。規範の遵守は書き手に委ねられており、`docs/reference/ai-review-and-verification-practices.md` §6 の「記述による規律は再発を防がず、実効的なのは機械検査である」に照らすと弱い
- 本 ADR は ADR-0063（配布先からの申し送りの起票経路と close トリガー）から分割された。両者は同じ取り込み作業の中で決まったが、答える問いが異なる（ADR-0059 / ADR-0060 の粒度規範）
- **部分修正（ADR-0105）**: 名指しする folder-structure の節番号は「7. 仕様書の運用規約」新設で繰り上がった（規範内容は不変）
