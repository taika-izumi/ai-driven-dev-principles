# ADR-0070: サブエージェント委譲の常時制約は規範文で実装し、フックによる機械注入は採らない

- **Status**: Accepted
- **Date**: 2026-08-05

## Context

ADR-0066 は、サブエージェント委譲時の定型項目を A 群（常時適用 4 件）と B 群（条件発火 8 件）に分けた。ただし決めたのは**どれをいつ適用するか**であり、**それをどこにどう書くか**は決めていない。

ADR-0039 は、規範・運用ルールを追加する前に環境・ツール設定による構造的解決が可能かを先に調査することを定めている。本決定はその調査を実施した結果である。

調査結果（Claude Code 公式ドキュメント `code.claude.com/docs/en/hooks`、2026-08-05 取得）:

- `PreToolUse` フックは `Task`（サブエージェント委譲）を matcher に指定できる
- `hookSpecificOutput.updatedInput` により、ツール入力（委譲プロンプト）を実行前に書き換えられる
- フックはプラグインの `hooks/hooks.json` で配布でき、`${CLAUDE_PLUGIN_ROOT}` からスクリプトを起動できる
- `SubagentStart` / `SubagentStop` イベントも存在する

**A 群 4 件は無条件適用であり、タスクの型を判定せずに注入できる。** したがって機械注入は技術的に成立する。B 群は発火条件の判定が要るため、同じ手段では扱えない。

## Considered Alternatives

1. **フックによる自動注入のみ（スキルに A 群を書かない）** — 規範の二重管理を避けられるが、フックが無い環境（Copilot CLI、フック未設定の Claude Code）では A 群が完全に消える。加えて、効いている制約が設定ファイルの中にしか存在せず、作業中のエージェントからも人間からも見えない。Issue-0039（ガイドライン遵守が不可視機構に依存しうる）と同型のリスクを新規に作り込むことになる
2. **規範文＋フックの併用** — 遵守の確実性は最も高い。ただしスクリプト実装・プラグインへの配線・動作検証が加わり、今サイクルの規模が 1.5〜2 倍になる
3. **規範文のみ** — 採用

## Decision

**A 群の常時適用はスキルの規範文として実装する。フックによる機械注入は今サイクルでは採らない。**

判断の根拠は 3 点。

- **ツール中立性**: 本リポジトリのガイドラインは Claude Code と GitHub Copilot CLI の双方を対象にしている（`CLAUDE.md` 前提条件）。フックは Claude Code 固有の機構であり、Copilot CLI の利用者には効かない。規範文はどちらでも同じに効く
- **出口への到達を優先する**: Issue-0033 / 0034 は `adopted` のまま 4 サイクル目に入っている。ADR-0065 は「設計 ADR が出ないまま次サイクルへ送られた場合、本決定は失敗とみなす」という判定基準を自ら置いた。今サイクルの目的は台帳を `skillified` へ到達させることであり、機械注入の実装はその目的に対して追加の risk である
- **不可視機構への依存を増やさない**: 代替案 1 の問題は併用（代替案 2）でも部分的に残る。規範文とフックが同じ制約を二重に持つと、片方だけを更新したときに実際に注入される文言と規範文が食い違い、どちらが効いているかを実行中に確認する手段がない

フックによる機械注入は**破棄せず、課題として起票する**（Issue-0047）。本決定は「今サイクルでは採らない」であって「フックは使わない」ではない。

## Consequences

- **ツールを問わず適用される。** 配布先が Copilot CLI であっても A 群は効く
- **今サイクル内で完成する。** スクリプト実装・配線・検証の工程が入らないため、authoring とスキル配線だけでサイクルが閉じる
- **遵守は AI の規範読解に依存し、取りこぼしうる。** これは本決定が引き受けるリスクである。Issue-0033 の根拠 10 件中 9 件が `friction`（人間の指摘を待たず AI が自力で踏んだ手戻り）であり、**規範文を書けば再発が止まるという保証はない**。ADR-0066 の Consequences が指摘した「A 群を条件判断に委ねてはならない」は、規範文でも判断の余地を残す
- **効き目は worklog で測れる。** 本決定の後に同型の delta（A 群の項目を渡し忘れた記録）が中央ストアへ再び現れた場合、それが規範文だけでは不足であることの実測になり、Issue-0047（フック化）へ着手する根拠になる。逆に現れなければ規範文で足りている
- **フック機構の調査結果は失われない。** Issue-0047 に取得日つきで記録するため、着手時に再調査を要しない
