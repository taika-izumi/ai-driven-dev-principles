# ADR-0073: 委譲制約の規範項目には根拠と世代を添え、実測にもとづく退役経路を持たせる

- **Status**: Accepted
- **Date**: 2026-08-05

## Context

設計承認後のユーザーレビューで、本サイクルの成果物（委譲制約の規範群）に対して「現行 AI モデルへの過剰最適化・将来のモデルやプロジェクトへの不適合」の懸念が提起された。点検した結果、骨格（A/B 分割・規範文方式・ユーザー起動レビュー）は各分岐で緩い側を選んでおり維持できるが、局所的に過剰適合の芽が 3 点確認された。

1. **B 群のミューテーション検査 3 項目の根拠が狭い。** 「各変異行に検出できる入力を併記」「throw だけの検査を RED 件数から除外」等は、根拠 8 件全件が単一プロジェクト（LoopForAlpha）のテスト運用出所である（Issue-0033 の 2026-08-05 追記）。単一プロジェクトの教訓を汎用スキルの拘束的規範へ昇格させると、異なるテスト文化のプロジェクトで不適合を起こす
2. **ADR-0071 の「将来の項目は既存 5 条件に収めることを優先」が硬い。** 5 行固定は「委譲 1 回ごとの読み下ろし担保」としては正しいが、表の行構成を将来にわたり固定する理由にはならない。5 条件は現在の作業様式の写像であり、未知のプロジェクト型では条件自体が入れ替わるべきである
3. **撤去条件が非対称。** ADR-0070 は「同型 delta が再発したらフック化へ強める」方向を定義したが、「発火しなくなった項目を退役させる」方向のトリガーが無い。CLAUDE.md には棚卸しフロー（ADR-0040）があるのに、スキル内規範には日没機構が無く、モデル世代が進んで不要になった制約が残留する経路が開いている

## Considered Alternatives

1. **修正せず進める** — 既存の測定ループ（delta 再発の監視）は「強める」方向しか持たず、懸念 3 が残る
2. **A 群の常時適用まで含めて根本から再設計する** — A 群は能力の制限ではなく原則 2/4 の委譲先への伝播であり、モデル性能と独立に成立する。再設計の根拠が無い
3. **骨格を維持し、過剰適合の芽 3 点のみを修正する** — 採用

## Decision

以下の 3 点を設計へ反映する。

### (a) ミューテーション検査 3 項目を「条件の適用例」へ降格する

B 群の発火条件「ミューテーション検査を委譲するとき」は維持するが、紐づく 3 項目は拘束的規範ではなく**適用例**として記載し、単一プロジェクト出所であることを明記する。委譲側は例を出発点に、対象プロジェクトのテスト文化に合わせて内容を調整する（ADR-0066 の部分修正。発火条件の分類そのものは現役）。

### (b) ADR-0071 の固定条項を撤回する

「将来 B 群へ項目を追加する場合は既存 5 条件へ収めることを優先」を撤回する。担保の本体は「**委譲の時点で、その時点の表の全行を読み下ろし、判定行を残すこと**」であり、表の行構成そのものは worklog の実測にもとづき見直してよい（ADR-0071 の部分修正。読み下ろし手順と判定行は現役）。

### (c) 各項目に根拠と世代を添え、退役経路を持たせる

- スキルに記載する各制約項目には、根拠エントリ id（または Issue 番号）と、その delta が観測されたモデル世代を 1 行で添える
- 退役規範: 項目に対応する同型 delta が長期にわたり中央ストアへ現れない場合、その項目は退役候補としてユーザーへ提案する。退役の判断はユーザーが行う
- 退役候補の検出を `worklog-extract` の走査へ機械的に組み込む改修は、今サイクルの規模を超えるため Issue-0048 として分離する。それまで検出は手動（棚卸し時・ユーザー指示時）で行う

## Consequences

- **規範が反証可能になる。** 各項目が「どの実測に基づき、どの世代で観測されたか」を持つため、「もう起きていない」ことを根拠に退役させられる。強める方向（ADR-0070）と合わせ、測定ループが双方向になる
- **単一プロジェクト出所の知見が失われない。** ミューテーション 3 項目は例として残り、該当するプロジェクトでは従来どおり使える。拘束力だけが下がる
- **項目ごとの記載が 1 行増える。** 根拠と世代の記録は authoring 時のコストだが、退役判断の材料としてそのまま使われる
- **退役検出は当面手動である。** Issue-0048 が実装されるまで、発火しなくなった項目の検出は棚卸しに依存する
- ADR-0066 / ADR-0071 は本 ADR による部分修正を Consequences に追記して現役のまま維持する（Superseded にはしない。答えている問いが異なるため）
