# ADR-0077: handoff の外部参照は安定識別子で書く

- **Status**: Proposed
- **Date**: 2026-08-06

## Context

Issue-0049 の一部: handoff から外部文書への参照が節名・項番（「〜の第 2 節」「手順書の項目 3」等）で書かれており、参照先の構造が変わると追随せず壊れる。配布先（LoopForAlpha）では、不可逆操作の手順書への参照が節名の取り違えで誤ったまま複数セッション残存した（実害は正本への突き合わせで回避）。

ADR-0075 の剪定は「詳細を正本への参照へ置き換える」操作を含むため、参照の壊れにくさは剪定規約の前提条件になる。

## Considered Alternatives

1. **安定識別子での参照を必須にする** — ADR 番号 / Issue 番号 / ファイルパス / コミットハッシュなど、リネーム・構造変更に対して安定な識別子で参照する。節名・項番は補助としての併記のみ許す
2. **現状のまま（自由記述）** — 規約コストはないが、実測済みの失敗（節名取り違えの残存）が再発する
3. **参照先にアンカー（見出し ID 等）を整備する** — 参照先ドキュメント側の改修が必要で、対象が全文書に及ぶ。コストが利得に見合わない

## Decision

案 1 を採用する。**handoff に外部文書への参照を書くときは、安定識別子（ADR-NNNN / Issue-NNNN / ファイルパス / コミットハッシュ）を必ず含める。** 節名・項番だけの参照は書かない（安定識別子への併記は可。例: `skills/retrospective/SKILL.md の Phase 3` は可、「振り返りスキルの仕上げ節」だけは不可）。

適用範囲は handoff とする（Issue-0049 のスコープ。他文書への一般化は必要が観測された時点で別途決定する）。

## Consequences

- 参照先の構造変更・改名に対して参照が壊れにくくなり、剪定（ADR-0075）の「参照への置き換え」が安全に機能する
- ファイルパスはリネームで壊れ得るが、git 履歴で追跡可能であり、節名より安定性が高い
- 書き手（エージェント）に識別子確認の手間が 1 回分増える
- `session-handoff` スキルのフォーマット節への規約追記が必要
