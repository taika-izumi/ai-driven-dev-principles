# ADR-0078: 体系の呼称を「メタ・ガイドライン」から「AI駆動開発ガイドライン」へ改める

- **Status**: Proposed
- **Date**: 2026-08-06

## Context

本リポジトリが整備する体系（5 原則 + エージェント行動指示 + スキル群）は「メタ・ガイドライン」と呼ばれてきたが、この名称は初見の読者に意味が伝わらない（「メタ」が指す内容＝開発の進め方そのものを対象とする、が名前から読み取れない）。本リポジトリ自身の命名規律（ADR-0022: 説明的な表現を用い、定義のない記号的呼称を避ける）に照らしても弱い。ユーザーの問題提起により改名を検討した。

## Considered Alternatives

1. **「メタ・ガイドライン」を維持** — 変更コストゼロだが、初見に伝わらない問題が残る
2. **「AI駆動開発ガイドライン」** — 平易でリポジトリ名 `ai-driven-dev-principles` と一致。「テスト駆動開発」等の「◯◯駆動開発」慣習により「AI が開発プロセスを駆動する」と読まれる。懸念として `docs/overview/folder-structure.md` の既存用語「AI駆動システム」（開発対象の属性）と「AI駆動」を共有するが、エージェントは常に CLAUDE.md 等の文脈定義とともに名称に接するため実務上の混同は起きにくい（人間には業界慣習が効く）
3. **「AIエージェント駆動開発ガイドライン」** — 駆動の主語が明確になるが長く、複合語である以上「エージェント駆動システムの開発」という誤読経路は原理的に残る（優位性が長さに見合わない）
4. **「AIエージェントを活用した開発ガイドライン」** — 助詞により文法的に誤読不能だが、名前として長く、見出し・複合参照での収まりが悪い

## Decision

案 2 を採用する。**体系の正式呼称を「AI駆動開発ガイドライン」とする。**

あわせて、README・CLAUDE.md 等の初出箇所には一行定義（例:「AIエージェントと協働して開発を進めるための原則・行動指示・スキルの体系」）を添える（ADR-0022 の初出説明規範の適用）。名前単体の誤読リスクは、業界慣習（人間向け）と文脈定義（エージェント向け）の二重で抑える。

## Consequences

- 初見の読者・エージェントに体系の対象（開発の進め方）が名前から伝わる
- 書き換え対象は現行の規範文書（README / CLAUDE.md / principles.md / CONTRIBUTING / スキル本文 / template / plugin メタデータ）。追記型の記録（過去の ADR・retrospective・完了済み plan / handoff）は書き換えない（ADR-0011）。具体的な対象範囲は実装サイクルの plan で確定する（リポジトリ内の全出現は 94 箇所・46 ファイル、2026-08-06 時点の実測）
- 「AI駆動システム」（folder-structure.md）は定義付きの現状のまま維持する
- template 対象ファイル（CLAUDE.md / principles.md）の変更を含むため `scripts/sync-template.ps1` の実行が必要
- 実装完了・検証後に Accepted へ昇格する（ADR-0019）
