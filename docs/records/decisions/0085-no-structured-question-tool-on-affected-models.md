# ADR-0085: 事象確認済みモデルでは構造化質問ツールを使用せず、テキストの番号付き選択肢に一本化する

- **Status**: Accepted
- **Date**: 2026-08-13

## Context

ADR-0029 は「構造化質問ツールと同一ターンのテキストが表示されない」事象への対処として、事象確認済みモデル（Claude Fable 5）に限り「質問の自己完結」＋「長い説明が必要な場合のテキストフォールバック」の 2 本立てを定めた。

しかしその後も事象の再発が続き（2026-08-03 にモデル切替後の再評価漏れによる再発 `MakeAiInstructions-2026-08-03-01`、2026-08-08 に配布先 LoopForAlpha でユーザーから「質問ツールの使用を控えてください」の先行指示 `LoopForAlpha-2026-08-08-01`、2026-08-13 にも発生）、2026-08-13 にユーザーから「モデルが Fable 5 の時は質問ツールを使用しないでください。メッセージ本文が表示されず、質問ツールの質問と選択肢しか見えない現象がこれまで何度も確認されています」と明示指示があった。自己完結形式であっても、質問文・選択肢説明の欄に収まる情報量には限界があり、表示されない本文に文脈を置く事故が構造的に再発する（自己完結の判定そのものがエージェントの裁量判断であり、確実に守られる保証がない）。

CONTRIBUTING の「CLAUDE.md を更新するとき」事前判定の記録: 放置リスクは「顕在化はするが、顕在化した時点でユーザーは説明を読めないまま選択を迫られており、判断の誤誘導が既に発生している（事後検出では回復できない）」型であり、常時指示（CLAUDE.md）の維持が妥当と判定した。実測は変更前 11369B・38 箇条 → 変更後も閾値内（Consequences 参照）。

## Considered Alternatives

1. **事象確認済みモデルでは構造化質問ツールを全面不使用とし、テキストの番号付き選択肢に一本化する（採用）** — 事故経路（本文に文脈を置く／自己完結判定の誤り）を構造的に塞ぐ。ADR-0029 が不採用とした案 C（常時テキスト回帰）と異なり、モデル条件付きのため未確認モデルでは構造化ツールの利点を維持する
2. **ADR-0029 の 2 本立てを維持し、自己完結判定を厳格化する** — 判定基準をどれだけ厳格化しても判定主体はエージェントのままで、誤判定の再発経路が残る。実測で複数回再発しており不採用
3. **無条件の全面不使用（モデル条件なし）** — 事象が発生しないモデルでの利便性（誤操作防止・回答コスト減。ADR-0024/0036）を不必要に失う。ADR-0029 の案 C と実質同一で、同じく過剰対応のため不採用
4. **環境・ツール設定による構造的ブロック（配置先優先順位①の調査記録）** — permissions の deny 等でツール自体を無効化する解決は、設定側でモデル条件の分岐を表現できず、無条件 deny は案 3 と同じ過剰対応になる。フックによる条件付き機械注入は、同種の検討で規範文実装を優先した先例（ADR-0070）に照らして複雑さが利得に見合わない。よって規範文（CLAUDE.md）実装を維持する

## Decision

案 1 を採用する。`CLAUDE.md`「ユーザーへの質問と意思決定要求」のモデル条件付き対処を次の内容に置き換える。

1. **適用条件**（ADR-0029 から継承・判定手段を追加）: 「構造化質問ツールと同一ターンに書いた説明テキストがユーザーに表示されない」事象が確認されているモデルで動作している場合にのみ適用する。事象確認済みモデル: Claude Fable 5（2026-06〜2026-08 に複数回確認）。ゲートは**モデル単独**とし、ツールとの組み合わせでは条件付けない（テキスト提示への切替はどのツール環境でも安全に成立し、誤発動側の損失が小さいため。ADR-0029 が未決としていたモデル×ツールの帰属はこの安全側配置で吸収する）。動作モデルはシステムプロンプトの記載とモデル切替通知で確認し、**判定できない場合は使用しない側に倒す**。リストへの追記は、ユーザーが新たなモデルでの同事象を指摘した時点で行う（事象はユーザー画面上の現象でありエージェントから観測できないため、判断主体をユーザーに置く）
2. **対処内容**（本 ADR で変更）: 事象確認済みモデルでは、質問の重要度・自己完結の可否を問わず**構造化質問ツールを使用しない**。すべての質問をテキストのみのターンで行う（選択肢を提示できる質問は説明と番号付き選択肢（推奨を先頭に「（推奨）」付き。ADR-0024 の提示規範）を添え、自由記述が本質的に必要な質問は ADR-0024 の例外に従う）。ADR-0036 の分岐 1（防止設定確認済みなら使用してよい）に対しては本条項が優先し、その旨を分岐 1 側の箇条にも例外参照として明記する
3. **評価タイミング**（本 ADR で新設）: 本条項の適用可否は、セッション開始時に加え、モデル切替の通知を見た時点で再評価する（2026-08-03 の再発は切替後の再評価漏れが経路であったため、評価タイミングを規範本文に含める）
4. **撤去基準**（ADR-0029 から継承）: 事象が発生しないモデルの利用が常態化したとユーザーが判断し撤去を指示した時点で本項目を削除し、本 ADR を Deprecated に更新する

ADR-0029 は Superseded by ADR-0085 とする（適用条件・撤去基準の枠組みは本 ADR が継承し、対処内容を置換）。実装位置は ADR-0029 と同じく Layer 2（`CLAUDE.md`）のみとする。

## Consequences

- 事象確認済みモデルでの「本文が見えないまま選択を迫られる」事故が、エージェントの裁量判定を経由せず構造的に防止される
- 事象確認済みモデルでは構造化ツールの誤操作防止効果（ADR-0036 の環境設定と併用していた）を失い、番号の打ち間違い等はユーザーの入力注意に依存する
- 構造化質問ツールのタイムアウト停止規範（ADR-0035）は、事象確認済みモデルでは発動機会がなくなる（規範自体は未確認モデル向けに現役のまま）
- 残存リスク（ADR-0029 から継承）: 未確認モデル・派生/後継モデル名への切替直後は条件が偽となり、事象が再発しうる。再発時はユーザー指摘によるリスト追記で対応する
- 実測記録（CONTRIBUTING 事前判定 1）: CLAUDE.md は変更前 11369B・38 箇条 → 初回置換で 11254B・38 箇条（115B 純減）。レビュー反映後も閾値（12000B / 45 箇条）内であることを sync-template の自動計測で確認する
- `CLAUDE.md` は template.manifest 対象のため、変更後に `scripts/sync-template.ps1` の実行が必要
- 本 ADR は確定前レビュー（3 観点独立レビュー）の指摘を反映して Accepted 後に改訂された（許可条項との衝突解消・評価タイミングの新設・判定手段の明記・出所実数の記載）
