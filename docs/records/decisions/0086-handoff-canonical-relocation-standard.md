# ADR-0086: handoff に溜まる情報の正本置き場を種類別対応表で定め、finalize に移設工程を新設する

- **Status**: Proposed
- **Date**: 2026-08-13

## Context

Issue-0079: finalize の基準付き圧縮（ADR-0075）は「正本が handoff 以外にないもの」を圧縮対象から除外するが、この保護規則は「handoff を正本として書けば何でも無制限に保護される」という抜け道を持つ。LoopForAlpha の実測（2026-08-13）では、「進行中のタスク」節 31.5KB に教訓の番号付きリスト 32 項目が蓄積し、「正本がここにしか無いもの」と明示した小節まで存在した。蓄積されている情報自体は高価値であり、削るべき情報ではなく**置き場を誤った情報**が溜まっている。

ユーザー制約: ハンドオフの簡略化しすぎで引継ぎ後の作業精度を落とさない（対策は削除ではなく正本の移設）。

設計中にユーザーから「情報の配置先ルールをどこで定義するか。整理ルールは整理に使うスキル側で保持したいが、folder-structure.md にも配置定義がある。役割分担を明確にしたい」という論点が提起された（2026-08-13）。

## Considered Alternatives

1. **対応表をスキルに置き、移設先は分類名で参照する（採用）** — 配置定義（What/Where）は folder-structure.md、移動手順（When/How）はスキル、という役割分担。スキルはプラグイン配布（中央改定が全プロジェクトへ届く）、folder-structure は template 配布（プロジェクト初期に複製され以後プロジェクト所有）という配布経路の性質と一致する
2. **対応表を folder-structure.md に置く** — handoff 固有の細粒度がオリエンテーション文書に混ざり肥大する。スキル手順の改善のたびに template 側の同期が要り、配布経路の性質と合わない。不採用
3. **folder-structure.md を削除しスキルへ一本化する** — 配置定義は organize-inbox・decision-log・人間の手動配置など複数の利用者が参照する共通基盤であり、スキルへ一本化すると分類定義が各スキルに重複し、二重定義の片側だけ更新されるドリフト（Issue-0082 と同型）を量産する。配布先でスキルは編集しない前提（ADR-0069）のため、プロジェクト固有のフォルダ調整の受け皿も失う。不採用
4. **保護量に上限を設けて超過分を強制削除する** — 情報を失い、ユーザー制約（引継ぎ精度）に反する。不採用

## Decision

案 1 を採用する。

1. **役割分担ルール**: 情報分類と配置先の定義（What/Where）の正本は `docs/overview/folder-structure.md`（従来どおり「配置判断の唯一の参照元」）。情報を移動する契機と手順（When/How)の正本はスキル。スキルは移設先を **5 分類の分類名**で参照し、具体パス・分類定義を再定義しない
2. **種類別対応表**を `session-handoff` スキルに置く:

   | 情報の種類 | 正本の置き場 | handoff に残すもの |
   |---|---|---|
   | 進行中タスクの状態・残り | handoff（唯一 handoff が正本でよい） | そのまま |
   | 教訓・技術知見（サイクルを跨いで再利用するもの） | 参照知識（標準は `docs/reference/`。配置はプロジェクトの folder-structure.md に従う） | 参照＋1 行要約 |
   | 未解決の論点・要対応事項 | 課題（`docs/working/issues/`） | Issue 番号の参照 |
   | 今サイクル限りの一時的な注意・ブロッカー | handoff「既知のブロッカー・懸念」（分量目安内） | 1 件 1〜2 行 |
   | レビュー結果・検査の詳細 | 計画・監査記録・課題等の正本 | 消化記録 1 行（参照のみ） |

3. **finalize に移設工程を新設する**: 基準付き圧縮の前段として、handoff が正本になっている記述を対応表で走査し、正本を外部に作成（または追記）してから handoff を参照＋1 行要約へ置換する。移設は「情報の削減」ではなく「正本の引っ越し」である
4. **ADR-0075 の部分修正**: 「圧縮しないもの＝正本が handoff 以外にないもの」の規定は維持するが、その保護は移設工程とセットで運用する（正本が handoff にしかない状態を圧縮で保護し続けるのではなく、移設で正本を外へ作って保護対象から外す）。ADR-0075 は Accepted のまま Consequences に部分修正を追記する
5. **folder-structure.md の配置表に 1 行追加する**: 「セッション跨ぎに再利用する教訓・作業知見 → `docs/reference/`」

## Consequences

- 高価値な教訓・申し送りが handoff の外の恒久的な置き場（参照知識・課題）を得て、サイクルを跨いだ再利用（Issue-0021 の問題意識）が可能になる
- finalize の作業量が移設工程の分だけ増える（正本ファイルの作成・追記と参照置換）。増加分はサイズトリガー（ADR-0087）の発火時に集中し、平時は対応表に従った書き分けで抑制される
- 参照を辿らないと詳細に到達できない 1 ホップが増える（ADR-0075 と同じトレードオフ。参照は安定識別子で書く ADR-0077 とセットで運用）
- `session-handoff` スキルと folder-structure.md の両方の改定が必要（プラグイン更新と template 同期の両方を要する）
