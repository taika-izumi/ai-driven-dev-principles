# ADR-0086: handoff に溜まる情報の正本置き場を種類別対応表で定め、移設を独立手順として組み込む

- **Status**: Proposed
- **Date**: 2026-08-13

## Context

Issue-0079: finalize の基準付き圧縮（ADR-0075）は「正本が handoff 以外にないもの」を圧縮対象から除外するが、この保護規則は「handoff を正本として書けば何でも無制限に保護される」という抜け道を持つ。LoopForAlpha の実測（2026-08-13）では、「進行中のタスク」節 31.5KB に教訓の番号付きリスト 32 項目が蓄積し、「正本がここにしか無いもの」と明示した小節まで存在した。蓄積されている情報自体は高価値であり、削るべき情報ではなく**置き場を誤った情報**が溜まっている。

ユーザー制約: ハンドオフの簡略化しすぎで引継ぎ後の作業精度を落とさない（対策は削除ではなく正本の移設）。

制約: 知見の記録は消費装置（worklog-extract）を持つ worklog へ一本化する決定（ADR-0056）が既にある。消費経路のない知見置き場の新設は、明示アーカイブを退けた理由「アーカイブ自体が肥大し、問題の場所が移るだけになる」（ADR-0074 の代替案評価）を再現するため、移設先には消費経路と索引が要る。

配置定義とスキル手順の責務境界は ADR-0089 に従う（配置定義は folder-structure.md が正本、スキルは分類名＋標準パス併記で参照する）。

## Considered Alternatives

1. **種類別対応表＋独立手順「移設」（採用）** — 情報の種類ごとに正本の置き場を定め、移設を名前付き手順として finalize・read 超過受諾時・cycle-reset 前段の 3 箇所から呼ぶ。スキル化に有用な delta 型は worklog へ（ADR-0056 と整合）、プロジェクト固有の参照知識は索引つきの参照知識置き場へ振り分ける
2. **教訓をすべて worklog パイプラインへ寄せる** — worklog の消費装置（worklog-extract）はスキル化・ルール化候補の抽出が目的であり、「次サイクルの作業者が読むプロジェクト固有の運用ノウハウ」の置き場としては消費経路が合わない（延々と抽出されない delta が滞留する）。振り分けの片側としては採用し、一本化はしない
3. **保護量に上限を設けて超過分を強制削除する** — 情報を失い、ユーザー制約に反する。不採用
4. **移設先を新設の専用アーカイブとする** — ADR-0074 が退けた明示アーカイブの再導入であり、既存の 5 分類（参照知識・課題）で受けられる以上、新しい管理対象を増やす理由がない。不採用

## Decision

案 1 を採用する。

1. **種類別対応表**を `session-handoff` スキルに置く（移設先は 5 分類の分類名＋標準パス併記。ADR-0089）:

   | 情報の種類 | 正本の置き場 | handoff に残すもの |
   |---|---|---|
   | 進行中タスクの状態・残り | handoff（進行中の作業。唯一 handoff が正本でよい） | そのまま（節別規範の分量内） |
   | 教訓のうち、スキル化・ルール化に有用な delta 型（AI の挙動と必要だったことの差分） | worklog 中央ストア（記録経路は worklog-record） | 記録済みなら削除してよい（worklog が消費装置を持つため参照も不要） |
   | 教訓のうち、プロジェクト固有の参照知識（次サイクルの作業者が読む運用ノウハウ・既知の落とし穴） | 参照知識（標準: `docs/reference/`。初回に索引 README を作り、ドキュメント追加時に行を足す） | 「関連ドキュメント」節に正本ドキュメント単位で参照 1 行 |
   | 未解決の論点・要対応事項 | 課題＝進行中の作業（標準: `docs/working/issues/`。system/flow の分岐と採番・インデックス追記はプロジェクトの課題管理規約に従う） | Issue 番号の参照 |
   | 今サイクル限りの一時的な注意・ブロッカー | handoff「既知のブロッカー・懸念」 | 1 件 200 字以内 |
   | レビュー結果・検査の詳細 | 計画・課題・記録類の正本（進行中の作業または追跡型の記録） | 消化記録 1 行（参照のみ） |

   判別の指針: 「AI の挙動改善に使う差分か?」→ worklog、「次サイクルの人間・AI が読み返す知識か?」→ 参照知識、「誰かが対応すべき未解決事項か?」→ 課題、「今サイクルの作業状態か?」→ handoff に残す
2. **移設を独立手順として定義する**: 対象特定 → 実施サマリー提示（複数ファイル変更の中リスク対応）→ 正本の作成・追記（参照知識は索引 README も更新、課題はインデックス追記と通し採番）→ handoff 側を参照へ置換 → 変更した正本ファイルをコミット対象に含める。呼び出し箇所は (a) finalize の圧縮前段（必須工程）、(b) read でサイズ超過を提案しユーザーが受諾した時、(c) cycle-reset の申し送り現役性点検の前段（教訓型を落とす前に移設する）の 3 つ
3. **移設で作成・更新した正本ファイルを、起点を問わず handoff と同じコミットに含める**: finalize ではコミット手順の add 対象に含め、read・cycle-reset 起点では次のコミット時に handoff と同時に add する（正本が git 履歴に入らないまま handoff が参照だけになる状態を防ぐ）
4. **「圧縮しないもの」規定の文言を改稿する**: 保護は「移設で正本を外へ作るまでの暫定」であることを `session-handoff` の finalize 手順に明記する（保護規定を根拠に移設をスキップする読みを塞ぐ）
5. **ADR-0075 の部分修正**: 「圧縮しないもの」の保護規定は移設工程とセットで運用する。ADR-0075 は Accepted のまま Consequences に部分修正を追記する
6. **folder-structure.md の配置表の既存行を拡張する**: 「技術調査・検証メモ」行を「技術調査・検証メモ、セッション跨ぎに再利用する教訓・作業知見」へ拡張する（新規行を増やさず、同一配置先の行の重複を避ける）

## Consequences

- 高価値な教訓・申し送りが消費経路つきの置き場を得る: delta 型は worklog-extract が抽出し、参照知識は「関連ドキュメント」節の参照と索引 README から次サイクルが読む。参照知識の読み込みはオンデマンドであり、handoff と違い毎セッションのコンテキストに常駐しない（肥大の害が構造的に小さい）
- 「関連ドキュメント」節の参照はドキュメント単位（項目単位ではない）のため線形累積しない。cycle-reset では、正本側の索引に載っているものは handoff から落としてよい
- finalize・cycle-reset の作業量が移設の分だけ増える。平時は対応表に従った書き分けが発生源を抑え、まとまった移設はサイズトリガー（ADR-0087）発火時に集中する
- template 更新（folder-structure.md の行拡張）は既存配布先へ自動では届かない。既存プロジェクトではスキル併記の標準パスが実質の既定値になる（ADR-0089）
- `session-handoff` スキルと folder-structure.md の両方の改定が必要（プラグイン更新と template 同期の両方を要する）
- 退役経路: サイズトリガーが長期にわたり未発火で、移設の実績も生じない状態が続いた場合、移設工程の簡素化・退役を候補としてユーザーへ提案する。判断はユーザーが行う
