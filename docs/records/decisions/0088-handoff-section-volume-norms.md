# ADR-0088: handoff の節別記載規範を定める（消化記録 1 行限定・分量目安・圧縮記録の残置禁止）

- **Status**: Proposed
- **Date**: 2026-08-13

## Context

Issue-0080 / Issue-0081: session-handoff のフォーマットは節構成を定めるが、各節の分量・記載形式の規範がない。LoopForAlpha の実測（2026-08-13、99KB のうち）: 消化記録節 28KB（1 行平均 875B・最大 2.5KB。正本を名指ししながら同じ行に詳細を重複記載）、見出し 1 行 3.4KB（状態・進捗・ADR 参照まで詰め込み）、「次セッション開始時のアクション」11.5KB（スキル想定は 3 項目）、「要点のみ」と称した抜粋が数百バイト×数十項目、finalize の圧縮で削除した内容の記録 1.5KB を handoff 内に残置（ADR-0074「受け皿は git 履歴のみ」からの逸脱）。

節ごとの規範がないため、finalize の圧縮対象基準に該当しない場所へ肥大が移る構造になっている。

## Considered Alternatives

1. **節別の内容限定・分量目安と残置禁止を規範化する（採用）** — 肥大の発生源（書く時点）に規範を置く。数値は目安（デフォルト値）とし、機械検査は設けない
2. **形式は自由のまま圧縮頻度を上げる** — 発生源を放置し、圧縮の作業量が増え続ける。書かれた詳細の圧縮は情報の要約損失を伴い、書く時点の抑制より品質が悪い。不採用
3. **文字数上限の機械検査を導入する** — handoff はプロジェクトごとの自由記述文書であり、検査機構の導入・配布コストが規範の便益に見合わない。目安超過の検出はサイズトリガー（ADR-0087）が代替する。不採用

## Decision

案 1 を採用する。`session-handoff` のフォーマット節・update 手順に以下を明記する。

1. **消化記録の 1 行**: 内容を「判定結果＋安定識別子（ADR 番号 / worklog id / Issue 番号 / コミットハッシュ）＋正本への参照」に限定する。目安 200 字。レビューの走査母数・指摘件数・内訳などの詳細は正本（計画・監査記録・課題）側へ書く。update 手順に「詳細を書きたくなったら正本へ書き、行には参照を書く」の分岐を明記する
2. **タイトル（見出し 1 行）**: 作業名のみ。進捗・状態・参照は Status / Current Phase / 本文の各節へ
3. **次セッション開始時のアクション**: 3 項目・各 1〜2 行。確認ファイルの列挙が全景説明にならないよう、詳細は参照で書く
4. **「要点のみ」と称する抜粋**: 1 項目 1〜2 行とし、必ず正本への参照を伴う（参照なしの「要点」は正本の複製として肥大する）
5. **既知のブロッカー・懸念**: 1 件 1〜2 行。教訓型に膨らんだものは移設対象（ADR-0086 の対応表を適用）
6. **圧縮・削除の実施記録は handoff に残さない**: 落とした情報の受け皿は git 履歴のみ（ADR-0074）であり、「何を削除したか」の記録行も残置しない

## Consequences

- 消化記録が証跡（1 行）に戻り、read 時の要約コストが下がる。ADR-0080 の保持規則（本サイクルの `review=` 行を残す）と掛け算になっていた節肥大が解消する
- 数値は目安であり機械検査はない。逸脱の検出はサイズトリガー（ADR-0087）の発火時にまとめて行われる
- 詳細が正本側へ移ることで、handoff 単独では詳細に到達できない（参照 1 ホップ。ADR-0077 の安定識別子規約とセットで運用）
- 本規範が不要になったことの判定（節別規範なしでも肥大が再発しない状態の常態化）はユーザーが行い、撤去を指示した時点で削除する
