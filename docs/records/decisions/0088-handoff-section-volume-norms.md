# ADR-0088: handoff の節別記載規範を定める（内容限定・字数目安・列挙外の節への既定規則・圧縮記録の残置禁止）

- **Status**: Accepted
- **Date**: 2026-08-13

## Context

Issue-0080 / Issue-0081: session-handoff のフォーマットは節構成を定めるが、各節の分量・記載形式の規範がない。LoopForAlpha の実測（2026-08-13、99KB のうち）: 消化記録節 28KB（1 行平均 875B・最大 2.5KB。正本を名指ししながら同じ行に詳細を重複記載）、見出し 1 行 3.4KB、「次セッション開始時のアクション」11.5KB（スキル想定は 3 項目）、「要点のみ」と称した抜粋が数百バイト×数十項目、finalize の圧縮で削除した内容の記録 1.5KB を handoff 内に残置（ADR-0074「受け皿は git 履歴のみ」からの逸脱）。

規範の単位に関する実測: 「1 行」は分量の単位にならない（実測で見出し「1 行」が 3.4KB。1 項目 1 行の形式を守ったまま節が 5KB 超の例もある）。分量規範は文字数で与える必要がある。

また、節を列挙するだけの規範は「列挙されなかった節が新しい肥大の移動先になる」型の再発を招く（Issue-0080/0081 の診断「規範がない場所へ肥大が移る」と同型）。列挙外の節への既定規則が要る。

## Considered Alternatives

1. **節別の内容限定・字数目安＋列挙外への既定規則＋残置禁止を規範化する（採用）** — 肥大の発生源（書く時点）に規範を置く。単位は文字数（「行」は実測で反証されたため使わない）。数値は目安（デフォルト値）とし、機械検査は設けない
2. **形式は自由のまま圧縮頻度を上げる** — 発生源を放置し、圧縮の作業量が増え続ける。書かれた詳細の圧縮は要約損失を伴い、書く時点の抑制より品質が悪い。不採用
3. **文字数上限の機械検査を導入する** — handoff はプロジェクトごとの自由記述文書であり、検査機構の導入・配布コストが規範の便益に見合わない。逸脱の累積はサイズトリガー（ADR-0087）が検出する。不採用

## Decision

案 1 を採用する。`session-handoff` のフォーマット節・update 手順に以下を明記する。字数は全角換算の文字数、数値はすべて目安（デフォルト値）である。

1. **消化記録の 1 行**: 現行形式の必須要素（日付・マイルストーン名（確定点ラベルを含む）・`ADR=` / `worklog=` / `review=` の各フィールド・なし/棄却時の理由）は**維持**した上で、各フィールド値の内容を「判定結果＋安定識別子（ADR 番号 / worklog id / Issue 番号 / コミットハッシュ）＋正本への参照」に限定する。1 行 200 字以内。レビューの走査母数・指摘件数・内訳などの詳細は正本（計画・課題・記録類）側へ書く。update 手順に「詳細を書きたくなったら正本へ書き、行には参照を書く」の分岐を明記する
2. **タイトル（見出し 1 行）**: 作業名のみ。進捗・状態・参照は Status / Current Phase / 本文の各節へ
3. **次セッション開始時のアクション**: 3 項目・各 200 字以内。詳細は参照で書く
4. **「要点のみ」と称する抜粋**: 1 項目 200 字以内とし、必ず正本への参照を伴う（参照なしの「要点」は正本の複製として肥大する）
5. **既知のブロッカー・懸念**: 1 件 200 字以内。教訓型に膨らんだものは移設対象（ADR-0086 の対応表を適用）
6. **列挙外の節への既定規則**: 本規範に個別の定めがない節（完了済みタスク・未着手のタスク・作業の目的・背景・重要な意思決定の履歴など）も 1 項目 200 字以内を既定とし、超える内容は対応表（ADR-0086）に従って正本へ移して参照に置き換える。ただし handoff が正本の記述（進行中タスクの状態・残り）は対応表上も移設対象外であり、200 字超過時は項目を分割する（項目数は制約しないため）
7. **圧縮・削除の実施記録は handoff に残さない**: 落とした情報の受け皿は git 履歴のみ（ADR-0074）であり、「何を削除したか」の記録行も残置しない

## Consequences

- 消化記録が証跡（1 行）に戻り、read 時の要約コストが下がる。必須要素を維持するため、ADR-0057 の「未発火と棄却の外形的区別」と ADR-0080 の欠落検査（確定点ラベルによる対象行の識別）は壊れない
- 項目の**数**は制約しない（作業量に比例するため）。項目数の増加による節の肥大は、既定規則による移設とサイズトリガー（ADR-0087）が受け止める二段構え
- 数値は目安であり機械検査はない。逸脱の累積はサイズトリガーの発火時にまとめて検出・是正される
- 詳細が正本側へ移ることで、handoff 単独では詳細に到達できない（参照 1 ホップ。ADR-0077 の安定識別子規約とセットで運用）
- 本規範が不要になったことの判定（節別規範なしでも肥大が再発しない状態の常態化）はユーザーが行い、撤去を指示した時点で削除する
