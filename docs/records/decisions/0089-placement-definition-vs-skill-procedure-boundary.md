# ADR-0089: 情報の配置定義は folder-structure.md を正本とし、スキルは分類名で参照する

- **Status**: Proposed
- **Date**: 2026-08-13

## Context

handoff 肥大化対策（ADR-0086）の設計中に、ユーザーから「情報の配置先ルールをどこで定義するか。整理ルールは整理に使うスキル側で保持したいが、folder-structure.md にも各フォルダに何を置くかの記載がある。役割分担を明確にしたい。必要なら folder-structure.md を削除して一本化する案も検討してよい」という論点が提起された（2026-08-13）。

この責務境界は handoff に限らず、情報を配置・移動するすべてのスキル（organize-inbox / decision-log / session-handoff 等）に共通する構造の問いであるため、handoff 対策の ADR から独立させて記録する（ADR-0059 の粒度規範）。

前提となる配布経路の非対称: スキルはプラグイン配布（中央で改定すると全プロジェクトへ届く。配布先では編集しない = ADR-0069）、folder-structure.md は template 配布（プロジェクト初期に複製され、以後プロジェクトの所有物として自由に調整される。既存プロジェクトへ更新は自動では届かない）。

## Considered Alternatives

1. **配置定義は folder-structure.md、移動手順はスキル、という役割分担（採用）** — 配置はプロジェクトが調整できる場所（template 系）に、手順は中央改定が届く場所（プラグイン系）に置く。配布経路の性質と責務が一致する
2. **配置定義もスキルに置く** — プロジェクト固有のフォルダ調整の受け皿がなくなる（スキルは配布先で編集しない前提）。複数スキルに分類定義が重複し、片側だけ更新されるドリフト（Issue-0082 と同型）を量産する。不採用
3. **folder-structure.md を削除しスキルへ一本化する** — 案 2 と同じ欠陥に加え、人間の手動配置判断・organize-inbox など複数の利用者が参照する共通基盤が消える。不採用

## Decision

案 1 を採用する。

1. **情報分類と配置先の定義（What/Where）の正本は `docs/overview/folder-structure.md`**（従来どおり「配置判断の唯一の参照元」）
2. **情報を移動する契機と手順（When/How）の正本はスキル**
3. スキルが移設先・配置先を書くときは **5 分類の分類名**（オリエンテーション / 現在の正 / 進行中の作業 / 追跡型の記録 / 参照知識）で参照し、分類定義・配置先を再定義しない。標準パスを括弧で併記してよい（例: 参照知識（標準: `docs/reference/`））
4. 本規範は情報を配置・移動するすべてのスキルに適用する。既存スキルの表記の置き換えは改定機会に順次行う（一括改稿はしない）

## Consequences

- 配置の調整はプロジェクト側（folder-structure.md）で、手順の改善はガイドライン側（スキル）で、互いに独立に進められる
- template 更新は既存配布先に自動では届かないため、スキルに併記する標準パスが**既存プロジェクトでの実質の既定値**になる。folder-structure.md が未整備・未更新のプロジェクトでは標準パスへフォールバックする
- スキルの記述が 1 段抽象的になる（分類名 → パスの解決が読み手に必要）。標準パスの併記で緩和する
- 本規範が不要になる条件（配布経路の非対称が解消される等）が生じた場合、ユーザーの判断で撤回する
