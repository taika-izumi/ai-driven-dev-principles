# ADR-0101: 全数監査の判定を keep 72・統合 22・保留 44・簡素化 3・退役 0 で確定し、増設の歯止めは評価可能性の義務化（弱い形）とする

- **Status**: Proposed
- **Date**: 2026-08-16

## Context

ADR-0100 の方法による一回限りの監査（Issue-0092）が完了し、常時発火規範の全数台帳（155 レコード・対象 141）と分類案が `docs/records/audits/2026-08-16-guideline-process-audit/`（`ledger.md`・`report.md`）に確定した。分類は Phase A で事前登録した判定の向き・露出閾値 30（ユーザー承認済み）・規則 1〜5 からの機械的導出であり、閾値の後決めは行っていない。主要な実測:

- 検出実績なしは対象 141 行中 107 行（76%）。ただし三読み（不要 / 機会なし / 検出器が壊れている）を検出力実証と既存退役条項の成否で切り分けた結果、退役を即断できる行は 0
- 新工程が最大の検出源だった実測がある: 確定前レビュー（H-02、2026-08-07 新設）は 8 回の発火で 156 件を検出。検査三層が捕捉した欠陥の型は相互に重複しない
- 増殖の主因は新設そのものではなく、(1) 追加時の二重記載（統合候補 22 行。CLAUDE.md の対象 14 行中 6 行・start-work の 18 行中 7 行に集中）、(2) 導入時に便益見込みと評価手段を書き残さないこと（保留 44 行の直接原因。退役条項なし 92 行、条項があっても「長期」未定義）
- 台帳を消費する経路が動いていない実測: organize-inbox 実行 0 件・課題フォルダ昇格 0 件・inbox 滞留 3 件

本 ADR は Phase B のユーザー判断（2026-08-16。分類確定・歯止め方針・消費装置要否）を記録する。判定材料の正本は `ledger.md`（1 規範 = 1 レコード）と `report.md`（分布・規則・分類・仮説検証）。

## Considered Alternatives

1. **強い形の歯止め（ADR-0099 の複雑化抑制制約「新しい工程・観点・規則は作らない」を全拡張の既定に一般化する）**: 増設を最も強く抑えるが、H-02 の実測（新工程が 156 件を検出）と正面から矛盾する。完璧な対策が不可能でも手順の増加と引き換えに穴を塞ぐ方が合理的な欠陥は実在する（設計時のユーザー指摘・2026-08-16）ため不採用。ADR-0099 の制約は当該サイクルの限界費用判断の先例として残す
2. **歯止めの規範化を行わない（ADR-0099 の先例参照のまま）**: 追加コストゼロだが、「評価不能なまま積まれる」構造（保留 44 行を生んだ直接原因）が続く。次の拡張作業で先例が想起されるかは確率的であり不採用
3. **原則（Layer 1）への昇格**: 最も強い位置づけだが、まず CONTRIBUTING での運用実績を作ってから判断すべき段階のため今回は見送り（昇格の要否は運用実績を材料にユーザーが判断する）
4. **保留 44 行の消費装置を常設する（retrospective への接続、または worklog-extract への退役候補走査の追加〈Issue-0048 の設計〉）**: 再判定の確実性は上がるが常設工程が 1 つ増える。監査自身が「台帳を消費する経路が動いていない」ことを実測しており、装置の追加は本末転倒のため不採用。機械化の選択肢は Issue-0048 として温存する
5. **退役候補を出す判定**: 唯一の候補だった I-18（rubber-duck 独立レビュー）は、重複先とされた確定前レビューと対象成果物・観点・発火点が重ならないことが正本で確認され（完全被覆の不成立）、保留へ改めた。検出 0 件の行はいずれも「不要」と「機会不足」を区別できず、退役の実測根拠を持つ行が無いため、本監査での退役は 0 行とする

## Decision

### 1. 分類の確定

対象 141 行の分類を **keep 72 / 統合 22 / 保留（観測継続）44 / 簡素化 3 / 退役候補 0**（対象外 14）で確定する。個別行の変更なし。行ごとの判定と根拠の正本は `ledger.md`、区分別リストと解説は `report.md` を参照。

### 2. 改修の次サイクル委譲

ADR-0100 決定 1 のとおり、個別規範の改修は本サイクルで行わず Issue として起票する: 統合 22 行（Issue-0093。クラスタ単位の内訳は report 1-6）、簡素化 3 行（Issue-0094。C-11 / D-11 / I-17）、A-13 の再設計（Issue-0095。検出力が反証された唯一の行。Issue-0056 / 0073 と関連）。

### 3. 増設の歯止め — 評価可能性の義務化（弱い形）

新工程・新観点・新規則の新設は**禁止しない**。代わりに、次の 2 点を次サイクルで CONTRIBUTING（拡張の入口）へ一般規範化する（Issue-0096）:

- (a) 規範・工程を新設する ADR は、「既存工程の文言拡張・リスク受容で足りないか」の比較を Considered Alternatives に含める
- (b) 新設する場合は、期待検出量（発火機会の見込みと捕捉したい欠陥型）と観測可能な退役条件を ADR に 1〜2 行で明記する

これにより次回の棚卸しは「見積り対実測」の比較で機械的に判定できる。強い形（新設を既定で禁止）は Considered Alternatives 1 のとおり不採用。

### 4. 保留の扱い — 消費装置は新設しない

保留（観測継続）44 行は、各行の計測点・再判定条件（`ledger.md` に記載）とともに条件付き backlog（Issue-0097）へ束ねる。再判定は次回の棚卸し（ユーザーが指示した時点）で行い、常設の消費工程は作らない。機械化は Issue-0048 の管轄のまま温存する。

### 5. 監査記録の確定

`ledger.md`・`report.md` は本 ADR の記録をもって確定とし、以後不変とする（ADR-0100 決定 4 の確定時点）。`docs/records/audits/README.md` の「結果の決定」列に本 ADR を記入し、Issue-0092 を close する（結論に ADR-0100 と本 ADR を記載）。監査で得た検出力の実測（実証 9・未実証 3・反証 1）は Issue-0042 へ、「長期」未定義が退役条項の成否判定を不能にした実測は Issue-0048 へ追記する。

## Consequences

- 良い影響: 全 141 行が実測と規則に基づく判定を持ち、感覚による削減を避けた（Issue-0092 の要求）。増設の歯止めが「禁止」ではなく「評価可能性」の形になり、価値ある新工程（H-02 型）を塞がずに次回棚卸しを機械化できる。判断（本 ADR）と実装（Issue-0093〜0097）が分離されている
- 悪い影響: 退役 0 行のため、監査単体では手順の総量は減らない（削減は統合 22 行・簡素化 3 行の次サイクル実装に依存する）。保留 44 行は消費装置を持たないため、次回棚卸しまで backlog に滞留する（受容済み。Considered Alternatives 4）
- 実装の同期対象: なし（変更は `docs/records/`・`docs/working/` 配下のみで、配布対象ソース・規範文書に触れない。課題インデックスへの行追加は空インデックス生成対象だが生成物に差分を生まないため執行点は空振り〈先例: `7a1bc54` / `de4ad6d`〉。plugin version bump 非該当）。歯止めの規範化（決定 3）を実装する次サイクルの ADR は過剰適合点検（ADR-0079）の適用対象となる
- 本 ADR は規範・手順・観点を追加または強化する拡張ではないため、過剰適合点検の適用対象外（規範化は Issue-0096 の実装側で点検する）
