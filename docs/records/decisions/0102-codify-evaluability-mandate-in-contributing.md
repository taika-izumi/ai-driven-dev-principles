# ADR-0102: 評価可能性の義務化（弱い形）は CONTRIBUTING「全シナリオ共通」新節と発火フックの配線で規範化する

- **Status**: Accepted
- **Date**: 2026-08-16

## Context

ADR-0101 決定 3 が、増設の歯止めとして「評価可能性の義務化（弱い形）」の内容を確定した（(a) 規範・工程を新設する ADR は「既存工程の文言拡張・リスク受容で足りないか」の比較を Considered Alternatives に含める、(b) 新設する場合は期待検出量と観測可能な退役条件を ADR に 1〜2 行で明記する）。規範化の実装は Issue-0096 として本サイクルへ委譲されており、残る決定は**配置・文言・発火経路**である。本 ADR の確定前に 3 観点の独立レビュー（claude-opus-5）を 3 巡実施し、以下の実測を設計の前提に組み込んだ:

- **配布対象該当性**: CONTRIBUTING.md は `template.manifest`（記載 5 ファイル）に含まれず `skills/` 配下でもないため、配布対象ソースに当たらない。Issue-0096 の「執行点 4 手順・plugin version bump の対象」という記載は CONTRIBUTING 単独の変更では該当しない（ただし本決定は発火フックで `skills/` に触れるため、結果として両方が必要になる。Consequences 参照）
- **観点 4 との関係**: 過剰適合点検（ADR-0079）の観点 4「退役経路」は (b) と部分的に重なるが、観点 4 は「判断主体の移譲のみ」の記載も許容するため (b)（観測可能な退役条件）より弱い。両者を同一とみなす参照は (b) を骨抜きにする。同型の許容は記述規律の実行可能性チェック（ADR-0032）にもあるため、本規範の要求は ADR-0032 の一般則に対する**特則**として明示する
- **発火経路の実測**: ADR-0098 は「文書にしか書かれていないトリガーは発火しない」（追記経路 9 本中、文書の該当節へ到達 0 本）を実測し、発火条件・手順はスキル側に置くことを決定している。新節を CONTRIBUTING に置くだけでは、decision-log 直呼びで起票される ADR（本 ADR 自身がその型）に届かない
- **点検の記録先の分岐**: 過剰適合点検の記録先は「spec を作る拡張 → spec の節 / spec を作らない拡張 → ADR 末尾」の 2 分岐であり、ADR 側だけを走査する候補抽出は spec 型拡張（実測: 記法規約を新設した ADR-0083、ハンドオフ肥大制御の ADR-0086〜0090 など 8〜9 本）を構造的に取りこぼす。spec はディレクトリ分割形式（`00-overview.md`）が既定のため、候補抽出は spec 側を**再帰で**検索対象に含める
- **機会不足と不要の区別**: ADR-0101 Considered Alternatives 5 は「検出 0 件の行は『不要』と『機会不足』を区別できない」として 0 件からの退役を却下している。本規範自身の退役条件も、適用対象 0 件を退役の根拠にしない（機会不足として保留する）
- **次回監査の転記仕様**: Issue-0097 は「追加規範は各導入 ADR の期待検出量・観測可能な退役条件から転記して差分の台帳を作り、転記が機械的にできたか自体を次回監査の検証項目とする」ことを確定している。転記には発火機会の計数手段（期間・コマンド）が要る。台帳 1 行相当（16 フィールド）のうち転記対象フィールドの列挙と合格基準は次回棚卸しの設計時に確定する（Issue-0097 へ記録）
- **数値の是正**: ADR-0101 Context の「退役条項なし 92 行」は台帳実測 95 行（ledger.md の `既存退役条項: なし` 95 件）。転記誤りであり、本サイクルで ADR-0101 側も誤記修正する

## Considered Alternatives

1. **既存節「過剰適合の点検」への観点追加（既存工程の文言拡張）**: 新節を作らない最小案。しかし点検は spec / ADR 確定前の**検査工程**であり、(a) の Considered Alternatives 比較義務と (b) の期待検出量は**ADR 起草時の記載要件**で性質が異なる。定型ブロック（4 観点表）の改造は全拡張の点検コストを恒常的に増やし、Issue-0096 の「1〜2 文で明文化」の範囲も超えるため不採用。ただし (b) の退役条件と観点 4 の部分的な重なりは、条件を限定した参照注記（Decision 2）で二重定義を避ける
2. **規範本文を decision-log スキルへ配置**: ADR-0101 決定 3 が配置先を「CONTRIBUTING（拡張の入口）」と確定済みであり、規範本文のスキル側への複写は ADR-0098 決定 3（境界をまたぐ複写の禁止）に反するため不採用。ただし**発火フックとしての節名ポインタは採用する**（Decision 3。ADR-0098 決定 1「発火条件はスキル側に置く」への整合であり、ポインタは複写禁止に抵触しない。decision-log 内に同型の先例あり）
3. **リスク受容（規範化しない）**: ADR-0101 Considered Alternatives 2 で不採用が確定済み（評価不能なまま積まれる構造が続く）
4. **機械検査（コミット前フック・生成器検査）による構造的解決**: 行動規範より優先して検討する対象だが不採用。CONTRIBUTING の執行にはコミット前フックが無いことが明文化されており、(a) の比較の充足は自然文の判定で機械化できない。点検節見出しの走査は**候補集合の機械抽出**に限り有効なため、次回棚卸しの読み出し手段として Decision 2 の執行点に残す
5. **導入文（設計思想末尾）の書き換えで到達性を上げる**: 不採用。CONTRIBUTING 冒頭の全体読解義務と重複し、ADR-0079 が設計した「点検を先に読む」読解順序（Issue-0092 監査で keep 判定）を無言で変更することになり、現役 spec（2026-08-07 過剰適合点検設計）の同文言も陳腐化させる
6. **採用案**: 「全シナリオ共通」の節（`##` レベル）を過剰適合点検の直後に新設し、執行点は点検の執行点に相乗り、発火はチェックリスト行・手順・記述規律行・点検執行点からの前方参照・decision-log ポインタ・extend-guidelines 手順 5 で配線する

## Decision

### 1. 配置

CONTRIBUTING.md の「全シナリオ共通: 過剰適合の点検」の直後（「全シナリオ共通: 配布対象ソースの記法規約」の前）に、節「## 全シナリオ共通: 新設の評価可能性」を新設する（節名は参照の完全一致 grep を成立させるため見出しと引用形を同一にする）。設計思想末尾の導入文は変更しない（Considered Alternatives 5）。

### 2. 規範文

新節の本文は次のとおりとする。規範文本体は (a)(b) の 2 箇条で、退役条件の再掲省略規定（第 3 箇条）・前置き・執行点・退役規範小節は兄弟 2 節と同型の構造要素である（Issue-0096 の「1〜2 文で明文化」は規範文本体に適用した）:

> 新しい規範・手順・観点の新設は禁止しない（ADR-0101 の言う新工程・新観点・新規則は、それぞれ手順・観点・規範に含めて扱う。新工程が最大の検出源だった実測があるため。ADR-0101）。代わりに評価可能性を義務づける。適用対象は「全シナリオ共通: 過剰適合の点検」の適用対象のうち**新設**を含む拡張の ADR とする（既存規範の文言強化のみの拡張は対象外）:
>
> - 新設を含む ADR は、「既存工程の文言拡張・リスク受容で足りないか」の比較を Considered Alternatives に含めること
> - 新設する場合は、期待検出量（発火機会の見込みと捕捉したい欠陥型。発火機会は対象期間・計数手段を添えた計数可能な形で書く）と観測可能な退役条件を ADR に 1〜2 行で明記すること。退役条件には成否の向き（何が観測されたら退役側か）まで書き、判断主体の移譲のみの記載は認めない（判断主体の移譲を許容する一般則〈ADR-0032〉に対する特則）
> - 退役条件の再掲は、観測可能な条件と向きを書いた同一 ADR 内の過剰適合点検ブロック「退役経路」欄の記載がある場合に限り省いてよい（観測対象の名指しのみ・向きの無い記載では省略の要件を満たさない。点検ブロックを spec 側に記録する拡張では、上記の 1〜2 行を ADR に直接書く）
>
> 本節は `decision-log`（ADR 作成手順の注記）と `extend-guidelines`（手順 5）から参照される。
>
> **執行点**: 新設を含む拡張に限り、当該拡張の ADR をコミットする直前に、その ADR に上記の各点の記載があることを確認する（過剰適合点検の執行点と同時でよい）。無ければコミットしない。点検の再点検規定（文言・適用範囲の変更時の再実施・更新）は本節の記載にも準用する。次回の棚卸しは、点検ブロックの見出しの走査（PowerShell 例: `Get-ChildItem -Path 'docs/records/decisions','docs/current/specs' -Filter '*.md' -Recurse | Select-String -List -Pattern '^#{2,3} 過剰適合点検'`）で候補を抽出し、この見積りと実測の比較で判定する（ADR-0101。spec 側に点検を記録した拡張を取りこぼさないため spec を再帰で検索対象に含める）。
>
> ### 本規範自体の退役規範
>
> 次回の全数棚卸しで、適用対象 ADR からの台帳転記が機械的にできたか（Issue-0097 の検証項目）が実測される。転記が機能しなかった場合は本規範の改良を候補としてユーザーへ提案する。適用対象 ADR が 0 件の場合は機会不足として判定を保留し次回へ持ち越す（機会不足と不要を区別できないため 0 件を退役の根拠にしない。ADR-0101 の三読みと同じ扱い）。退役の提案は、本規範を不要にする変化（転記工程の廃止・監査方式の変更など）が実測された時点で行う。判断はユーザーが行う。棚卸しの発火はユーザー指示のみであり（ADR-0101 決定 4 のリスク受容を引き継ぐ）、指示が無い限り本評価は行われない。

(b) への追補（計数可能な形の要求・成否の向きの要求・退役条件の再掲省略条件）は、Issue-0097 の転記仕様を満たし抜け穴を塞ぐための ADR-0101 決定 3 への最小限の追加決定である。

**本規範の自己適用（(b) の第 1 号）**: 期待検出量 — 発火機会（候補集合）はガイドライン拡張サイクルあたり 0〜4 件（直近 4 サイクルの近似実測 1 / 4 / 1 / 0 件。計数は期間内の点検ブロック見出しの走査〈上記執行点の PowerShell 例。ADR と spec の両方を再帰〉の増分を候補集合とし、新設該当を目視判定。実測 4 点かつ候補集合ベースのためレンジは暫定であり、次回棚卸しでは候補集合数と新設該当数を分けて記録してレンジを後者へ置き換える）。捕捉したい欠陥型は「評価不能なまま積まれる規範」（Issue-0092 監査で保留 44 行・退役条項なし 95 行を生んだ型）。退役条件 — 上記退役規範小節のとおり（向き: 転記不能の実測 → 改良候補、適用対象 0 件 → 機会不足として保留、本規範を不要にする変化の実測 → 退役候補。点検ブロック「退役経路」欄に記載）。

### 3. 発火フックの配線

- **CONTRIBUTING 内**: 過剰適合点検のチェックリスト行を持つ各シナリオ（7 箇所）へ「新設を含む場合、評価可能性の記載要件を満たしたか」の確認行を 1 行ずつ追加する。チェックリストを持たない「CLAUDE.md を更新するとき」は手順 5（点検必須）へ同旨を追記する。「シナリオ: ADRを記録するとき」の記述規律へ、新節への参照 1 行（ADR-0032 特則の明示付き）を追加する。過剰適合点検の執行点の本文（「無ければコミットしない」の直後・再点検規定の前）に新節執行点への前方参照 1 文を追加する
- **skills/decision-log/SKILL.md**: ADR 作成手順の注記部へ、ガイドライン配信元リポジトリ限定のゲート付きポインタを追加する（節名参照と優先関係の記述のみ。規範文の条件は複写しない。ADR-0098 決定 3 適合。決定 5 に従い、参照先の節が見つからない環境では適用しない旨のフォールバックを明記し、CONTRIBUTING 新節側にも「スキルから参照される」注記を置く。フォールバック時のユーザー報告は課さない〈配布先での常時報告はノイズになるため意図的に簡略化〉）
- **skills/extend-guidelines/SKILL.md**: 手順 5（確定前の過剰適合点検）へ、新設を含む拡張での評価可能性確認の 1 文を追加する（配信元ゲート・フォールバックは付さない。同手順の既存文と同型で、スキル全体が CONTRIBUTING の存在を前提とするため）

## Consequences

- 良い影響: 発火経路が「ADR 起草時（decision-log ポインタ）・拡張の入口（extend-guidelines の CONTRIBUTING 全文読込と手順 5）・確定前（チェックリスト行・CLAUDE.md 更新手順・執行点相乗り）」で配線され、ADR-0098 が実測した「文書にしか無いトリガーは発火しない」型を避ける。次回棚卸しは点検節見出しの再帰走査（ADR＋spec）による候補抽出＋目視判定で「見積り対実測」の比較ができる（完全な機械判定ではない。候補抽出のみ機械化）
- 悪い影響: 記載を強制する機械ゲートは無く、執行は人手（兄弟 2 節と同水準）。`skills/` に触れるため執行点 4 手順（生成器実行・両 `-Check`・`dist/` 同一コミット・配布物の目視 5 型）と plugin version bump（0.1.6 → 0.1.7）が必要になる。配布先プロジェクトで独自に書かれる ADR には decision-log のポインタ（配信元リポジトリ限定ゲート）は発火しない（ガイドライン拡張は配信元で行う運用のため受容）。本規範の評価・退役は次回棚卸し（発火はユーザー指示のみ）に依存する（ADR-0101 決定 4 のリスク受容を引き継ぐ）
- 実装の同期対象: CONTRIBUTING.md（新節・チェックリスト 7 行・CLAUDE.md 更新手順 1 箇所・記述規律 1 行・点検執行点の前方参照 1 文）/ `skills/decision-log/SKILL.md`（ポインタ）/ `skills/extend-guidelines/SKILL.md`（手順 5 の 1 文）/ ADR-0101 Context の誤記修正（92→95）。CONTRIBUTING への節挿入により監査台帳 `ledger.md` の CONTRIBUTING 行番号参照 11 レコード（E-03〜E-13）と E-14 の総行数記載（506 行）が実体とずれるが、台帳は不変規約（ADR-0101 決定 5）により修正せず、次回棚卸しは節見出しと id の grep で引き直す（Issue-0097 の読み出し方法と整合）
- 改訂記録: Accepted 昇格後、確定前レビュー第 2〜4 巡の指摘を反映して Context・Decision 2・3 と点検ブロックを改訂した（2026-08-16。再点検実施済み。第 4 巡で Critical / Major 0 の収束判定。反復レビューの発動基準は Issue-0098 で扱う）
- 本 ADR の Accepted 昇格（実装完了・検証後）をもって Issue-0096 を close する（結論に本 ADR と ADR-0101 を記載）

## 過剰適合点検（ADR-0079）

| 観点 | 判定 | 根拠 |
|------|------|------|
| 出所の偏り | 問題なし | 出所は本リポジトリの全数監査 1 件（Issue-0092。台帳 155 レコード、保留 44 行・退役条項なし 95 行の実測）と発火経路の実測（ADR-0098。追記経路 9 本中到達 0 本）。モデル世代は 2 世代（claude-fable-5 = 設計・監査実施 / claude-opus-5 = ADR-0098 の検出と本 ADR の確定前レビュー 3 巡。台帳に現れる claude-opus-4-8 は他規範の来歴であり本 ADR の出所には数えない）。単一プロジェクト由来だが、適用先は同一リポジトリの拡張プロセス自身（CONTRIBUTING は配布対象外、decision-log ポインタは配信元リポジトリ限定ゲート付き）に閉じ、無条件の一般規範への昇格に当たらない |
| システム種別依存性 | 問題なし | ADR の記載要件でありシステム種別・技術スタックを前提にしない。引き写し箇所: (1) ADR-0101 決定 3 (a)(b) — ゲート「新設を含む ADR」を引き継ぎ、追補（計数可能性・成否の向き・再掲省略条件）は Decision 2 で追加決定として明示、(2) 過剰適合点検 観点 4 — 「同一」ではなく部分的な重なり（観点 4 は移譲型も許容し弱い）と判定し、参照注記を「同一 ADR 内・観測可能な条件と向きの記載時」に限定してゲートを保存、(3) ADR-0098 決定 1〜3・5 — 「発火条件はスキル側」のゲートをポインタ配線（Decision 3）で引き継ぎ、複写禁止は節名参照＋優先関係のみで、決定 5 は decision-log 側のフォールバック明記と被参照注記で対処（報告要素と extend-guidelines 側は Decision 3 に理由を明示した意図的簡略化）、(4) ADR-0079 記録義務・執行点 — 執行点への相乗りと再点検規定の準用で引き継ぎ、記録先（spec / ADR 末尾）の分岐は「spec 型では ADR に直接書く」の明示と spec 側再帰走査で対処、(5) ADR-0032 実行可能性チェック — 移譲許容の一般則を残したまま、本規範の退役条件に限る特則として明示（無断の上書きをしない）、(6) ADR-0101 Considered Alternatives 5（三読み）— 「0 件＝機会不足≠不要」のゲートを退役規範に引き継ぎ、0 件を退役の根拠にしない |
| AIモデル/ツール依存性 | 問題なし | 特定モデル・ツールの挙動を前提にしない。計数手段はリポジトリの主シェル（PowerShell）で動作する再帰形を実行確認のうえ記載。引き写し箇所は観点 2 の 6 箇所と同一（判定は左記のとおり） |
| 退役経路 | 定義済み | 次回の全数棚卸しで実測される「適用対象 ADR からの台帳転記の機械的可否」（Issue-0097 の検証項目）を判断材料に、向き付きで提案する（転記不能 → 改良候補、適用対象 0 件 → 機会不足として保留、本規範を不要にする変化の実測 → 退役候補）。最終判断はユーザーが行う（Decision 2 の退役規範小節） |
