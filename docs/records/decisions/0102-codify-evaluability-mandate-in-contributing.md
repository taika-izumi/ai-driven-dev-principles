# ADR-0102: 評価可能性の義務化（弱い形）は CONTRIBUTING「全シナリオ共通」新節と発火フックの配線で規範化する

- **Status**: Proposed
- **Date**: 2026-08-16

## Context

ADR-0101 決定 3 が、増設の歯止めとして「評価可能性の義務化（弱い形）」の内容を確定した（(a) 規範・工程を新設する ADR は「既存工程の文言拡張・リスク受容で足りないか」の比較を Considered Alternatives に含める、(b) 新設する場合は期待検出量と観測可能な退役条件を ADR に 1〜2 行で明記する）。規範化の実装は Issue-0096 として本サイクルへ委譲されており、残る決定は**配置・文言・発火経路**である。本 ADR の確定前に 3 観点の独立レビュー（claude-opus-5）を実施し、以下の実測を設計の前提に組み込んだ:

- **配布対象該当性**: CONTRIBUTING.md は `template.manifest`（記載 5 ファイル）に含まれず `skills/` 配下でもないため、配布対象ソースに当たらない。Issue-0096 の「執行点 4 手順・plugin version bump の対象」という記載は CONTRIBUTING 単独の変更では該当しない（ただし本決定は発火フックで `skills/` に触れるため、結果として両方が必要になる。Consequences 参照）
- **観点 4 との関係**: 過剰適合点検（ADR-0079）の観点 4「退役経路」は (b) と部分的に重なるが、観点 4 は「判断主体の移譲のみ」の記載も許容するため (b)（観測可能な退役条件）より弱い。両者を同一とみなす参照は (b) を骨抜きにする
- **発火経路の実測**: ADR-0098 は「文書にしか書かれていないトリガーは発火しない」（追記経路 9 本中、文書の該当節へ到達 0 本）を実測し、発火条件・手順はスキル側に置くことを決定している。新節を CONTRIBUTING に置くだけでは、decision-log 直呼びで起票される ADR（本 ADR 自身がその型）に届かない
- **次回監査の転記仕様**: Issue-0097 は「追加規範は各導入 ADR の期待検出量・観測可能な退役条件から転記して差分の台帳を作り、転記が機械的にできたか自体を次回監査の検証項目とする」ことを確定している。転記には発火機会の計数手段（期間・コマンド）が要る
- **数値の是正**: ADR-0101 Context の「退役条項なし 92 行」は台帳実測 95 行（ledger.md の `既存退役条項: なし` 95 件）。転記誤りであり、本サイクルで ADR-0101 側も誤記修正する

## Considered Alternatives

1. **既存節「過剰適合の点検」への観点追加（既存工程の文言拡張）**: 新節を作らない最小案。しかし点検は spec / ADR 確定前の**検査工程**であり、(a) の Considered Alternatives 比較義務と (b) の期待検出量は**ADR 起草時の記載要件**で性質が異なる。定型ブロック（4 観点表）の改造は全拡張の点検コストを恒常的に増やし、Issue-0096 の「1〜2 文で明文化」の範囲も超えるため不採用。ただし (b) の退役条件と観点 4 の部分的な重なりは、条件を限定した参照注記（Decision 2）で二重定義を避ける
2. **規範本文を decision-log スキルへ配置**: ADR-0101 決定 3 が配置先を「CONTRIBUTING（拡張の入口）」と確定済みであり、規範本文のスキル側への複写は ADR-0098 決定 3（境界をまたぐ複写の禁止）に反するため不採用。ただし**発火フックとしての節名ポインタ 1 行は採用する**（Decision 3。ADR-0098 決定 1「発火条件はスキル側に置く」への整合であり、ポインタは複写禁止に抵触しない。decision-log 内に同型の先例あり）
3. **リスク受容（規範化しない）**: ADR-0101 Considered Alternatives 2 で不採用が確定済み（評価不能なまま積まれる構造が続く）
4. **機械検査（コミット前フック・生成器検査）による構造的解決**: 行動規範より優先して検討する対象だが不採用。CONTRIBUTING の執行にはコミット前フックが無いことが明文化されており、(a) の比較の充足は自然文の判定で機械化できない。点検節見出しの grep は**候補集合の機械抽出**に限り有効なため、次回棚卸しの読み出し手段として Decision 2 の執行点に残す
5. **導入文（設計思想末尾）の書き換えで到達性を上げる**: 不採用。CONTRIBUTING 冒頭の全体読解義務と重複し、ADR-0079 が設計した「点検を先に読む」読解順序（Issue-0092 監査で keep 判定）を無言で変更することになり、現役 spec（2026-08-07 過剰適合点検設計）の同文言も陳腐化させる
6. **採用案**: 「全シナリオ共通」の節（`##` レベル）を過剰適合点検の直後に新設し、執行点は点検の執行点に相乗り、発火はチェックリスト行・記述規律行・decision-log ポインタの三点で配線する

## Decision

### 1. 配置

CONTRIBUTING.md の「全シナリオ共通: 過剰適合の点検」の直後（「全シナリオ共通: 配布対象ソースの記法規約」の前）に、節「## 全シナリオ共通: 新設の評価可能性（増設の歯止め）」を新設する。設計思想末尾の導入文は変更しない（Considered Alternatives 5）。

### 2. 規範文

新節の本文は次のとおりとする。規範文本体は 2 文（箇条書き 2 点）で、前置き・執行点・退役規範小節は兄弟 2 節と同型の構造要素である（Issue-0096 の「1〜2 文で明文化」は規範文本体に適用した）:

> 新しい規範・手順・観点（工程を含む）の新設は禁止しない（新工程が最大の検出源だった実測があるため。ADR-0101）。代わりに評価可能性を義務づける。適用対象は「全シナリオ共通: 過剰適合の点検」の適用対象のうち**新設**を含む拡張の ADR とする（既存規範の文言強化のみの拡張は対象外）:
>
> - 新設を含む ADR は、「既存工程の文言拡張・リスク受容で足りないか」の比較を Considered Alternatives に含めること
> - 新設する場合は、期待検出量（発火機会の見込みと捕捉したい欠陥型。発火機会は対象期間・計数手段を添えた計数可能な形で書く）と観測可能な退役条件を ADR に 1〜2 行で明記すること。退役条件は、観測可能な条件を書いた同一 ADR 内の過剰適合点検ブロック「退役経路」欄の記載をもって再掲を省いてよい（判断主体の移譲のみの記載では満たさない）
>
> **執行点**: 過剰適合点検の執行点（拡張 spec / 拡張 ADR のコミット直前）と同時に、上記 2 点の記載を確認する。無ければコミットしない。次回の棚卸しは、点検ブロックの見出し（`## 過剰適合点検`）の grep で候補 ADR を抽出し、この見積りと実測の比較で判定する（ADR-0101）。
>
> ### 本規範自体の退役規範
>
> 次回の全数棚卸しで、適用対象 ADR からの台帳転記が機械的にできたか（Issue-0097 の検証項目）が実測される。その結果を判断材料に、簡素化・退役を候補としてユーザーへ提案する。判断はユーザーが行う。

(b) への追補（計数可能な形の要求）は、Issue-0097 の転記仕様を満たすための ADR-0101 決定 3 への最小限の追加決定である。

**本規範の自己適用（(b) の第 1 号）**: 期待検出量 — 発火機会はガイドライン拡張サイクルあたり 0〜4 件（直近 4 サイクルの近似実測 1 / 4 / 1 / 0 件。計数は期間内の `grep -l '^## 過剰適合点検' docs/records/decisions/*.md` の増分を候補集合とし、新設該当を目視判定。実測 4 点のためレンジは暫定）。捕捉したい欠陥型は「評価不能なまま積まれる規範」（Issue-0092 監査で保留 44 行・退役条項なし 95 行を生んだ型）。退役条件 — 上記退役規範小節のとおり（観測可能な材料は Issue-0097 検証項目の実測結果。点検ブロック「退役経路」欄に記載）。

### 3. 発火フックの配線

- **CONTRIBUTING 内**: 過剰適合点検のチェックリスト行を持つ各シナリオ（7 箇所）へ「新設を含む場合、評価可能性の記載要件を満たしたか」の確認行を 1 行ずつ追加する。「シナリオ: ADRを記録するとき」の記述規律へ、新節への参照 1 行を追加する
- **skills/decision-log/SKILL.md**: ADR 作成手順の注記部へ、ガイドライン配信元リポジトリ限定のゲート付きポインタ 1 行を追加する（節名参照のみ。規範文は複写しない。ADR-0098 決定 3 適合）

## Consequences

- 良い影響: 発火経路が「ADR 起草時（decision-log ポインタ）・拡張の入口（extend-guidelines の CONTRIBUTING 全文読込）・確定前（チェックリスト行と執行点相乗り）」の三点で配線され、ADR-0098 が実測した「文書にしか無いトリガーは発火しない」型を避ける。次回棚卸しは点検節 grep による候補抽出＋目視判定で「見積り対実測」の比較ができる（完全な機械判定ではない。候補抽出のみ機械化）
- 悪い影響: 記載を強制する機械ゲートは無く、執行は人手（兄弟 2 節と同水準）。`skills/` に触れるため執行点 4 手順と plugin version bump が必要になる。配布先プロジェクトで独自に書かれる ADR には decision-log のポインタ（配信元リポジトリ限定ゲート）は発火しない（ガイドライン拡張は配信元で行う運用のため受容）
- 実装の同期対象: CONTRIBUTING.md（新節・チェックリスト 7 行・記述規律 1 行）/ `skills/decision-log/SKILL.md`（ポインタ 1 行）→ `scripts/build-dist.ps1` 実行・両生成器 `-Check`・`dist/` 同一コミット・version bump / ADR-0101 Context の誤記修正（92→95）。CONTRIBUTING への節挿入により監査台帳 `ledger.md` の CONTRIBUTING 行番号参照（13 レコード）が実体とずれるが、台帳は不変規約（ADR-0101 決定 5）により修正せず、次回棚卸しは節見出しと id の grep で引き直す（Issue-0097 の読み出し方法と整合）
- 本 ADR の Accepted 昇格（実装完了・検証後）をもって Issue-0096 を close する（結論に本 ADR と ADR-0101 を記載）

| 観点 | 判定 | 根拠 |
|------|------|------|
| 出所の偏り | 問題なし | 出所は本リポジトリの全数監査 1 件（Issue-0092。台帳 155 レコード、保留 44 行・退役条項なし 95 行の実測）と発火経路の実測（ADR-0098。追記経路 9 本中到達 0 本）。モデル世代は Fable 5（設計・監査実施）と claude-opus-5（台帳が計上したレビュー検出・本 ADR の確定前レビュー）の 2 世代。単一プロジェクト由来だが、適用先は同一リポジトリの拡張プロセス自身（CONTRIBUTING は配布対象外、decision-log ポインタは配信元リポジトリ限定ゲート付き）に閉じ、無条件の一般規範への昇格に当たらない |

| AIモデル/ツール依存性 | 問題なし | 特定モデル・ツールの挙動を前提にしない。引き写し箇所は上記 4 箇所のみ（判定は左記のとおり） |
