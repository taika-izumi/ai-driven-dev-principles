# ADR-0103: Issue-0093 の統合 22 行（全 13 クラスタ）と Issue-0094 の簡素化 3 行を単一サイクルで実施する

- **Status**: Accepted
- **Date**: 2026-08-17

## Context

全数監査（ADR-0100 / ADR-0101）で「統合」に分類された二重定義 22 行（13 クラスタ。Issue-0093）と、「簡素化」に分類された高コスト記録様式 3 行（C-11 / D-11 / I-17。Issue-0094）が、対策未実施のまま backlog にあった。次サイクル着手の判断にあたり、1 サイクルに取り込む範囲を決める必要があった。

判断材料:

- 変更の型は全クラスタで同質（重複側を削って統合先へ寄せる）であり、サイクルを分けるごとにレビュー・執行点 4 手順・plugin version bump・retrospective のサイクル固定費が繰り返しかかる
- Issue-0094 の D-11（`decision-log` 承認の昇格手順）は K6 クラスタ（B-13）の統合先であり、統合と様式削減を同時に行うのが自然と監査報告（report 3-3）が明記している
- C-11（`session-handoff` update 手順）のファイルは K1 の統合先吸収などで本サイクル中に編集される。I-17（`retrospective` Phase 2）は統合ではファイルを編集しないが、簡素化の型が C-11 / D-11 と同一でサイクル固定費（レビュー・執行点・version bump）を共有できる
- 簡素化 3 行の「欠落検出 0 件」は証跡 6 系統の遡及走査の結果であり、予防効果の可能性を排除しない。簡素化して問題が再発した場合は、その実測を材料に次の対策サイクルで再対応する（ユーザーが本サイクル開始時にこのリスク受容を明示）

## Considered Alternatives

1. **全 13 クラスタ＋Issue-0094 の 3 行を 1 サイクルで実施**（採用）: サイクル固定費が 1 回で済み、同一ファイルの二度改定を避けられる。サイクルが大きくなるリスクは、plan でのクラスタ単位のタスク分割とコミット分割で管理する
2. **影響の大きいクラスタ（K1・K2 ＋ CLAUDE.md 集中分）に絞る**: 1 サイクルは軽くなるが、残クラスタのサイクル固定費が別途かかり、統合の完了が数サイクル先に延びる
3. **軽量クラスタ数個で小さく始める**: 手応え確認には向くが、変更の型が同質なため試行で得る情報が少なく、固定費の重複だけが残る
4. **Issue-0094 を同梱しない／D-11 のみ同梱**: 統合に集中できるが、C-11・I-17 のファイルは本サイクルで編集するため、後続サイクルで同じ箇所を再改定することになる

## Decision

Issue-0093 の統合 22 行（全 13 クラスタ: K1〜K10・K12・K13・K18）と Issue-0094 の簡素化 3 行（C-11 / D-11 / I-17）を、単一の対策サイクル（feature/issue-0093-integrate-duplicated-norms）で実施する。

- report 1-6 の統合先案を出発点とし、実装時の再検討を許す（ADR-0101 が確定したのは分類であり、統合先の設計は本サイクルの成果物で確定する）
- 簡素化は退役ではなく様式の削減とし、証跡の検出可能性を落とさない範囲に限る（Issue-0094 の制約を引き継ぐ）
- 簡素化起因の問題が将来実測された場合は、その記録（worklog / issue）を材料に再対応する（リスク受容）
- 付随編集として次の 2 類型・4 件を含める（いずれも監査分類の変更ではない。設計は ADR-0105 の各クラスタ欄）: (a) 監査台帳にレコードを持たない複写の参照化 = `start-work` 冒頭の継続的 ADR 検出ルール引用ブロック（K2）と `pre-finalization-review` の frontmatter description（K12）、(b) keep 分類の記述置換 = folder-structure の目的宣言 J-18 の文言更新（K9）と `start-work` セッション終了処理手順 3（B-18）の参照形統一（K8）。このほか台帳非掲載複写の掃き出し（旧 spec の追従を含む）と既存 Accepted ADR への部分修正注記が ADR-0105 の定めに従い加わる

## Consequences

- サイクル固定費（確定前レビュー・執行点 4 手順・version bump・retrospective）が 1 回で済む
- 1 サイクルの変更範囲が編集対象 11 ファイル（内訳は ADR-0105 の Consequences）＋配布物に及ぶため、レビューと検証の負荷が 1 サイクルに集中する。plan のクラスタ単位分割で緩和する
- 簡素化 3 行は検出可能性を落とさない範囲での削減に限るため、削減幅は保守的になる
- 本サイクルの完了で Issue-0093・Issue-0094 を close できる（Issue-0093 の close 時は、結論に実変更 15 行＋覆し 7 行の内訳と、存置 5 行の条件付き backlog〈Issue-0099〉への参照を記録する）

なお、本 ADR はスコープの決定のみであり、規範・手順・観点を追加または強化する拡張ではないため、過剰適合点検の適用対象外である（点検は設計 ADR-0105 側に記録する）。
