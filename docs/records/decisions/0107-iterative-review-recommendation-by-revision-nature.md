# ADR-0107: 指摘反映後の再レビューは改訂の性質で推奨を切り替え、収束は指摘の分類で判定する

- **Status**: Proposed
- **Date**: 2026-08-18

## Context

確定前レビュー（pre-finalization-review）の指摘を反映して成果物を改訂したあと、改訂版へ再レビューをかけるかの基準が規範に無かった（Issue-0098）。現行規範（start-work「確定前レビューの提示規則」但し書き・ADR-0080）は「差分の再確認の要否はユーザー判断とし、選択肢として並記する」とのみ定め、(1) 並記の実施が徹底されない（Issue-0096 サイクルで提示漏れを実測）、(2) どの条件で反復を推奨側に置くかが未定義だった。

3 サイクル・確定点 4 回分の反復実測（一次記録: `docs/working/issues/flow/0098-iterative-review-trigger-criteria/0098-log.md`）、および本 ADR 群自身への先行適用 9 巡（同ログ 2026-08-18 実測行）が以下を示した:

- **改訂が新規の規範文・設計・配線を含む限り、重大指摘は次巡でも出続ける**。Issue-0084 サイクルでは Critical 件数が 4→1→3→4→1→0 と非単調に推移し、発生面が「直前巡の新設部分」へ移動し続けた（件数ベース停止基準への反例）
- **指摘の質に相転移がある**（設計実体 → ADR 間整合（文書間整合） → 修正由来の表記問題）。「新規の設計欠陥ゼロかつ残指摘が修正由来の機械検証可能な型のみ」を実質収束とすれば 2 巡分節約できた
- **修正の性質（一次記録の語では「規模」。本 ADR で一般化）が次巡の指摘量を決める**。文言・計数の機械的調整のみなら次巡の指摘は機械検証（grep 計数）で代替可能だった。「判断を入れた修正」と明示した箇所からの指摘的中は 2/3
- **フル N 巡 → 差分確認 1 巡で締める型**が 2 サイクルで追実測された（うち 1 サイクルは前巡指摘 24 件の対応表方式・1 体）
- **確定前反復と実装時レビューは補完関係**。確定前レビューで C/M ゼロ収束済みの成果物の実装でも、実装段の独立レビューが「計画が固定した母集団の外」「実装時に顕在化する参照到達性」の欠陥を検出した（Issue-0093/0094 実装側 5 件・Issue-0084 実装側 Important 級 5 件の 2 実測）
- **コスト実数**: フル 1 巡 ≈ 3 体で計 30〜70 万トークン＋報告受信で本体コンテキスト約 2 万トークン/巡。6 巡で 200 万トークン級
- 反復を毎巡サブエージェントの新規起動で行う方式は時間・コストがかかる一方、レビュアーの継続利用は独立視点数を減らすトレードオフがある（ユーザー提起）
- **先行適用 9 巡は、上記だけでは反復が停止しない構造も示した**（出所: `0098-log.md` 2026-08-18 実測行・分析行。ユーザー承認済みの設計還流）: (1) 規範・手順文書の反復では改訂がほぼ毎巡新規の規範文を含むため、2 段型単独では常時フル巡推奨に固定される（棘輪）。(2) 全指摘採用と規範文の増設による修正は次巡の検出面を再生産する。(3) 実質収束（残指摘が機械検証可能な型のみ）は漸近的で、9 巡でも終端に達しなかった。一方、**指摘の対象レイヤで見ると逓減は観測できた**: 中核の判定規則（2 段型・巡種定義・役割限定・記録の値定義）への Critical は後半の巡で出なくなり、指摘は設計縮小の帰結（削除整合・委譲配線）と写し漏れ・修正伝播型に移った（レイヤ別の巡別一次記録は無く、出所は同分析行〈事後分析〉に限られる。なお決定 2 のレイヤ定義〈記録機構・配線・削除を骨格に含める〉の下では後半にも設計縮小＝骨格改訂が発生しており、骨格安定が成立した巡は無い——決定 2・過剰適合点検参照）

なお、レビュー反復・実装時レビューが Accepted 昇格後の ADR 本文改訂を生む場合のステータス運用は、本 ADR とは別の問いとして ADR-0108 で扱う。

## Considered Alternatives

- **既存工程の文言拡張・リスク受容で足りないか**（新設の評価可能性・ADR-0102 の要求比較）: 現行但し書きの「並記」を太字強調するだけでは、(2) の推奨の向きが未定義のまま残り、提示漏れの実測（Issue-0096）にも判定材料を与えない。リスク受容（反復は毎回ユーザーが自力判断）は、実測が示した非自明な判定知識（非単調推移・相転移・機械検証代替）をユーザーの記憶に依存させることになり、3 サイクル・確定点 4 回で蓄積した実測を規範に写す方が安い。よって推奨規則の新設を採る
- **推奨のデフォルト（3 案比較）**: (a) 経済型＝常に軽量確認を推奨し前巡 Critical ありのみフル推奨 → 当該実測（Issue-0084）では全巡で前巡 Critical ありのため常時フル推奨と同一挙動になり、軽量側へ倒す判断材料を供給しない。Critical=0 の次巡に Critical が再出現した実測は無く、Issue-0093/0094 の C=0 以降 3 巡が軽量側で足りた実測はむしろ経済型を支持する側の材料である（反対材料として併記）。ただし改訂の性質は毎巡観測できるのに対し「前巡 Critical の有無」は当該実測群では常時真で判別力を検証できておらず、観測可能性と実測の裏づけの点で 2 段型を採る。(b) 保守型＝規範・手順文書の改訂では常にフル反復を推奨 → 「機械的調整のみの改訂は機械検証で代替可能だった」実測と不整合でコスト過剰。(c) **2 段型＝改訂の性質で切り替え（採用）** → 実測の相転移と対称で、コストが検出期待に比例する
- **レビュアー継続利用の扱い（3 案比較）**: (a) 全巡で継続利用可 → 独立視点の減少が新規欠陥検出（実測の主戦場）を直撃する。(b) 全面禁止 → 差分確認巡ではレビュアー自身が前巡指摘の全数リストを保持しており、委譲側リスト作成の構造的弱点（リスト漏れをレビュアーが検出できない）を緩和できる利点を捨てる。(c) **役割限定＝差分確認巡に限り可・新規欠陥検出が要る巡は新規レビュアー必須（採用）**
- **規範の配置（3 案比較）**: (a) pre-finalization-review へ一元化 → 推奨順位の正本が start-work と 2 箇所に割れ ADR-0080 の構造を崩す。(b) 反復専用スキルの新設 → YAGNI・新設義務が重い。(c) **現行の正本構造に沿った分散配置（採用）** → 各正本の既存責務と 1:1 対応
- **締めの機構（3 案比較。第 10〜12 巡の反復で追加）**: (a) 状態機械（成立・離脱・再突入とカウンタを規範で管理）→ 第 10 巡レビューで成立意味論・リセット・セッション跨ぎ復元の欠陥が多発し撤回。(b) 規範的述語（履歴から都度判定）→ 第 11〜12 巡レビューで反証規則・初回起点・跨ぎ復元の派生機構が増殖し撤回。(c) **判断材料＋推奨ヒューリスティック（採用・第 5 次設計縮小）** → 発動が毎回ユーザー判断である既存骨格に載り、判定機構を持たない。目安「フル巡 2 巡連続」の代替（1 巡 / 3 巡 / レイヤ別件数）は骨格安定自体が未追試のため比較材料が無く、2 巡を仮置きして退役条件で監視する

## Decision

Issue-0098 の対策として、確定前レビューの反復基準を次の 4 決定で規範化する。拘束的規範は決定 1〜4（発動条件〈設計縮小・締めモードの前置・3-2 準用とその ADR-0080 拡大条件の改定を含む〉・停止基準〈指摘の対象レイヤ・骨格安定による締めモード推奨と実質収束の第 2 経路を含む〉・実施方式の巡種定義と役割限定・記録方式。修正のタグ分け・差分リストの全数渡し・改訂前退避を含む。決定 3 内の草稿コミットのみ非拘束の推奨手順であり、その旨を当該文に明示する）に絞り、運用の型（重点指定・体制縮小・観点構成・写経実行）は後述「適用例」節に出所付きの非拘束で記載する（過剰適合点検の是正パターン「適用例への降格」を設計時に適用）。

反復の実施方式は決定 3 の 3 種（**フル巡 / 差分確認巡 / 機械検証**。巡を立てるのはフル巡・差分確認巡の 2 種で、機械検証は巡を立てない方式）を正本とし、決定 1 の提示はこの呼称に従う。決定 4 の記録は各方式に 1:1 対応する歴史的語彙（「フル実施」＝フル巡・「差分再確認」＝差分確認巡）を用いる（決定 4 参照）。

**決定 1（反復の推奨規則。正本: start-work「確定前レビューの提示規則」に小節を追加）**: 確定前レビューの指摘（機械検証で検出した齟齬を含む）を反映して成果物を改訂したら、確定へ進む前に毎回「フル巡 / 差分確認巡 / 機械検証 / このまま確定」を並記して提示する。反復提示を行わず確定へ進んでよいのは**指摘が無かった場合に限る**。指摘があったが採用しない場合は、不採用とした指摘の一覧と理由を添えて反復提示を行い、ユーザーが「このまま確定」を選ぶことで不採用が確定する（回答では一覧の一部のみを採用する指定もでき、その場合は採用分を改訂して本小節の提示へ戻る。採否の確定は反復提示への回答に一元化する。AI の判断のみで不採用として提示を省略しない）。改訂が発生していない提示では、検証対象の改訂が無いため差分確認巡・機械検証を選択肢から除いてよい（いずれも改訂を確認する方式であるため。フル巡 / このまま確定〈＝不採用の確定〉の並記で足りる）。推奨する選択肢を先頭に置き「（推奨）」を付す。発動は毎回ユーザー判断であり自動必須化しない（ADR-0072/0080 の骨格を維持）。推奨の向きは次の順で決める:

- **前置 1（設計縮小）**: 決定 2 の設計縮小の提示条件が成立している場合は「設計縮小」を選択肢に加えた 5 択とし、改訂の性質による判定に優先して**設計縮小を推奨側に置く**（縮小の狙いは収束性の回復であり、反復の継続は同型の増設を再生産する実測があるため）
- **前置 2（締めモード）**: 決定 2 の骨格安定と判断できる場合は、2 段型の判定に優先して**差分確認巡を推奨側に置く**（残る確認事項が機械検証可能な型のみなら機械検証を推奨する）。以下この推奨状態を「締めモード」と呼ぶ（**推奨の向きの切り替えであって、状態機械でも規範的述語でもない**。選択肢の集合も変えない——フル巡は常に選べ、選んでも規範への違反にはならない）。規範・手順文書の反復では改訂がほぼ毎巡新規の規範文を含むため、2 段型単独では常時フル巡推奨に固定される構造（先行適用 9 巡の分析）への対策である。直前の改訂が設計骨格に触れた場合（設計縮小の適用を含む）は本前置を適用せず、次巡の推奨は 2 段型の判定で決める（削除型の改訂は 2 段型の「追加」文言に該当しない場合があるが、その場合も「どの分岐にも該当しない場合はフル巡側へ倒す」既定によりフル巡側になる）
- **2 段型**: 改訂が新規の規範文・設計・配線（規範を発火点・記録先に接続する記述）の追加、または既存規範の適用条件の変更を含む場合 → フル巡を推奨。改訂が文言・計数・参照の機械的調整のみで、残る確認事項も機械検証可能な型（決定 2 の定義）のみの場合 → 機械検証を推奨。改訂が機械的調整のみだが、機械検証可能な型に収まらない確認を要する場合 → 差分確認巡を推奨。どの分岐にも該当しない場合、および判定に迷う場合 → フル巡側へ倒す
- 機械検証が齟齬ゼロを返した場合は改訂が発生しないため提示は不要である（確定へ進む）

指摘の重大度（前巡 Critical の有無）は推奨の向きの条件に用いない（当該実測では前巡 Critical ありが常時真であり、推奨の向きを分ける判別力を持たなかったため。件数の非単調推移も件数ベース判定の予測力を支持しない。Considered Alternatives の経済型を参照）。判定材料として、修正を「機械修正 / 判断を入れた修正」にタグ分けし、当該巡の概算コスト（判断材料であり閾値には使わない）とともに提示に添える。

反復提示にも提示規則 3-2（推奨の由来の明示・反対材料欄の常設）を準用する。準用は反復提示のすべてに及ぶ（当該確定点の推奨判定の真偽を問わない。反復提示自体が推奨を含む提示であるため）。この準用は ADR-0080 の適用範囲の変更であり、同 ADR の拡大条件を次のとおり改める:「拡大は、他プロジェクト・他モデルでの同型 delta 観測時にユーザーへ提案する。ただし**確定前レビューを実施した確定点での指摘反映後の反復提示への準用に限り**、ユーザーが個別に承認した場合に行える（本 ADR の準用がこの初適用）。非発火の確定点提示そのものへの拡大、および CLAUDE.md への一般化（あらゆる推奨提示への昇格）は従来どおり行わない」。あわせて start-work 3-2 節の適用範囲を定める 2 文（節冒頭の導入文と節末尾の適用範囲文）をいずれも「推奨判定が真になったサイクルの確定点提示、および確定前レビューを実施した確定点での指摘反映後の反復提示」を対象とする形へ改め、3-2 (a) の「上記の既定」は反復提示に準用する場合「フル巡側・設計骨格側へ倒すことを命じる各既定（2 段型の最終分岐・骨格安定の判断・レイヤ振り分け。レイヤ既定経由で前置 2 が非発火となった場合も既定由来に数える）」と読み替える旨を添える（実装対象に含める）。初回の確定点提示への 3-2 適用は従来どおり推奨判定が真の場合に限る（本改定が開くのは反復提示のみ）。

本規則の対象は確定前レビューの反復に限る。実装時レビュー（タスク単位の実装・レビューのループ）由来の改訂は対象外とする（実装時レビューは既存スキルが修正ループを持ち、提示を課すと過重なため。両者の関係は決定 2 の補完関係規定による）。成果物の型による追加条件は置かず、上流がレビュー済みの写像成果物という条件も同様に置かない（いずれも初回の推奨判定の責務）。このほか上流インプットのうち新規決定を置かなかったものは次の 2 件: 初回巡の観点構成の型別調整は本サイクルの対象外とし（反復に限定した合意スコープの帰結）、「実証なし指摘の不採用の委譲制約化」は既存規範（pre-finalization-review 手順 2・5）で充足済みのため新規決定を置かない。

既存但し書き「レビュー指摘を反映した改訂差分は『未レビューの内容』に数えない」は、確定点の推奨判定（初回フルレビュー推奨を立てるか）の規定として維持し、指摘反映後の反復推奨は本小節が独立に定める（判定対象が異なり矛盾しない旨を改定時に明記する）。但し書き後半「差分の再確認の要否はユーザー判断とし、選択肢として並記する」は新小節への参照に置き換える（同じ事柄の二重規定を残さない）。

**部分修正注記は次の 4 系統、明確化注記は 1 件を対象とする**: 部分修正——ADR-0080 へ (1) 上記の但し書きとの関係規定（後半の参照置換を含む）、(2) 3-2 の適用範囲の反復提示への拡張（拡大条件の上記改定と start-work 適用範囲文の改定を含む。注記には「同 ADR の適用範囲文は反復提示まで含めて読む」旨を明記する）、(3) 決定 4 による Decision 5 の改定（`review=` 値集合の拡張〈新方式値 `機械検証` の追加・方式要素の連結・巡数・終了状態〉と、記載条件の集約義務化〈反復の途中経過行には書かず確定点行へ集約〉。(1)〜(3) は 3 行に分けて書く）。ADR-0088 へ (4) 決定 4 の巡数・終了状態を消化記録の値限定の「判定結果」に含める関係規定（200 字上限との関係を含む）。以上は当該 ADR の Consequences へ部分修正注記（現存する注記の主要書式 `- **部分修正（ADR-XXXX）**:`）で残し、Status は Accepted を維持する（部分修正の型は ADR-0108 の対象外規定を参照）。明確化注記——ADR-0067 へ (5) 決定 3 のフル巡の体制縮小特則の注記（同 ADR の「観点は最低 3 つ」は初回巡・反復とも現役のまま。体数は同 ADR の決定事項ではないため決定の変更にはあたらず部分修正ではない。実装先〈pre-finalization-review「反復の実施」節〉が同 ADR の写像であるため誤読防止に `- **注記（ADR-0107）**:` の別書式で残す）。

**決定 2（停止基準。正本: 決定 1 と同じ小節）**: 反復の停止は件数・巡数でなく指摘の分類で判定する。「成果物の実体への新規の設計欠陥がゼロ、かつ残指摘が直前の修正に由来する機械検証可能な型（grep 等で機械判定できる計数・列挙・表記〈綴り・記法規約・書式〉に限る。判断を要する表記指摘は含めない）のみ」となった巡を実質収束とみなす。実質収束の判定結果は反復提示に添える。当該巡で改訂が発生せず提示を行わない場合も、確定へ進む直前に実質収束の成否を判定して記録（`review=` の終了状態）へ反映する（初回巡から指摘が 1 件も無いまま確定する場合は判定不要で `改訂なし確定` を採る）（推奨の向き自体は決定 1 に一元化する。実測では、収束後の締めは差分確認巡または機械検証で確定判定が取れており、2 段型はこの場面で自然に軽量側を推奨する）。巡数上限は設けない。ユーザーの打ち切りは正規の停止事由である（発動が毎回ユーザー判断であることの帰結）。実質収束は確定前工程の停止判定であり、実装時の独立レビューを代替しない（補完関係。Issue-0093/0094・Issue-0084 の実装側実測 2 件）。

停止判定には指摘の分類に加えて**指摘の対象レイヤ**を判断材料に用いる。各巡の指摘を「設計骨格（決定の構造・条件・機構そのものの欠陥。規範の判定条件・分岐・記録機構と、規範を発火点・記録先へ接続する配線の新設・変更・削除を含む——機構を減らす設計縮小も骨格に触れる改訂である）」と「周辺（文書間整合・写し漏れ・修正伝播・表現精度）」に振り分け、レイヤ判定に迷う場合（指摘・改訂のいずれの判定でも）は設計骨格側へ倒す（軽量側〈差分確認巡・機械検証〉への切り替えを遅らせる安全側の既定）。振り分けの結果は反復提示に添える（決定 1 の修正タグ・概算コストと同列の判断材料。記録・引き継ぎの機構は置かない）。

**骨格安定**は停止判断のためのヒューリスティックであり、規範的な述語・カウンタとしては定義しない（状態機械〈第 10 巡レビューで撤回〉・履歴から都度判定する述語〈第 11〜12 巡レビューで反証・初回起点・セッション跨ぎ復元の派生機構が増殖し撤回〉に続く第 5 次設計縮小）。目安は「直近のフル巡 2 巡が連続して設計骨格への新規指摘ゼロで、その後に設計骨格に触れる改訂が無い」こと。AI はこの目安に照らした判断とその根拠（直近のフル巡数・骨格新規指摘の有無・直近改訂のレイヤ）を反復提示に添え、骨格安定と判断できる場合に軽量側での締め（締めモード。決定 1 の前置 2）を推奨する。判断に迷う場合・判断材料が失われている場合（セッション跨ぎを含む）はフル巡側へ倒す。骨格への新規指摘または設計骨格に触れる改訂を観測したら（方式・採否を問わない）骨格安定の判断を取り下げ、以後のフル巡で改めて判断する。実質収束（機械検証可能な型のみへの縮退）が漸近的で単独では終端に達しない場合でも、骨格安定が停止判断の材料を与える（出所: 先行適用 9 巡の事後分析〈`0098-log.md` 2026-08-18 分析行〉。なお本レイヤ定義の下では、設計縮小が第 6↔7・第 8↔9 巡間にも発生しているため 9 巡中に骨格安定が成立した巡は無い——目安「2 巡」は未追試の設計判断であり、退役条件で監視する）。骨格安定と判断している間の反復では、方式を問わず次の 2 つを推奨の既定として適用する（いずれも最終判断はユーザー。継続レビュアーの扱いは決定 3）:

- **採否の推奨**: 設計骨格に触れない精度型の指摘（表現の精密化・網羅性の増強・書式など、機械検証可能な型に収まらないが骨格を変えない指摘）は「不採用とし実装時レビューへ委ねる」ことを推奨する（確定前反復と実装時レビューの補完関係——実装段の独立レビューがこの型に別の検出面を持つ実測——を採否の推奨に写した形）。不採用の確定は決定 1 の反復提示への回答による（回答では一覧の一部のみを採用する指定もできる。**AI の判断のみで不採用にしない**——ADR-0072 の「判断の機会を作る責務」と同じ向き。pre-finalization-review 手順 5 の採否決定は、反復の局面では推奨案の作成として読む〈実装対象の同スキル (6)〉）。委ねる場合は、不採用とした指摘の一覧を当該サイクルの正本（課題ログまたは plan）へ、実装時レビューへの引き継ぎ対象である旨を付して残す（実装時レビュー側の参照配線は本 ADR の実装対象外であり、委譲側が正本を読む既存運用に委ねる——受容）
- **修正の既定**: 採用する指摘への修正は「削る（記述の削除・簡素化）/ 受容（リスクの明示的受容の記載）」を既定とし、規範文の増設を既定にしない（全指摘採用と増設による修正が次巡の検出面を再生産した分析への対策。増設で応じる場合はその旨を反復提示に添える。削る修正が設計骨格に触れる場合は骨格安定の判断が取り下げられフル巡側へ戻る——締めが長引く方向の安全側として受容する）

実質収束の判定には第 2 の経路を加える: 骨格安定と判断している状態での締めの反復（巡を立てる方式〈フル巡・差分確認巡〉を 1 巡以上含む。機械検証を伴ってよい）が設計骨格への新規指摘なしで完了し、**かつ残指摘（当該確定点の反復全体で未解消のもの）が機械検証可能な型（本決定冒頭の定義）または不採用として正本へ委ねた精度型のみ**である場合も実質収束とみなす（終了状態は従来どおり `実質収束` を用い、新しい値は設けない）。

指摘対応の改訂が機構の増設（条件・分岐の追加）を 2 回連続して含む場合は（増設の計数は巡種を問わない。計数の材料がセッション跨ぎで失われた場合は直近の改訂差分〈退避・git〉から判断できる範囲で判断する）、決定 1 の前置 1 のとおり「設計アプローチの縮小（機構を減らす）」を選択肢に加えて推奨側に置く（縮小は改訂を伴う選択肢であり、適用後は決定 1 により改めて反復提示へ戻る。ユーザーが縮小を見送った場合は計数を白紙に戻し、新たに増設を含む改訂が 2 回連続するまで前置 1 による再推奨は行わない）。縮小は設計骨格に触れる改訂であるため、縮小の次の巡の推奨は 2 段型の判定によりフル巡側になる（判定経路は決定 1 前置 2 の注記のとおり）。設計そのものを変える修正（縮小を含む）はユーザー承認を挟んでから適用する。

**決定 3（反復の実施方式。正本: pre-finalization-review に「反復の実施」節を追加）**: 反復の実施方式は次の 3 種とする。

- **フル巡**: 3 観点（敵対的・実装整合性・仕様適合）を全数走査で覆う巡。**観点は 3 つを維持し、反復のフル巡に限り担当を兼務させて体数のみ 1〜3 体へ縮小してよい**（既定は 3 観点・3 体。pre-finalization-review 手順 1 の「3 観点」は初回巡・反復とも維持され、本節は体数の縮小特則である）。レビュアーは新規とする
- **差分確認巡**: 前巡指摘の対応表方式で改訂箇所を検証する巡（1 体）
- **機械検証**: レビュアーを立てず、grep 計数等の機械判定のみで確認する方式（巡は立てない）。齟齬を検出して修正した場合は決定 1 の反復提示へ戻る（発火配線は start-work 側の自己ループ 1 行による。Consequences の実装対象を参照）

前巡レビュアーの継続利用（起動済みサブエージェントへの追送）は差分確認巡に限り認め、起動済みエージェントへ追加の指示を送るツール・機能がその環境のツール一覧・機能一覧で確認できる場合に限り用いる（能力ゲート）。追送が失敗した場合は新規レビュアーで差分確認巡を行う。改訂が新規の規範文・設計を含む巡では新規レビュアーを必須とし、**両条件が競合する場合（新規の規範文を含む改訂に対しユーザーが差分確認巡を選んだ場合）は新規レビュアー必須が優先する**（継続レビュアーは自らが示唆した修正方向を追認するバイアスを持ち、独立視点数の減少が新規欠陥検出を弱めるため）。ただし**骨格安定（決定 2）と判断している状態での差分確認巡に限り、継続レビュアーを認める**（骨格新規指摘ゼロのフル巡 2 巡の観測が、継続バイアスの被害面〈骨格欠陥の見逃し〉を狭めているため。改訂が設計骨格に触れる場合は骨格安定の判断が取り下げられるため本例外には至らず、新規レビュアー必須が優先する。レイヤ判定・骨格安定の判断に迷う場合は新規レビュアー側へ倒す〈決定 2 の既定と同じ向き〉。規範・手順文書の反復では改訂がほぼ毎巡新規の規範文を含み、本例外なしでは継続利用の窓が開く局面がほぼ生じない——先行適用 9 巡はすべてフル巡で、窓が開く局面自体が無かった〈反実仮想としての対処であり、窓が閉じたことの直接実測ではない〉）。継続レビュアーへの追送も委譲であり、subagent-dispatch の A 群 4 件・B 群判定行・当該巡で発火した B 群項目を追送プロンプトで再掲する。前巡が複数体の場合は継続する対象体（担当観点）を反復提示に明記する。

差分確認巡では委譲側が改訂箇所の全数リストを作って渡す。リストの機械列挙のため、**すべての指摘反映の改訂に着手する前に、草稿の複製を一時領域へ退避し（成果物がディレクトリ形式の場合はディレクトリごと退避する）、改訂後に比較して差分を取る**（反復方式の選択は改訂後の提示で行われ退避時点では判定できないため、無条件とする。成果物型を問わない共通手順。コミット済みの成果物では `git diff` で代替してよい）。退避先は**セッションを跨いで残る場所**（リポジトリ外の恒久領域。worklog 中央ストアと同格の `<home>` 配下、例: `<home>/.ai-dev-review-snapshots/`）を第一選択とし、セッション限りの一時領域は同一セッション内で反復を完結させる場合に限る（リポジトリ配下は未追跡ファイルが変更列挙・コミット作法へ干渉するため用いない）。退避が無い・失われていた場合は差分確認巡を選べないため、フル巡側へ倒す（追送失敗時のフォールバックと同じ型）。本退避の発火点は pre-finalization-review 手順 6 の修正着手直前（同手順冒頭へ退避を命じる 1 文を置く）と、start-work 反復推奨小節（スキル外で行う改訂〈機械検証由来の修正等〉用の 1 行）の 2 箇所に配線する（実装対象参照）。改訂前に草稿をコミットしておく手順も使える（非拘束の推奨手順）が、設計文書兼用 ADR（spec 確定点 (c) の型。確定点はドラフトをコミットする直前）では用いない。`git stash create` は未追跡ファイルを含めないため、未追跡ドラフトの退避手段に用いない（写経実験で無音の空振りを実証済み）。

**決定 4（記録方式。正本: session-handoff の `review=` 値定義）**: `review=` の値を次のとおり定める（第 3 巡までの反復で記録機構の増設が欠陥源になった実測を受け、設計縮小を適用した形。機械検査・語彙移行・転換点併記は置かない）。

- 値は `見送り` / `非発火（推奨判定が偽）`、または**実施記録**とする。実施記録は 1 個以上の方式要素を `＋` で連結したもので、実施順に全要素を残す（方式の連鎖〈例: フル 2 巡→差分確認 1 巡〉が記録から消えないようにする）。同一方式が連続する場合は既存要素の巡数を加算し、方式が切り替わったとき、または同一方式でもレビュアーのモデルが変わったときは新要素を足す（モデルは方式要素の識別子に含まれるため。`機械検証` はレビュアーを立てずモデル欄を持たないため本規則の対象外）。`見送り` / `非発火` は反復局面（実施後の改訂発生時）では使わないが、推奨判定が偽のままユーザー指示で実施した場合は方式要素の括弧内に「推奨判定は偽」を併記してよい（任意）
- 方式要素は `フル実施（モデル・N 巡）` / `差分再確認（モデル・N 巡）` / `機械検証（N 回）`。値語彙「フル実施」「差分再確認」は歴史的語彙として維持し、それぞれフル巡・差分確認巡に対応する（改名による移行機構は設けない）。計数の単位は巡（フル・差分確認）または回（機械検証）。**N は当該方式要素が表す連続区間の巡数とし、確定点の初回レビュー巡はその方式に対応する最初の方式要素に含める**（確定点全体の通算はすべての方式要素の N の和として読む。機械検証は回数であり初回巡の概念を持たない。既存記録・先行適用の数え方と整合させる。反復の深さを読むときは初回の 1 巡を差し引く）
- 末尾の方式要素の括弧内の最後に**終了状態**を書く（例: `フル実施（claude-opus-5・2 巡）＋差分再確認（claude-opus-5・1 巡・実質収束）`）
- 終了状態は次の 4 値とし、**記録全体の帰結**を表す（末尾要素に書くのは位置の規約であり、対象は当該確定点の反復全体）。終了状態は**反復の終了時に書く**（値が `見送り` / `非発火` の場合は方式要素が無いため終了状態を書かない）。反復継続中の行は方式要素のみの記載でよく、継続中である事実・再開手順・セッション跨ぎの申し送りは handoff「進行中のタスク」節が正本として担う（`review=` 値に反復途中の状態を持たせる機構は置かない。第 5〜6 巡の反復で当該機構が欠陥源になった実測による設計縮小）。**委譲先へ書く項目は、対象確定点の型・実施済みの方式と巡数・レビュアーのモデル・保留中の選択（次に実施する方式または回答待ちの提示）・改訂前退避ファイルのパス・骨格安定と判断していたか（Yes/No と根拠 1 行。判断材料であり規範的判定には使わない）・Accepted 済み ADR 本文の改訂の有無（改訂記録の未記入がある場合）とする。反復終了時は当該記載を除去または最新化する**（書き込みの配線は実装対象の session-handoff (6) による）:
  - `実質収束` — 決定 2 の実質収束（いずれかの経路）の判定が真のまま確定した場合（改訂が 1 度以上発生した場合に限る。改訂が 1 度も発生しなかった場合は `改訂なし確定` または `提示後確定` を採る）
  - `提示後確定` — 反復提示への回答としてユーザーが「このまま確定」を選んだ場合、または回答として選ばれた方式を実施した結果さらなる改訂が生じなかった場合（実質収束の判定が否の場合は `提示後確定（実質収束せず）` と併記する。判定が真の場合は優先順位により `実質収束` を採る）
  - `ユーザー打ち切り` — 反復提示の選択肢への回答としてではなく、ユーザーが反復の終了を明示的に指示した場合
  - `改訂なし確定` — **改訂が 1 度も発生せず、反復提示も行われなかった場合**（＝指摘が無かった場合。指摘があったが全て不採用の場合は提示を経由するため優先順位により `提示後確定` 側になる）

  反復終了後に複数が成立する場合は**実質収束 ＞ ユーザー打ち切り ＞ 提示後確定 ＞ 改訂なし確定**の順で採る
- **`review=` の値は当該確定点のマイルストーン行 1 行に集約する**。反復の途中経過が独立のマイルストーン（スキル完了・重要な分岐）になる場合、その行には `ADR=` / `worklog=`（および該当時 `cyclecheck=`）を通常どおり書き、`review=` は書かずに確定点行へ集約する（read の未消化検査は確定点ラベルを含む行にのみ `review=` を求める現行仕様のため矛盾しない）。反復中に update を重ねる場合は、既存の方式要素を残したまま末尾要素の追記（および反復終了時の終了状態の記入）で最新化する（書き換えで巡種の履歴を消さない）。spec 確定点 (c) の型では確定点行は当該確定点の通過時（ドラフトのコミット直前の update）に作成し、それまでの反復の記録はその 1 回でまとめて書く（反復途中の状態は handoff「進行中のタスク」節が担う）
- 巡数・終了状態の記入は本形式定義と書き手の規律に委ね、read の機械検査は既存の「確定点行に `review=` があるか」のみとする（巡数・終了状態の欠落を検査する機械検査は**置かない**。第 3 巡までの反復でこの種の検査が塞ぐたびに機構を増殖させた実測による見送り。記入漏れ・提示漏れは値として表現されないため、事後監査は git 履歴上の改訂コミットと `review=` 値の突合で行う。改訂がコミットに現れない spec 確定点 (c) の型ではこの突合は成立せず、**(c) 型は記入漏れ・提示漏れの機械的な事後監査を持たない**——第 3 次設計縮小による端的な受容。防御は発火側〈並記義務・自己ループ・退避配線〉に依る）
- 決定 2 の「設計そのものを変える修正」を挟んだ場合も巡数は通算する。転換の経緯は値に書かず、正本（plan・ADR・課題ログ）側へ書く（ADR-0088 の「内訳は正本側」の原則に従う）
- 巡数・終了状態は、消化記録の値限定（ADR-0088。判定結果＋安定識別子＋正本への参照）の「判定結果」として扱う（走査母数・指摘件数などの内訳は従来どおり正本側へ書く）。1 行 200 字（ADR-0088）に収まらない場合は、行には最初と最後の方式要素＋通算計数（全方式要素の N の和）＋終了状態を残し、完全な連鎖は正本（plan・ADR・課題ログ）側へ書く（本縮退規定の着地先は session-handoff の形式行側）。この関係規定は ADR-0088 への部分修正にあたる（決定 1 の注記列挙 (4)）

## 評価可能性（ADR-0102）

発火機会は確定点ごとに数える（反復の深さは `review=` 値の計数〈N 巡 / N 回〉を副指標とする）。実測の base rate: 直近 3 サイクルで確定点 5 回・うち改訂が発生し反復実測が取れたのは 4 回（残り 1 回〈Issue-0084 サイクルの実装 plan 確定点〉は写像 plan で改訂なし〈改訂なしは行の記載からの読み取り〉——当該消化記録行の `review=` は「30 要件中欠落 0」、同行の `worklog=` は「写像脱落 3 件は独立レビューの想定内で delta なし」と記しており「指摘ゼロ」ではない。出所は一次記録でなく git 履歴上の handoff 消化記録行）。本サイクル自身の確定点（spec 確定点 (c)・先行適用）は通過時に計数へ加える。計数手段は、本サイクル内は handoff 消化記録の `review=` 行、サイクル横断は git 履歴上の `review=` 行と課題・retrospective の記録とする（作業ツリー上の handoff は cycle-reset で消化記録を全行削除するため用いない。git 履歴では同一マイルストーン行が update のたびに再コミットされるため、日付＋確定点ラベル＋handoff ファイル名（ブランチ）をキーに重複排除し最終状態のみを採る（同一日に同型の確定点が複数生じた実測があるため、日付＋ラベルだけでは潰れる）。retrospective は自由記述で計数欄を持たないため機械計数は git 履歴側で行う。なお ADR-0106 も handoff 消化記録を計数手段にしない点は同じだが、計数面には振り返り記録の様式欄と `git log --merges` を使う〈本 ADR とは別の面〉）。対象期間は次回の全数棚卸しまで。捕捉したい欠陥型は「新規の規範文・設計を含む改訂が次巡へ持ち込む設計欠陥」（実測: 該当改訂の次巡で Critical 1〜4 件）。退役条件（向き付き）: 軽量側（差分確認巡・機械検証。締めモード下の巡を含む）を推奨した改訂の後工程、または採否の推奨により不採用とし正本へ委ねた指摘（方式を問わない）の後工程で、重大欠陥（Critical 相当）が検出される同型事象が観測されたら 2 段型・締めモード（骨格安定の目安・レイヤ判定）の判定条件を改良する側へ、フル巡推奨が長期（目安 5 サイクル）にわたり全て見送られ・かつ見送りによる欠陥流出も観測されない場合は推奨規則の簡素化・退役を候補としてユーザーへ提案する側へ倒す。骨格安定の判断が長期（目安 5 サイクル）にわたり一度も立たない場合も、目安の緩和または締めモード条項の簡素化を候補としてユーザーへ提案する。

## Consequences
