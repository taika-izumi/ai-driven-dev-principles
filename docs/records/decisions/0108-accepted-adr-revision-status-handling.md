# ADR-0108: Accepted 昇格後の ADR 本文改訂は決定内容の変更有無でステータス運用を分ける

- **Status**: Proposed
- **Date**: 2026-08-18

## Context

確定前レビューの反復や実装時レビューの指摘反映が、Accepted 昇格済みの ADR 本文の改訂を生む場面が実測されている。直近 3 サイクルで、**改訂記録を残して** Accepted を維持した実施例は ADR-0102 の 1 例（Accepted 昇格後、確定前レビュー第 2〜4 巡の指摘を反映して本文を改訂し、Consequences に改訂記録 1 行を残した）。それ以前には、Accepted 状態の本文をレビュー指摘・訂正で書き換えながら**記録を残さなかった**例が複数ある（ADR-0085 `8774342`・ADR-0084 `b8b60f0`・ADR-0078 `c446a67`・ADR-0061 `58052a8`。記録が残らない改訂が常態化していた実測であり、本規範の必要性の根拠になる）。ADR-0106 にも改訂 2 コミットがあるが、これらはコミット済み Proposed 段階の改訂であり、本 ADR の対象（Accepted 昇格後）に入らない。

なお、これと別カテゴリとして「**他 ADR が既存 Accepted ADR の決定の一部を改め、旧 ADR の Consequences に部分修正注記を残して Accepted を維持する**」型（型の実質は ADR-0073 が定義: Consequences へ追記・Accepted 維持・Superseded にしない。`- **部分修正（ADR-XXXX）**:` の書式は既存慣行〈ADR-0080 等の実例〉による）が確立しており、部分修正注記は現存 32 行（主要書式 27 行のほか変種が計 5 行〈太字あり・日付併記 2／太字なし・日付併記 3〉。うち 21 行は 2026-08-17 の一括追記。計数パターン: `部分修正（` を含む箇条行から ADR-0105 の Decision 文と本サイクルの 2 ADR を除く）ある。本 ADR はこの部分修正の型を変更しない（Decision の対象外規定を参照）。

自 ADR 本文の書き換えケースのステータス運用（Proposed へ戻すか・改訂記録で足りるか・記録の書式はどうするか）は decision-log に未定義で、Issue-0098 の検討範囲に含めると 2026-08-17 の retrospective で明記されていた。反復の発動・停止・実施・記録の基準は ADR-0107 が定めるが、本件は「昇格済み ADR の本文を直したらステータスをどう扱うか」という別の問いであり、実装時レビュー由来の改訂（反復の枠外）も対象に含むため、独立の ADR とする（ADR-0107 の確定前レビュー第 1 巡の粒度指摘による分離）。

## Considered Alternatives

- **既存工程の文言拡張・リスク受容で足りないか**（新設の評価可能性・ADR-0102 の要求比較）: decision-log「ステータス変更」節はステータスを変更する場合の手順のみを定めており、変更しないケース（改訂しても Accepted を維持する）の規定・書式がそもそも存在しない。文言拡張では書き分けの判定基準（決定内容を変えるか）を供給できず、リスク受容は ADR-0102 で既に書式の割れ（改訂記録形式と部分修正形式の 2 カテゴリの書式が規定なしに並ぶ状態）を生んでいる。よって規範の追記を採る
- **Proposed へ戻す運用**: 状態遷移は単純だが、昇格時に実施済みのサイクル全体整合検査（ADR-0092）の効力が曖昧になり、Accepted だった期間の履歴も失われ、遷移表（Accepted の遷移元は Proposed のみ・Accepted からの遷移先は終端のみ）に無い遷移を運用することになる
- **常に改訂記録 1 行**: 最軽量だが、決定変更級の改訂まで記録 1 行で流れる危うさが残る
- **決定内容の変更有無で 2 分岐（採用）**: 決定を変えない改訂は軽量に、決定を変える改訂は Superseded 連鎖で履歴を残す。decision-log の既存ステータス運用（終端ステータスの意味境界）と整合する

## Decision

Accepted 昇格後に**当該 ADR 自身の本文を書き換える改訂**（確定前レビューの反復・実装時レビューの指摘反映・整合検査による修正など、契機を問わない）が生じた場合のステータス運用を次のとおり定める。正本は decision-log「ステータス変更」節への追記とする。

- **決定内容を変えない改訂**（文言精度・参照整合・レビュー指摘の反映で、Decision が定める内容の実質が変わらないもの）: Status は Accepted のまま維持し、当該 ADR の Consequences 末尾に改訂記録を 1 行残す。書式は `- 改訂記録（<契機>）: <改訂箇所>・<日付>。Status は Accepted のまま維持` に固定する（Consequences 直下のトップレベル箇条として置く。計数 grep の前提）。同一の確定前レビュー反復（ADR-0107 の 1 確定点）に由来する複数巡の改訂は改訂記録 1 行に集約し、`<契機>` に巡の範囲を書く。**改訂記録は反復の終了時（ADR-0107 決定 4 の終了状態を確定させる時点）に 1 回書き、反復の途中では書かない**（発火点の配線 (ii) は各改訂時に「対象が Accepted 済み ADR 本文である」ことの認識を課し、書き込み自体は終了時に行う。終了時の発火は ADR-0107 実装対象 session-handoff (4) の句〈終了状態を記入する更新で Accepted 済み ADR 本文の改訂を含んでいた場合は本規定を適用〉が担い、セッション跨ぎは同決定 4 の handoff 委譲項目〈Accepted 済み ADR 本文の改訂の有無〉が事実を引き継ぐ）。**反復以外の契機（実装時レビュー・整合検査など）による改訂は、改訂の都度その場で改訂記録を 1 行書き、同一サイクル内の同一 ADR への 2 回目以降の改訂は行を増やさず既存行の契機・改訂箇所・回数を更新する**（`<契機>` に契機名と改訂回数を書く。書き込みを繰り延べる方式は発火点が失われるため採らない——配線 (ii) の各改訂時発火だけで完結させる）。（ADR-0102 の既存行は書式こそ固定前の形だが、集約と巡の範囲の書き方はこの実例にあたる）
- **決定内容を変える改訂**: 当該 ADR の Decision の骨格・帰結が置き換わる場合に限る。本文を書き換えず、新 ADR を作成して旧 ADR を `Superseded by ADR-XXXX` へ更新する（decision-log の既存手順）。**決定の一部のみが改まる場合は対象外 1（部分修正の型）へ振る**（新 ADR を作る点は同じだが、旧 ADR は Accepted 維持＋部分修正注記とする）。全部か一部かの判定に迷う場合はユーザーへ確認する
- **Accepted → Proposed の差し戻しは、上記いずれのケースでも用いない**（遷移表に存在しない遷移を運用しない。Accepted 済みの決定を再検討する場合は、終端ステータスへの遷移〈Deprecated 化・新 ADR による Superseded 化〉で行う）
- **対象外 1（部分修正）**: 他 ADR が既存 ADR の決定の一部を改める場合（部分修正）は本規範の対象外とし、既存の部分修正の型（旧 ADR の Consequences へ `- **部分修正（ADR-XXXX）**:` 書式で注記を追記し、Status は Accepted 維持・Superseded にはしない）に従う。部分修正を本規範の 2 分岐に当てはめて Superseded 化しないこと
- **対象外 2（コミット済み Proposed への改訂）**: Accepted 昇格前でありサイクル全体整合検査の効力範囲に入らないため、本規範の記録義務は課さない（改訂の履歴は git 履歴が担う）
- **対象外 3（終端ステータスの ADR への改訂）**: Rejected / Deprecated / Superseded 済み ADR の本文改訂（参照の張り替え・誤記修正等）にも記録義務は課さない（git 履歴が担う）
- decision-log「ステータス変更」冒頭の例示「いったん Accepted にした決定の見直し」について、見直しは終端ステータスへの遷移（Deprecated 化・新 ADR による Superseded 化）として行うものであり、Accepted → Proposed の差し戻しを含意しない旨を同節の改定時に明記する。あわせて、差し戻し不使用により到達不能となる再昇格関連の記述 3 箇所——「ステータス変更」節末尾の「（初回昇格・見直し後の再昇格とも）」の括弧書き、同文後半の「Consequences への追記は、初回昇格では不要とし、再昇格では変更理由を追記する。」の一文（「初回昇格では Consequences への追記は不要とする（本文改訂の改訂記録規定は昇格ではなく改訂に適用される）。」へ書き換えて初回昇格側の規定を残す）、「承認の昇格」節冒頭の「（見直し後の再昇格を含む）」の括弧書き——を削除・整理する（承認の昇格は初回昇格に一本化する。遷移表には触れず、新しい遷移も追加しない）。**この 3 箇所は ADR-0092 の Decision とその実装が導入した記述であり（2 箇所目のうち初回昇格側の規定は ADR-0092 以前から存在し〈`954eabf^` の「初回昇格は…Consequences への追記は不要とする」〉、再昇格への拡張部分が同 ADR 由来）、本削除は ADR-0092 への部分修正にあたる**（同 ADR の Consequences へ部分修正注記を残す。検査工程の規範本体は現役のため Status は Accepted 維持）

**発火点の配線**（文書にしか無いトリガーは発火しない実測〈ADR-0098/0102〉への対処。実装対象に含める）: (i) decision-log「いつ使うか」へ、強・弱トリガーの小節と並列に小見出し「意思決定を伴わない起動契機」を設けて 1 行を追加する（「Accepted 済み ADR の本文を改訂するとき — 意思決定の有無を問わず『ステータス変更』節の改訂記録規定を適用する。ただし他 ADR への部分修正注記の追記は対象外 1 に従う。トリガー一覧の判断基準文の適用外」。decision-log 実行中に他の Accepted 済み ADR を改訂する場合も同じ）。(ii) pre-finalization-review 手順 6〈修正と報告〉と start-work 横断的ラッパー Post 項目 1〈ADR 候補検出〉へ「改訂対象が Accepted 済み ADR 本文なら decision-log の改訂記録規定を適用する」のポインタ 1 行を置く。サイクル全体整合検査への検査項目の追加は行わない（発火実測 1 例の規範のために全昇格チェックポイントへ常設検査を増やさない。ADR-0107 第 4 巡前の設計縮小で見送り）。

## 評価可能性（ADR-0102）

発火機会は Accepted 昇格後の自 ADR 本文改訂の発生ごと（実測: 直近 3 サイクルで記録付き 1 例〈ADR-0102〉＋それ以前の記録なし改訂 4 例〈Context 参照。例示であり全数走査ではない。記録なし改訂は計数手段では原理的に拾えない〉。部分修正注記 32 行は別カテゴリで、本規範の発火機会に数えない）。計数手段は `docs/records/decisions/` 配下の `^- 改訂記録` 行の grep（前方一致。固定書式化前の既存行〈ADR-0102〉も拾える）。対象期間は次回の全数棚卸しまで。捕捉したい欠陥型は「決定変更級の改訂が記録 1 行で流れて Superseded 連鎖が途切れる」型と「書式の割れによる機械計数の不能」型。退役条件（向き付き）: 決定変更級の改訂が改訂記録 1 行で処理された事象が観測されたら 2 分岐の判定基準を強化する側へ（観測経路: レビュー・棚卸しでの同型検出が課題起票・retrospective 記録に至った時点。grep の件数計数では判別できず、常設の検査項目も置かないため観測面は弱い。この弱さは設計縮小の受容事項として明記する）、改訂記録・Supersede とも長期（目安 5 サイクル）に発生しない場合は本規範の簡素化を候補としてユーザーへ提案する側へ倒す。

## Consequences

- 良い影響: 昇格済み決定の履歴が消えず、整合検査の効力の範囲が明確になる。改訂記録の書式固定により、**同一カテゴリ（自 ADR 本文の改訂記録）内で**書式が割れなくなる（部分修正側は既に複数の書式変種が併存しており、本 ADR は遡及改修しない。固定するのは改訂記録側の書式である）。`^- 改訂記録` の前方一致 grep が評価可能性の計数手段を兼ねる
- 悪い影響・リスク: 「決定内容を変えるか」の判定は AI の自己判定を経てユーザーが確認する運用になり、判定を誤ると決定変更が記録 1 行で流れる。常設の機械的監視は置かないため、検出はレビュー・棚卸し頼みになる（設計縮小による受容。観測されたら退役条件の強化側で判定基準を改める）
- 実装対象: decision-log の改定（「ステータス変更」節への追記・「いつ使うか」への起動契機 1 行・再昇格関連 3 箇所の削除・整理〈Decision 最終箇条のとおり〉。配布対象ソース）と、pre-finalization-review・start-work へのポインタ各 1 行、**ADR-0092 への部分修正注記**（再昇格関連記述の削除。Status は Accepted 維持）。現行 spec の同期は `docs/current/specs/2026-04-12-meta-guidelines-design.md` の decision-log 更新トリガー節へ第 3 の経路（決定を変えない改訂 → Consequences へ改訂記録 1 行）を追記し、`docs/current/specs/2026-04-25-record-strengthening-design.md` の start-work Post 項目 1 の記述へ配線 (ii) の起動契機（意思決定の有無を問わない改訂記録規定の適用）を反映する。ADR-0107 の実装と同一サイクルで実施し、執行点 4 手順＋version bump は合流して 1 回でよい
- 既存行は遡及改修しない: 部分修正形式（`- **部分修正（ADR-XXXX）**:` とその変種・現存 32 行）は別カテゴリとしてそのまま有効。ADR-0102 の既存改訂記録行（固定書式前の形）もそのまま残す（計数は前方一致 grep が拾う）。いずれも次にその ADR の当該行を触る機会に各カテゴリの固定書式へ揃えることを妨げない。Superseded 化に伴う既存改訂記録行の末尾句（「Status は Accepted のまま維持」）の書き換えも行わない（当該行は改訂時点の記録である）
