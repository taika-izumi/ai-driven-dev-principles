# ADR-0109: 構造化質問ツールを全ツール・全モデルで廃止しテキスト選択肢に一本化、クリック操作を再有効化する

- **Status**: Accepted
- **Date**: 2026-08-18

## Context

ユーザーへの質問・意思決定要求の規範は、ADR-0024（選択肢＋推奨の提示）を土台に、選択 UI の誤クリック即確定への対処（ADR-0036: 環境変数 `CLAUDE_CODE_DISABLE_MOUSE_CLICKS=1` の設定確認を条件とする 2 分岐）、本文非表示事象への対処（ADR-0029 → ADR-0085: 事象確認済みモデルでの全面不使用）、タイムアウト時の停止（ADR-0035）と、条件分岐を重ねて成長してきた。

2026-08-18 にユーザーから、次の実測に基づく方針変更の指示があった:

1. **テキストの番号付き選択肢で不便がない**: ADR-0085 の運用（Fable 5 でのテキスト提示一本化。2026-08-13〜）を経て、構造化質問ツールを使わなくても意思決定の提示・回答に支障がないことが確認された
2. **クリック無効化の副作用が顕在化**: `CLAUDE_CODE_DISABLE_MOUSE_CLICKS=1`（ADR-0036）は TUI 全体のマウスクリック確定を無効化する設定であり、CLI 上でメッセージのコピー＆ペーストができない恒常的な不便が生じている。質問ツールを使わなければ、選択 UI での誤クリック即確定の経路そのものが消えるため、質問ツール対策としてこの設定を維持する理由もなくなる

ADR-0085 は「無条件の全面不使用（モデル条件なし）」を、事象が発生しないモデルでの利便性（誤操作防止・回答コスト減）を失う過剰対応として不採用にしていた。本決定はその判断軸を更新するものである: 当時は構造化ツールの利便性を保持する価値を前提にしていたが、テキスト提示で不便がないという運用実測と、クリック有効化（コピペ）の利便性という新しい判断材料により、条件分岐を維持するコストの方が上回ると判断した。なお 2026-08-16 の全数監査（台帳 A-10）は当該規範群を keep と判定していたが、本決定は監査時に存在しなかった材料（上記のユーザー指示とコピペ不可の不便の実測）により判定を反転する（台帳は追記型の時点記録のため遡及修正しない）。

CONTRIBUTING「CLAUDE.md を更新するとき」事前判定の記録:

- **手順 1（実測）**: 変更前 10732B・28 箇条（2026-08-18）。変更後は純減となる見込みで、閾値（12000B / 45 箇条）内を `sync-template.ps1` の自動計測で確認する
- **手順 2（放置リスク評価）**: 残す規範（テキスト提示一本化）が防ぐ失敗は ADR-0085 と同型（本文非表示・誤クリックによる判断の誤誘導は顕在化した時点で回復できない）であり、常時指示（CLAUDE.md）の維持が妥当。加えて条件分岐の放置はモデル切替時の再評価漏れ（ADR-0085 の Context で実測）として静かに再発する型であり、無条件化はこの経路を消す
- **手順 3（配置先の優先順位）**: ①環境・ツール設定による構造的解決を再検討した（Considered Alternatives 5。ADR-0085 の却下理由が本決定で失効するため再検討が必要だった）。不採用につき CLAUDE.md の規範文実装を維持する。②（Layer 3 スキル）・③（発生箇所の手順書）への降格は、対象が既存 CLAUDE.md 条項の縮減であり降格先に置く便益がないため不検討とした
- **手順 4（ゲート必須）**: 本規範の発動条件は「ユーザーへ質問・意思決定を求めるとき」という観測可能な局面であり、ADR-0032 が避けるべきとする無条件の「常に〜せよ」型ではない。本決定で撤廃するのはモデル・環境変数という副次条件であり、発動ゲートの喪失にはあたらない
- **手順 5（点検必須）**: 末尾の「過剰適合点検（ADR-0079）」節に記録した。また本決定は新設（新規範・手順・観点）を含まない（既存条項の削除・既存条項〈テキスト提示〉の適用条件の拡大・参照追従・ステータス整理のみ）ため、「新設の評価可能性」（ADR-0102）の記載要件は非該当と判定した
- **手順 6（追加後の確認）**: 変更後に `sync-template.ps1` を実行し、自動計測で閾値内を確認する（手順 1 の確認と同一。Consequences の執行手順にも記載）

## Considered Alternatives

1. **全ツール・全モデルで無条件に構造化質問ツールを廃止し、テキストの番号付き選択肢に一本化する（採用）** — 規範が最も単純になり、モデル・ツール・環境変数の条件分岐がすべて消える。廃止の動機（テキスト提示で不便がない・コピペを可能にしたい）はツール・モデルを問わず成立する
2. **Claude Code のみ廃止し、GitHub Copilot CLI の `ask_user` は従来の分岐を残す** — ツール別の条件分岐が残り、簡素化の効果が半減する。Copilot CLI 側でだけ構造化ツールを維持する積極的な理由もない。不採用
3. **「テキスト提示を既定、ユーザーが個別に指示した場合のみ質問ツール使用可」とする** — 実質は案 1 と同じだが例外条項の維持コストが残る。再有効化はユーザー指示による本 ADR の見直し（退役経路）で足りる。不採用
4. **タイムアウト停止規範（ADR-0035）の扱い**: (a) CLAUDE.md の箇条・原則4 の一文とも削除、(b) 両方残す、(c) CLAUDE.md の箇条のみ削除し原則4 の一文は残す（採用）。CLAUDE.md 側は「構造化質問ツールのタイムアウト」専用で発動機会がゼロになるため削除する。原則4 の一文はツール非依存の抽象表現（「人間の判断を仰いだが得られないまま自動的な続行を促される状況では停止を既定の撤退とする」）であり、撤退条件の一般則として残す。なお現時点のリポジトリで「自動的な続行を促される」具体機構は削除対象の質問ツールのタイムアウトのみであり、他の具体機構は不在である（不在の判定を記録する。将来のツール挙動への抽象則としての保持であり、棚卸しで死条項と判定された場合は削除してよい）
5. **環境・ツール設定による構造的ブロック（permissions の deny 等で質問ツール自体を無効化する。配置先優先順位①の再検討）** — ADR-0085 はこの案を「無条件 deny は過剰対応」として却下していたが、本決定は無条件廃止を採るため当該却下理由は失効する。改めて検討した結果、不採用とする: (a) permissions 設定はツール固有かつユーザー環境側にあり、配布物（template は CLAUDE.md 等のみ）に載らないため配布先プロジェクトへ強制できない、(b) GitHub Copilot CLI に同等の deny 機構が確認できていない、(c) テキスト提示側の行動（選択肢＋推奨の形式）は規範文でしか規定できず、deny を併用しても規範文は消せない（二重管理になる）。よって CLAUDE.md の規範文実装を正とする。ユーザーが自環境で deny 設定を併用することは妨げない（任意の補助であり規範化しない）

## Decision

案 1 を採用し、タイムアウト規範は案 4-(c) で整理する。タイムアウト規範の撤去は質問ツール廃止の従属的帰結（発動機会がゼロになる）であり、独立の問いを構成しないため本 ADR に含める（粒度判定の記録）。

1. **CLAUDE.md「ユーザーへの質問と意思決定要求」節を 3 箇条に置き換える**:
   - 選択肢の提示＋推奨を先頭に「（推奨）」＋推奨理由一言（ADR-0024 の規範を維持）
   - 質問・意思決定要求はすべてテキストのみのターンで行い、説明に続けて番号付き選択肢を提示する。構造化質問ツール（Claude Code の AskUserQuestion、GitHub Copilot CLI の ask_user 等）は、モデル・ツール・環境設定を問わず使用しない
   - 本質的に自由記述が必要な質問の例外（ADR-0024 の例外を維持）

   削除する条項: 環境変数ゲートの 2 分岐（ADR-0036）、事象確認済みモデル条項（ADR-0085）、タイムアウト停止規範の箇条（ADR-0035 の CLAUDE.md 実装）
2. **`docs/overview/principles.md` 原則4 は無変更**（選択肢＋推奨の一文、停止を既定の撤退とする一文とも維持）
3. **参照箇所の追従**:
   - `skills/start-work/SKILL.md` の差分明示にある構造化質問ツール利用可否の条件文を「説明と番号付き選択肢をテキストで提示する」に単純化する
   - `skills/worklog-record/SKILL.md` のエントリ例（題材が質問ツール＋環境変数確認で、廃止後の運用と矛盾する）を中立的な題材へ差し替える。差し替え後も記法規約（R4/R5）を維持する（`project` は中立名 `X`、`applied_rules` はプレースホルダのまま）
   - `CONTRIBUTING.md` の是正パターン「観測可能な発動条件でゲート」の実例参照（本規範を名指し）を履歴表現（撤回済みである旨の併記）へ改め、spec スナップショット `docs/current/specs/2026-08-07-overfitting-check-for-extensions-design.md` の同文も同期する
   - `CONTRIBUTING.md` の「環境・ツール設定による構造的解決」調査手順にある事例参照（ADR-0036）は、撤回されなかった構造的解決の実例（ADR-0037 の .gitattributes 改行正規化）へ差し替える
   - 生成器移行 spec `docs/current/specs/2026-08-07-distributed-artifact-generation/05-source-migration.md` の worklog-record サンプル行は移行時点の処理台帳であり追従不要と判定する
4. **環境・メモリの撤回**:
   - ユーザー環境の `~/.claude/settings.json` から `CLAUDE_CODE_DISABLE_MOUSE_CLICKS` を削除し、クリック操作を再有効化する（次セッション起動から有効）。ADR-0036 が定めた「推奨環境設定としての文書化」も撤回する（配布物に当該環境変数の推奨は残さない）
   - `.claude/settings.local.json` に残る当該環境変数確認用の permission エントリを削除する（git 管理外・配布影響なしの掃除）
   - プロジェクトメモリ `askuserquestion-text-not-visible.md` と索引 `MEMORY.md` の該当行を、モデル条件なしの全面不使用へ更新する（モデル切替時の再評価を指示する記述を除去する）
5. **旧 ADR の整理**:
   - ADR-0085・ADR-0036 を `Superseded by ADR-0109` へ更新する。この 2 件に限り decision-log「ステータス変更」の 4 手順（ADR ファイルの Status 更新・`docs/records/decisions/README.md` の該当行更新・両 ADR の Consequences への置換理由追記・コミット）を適用する。ADR-0085 の撤去基準は Deprecated を想定していたが、置換 ADR が存在するため decision-log の遷移表に従い Superseded とする
   - ADR-0035 は Status 遷移なし。Accepted のまま部分修正の型（Consequences へ `- **部分修正（ADR-0109）**:` 書式で注記を追記）で、CLAUDE.md 実装は本 ADR で撤去・原則4 の一文は現役である旨を残す。ADR-0035 の決定のうち原則4 の一文（決定 2）が現役で残るため「一部のみが改まる」に該当すると判定した（ADR-0108 の部分修正の型）
   - ADR-0024 の Status 注記を最新化する（提示規範はテキスト一本化のもとで現役）。ADR-0024 は既存の Status 行集約形式を踏襲する（書式の遡及改修はしない）
6. **spec スナップショットの回復**: `docs/current/specs/2026-06-16-choice-with-recommendation-design.md` の質問ツール関連記述を本決定後の規範（テキスト一本化）へ書き換え、open 中の Issue-0082（同 spec のスナップショット規約違反）を close する。本決定は同 spec の乖離を 4 世代目へ拡大させるため、据え置きではなく本サイクルでの回復を選ぶ
7. **退役経路**: ユーザーが構造化質問ツールの再導入を指示した時点で本 ADR を見直す（新 ADR による置換）。判断主体はユーザーに置く（テキスト提示の不便・構造化ツールの改善はユーザー画面・体験上の事象であり、エージェントから観測できないため）

## Consequences

- CLI 上のクリック操作が再有効化され、メッセージのコピー＆ペーストが可能になる（ユーザー環境では次セッションから）
- **残存リスクの受容**: `CLAUDE_CODE_DISABLE_MOUSE_CLICKS` は TUI 全体のクリック確定を無効化していたため、撤去により質問ツール以外の確定面（ツール実行の許可プロンプト・plan 承認・pre-action-review の承認必須局面）での誤クリック確定が再び可能になる。質問ツール廃止ではこの面は塞がらない。ユーザーのコピペ利便性を優先し、このリスクは受容する（誤確定が実測されたら本判断を見直す）
- 質問関連規範の条件分岐（モデル判定・環境変数確認・タイムアウト分岐）がすべて消え、CLAUDE.md が純減する。モデル切替時の再評価漏れによる事故経路（ADR-0085 の Context で実測）も構造的に消滅する
- 選択 UI 上の誤クリック即確定のリスク（Issue-0005）は、質問ツール自体を使わないため対処不要になる（ADR-0036 の防止対象のうち選択 UI 面は消える。TUI 全体面は上記の受容に含む）
- 構造化質問ツールのワンクリック回答の利便性を失う。番号のタイプ入力はユーザーの実測で許容済み
- タイムアウト停止規範（ADR-0035）は CLAUDE.md から消えるが、原則4 の抽象則が撤退条件の一般則として残る
- 配布先プロジェクトは template 再取得まで旧規範（3 分岐）で動くが、環境変数が未設定の環境では旧規範も分岐 2（テキスト提示）へ倒れるため、移行期間中も安全側で一致する
- 現役文書の追従は Decision 3〜6 で行うほか、master handoff の環境変数留意行の削除・Issue-0043 の関連欄の張り替えは実装時の session-handoff update / 課題更新で行う
- `CLAUDE.md` は template.manifest 対象のため `scripts/sync-template.ps1`、`skills/` は配布対象ソースのため `scripts/build-dist.ps1` の実行と version bump（0.1.10 → 0.1.11。`.claude-plugin/plugin.json`・`.claude-plugin/marketplace.json`・`dist/.claude-plugin/plugin.json` の 3 箇所）が必要
- 残存リスク: 将来、テキスト提示では困難な質問形態（大量の選択肢・視覚比較等）が出た場合も質問ツールへ戻らない規範のため、提示が長文化する。その場合は退役経路（ユーザー指示）で見直す

## 過剰適合点検（ADR-0079）

| 観点 | 判定 | 根拠 |
|------|------|------|
| 出所の偏り | 問題なし | 出所は 2 プロジェクト（MakeAiInstructions / LoopForAlpha）でのテキスト提示運用の実績（ADR-0085 適用下・2026-08-13〜08-18）と、本プロジェクトでのコピペ不可の不便の実測 1 件、および 2026-08-18 のユーザー明示指示 1 件。モデル世代は claude-fable-5 中心だが、本決定はモデル依存の事象対処ではなく UI 運用の選好決定であり、退役経路（ユーザー指示）で回復可能 |
| システム種別依存性 | 問題なし | 対話 UI の運用選好であり、開発対象システムの種別・技術スタックに依存しない。引き写し箇所: ADR-0024 の提示規範（選択肢＋推奨・自由記述例外）を無変更で継承。同規範は元々無条件の常時規範でありゲートの脱落なし |
| AI モデル/ツール依存性 | 問題なし | モデル・ツール条件を撤廃する方向の変更であり、特定モデルの挙動を前提にしない。構造化質問ツールという機能の不使用は将来モデルでも課される制約だが、判断の根拠はモデル性能と独立したユーザーの UI 選好（コピペ可能性・テキスト提示で十分）であり、性能発揮の制限にはあたらない。引き写し箇所: ADR-0085 の「無条件廃止＝過剰対応」の判定は本 ADR の Context で判断軸の更新として明示的に扱った（黙って落としていない）。ADR-0085 の環境設定案の却下理由の失効も Considered Alternatives 5 で明示的に再検討した |
| 退役経路 | 定義済み | ユーザーが構造化質問ツールの再導入を指示した時点で本 ADR を見直す（判断主体をユーザーへ明示的に移譲。ADR-0029/0085 と同じ型。本決定は新設を含まないため ADR-0102 の特則〈観測可能な向きの必須化〉は非該当であり、一般則〈ADR-0032〉の移譲で足りる） |
