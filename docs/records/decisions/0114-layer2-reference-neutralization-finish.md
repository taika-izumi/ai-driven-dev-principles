# ADR-0114: Layer 2 参照の中立化は、探索対象の明示・書き込み先の二段フォールバック・ツール列挙の開放で仕上げる

- **Status**: Accepted
- **Date**: 2026-08-25

## Context

Codex 対応サイクルの Task 4（コミット `691a901`）で、`skills/` 配下の Layer 2 参照 18 箇所とローカルスキルパス 3 箇所を中立化した。仕様適合レビューは要求 46 件中 46 件充足で通過している（親コミットに計画の置換規則のみを機械適用した再構成が実コミットとバイト単位で一致）。

続くコード品質レビュー（独立サブエージェント・claude-opus-5）が Important 3 件・Minor 1 件を報告した。いずれも隔離コピーでの実測つきで、本セッションでも実体を確認した。

**(1) 二段フォールバック句の探索対象が一意に読めない（6 箇所）**。採用した句は `プロジェクトの AGENTS.md（記載が無ければ CLAUDE.md）に調整値があればそれを優先` だが、「記載」の目的語（`調整値`）が括弧の外・後方にしか現れないため、「調整値の記載が無ければ」とも「AGENTS.md そのものが無ければ」とも読める。計画 Task 4 の前文と ADR-0111 は前者を明示している（「ファイルの有無ではなく調整値の記載の有無で探索する」）。さらに**同じコミット内の `skills/session-handoff/SKILL.md:113` は `AGENTS.md に調整値の記載が無い場合は` と曖昧さなく書けており、内部で表現が割れている**。読み違えが発火する状態は計画 Task 6 Step 5 が定める移行手順（① 内容を AGENTS.md へ退避 → ② CLAUDE.md をポインタ化）の①と②の間であり、文書化された経路として必ず通る。誤読すると調整値を読み飛ばして組み込みデフォルト（10KB / 40KB）へ落ちる。

**(2) ローカルスキル配置先の併記が利用ツールを閉じた列挙にしている（3 箇所）**。`利用ツールのスキル配置先。Claude Code は …、Codex は …` という書き方は、列挙されたツールがすべてであるかのように読める。ADR-0016 は Copilot CLI について `~/.copilot/installed-plugins/<marketplace>/<plugin>/skills/` のみがスキルソースであり、プロジェクトローカルの `skills/` は認識されないと記録している。設計 spec 自身は「Claude Code …・Codex … **等**」と開いた列挙を意図していた。加えて `skills/worklog-skillify/SKILL.md:36`（スコープ 3 分岐表のセル）だけ先頭の一般則が欠落し、2 ツールの列挙のみになっている。

**(3) Layer 2 への書き込み先に移行ラグの手当てが無い（1 箇所）**。`skills/worklog-skillify/SKILL.md:37` の `そのプロジェクトの AGENTS.md に追記` は skills 配下で唯一の Layer 2 書き込み点である。設計 spec はこれを「二段フォールバック 8 箇所」ではなく「AGENTS.md 化 11 箇所」へ分類していた（8 箇所の内訳は skills 7 ＋ `docs/overview/issue-management.md` 1 で、本セッションで実測確認済み）。未移行の配布先（`CLAUDE.md` が本文を持ち `AGENTS.md` が無い）でプラグインだけ更新されると、エージェントは新規に `AGENTS.md` を作ってそこへ固有ルールを書く。`CLAUDE.md` にインポート行が無いため Claude Code はその `AGENTS.md` を読まず、**ユーザーはルールを登録したつもりで規範が無言で不発になる**。

**(4)（Minor）観測できない限定句**。`skills/session-handoff/SKILL.md:113` の `（移行途中で AGENTS.md に調整値の記載が無い場合は …）` の「移行途中で」は、エージェントが判定できない状態を条件節の頭に置いている（ADR-0032 が避けるべきとする型）。

これらは規範文書の欠陥であり、実行による安全網が無い。本計画は確定前レビュー（フル巡 2＋機械検証 1＋差分確認巡 2＋機械検証 1）を通過して確定しており、計画からの逸脱には判断を要する。

## Considered Alternatives

1. **すべて Issue 起票し、計画どおり Task 5 へ進む**: 逸脱をゼロに保てる。しかし (1) は計画自身が前文で述べた意図を文面が満たしていない不整合であり、放置すると計画の意図と配布物の実体が食い違ったまま確定する。(3) は実行時に誰も気づけない型で、実装時レビューでも捕捉できない
2. **(1) のみ是正する**: 計画の意図との不整合の解消に限定でき、逸脱幅は最小。しかし (3) の無言の不発が残る
3. **レビュアーの提案どおり「Copilot CLI はプロジェクトローカル配置に非対応」と明記する**: 記述として最も具体的。しかし根拠の ADR-0016 は本サイクルより前の実測であり、Copilot CLI 側の仕様変更を本サイクルで再確認していない。断定は将来の誤りになりうる
4. **(3) を「AGENTS.md が未整備なら新設とポインタ化をユーザーへ提案する」という新しい手順として書く**: 移行を促す点で親切。しかし新しい拘束的文の追加＝規範の新設にあたり、CONTRIBUTING の「新設の評価可能性」の記載要件が発火する。同じ効果は既存パターン（二段フォールバック）の適用で得られる
5. **（採用）4 件すべてを、既存パターンの適用と表現の明確化の範囲で是正する**

## Decision

案 5 を採用し、Task 4 のコミット `691a901` を amend して次の 4 点を反映する。**規範の新設は行わず、既に本サイクルで採用済みのパターンの適用と、表現の曖昧さの解消に留める。**

1. **探索対象の明示（6 箇所）**: 二段フォールバック句を `プロジェクトの AGENTS.md（当該調整値の記載が無ければ CLAUDE.md）に調整値があればそれを優先` とする。「当該調整値の」の 6 文字を足すだけで、目的語の前方参照が解消される。同一コミット内の `session-handoff:113` が既に達している明確さへ寄せる
2. **書き込み先の二段フォールバック（1 箇所）**: `skills/worklog-skillify/SKILL.md:37` を `そのプロジェクトの \`AGENTS.md\` に追記（\`AGENTS.md\` が無いプロジェクトでは \`CLAUDE.md\` に追記する）` とする。読み側 7 箇所と同じ二段フォールバックを書き込み側へ適用するものであり、新しい手順ではない。未移行プロジェクトでは `CLAUDE.md` へ書くため、Claude Code が確実に読む
3. **ツール列挙の開放（3 箇所）**: 併記の末尾に `など` を添えて列挙を閉じない。あわせて `worklog-skillify:36` のセルへ欠落していた一般則の前置き（`利用ツールのスキル配置先。`）を復元する。**特定ツールの非対応を断定しない**（案 3 を採らない理由は Considered Alternatives 参照）
4. **観測できない限定句の削除（1 箇所）**: `session-handoff:113` から `移行途中で` を削り、`（AGENTS.md に調整値の記載が無い場合は CLAUDE.md の調整値を読む）` とする

**規範の新設・強化には当たらないと判定する**。1・3・4 は規範の内容を変えない表現の明確化であり、2 は本サイクルの spec が既に「二段フォールバック化」として過剰適合点検に記録しているパターンの適用先を 1 箇所増やすものである。CONTRIBUTING の「新設の評価可能性」の記載要件は発火しない。ただし点検の**再点検規定**（点検後に規範の文言・適用範囲を変更した場合の再実施）に従い、設計 spec の過剰適合点検ブロックへ本差分の再点検結果を追記する。

## Consequences

- 二段フォールバックの探索対象が文面から一意に決まり、移行手順の中間状態で調整値を読み飛ばす経路が塞がる。この経路は計画 Task 6 Step 5 が定める移行手順そのものに含まれるため、確実に通る
- skills 配下の Layer 2 書き込み点が、未移行プロジェクトでも Claude Code に届く先へ解決される。「規範を登録したのに無言で不発」という、実行時に誰も気づけない失敗が消える
- **受容する残余（決定 2 の分岐条件について。再レビューの指摘を受けて検討した）**: 決定 2 の分岐は `AGENTS.md` の存在という観測可能な一点で行うが、Claude Code の到達可否を実際に決めているのは `CLAUDE.md` が `@AGENTS.md` を取り込んでいるかである。両者がずれる構成が 2 つあり、いずれも受容する:
  - **状態 A（部分移行）**: `AGENTS.md` に本文があり `CLAUDE.md` にまだ取り込み行が無い構成では、追記先が `AGENTS.md` になり Claude Code に届かない。ただしこれは計画 Task 6 が定める移行手順の①（内容を AGENTS.md へ退避）と②（CLAUDE.md をポインタ化）の**間**にのみ成立する数分の窓であり、②の完了で自動的に解消し、追記した内容も失われない。移行前の長い期間（`AGENTS.md` なし）は決定 2 が正しく `CLAUDE.md` を選ぶため、危険な窓は「移行するまでの不定期間」から「移行作業中の数分」へ縮んでいる
  - **状態 B（未移行かつ Codex 利用）**: `AGENTS.md` が無い構成では追記先が `CLAUDE.md` になり Codex に届かない。ただしその構成では Layer 2 **全体**が Codex に届いていないため、本決定に起因する欠落ではない。移行の実施で解消する
- **両ファイルへ書く案は採らない**。全状態で到達を確保できるが、ADR-0111 が Considered Alternatives 3（両ファイルへ同一内容を複製）を「物理正本が 2 つになり複写乖離型の監視点を増やす」として不採用にしており、同 ADR が ADR-0023 Decision 1 へ入れる部分修正注記も「物理ファイルはツール到達経路として複数置いてよい。**ただし内容を持つのは正本のみ**」と定めている。この設計制約を守ることを、上記 2 状態の受容より優先する
- 未移行のプロジェクトを検知して移行を促す機構は本サイクルでは設けない。移行の契機は README の移行手順（人間向け文書。Task 6 で新設）に委ねる
- ツール列挙が開いた形になり、GitHub Copilot CLI のような列挙外のツールで作業するエージェントが、存在しない配置先を発明する誘因が減る。ただし列挙外ツールでの具体的な配置先は本サイクルでは定めない（Copilot CLI の現行仕様を再確認していないため。断定を避けた結果として、判断はその場のエージェントとユーザーに残る）
- 計画本文の同期が必要になる。影響は Task 4 の Step 2・Step 3・Step 4・Step 5・Step 6・Step 8 と前文、**および未実施の Task 5 Step 1・Task 9 Step 12・Task 11 Step 7** に及ぶ（後者 3 つは旧表現のまま実施すると Task 4 の成果物と食い違う表現をリポジトリへ持ち込む）。設計 spec 側の該当記述（二段フォールバック句の引用と過剰適合点検ブロック）も同時に同期する
- ADR-0111 の Decision 節は二段フォールバック句を旧表現（`AGENTS.md（記載が無ければ CLAUDE.md）`）で記録しているが、**本 ADR はそれを書き換えず、句の精密化として上書きする**。ADR-0111 が述べた設計意図（「ファイルの有無ではなく調整値の記載の有無で探索する」）は変わっておらず、本 ADR はその意図を文面が満たすよう表現を直したものである。実装・計画・spec の正本は本 ADR の表現に従う
- Task 4 における計画からの逸脱は 4 点になった。仕様適合レビューの判定対象（「逸脱が承認済みの N 点に限られるか」）はそのぶん広がる。ADR-0113 が定めた採用基準 (i)(ii) は生成器の入力ガードに固有の基準であり、本 ADR の判断はそれとは別に、「規範文書の欠陥は実行による安全網が無く数サイクル後まで潜伏する」という性質に基づく
- 同種の見落とし（書き込み点を単純改名として扱う、列挙を閉じる、条件節の目的語を前方参照にする）が Task 5 以降の中立化タスクにも潜在しうる。Task 5（`docs/overview` の 8 番目の二段フォールバック箇所を含む）では本 ADR の 4 点を先に適用した形で実装する
