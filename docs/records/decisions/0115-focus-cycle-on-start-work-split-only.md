# ADR-0115: start-work 責務過多の解消サイクルは分割の実施に集中し、SKILL.md サイズ・分割の一般規範は扱わない

- **Status**: Accepted
- **Date**: 2026-08-28

## Context

start-work スキルが責務過多ではないかという指摘を受け、分析を実施した（2026-08-28）。実測では `skills/start-work/SKILL.md` は 34.7KB で全 13 スキル中最大。バイト実測で本文の約 49% を「確定前レビューの提示規則」、約 12% を「完了処理のマージ方式確認」が占め、オーケストレーション以外のドメイン規範の正本 2 つがファイルの約 6 割を構成している。start-work は毎セッション冒頭で全文読み込まれるため、確定点に到達しないセッションでもこの分のコンテキスト費用が発生する。同型の偏りは既に実測・起票されている（Issue-0105。SKILL.md のサイズ・分割規範が無いという一般課題）。

分割の実施と同時に、肥大を将来検知・抑止する一般規範（目安値・分割単位・移設手順）まで設計するかがスコープの分岐となった。

## Considered Alternatives

1. **start-work の分割に集中し、一般規範は扱わない（採用）**: 本サイクルの分割作業自体が「分割の実例」となり、一般規範は実例を根拠に後続サイクルで設計できる
2. **分割＋最小限のサイズ規範（目安値のみ）の同時導入**: 検知は早まるが、規範の根拠が start-work 1 例に偏る
3. **分割＋分割規範一式の導入（Issue-0105 を close まで）**: サイクル規模が大きくなり、新設規範の評価可能性・過剰適合点検の負担も増える。根拠の偏りは案 2 と同じ

## Decision

本サイクルは start-work の責務分割の実施に集中し、SKILL.md のサイズ・分割に関する一般規範の設計は行わない。Issue-0105 は open のまま、本サイクルの分割実例を検討状況へ追記する。

条件発火の手順・規範を references フォルダへ分割する手法の適用範囲も、本サイクルで改修対象となるスキル（start-work・pre-finalization-review）に限定する。他の肥大スキル（session-handoff・decision-log 等）への横展開は、本サイクルの実例を根拠に後続サイクルで判断する。

単一プロジェクト・単一事例の教訓を無条件の一般規範へ昇格させない（過剰適合点検の「出所の偏り」観点）ことと整合させるためである。

## Consequences

- 本サイクルの変更範囲が限定され、レビュー・検証の対象が絞られる
- 他スキルの肥大（session-handoff 30.8KB・decision-log 26.8KB）は本サイクルでは解消されない
- 一般規範の設計材料（分割の工数・効果の実測）が本サイクルから得られ、Issue-0105 の後続検討に供給される
