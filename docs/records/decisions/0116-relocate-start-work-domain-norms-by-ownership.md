# ADR-0116: start-work のドメイン規範 2 節は責務帰属で移設し、提示規則は pre-finalization-review へ・マージ方式確認は references へ移す

- **Status**: Accepted
- **Date**: 2026-08-28

## Context

start-work の本文の約 6 割を占めるドメイン規範 2 節（確定前レビューの提示規則・完了処理のマージ方式確認）を切り出すことになった（スコープは同日の別決定を参照）。移設先の設計では次の制約がある:

- 条文複写の禁止: 2 つ以上の正本ファイルに同一条文を持つ二重定義は監査で 22 行が実測され統合済みであり、分割で再導入しない。移すなら正本ごと移し、参照を張り替える
- 提示規則の現行配線は、実行スキル側（pre-finalization-review）が「提示・推奨順位の規則は start-work が正」と逆参照する構造になっている
- 完了処理を担う superpowers:finishing-a-development-branch は外部プラグインで改変できず、マージ方式確認には所有スキルが存在しない
- references フォルダ配下のファイルは既に 2 スキルで使われ、配布機構（dist 生成）でも配布実績がある

## Considered Alternatives

1. **責務帰属型 — 節ごとに所有者へ移す（採用）**: 下記 Decision のとおり
2. **一律 references 型 — 両節とも `skills/start-work/references/` へ**: 配線変更が最小だが、レビュー政策の正本がオーケストレーター配下に残る帰属のねじれが解消されない
3. **新スキル型 — 確定点提示を担うスキルを新設**: 分離は明確だが、スキル数が増え、既存の pre-finalization-review と「提示 vs 実施」で責務が隣接して境界説明が新たに必要になる
4. （分割対象の範囲について）提示規則のみ切り出す案、インラインフォールバックを含む 3 節すべてを切り出す案も検討した。前者はマージ方式確認（約 12%）が残り、後者はフォールバック（約 3%・superpowers 不在時の縮退ナビゲーション）が起点スキルの責務の一部であるため、2 節の切り出しを採った
5. （境界の明文化について）CONTRIBUTING.md の既存チェックリスト項目の文言拡張のみで済ませる案も検討した。しかし CONTRIBUTING の拡張フローを経ない微修正が既存スキルへの追記として肥大を積み上げた実測（Issue-0105）があり、追記者が編集中のファイル内で境界を読める本文宣言を併設しないと文言拡張だけでは届かない経路が残るため、両方を採った（新設の評価可能性の「既存工程の文言拡張・リスク受容で足りないか」の比較）

## Decision

節ごとに責務の所有者へ移設する:

1. **確定前レビューの提示規則 → pre-finalization-review スキルへ移設する**。同スキルに「確定点での提示」操作を追加し（操作分化の型）、提示・推奨順位・反復・停止判定の正本と実行手順を 1 スキルに揃える。start-work は確定点で同スキルを呼ぶポインタのみを持つ。これにより実行スキルから起点スキルへの逆参照が解消される
2. **完了処理のマージ方式確認 → `skills/start-work/references/` 配下へ移設する**。所有スキルが存在しないため起点スキルの配下に留め、完了処理の直前にのみ読む遅延読み込みとする
3. **移設は正本の引っ越しとして行う**。条文は移設先にのみ置き、start-work 側および他スキルの参照は移設先を指すよう張り替える。条文の複写は行わない
4. **改修対象スキルの内部でも、条件発火の手順・規範は references 配下への分割を許す**。毎回読む必要のない条文を SKILL.md 本文から外し、発火時にのみ読む構造とする。ただし本サイクルでは pre-finalization-review への内部分割は適用しない（無改変移設の diff 検証を優先し、肥大が問題化した時の受け皿として残す）
5. **移設後の責務境界を明文化する**。start-work 本文に「正本として持つのはオーケストレーションのみ。ドメイン規範の正本は所有スキルまたは references へ置き、本文にはポインタのみ」の境界宣言を、pre-finalization-review 本文に「確定点の定義・提示・推奨順位・反復・停止判定・実施方式の正本は本スキル」の管轄宣言を置く。CONTRIBUTING.md の start-work シナリオは、既存チェックリスト項目「フェーズの責務分離が崩れていないか」の文言拡張で対応し、新規チェックリスト項目は追加しない

境界宣言・管轄宣言は拘束的な文の新規追加（新設）にあたるため、評価可能性を次のとおり定める。期待検出量: start-work または pre-finalization-review へ規範を追加する改定サイクルごとに配置判断（本文へ書くか正本側へ書くか）1 回以上の発火を見込み、当該改定の ADR・handoff 消化記録で計数する。退役条件: SKILL.md のサイズ・分割の一般規範が導入され本宣言の内容がそちらに包含されたことが確認された時点で退役する（包含されないまま宣言だけが残り続ける場合は存置が正であり、退役側ではない）。

## Consequences

- start-work の SKILL.md からドメイン規範の正本が消え、毎セッションの読み込みがオーケストレーションとポインタに絞られる
- pre-finalization-review の管轄は増えるが、読み込みは確定点到達時・実施時に限られる。肥大が問題になる場合は Decision 4 の内部分割で受ける
- 参照配線の張り替えが必要になる（session-handoff・decision-log・feature-block-design・retrospective・pre-finalization-review・現用 spec・README ほか、start-work の節を指している全参照。AGENTS.md は実測で節名参照なしのため対象外）
- 正本所在の変更にあたるため、所在を定めた既存決定への部分修正注記を実装時に追記する。対象は実装計画の作成時に導入 ADR を全数走査して確定する（レビューで判明している分: ADR-0067・0072・0080・0091・0092・0105・0106・0107）
- 旧設計仕様書と現行 SKILL.md の乖離（Issue-0101）は本改修でさらに広がる。同課題の扱いは変えない（open のまま）
- 配布対象ソースの変更であり、執行点 4 手順と plugin version bump の対象になる
