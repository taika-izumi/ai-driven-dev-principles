# ADR-0118: LoopForAlpha のレビュー関連 flow 課題 4 件を一括委譲し、Issue-0110 対策設計と同一サイクルで扱う

- **Status**: Accepted
- **Date**: 2026-08-30

## Context

前提実在観点サイクル（ADR-0117）完了後の次サイクルテーマとして Issue-0110（確定済み計画からの逸脱判断に既定が無い）を選定した。着手にあたりユーザーから、LoopForAlpha プロジェクトに flow 型 Issue として蓄積された過去のレビュー時の記録を、まず本リポジトリへ委譲することから検討したいとの指示があった。

調査の結果、LoopForAlpha 側にはレビュー関連の open な flow 型 Issue が 4 件あり、いずれも「規範の正本はガイドライン配信元リポジトリにあり、対策の設計はガイドライン repo 側が受ける」と明記されている:

- **LoopForAlpha#Issue-0109**（約 40KB）: 確定前レビューの反復規範が状況の実測を無視して推奨を決める。乖離事例 8 件＋横断観測 2 組。本リポジトリの Issue-0107 が受け皿として「将来こちらへ移譲される予定」と明記済み（移譲は未着手）
- **LoopForAlpha#Issue-0117**（約 86KB）: レビュー・品質投資の限界効用の実測。軸 1（レビュー工程）の集計・コスト実測完了、既定の層別再設計は未着手。本リポジトリの Issue-0103（反復のコスト予算）が隣接
- **LoopForAlpha#Issue-0096**（約 51KB）: 実装工程 2 型（タスク別独立レビュー往復 / 確定前レビューへの前倒し）の使い分け基準。「実装が計画コードから逸脱したら格下げ」の安全弁など Issue-0110 の主題に直結する観測を含む
- **LoopForAlpha#Issue-0043**（2.6KB）: 多層レビュー（5 層）の役割分担指針の未明文化。「ガイドライン repo への申し送り候補」と明記されたまま申し送り未了・受け皿なし

4 件は相互参照し合うクラスタである（0117 が 0096 を集計材料に使い、0109 と 0117 軸 1 は主題が隣接）。なお同クラスタの LoopForAlpha#Issue-0125 は前サイクルで還流済み（ADR-0117）。

## Considered Alternatives

1. **レビュー関連 4 件（0043 / 0096 / 0109 / 0117）を一括で委譲対象とし、brainstorming で受け皿設計と Issue-0110 対策への接続を検討する（採用）** — 4 件は一体のクラスタであり、受け皿の設計判断が一度で済む。Issue-0110 の対策設計に全件が材料になる
2. **受け皿が予定済みの LoopForAlpha#Issue-0109 のみ先に移譲し、他は今回スコープ外** — 最小スコープだが、LoopForAlpha#Issue-0117 の定量データ（層別実測・コスト実測）を使わずに Issue-0110 の設計をすることになる
3. **委譲（記録の移設）だけを今回サイクルとし、Issue-0110 の対策設計は次サイクルへ分離** — サイクルは軽くなるが、委譲した記録の受け皿設計と対策設計が別サイクルに割れ、同じ材料を二度読み込むことになる

## Decision

案 1 を採用する。本サイクル（feature/review-records-reflux）のスコープを次の 2 段とする:

1. LoopForAlpha のレビュー関連 flow 課題 4 件（0043 / 0096 / 0109 / 0117）の記録を本リポジトリへ一括委譲する
2. 委譲した記録を精読したうえで、Issue-0110（確定済み計画からの逸脱判断の既定）の対策設計へ接続し、対策の実装（規範改定が確定した場合はスキル改定・version bump・執行点手順を含む）まで本サイクルで行う

選定理由: 4 件は相互参照し合う一体のクラスタで、分割して委譲すると受け皿の設計判断と材料の読み込みが複数サイクルに重複する。Issue-0110 の対策（採用基準の計画側への先置き等）は LoopForAlpha#Issue-0096 の工程型使い分け観測・LoopForAlpha#Issue-0117 の層別実測を直接の判断材料にできるため、委譲と対策設計を同一サイクルで扱うのが最も判断の重複が少ない。

委譲の実施方式（brainstorming で確定）:

- **委譲形態**: 全文コピーで取り込み、以後は本リポジトリ側を正本とする。LoopForAlpha 側の原本は残す（要約統合・物理移設は不採用。要約統合は対策設計時に毎回 LoopForAlpha リポジトリを読みに行くことになり、物理移設は LoopForAlpha 側 retrospective からの参照を壊すため）
- **受け皿の対応付け**: 統合 1 件＋新設 3 件。LoopForAlpha#Issue-0109 → Issue-0107 へ統合（0107 に明記済みの移譲予定どおり）。LoopForAlpha#Issue-0043 → Issue-0112（新設・単独ファイル）、LoopForAlpha#Issue-0096 → Issue-0113（新設・フォルダ形式）、LoopForAlpha#Issue-0117 → Issue-0114（新設・フォルダ形式。Issue-0103 と相互参照）。各課題が「後から探しに来るときの問い」1 つに答える粒度を保つため、射程の異なる課題同士の統合（例: LoopForAlpha#Issue-0117 → Issue-0103）は不採用
- **コピーの体裁**: 原本ファイルは本文を改変せず全文コピーし、`lfa-` 接頭辞と出所ヘッダ（LoopForAlpha 側番号を指す旨）を付す。番号衝突（両リポジトリに同番号の課題が実在）への対処
- **LoopForAlpha 側の状態遷移**: 4 課題へ「委譲済み・以後の正本はガイドライン repo」を追記し open 維持（LoopForAlpha 側の新観測の追記先として残す。close は対策実装後に効果を確認できた時点）
- **工程構成**: 二段構え。委譲を先に実施し、材料を精読してから Issue-0110 対策を設計する（委譲前の一括設計は「実体を読まずに要約から設計する」LoopForAlpha#Issue-0125 の再演になるため不採用）

## Consequences

- 本サイクルの作業量は委譲 4 件（合計約 180KB の記録の整理・受け皿配置）＋対策設計となり、前サイクルより大きくなる可能性がある。brainstorming で扱う範囲を段階分けする余地は残す（スコープの再分割が必要になった場合は本 ADR の見直しを提起する）
- 本リポジトリの Issue-0107（LoopForAlpha#Issue-0109 の受け皿）・Issue-0103（コスト予算）は委譲内容の統合先候補となり、内容が大きく更新される見込み
- LoopForAlpha 側の 4 課題は、委譲完了時に「ガイドライン repo へ委譲済み」の状態遷移が必要になる（LoopForAlpha 側の更新方法・クローズ判断はユーザーと確認する）
- 委譲された定量データ（乖離事例・層別実測・コスト実測）が本リポジトリの規範改定（Issue-0110 / 0107 / 0103 系）の共通の実証基盤になる
