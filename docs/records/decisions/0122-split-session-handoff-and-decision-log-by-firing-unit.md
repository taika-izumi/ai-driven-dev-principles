# ADR-0122: session-handoff と decision-log は発火単位で references へ分割し、SKILL.md 本文を共通部とディスパッチ表に絞る

- **Status**: Proposed
- **Date**: 2026-09-01

## Context

Issue-0115 / Issue-0116: ADR-0121 が導入したサイズ警告の目安値 20KB に対し、`skills/session-handoff/SKILL.md` は 31,169B、`skills/decision-log/SKILL.md` は 26,837B である（2026-09-01 実測）。ADR-0121 決定 5 は中核スキルの参照配線の張り替え規模を理由に本 2 件の分割実施を次サイクル以降へ送り、例外テーブルへ分割待ちの暫定行として登録した。本 ADR はその残余を処理する。

各行の値は節の先頭見出し行から次の見出し行の直前までの UTF-8 バイト数であり、節末の改行 1 バイトを含まない。ファイル末尾の節（次の見出し行を持たない節）も同様に、ファイル自体の末尾改行 1 バイトを含まない。したがって行の合計はファイル総量より節数ぶん小さくなる（session-handoff は 19 節で 31,150 対 31,169、decision-log は 23 節で 26,814 対 26,837）。

発火構造の観察: **両スキルとも、呼び出し時点で必要な内容が確定している**。session-handoff は操作名（read / create / update / finalize / cycle-reset）が引数として渡され、1 回の呼び出しで 1 操作しか使わない。decision-log は用途（新規ドラフト作成 / 未決事項の課題起票 / ステータス変更 / Accepted 昇格）が起動契機の側で決まる。したがって条件発火の単位は「操作・用途」であり、これに直交して複数の操作から共用される横断規範（`review=` の値定義・独立手順「移設」・節別の記載規範）が第 2 の単位として存在する。

制約:

- **条文複写の禁止**（ADR-0116 決定 3）。二重定義 22 行の統合実測（Issue-0093）があり、分割は条文複写の再導入リスクと隣り合わせである
- **条件発火節に限る**（ADR-0121 決定 4 ②）。発火時に毎回必要な内容の退避は認めない
- **参照のたどり損ないリスク**。ADR-0121 Consequences が pre-finalization-review 分割で新たに持つリスクとして名指しした型であり、本件は分割ファイル数がそれより多い
- session-handoff は Post ラッパーで毎マイルストーン読まれるため、肥大がセッションのコンテキスト費用へ反復的に効く（Issue-0105 の起票理由）

## Considered Alternatives

1. **発火単位で完全分割（採用）**: 操作・用途と横断規範の両方を references へ出し、本文を共通部＋ディスパッチ表に絞る。下記 Decision のとおり
2. **操作・用途の単位のみ分割（横断規範は本文残留）**: session-handoff 本文 約 19.6KB・decision-log 本文 約 12.9KB。update 経路の実読み込みは 23.8KB（現行比 −24%）にとどまり、かつ session-handoff の本文が閾値 20KB の直下に張り付く。分割サイクルの直後に次の追記で再び分割判断を強いられる状態を残すため不採用
3. **横断規範のみ分割（操作は本文残留）**: session-handoff 本文 約 19.4KB・update 経路 26.3KB（現行比 −16%）。最頻経路の削減が最小で、決定 1 の完了条件に最も合わない。不採用
4. **（完了条件について）本文 20KB 以下のみを条件とする案**: ADR-0121 の警告条件を満たすことだけを条件にすると、条件発火に当たらない内容を references へ動かしただけで実質改善がゼロの分割（発火のたびに結局全部読む形）が完了判定を通る。ADR-0121 決定 4 ② の「毎回必要な内容の退避は認めない」を測れる形にするため、最頻経路の実読み込み量を完了条件へ加えた（ユーザー決定 2026-09-01）
5. **（分割判断の型について）① 責務帰属型を適用して `review=` の終了状態 4 値を pre-finalization-review の `references/iteration-norms.md` へ移す案**: `実質収束` の判定は同スキルの停止判定であり、`フル実施` / `差分再確認` の語彙も同スキルの「フル巡 / 差分確認巡」の歴史的別名である。しかし `review=` は handoff の消化記録フィールドの値定義であり、記録媒体を所有する session-handoff が正本であるのが自然で、現行は既に判定規範側を参照で外出ししている。分けると条文が 2 ファイルへ割れて二重定義リスク（Issue-0093 の実測型）が増える。不採用（ユーザー決定 2026-09-01）
6. **（スコープについて）1 スキルずつ 2 サイクルに分ける案**: session-handoff は読み込み頻度が最も高く単独でも成果が出る。しかし両スキルは同一の分割方針を共有し、参照の張り替えも同じ現役文書群（start-work・CONTRIBUTING・pre-finalization-review ほか）に集中するため、2 サイクルに割ると同じ文書を 2 度開くことになる。1 サイクルで両方を扱う（ユーザー決定 2026-09-01）
7. **（例外テーブルについて）分割後も暫定行を承認済みサイズを更新して残す案**: 分割後の本文は目安値を大きく下回るため、行を残すと「承認済みサイズ以下は警告しない」規律により本来発火すべき成長まで沈黙する。行は削除する

## Decision

1. **完了条件（本サイクル限りの適用）**: 次の 2 つをともに満たしたときに分割完了とする。(a) 両スキルの `SKILL.md` 本文が目安値 20KB を下回る。(b) 最頻経路の 1 回あたり実読み込み量（`SKILL.md` 本文＋当該経路で読む references の合計バイト数）が現行比で半減する。最頻経路は session-handoff が **`update` の素経路**（消化記録行の追記と完了・進行中タスクの更新のみを行う経路。確定点の `review=` 記入・節別の記載規範の参照・移設判定を伴わないもの）、decision-log が新規ドラフト作成とする。**update が節別の記載規範と移設判定（種類別対応表）を伴う経路は 16.8KB＝現行の 54%、移設の実行まで伴う経路は 19.3KB＝62% にとどまり半減しない。これは明示的に受容する**（当該 3 節はいずれも書き分けの判断に実際に必要で、退避すれば ADR-0121 決定 4 ② の「毎回必要な内容の退避は認めない」に触れるため）。「半減」に先行する数値根拠は無く（ADR-0121 決定 4 ② は定性規範のみで数値を持たない）、本サイクル限りのユーザー受容値である。**本条件は本サイクルの分割の完了判定に用いるものであり、今後の分割一般に課す規範として新設しない**（一般化の当否は実測が 1 サイクル分しかないため本サイクルでは判断しない）
2. **① 責務帰属型は「該当なし」と判定する**: 節ごとの判定は次のとおり。session-handoff 側——独立手順「移設」と節別の記載規範は handoff という記録媒体そのものの規範で所有者は自スキル、`review=` の値定義は唯一の他スキル候補だが Considered Alternatives 5 のとおり session-handoff 所有を維持する。decision-log 側——サイクル全体整合検査・ステータス変更・承認の昇格は ADR の状態遷移を所有する自スキルの責務であり、未決事項の課題起票は正本が非配布のプロジェクト文書（`docs/overview/issue-management.md`）でスキル側にフォールバックつきで置く現行が正しく、いずれも移設先となる他スキルが存在しない。よって ADR-0121 決定 4 の ①→②→③ のうち **② references 型**を採る
3. **分割の軸は「発火単位」とする**: 条件発火の単位を (i) 操作・用途 と (ii) 複数の操作から共用される横断規範 の 2 系統とし、両方を `references/` 配下へ出す。`SKILL.md` 本文には全操作・全用途で必要な共通部と、**発火単位から参照先ファイルを一意に引けるディスパッチ表**のみを残す。**本サイクルで分割する 2 スキルについては**、各操作の節サイズの大小にかかわらず**全操作を例外なく references へ出す**（1 操作だけ本文に残すとディスパッチ規則が不規則になり、たどり損ないを増やすため。size の節約より規則の一様さを採る）。**この一様性は本サイクルの 2 スキルへの適用判断であり、今後の分割一般に課す規範として新設しない**（決定 1 と同じ理由。一般化するなら CONTRIBUTING.md の共通節へ書き足したうえで過剰適合点検と評価可能性の対象になるが、実測が本サイクルの 1 件しかないため本サイクルでは行わない）
4. **session-handoff の分割構成**: 本文（約 7KB）に残すのは 前文・ファイル配置・ハンドオフファイルのフォーマット・Status の意味・外部参照の書き方・「本サイクル」の定義・操作ディスパッチ表（現「## 操作」節の導入文を含む）・完了済みハンドオフの扱い・対応する原則。`references/` へ移すのは次の 9 ファイル:
   - `op-read.md` / `op-create.md` / `op-update.md` / `op-finalize.md` / `op-cycle-reset.md`（操作 5 種）
   - `relocation-map.md`（独立手順「移設」の導入と種類別対応表）と `relocation-procedure.md`（同手順 1〜6）——**対応表と手順を分けるのは、対応表を「書き分けの判定材料」として読む経路と、手順が実際に走る経路が一致しないため**（決定 3 の発火単位を実体の参照関係に合わせた結果）。実体の内訳: 対応表を判定材料として参照するのは update 手順 4・finalize 手順 4・cycle-reset 手順 2・節別の記載規範の 4 経路（本文 139 行が前 3 者のうち update・節別の記載規範・finalize を、251 行が cycle-reset を示す）。対して手順が走る起点は finalize の圧縮前段・read でユーザーが受諾した時・cycle-reset の申し送り現役性点検の前段の 3 起点に限られ（本文 133〜137 行）、いずれも「実際に記述を正本へ移す場合」であって、そのとき**起点を問わず手順 3〜6 に従う**（本文 139 行）。判定だけを行って移設に至らない経路が存在する一方、手順が走る経路は必ず対応表の判定を通る。両者の発火は包含関係にあって一致しない（最頻経路である素経路は決定 1 の定義どおり対応表も手順も読まない）。したがって**移設判定にとどまる経路は対応表のみ、移設を実行する経路は両方**を読む
   - `review-field-values.md`（`review=` の値定義）
   - `section-volume-norms.md`（節別の記載規範）

   本文残留の「ハンドオフファイルのフォーマット」節は `review=` の書式例（`フル実施（モデル・N 巡）` 等の具体値）を含み、その語彙の完全な定義は `review-field-values.md` へ移る。この跨りは受容し、**変更時の同期対象として実装計画に列挙する**（ADR-0121 決定 5 が 4 観点の名称列挙で採ったのと同じ扱い）
5. **decision-log の分割構成**: 本文（約 3.4KB）に残すのは 前文・検出トリガー一覧（強トリガー・弱トリガー・意思決定を伴わない起動契機・呼ぶ必要がない場面）・用途ディスパッチ表。`references/` へ移すのは次の 4 ファイル:
   - `adr-authoring.md`（ADR 作成手順 0〜4・Proposed の ADR へ決定を追記するとき・ユーザーへの確認）
   - `open-questions.md`（未決事項（open questions）の扱い）
   - `status-updates.md`（終端ステータスの意味境界・ステータス変更・承認の昇格）
   - `cycle-consistency-check.md`（サイクル全体整合検査）
6. **参照の張り替えは現役文書に限る**: 移設対象節を名指しする参照を実装計画の作成時に全数走査し、(a) 本文から移設先への参照 (b) 移設先から本文残留部への参照 (c) 移設先どうしの相互参照 (d) 他スキル・CONTRIBUTING.md・現用 spec からの外部参照 (e) 移設対象を記載箇所として名指しする ADR、を張り替えまたは部分修正注記する。**(a) の走査対象にはコードフェンス内の地の文を含める**（フォーマット節のテンプレート内に「`review=` の値の定義は本ファイルの…節を参照」という相対参照が実在し、分割後は「本ファイル」が偽になる。書式例と誤認して素通りしやすい）。**(d) の対象には他スキル・CONTRIBUTING.md・現用 spec に加えて README ほかの一般プロジェクト文書を含める**（ADR-0116 Consequences が張り替え対象に README を数えた先例。実測: `README.md` 38 行のスキル一覧が「独立手順「移設」」を名指ししている）。判明分——(d): `start-work`（read / create / update / finalize の 4 操作 4 箇所。cycle-reset の呼び出しは持たない）・`retrospective`（cycle-reset）・`worklog-record`（update の消化記録手順）・`pre-finalization-review`（SKILL.md 3 箇所のうち移設対象を指すのは 2 箇所、および `references/iteration-norms.md`・`references/review-procedure.md`）・`session-handoff` と `decision-log` の相互参照・`CONTRIBUTING.md`（節名を指す 7 行）・`README.md`（1 行）。現用 spec は実装計画の走査で確定する。(e): 節名の文字列一致で候補 26 件（0019/0025/0028/0041/0042/0056/0059/0060/0075/0080/0086/0088/0091/0092/0095/0096/0099/0100/0102/0103/0105/0107/0108/0109/0111/0121）。記載箇所としての名指しか否かの判別は実装計画の走査で行う。判明分の各件数は実装計画の全数走査で実測へ更新する。

   あわせて、本サイクルの実務として次の 2 種も走査する（(a)〜(e) と同じく本サイクル限りの実務であり、将来の全分割へ課す規範ではない。ADR-0121 の実装サイクルが「5 方向の全数走査」を一般規範として CONTRIBUTING へ置くのを撤回し、当該サイクルの ADR にとどめた判断と同じ扱い）。

   **(f) 分割によって新たに必要になる参照の新設**——同一ファイル内にあるがゆえに明示の参照を持たずに済んでいた依存は、既存参照の grep では検出できない（「まだ書かれていないもの」を探す作業になるため）。**完了基準: 分割後の 13 ファイルそれぞれについて、そのファイル単独では意味が確定しない語・手順・数値を列挙し、結果（空を含む）を実装計画へ 1 行ずつ書き出す。** 判明分 2 件: (1) `review-field-values.md` へ移る「巡数・終了状態は消化記録の値限定の『判定結果』に含まれる」が用いる「判定結果」の定義は `section-volume-norms.md` へ移る側にある。(2) `op-update.md` は移設を実行する場合に `relocation-procedure.md` の手順 6（update 起点の移設も handoff と同じコミットに含める規定）を要するが、現行の update 手順 4 は対応表への参照しか持たない。

   **(g) 移設対象節どうしで重複している条文の一本化**——正本側の 1 箇所へ残し他方を参照へ置き換える（同一ファイル内の重複は分割で別ファイル間の条文複写になり、ADR-0116 決定 3 と CONTRIBUTING.md の条文複写禁止に触れる。両者が禁じるのは「移設・分割という行為が複写を生むこと」であり、本項はその射程内）。判明分 2 クラスタ: **200 字上限クラスタ**——「1 行 200 字以内・各フィールド値は『判定結果＋安定識別子＋正本への参照』に限定」が節別の記載規範と操作 3 update に逐語で重複し、さらに「200 字」という数値自体が 3 箇所（`review=` の値定義の縮退規定・節別の記載規範・操作 3 update）へ分散するため、数値定数は正本 1 箇所に置き他は参照とする（ADR-0121 決定 5 が「（4 巡）」の数値直書きに課したのと同じ処理）。**git 履歴クラスタ**——同趣旨が 4 箇所（節別の記載規範・操作 4 finalize・操作 5 cycle-reset・完了済みハンドオフの扱い）にあり、最も近いのは操作 4 finalize（本文 226 行）と完了済みハンドオフの扱い（本文 259 行）で、共通部分「落とした情報の受け皿は git 履歴のみと」が一致する（語尾と後続節が異なるため完全な逐語一致ではない。後者は本文残留のため分割後は本文と references をまたぐ複写になる）。一本化では、節別の記載規範側の「圧縮・削除の実施記録を handoff に残さない」と finalize 側の「退避ファイルは作らない」が別の規定である点を保つこと。

   **確定後不変の記録類（retrospective・過去 plan・確定済み ADR の経緯記述）と旧 spec の独立したポインタは壊れを許容する**（ADR-0121 決定 5 と同じ実務）。open 課題は出所の名指しに限り必要に応じて現状へ合わせる
7. **例外テーブルの暫定行 2 件を削除する**: `scripts/build-dist.ps1` の例外テーブルから session-handoff・decision-log の行を削除し、両スキルを通常の目安値判定へ戻す。Issue-0115 / Issue-0116 は本 ADR の Accepted 昇格時に close する
