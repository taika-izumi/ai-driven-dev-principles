# ADR-0124: 確定前レビューの方式と人数は状況から推奨し、実施・見送りはユーザー判断に残す

- **Status**: Proposed
- **Date**: 2026-09-05

## Context

Issue-0107 の一次記録では、改訂に規範文が含まれることだけで全体レビューを推奨し続け、直前の修正の確認に適した差分再確認を選ぶために利用者の介入が必要になった。事例1・4〜6・14は確認範囲を絞る便益を示す一方、移譲資料の事例7は差分外の上流仕様との矛盾を見逃しており、軽い方式の一律適用も支持しない。

同課題の事例2・7・8では、追加するものの必要性を区別しない設計縮小の推奨も不適切だった。Issue-0124 は追加する仕組みの費用評価を求めているが、その判断は ADR-0125 へ分ける。

「恒久資産の規範文書は独立レビュー最低1回」を必須化すると、ADR-0072 の実施判断が変わる。ユーザーは2026-09-05に強い推奨と見送り権の維持を承認し、続けて状況による方式・人数の選択、歯止め、上流条件の照合、短い提示を承認した。

## Considered Alternatives

- 現行の形式条件へ例外を追加する。既存の推奨を補正できるが、事例ごとの条件追加と説明が増え、判断が規則の分類へ引かれる原因が残る。
- 状況から推奨し、初回の強い推奨・迷った場合の慎重な選択・増設と回数の注意喚起を残す。推奨の適合性を改善できるが、AIの判断が過小なレビューを選ぶ可能性は残る。
- 最低1回を必須化する、または回数上限で終了させる。費用や確認機会を固定できるが、利用者の判断を制限し、後半のレビューが欠陥を検出した対抗事例を取り逃す。

## Decision

1. 未レビューの規範文書の変更では独立レビュー最低1回を強く推奨する。実施・見送りはユーザー判断に残し、自動必須化しない。初回推奨の対象・誤記等の除外・レビュー済み上流の扱い・記録不明時の扱いは現行規範の範囲を引き継ぐ。
2. 全体レビューの4観点、1〜4体の担当、差分再確認1体、機械検証の既存方式を維持する。初回・反復とも、未確認範囲、変更の影響、直近の指摘の由来、残る懸念を確認できる方法を材料に方式・人数を推奨する。新規規範文の有無や成果物の型だけで方式・人数を固定しない。判断に迷う場合は懸念の確認範囲を広く取る側を推奨し、迷いを説明する。
3. 増設を含む改訂が2回連続したときの歯止めは、必要性と縮小余地の点検として残す。必要な検査の追加、既存要求の充足、追加物が自ら生む問題を区別し、具体的な縮小案が合理的な場合に縮小を推奨する。計数だけで削減の推奨を作らない。通常4回・規範改定8回の注意喚起と続行目的の明示を維持し、回数上限は設けない。
4. 差分再確認へ渡す対象には、改訂箇所と対応表に加え、変更の影響を受ける上流の条件・限定列挙・完了基準を含める。対象の上流条件と確認箇所を委譲時に示す。上流を含めて範囲を確定できない場合は、その不確実性を全体レビュー側の判断材料にする。
5. 推奨理由と最も強い反対材料を1〜2文で示す。材料が無い場合はその旨と確認した出所を簡潔に示す。初回の未レビュー範囲、方式・人数、反復の指摘採否、注意喚起発火時の回数・続行目的は既存の判断に必要な情報として残し、同じ説明を重複させない。

方式を状況で選ぶ規定は決定1の初回の強い推奨を解除しない。初回の強い推奨を満たした後の反復で、規範文の有無だけによる全体レビューの固定推奨を解除する。人数は初回・反復とも状況から判断する。

本決定は ADR-0072 の実施判断を維持する。既存の停止条件、改訂前退避、レビュアーの独立性と継続利用条件、記録形式を変更しない。推奨を決めるための形式分類は判断材料とし、停止・継続利用を判定する既存条件とは区別する。新しいレビュー工程・記録形式は設けない。

既存決定との関係: ADR-0080 の提示、ADR-0107 の推奨と差分再確認、ADR-0120 の初回人数の既定を部分修正する。各ADRのそれ以外の決定は維持し、全部置換は行わない。

## Consequences

- 利用者が規則と別にAI自身の判断を聞き直す往復を減らせる。
- 方式・人数の判断のばらつきや、見送り・狭い範囲のレビューによる取り逃しは残る。短い反対材料の提示と、上流条件を含む対象設定で判断を支えるが、網羅性を保証しない。
- 回数・状態の記録は既存手順を利用するため、今回専用の監視や採点表の維持費は生じない。
- 設計と実装の整合を検証するまで Proposed に据え置く。具体的な仕様と過剰適合点検は `docs/current/specs/2026-08-05-dispatch-and-pre-review-skills-design.md` を参照する。

## 評価可能性

導入後3サイクルの既存の計画・課題ログ・指摘対応表・ADRから、方式・人数の判断や差分再確認の上流条件を復元できる事例を数える。少なくとも1件の適用機会を見込み、固定推奨と状況判断の乖離、改訂による上流条件違反の捕捉を期待する。全適用機会を網羅する計数ではなく、評価時には復元できた範囲を示す。自動監視・追加の全件台帳・評価専用の必須保存項目は設けない。

ユーザーが評価を指示した時点で既存記録を確認する。復元できた適用事例で上流確認の明示が既存の照合と全件重複し、固有の欠陥検出がなく、記載負担だけが増えた場合は同義務の簡素化・廃止を候補にする。状況判断による見逃しが観測された場合は判断材料の改良側とする。記録にない事例の便益をゼロと推定せず、廃止条件を判定する情報が不足する場合は保留する。機会不足・記録不足を不要の根拠にしない。
