# ADR-0129: 判断観点の設計はAIの軽い概算を通常とし、見積もり専用の会話を増やさない

- **Status**: Accepted
- **Date**: 2026-09-06

## Context

Issue-0126で品質条件と費用を判断観点として整理したところ、ユーザーは、各項目の厳密な試算やデータ収集が毎回必要になることを懸念した。その時点のAIの感覚的な概算でよく、1応答程度で収まる試算は許容するが、見積もりのために何度も会話するのは本末転倒になると説明した。AIが示した軽い概算を通常とする整理を踏まえて、作業を進めるよう指示した。

## Considered Alternatives

- 毎回、品質条件と費用を測定・数値化して比較する。比較資料は揃うが、判断を変えない情報の収集や確認会話が増える。
- 手元の情報による定性的な概算を通常とし、判断を左右する不明点がある場合だけ追加確認・調査を提案する。見積もりの不確実性は残るが、ユーザーの求める検討負担に合う。

## Decision

Issue-0126の設計では後者を前提とする。通常はAIが手元の要求・文脈・既存資料から一度の応答内で概算し、厳密な数値、全項目の記入、測定用データの収集、見積もり専用の複数ターンの聞き取りを既定にしない。1応答程度で可能かつ判断に役立つ試算は行ってよい。

品質条件は既知の要求から読み取り、毎回の再定義・再承認は求めない。選択を左右する不明点がある場合だけ必要な確認・調査を提案する。推定は実測と区別し、成果物に必要な動作確認・要求充足の検証は見積もりの軽量化と区別する。

これは今回の設計に対するユーザー要求の記録であり、配布規範の実装確定を兼ねない。

## Consequences

- 設計要求は確定し、その具体的な規範への反映はADR-0130として2026-09-07に実装・検証した。

- 観点を設けたことが、毎回の計測・帳票・確認工程へ膨らむことを抑えられる。
- 精密な費用順位や最小費用を保証するものにはならない。概算の限界を保ったまま判断する。
- 原文の費用実測や導入効果の評価方法を、通常の判断時の必須工程へそのまま移すことはしない。
