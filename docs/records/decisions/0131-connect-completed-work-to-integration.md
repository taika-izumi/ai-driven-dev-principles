# ADR-0131: 実装完了と終了依頼を既存の統合・引き継ぎ工程へ接続する

- **Status**: Accepted
- **Date**: 2026-09-07

## Context

Issue-0128の対策。ユーザーはIssue-0128、続いてIssue-0129への着手を選択し、superpowersの指示を踏まえて妥当なら次へ進むよう指示した。追加照合と独立レビューにより既存の必須接続・表示規範との関係・終了時の条件を補正し、実装・検証を完了した。

改定前の`skills/start-work/SKILL.md`には次手提示と完了処理の案内先があったが、終了時の未マージ分岐がなかった。手順照合記録`docs/records/minutes/2026-09-07-session-workflow-gap-audit.md`のC07・C08では、実装後の統合案内が抜け、作業ブランチのpushで終了した。C03・C04は既存の次手提示規定の実行漏れであり、新規則の不足とは区別する。

既存の`merge-practice.md`は方式の判定、`finishing-a-development-branch`は統合の実行、`retrospective`はマージ後の振り返り、`session-handoff`は記録を担当する。ADR-0116の責務境界を維持して接続を補う。

### superpowersとの照合（6.3.0）

導入済みプラグインの各`skills/<skill-name>/SKILL.md`を実読した。初案時は完了スキルのみ、追加照合時は実装側2スキルと検証スキルも確認した。過去のC07・C08で実際にどの実装スキルを経たかは既存の照合記録だけでは確定できず、当時の違反箇所を推定で追加しない。

| 参照先 | 実在する指示 | 今回の設計への反映 |
|---|---|---|
| executing-plans / Step 3 | 全タスクの完了・検証後、finishing-a-development-branchを必須呼び出し | 通常経路の接続は既設。start-workが重ねて呼び出さない |
| subagent-driven-development / Final Review・Finish | 最終レビュー・残指摘の扱いを経て完了スキルを呼ぶ | テスト合格だけで最終レビューを飛ばさず、留保した指摘も引き継ぐ |
| finishing-a-development-branch / Steps 1〜5 | 統合前の検証、環境と対象ブランチの確認、環境別選択肢、選択の実行、マージ結果の再検証 | 選択肢の意味・環境分岐・停止条件は正本へ委譲。表示言語・推奨順位・質問形式は上位指示に従う。detached HEADではマージを提示しないなどの条件を維持 |
| verification-before-completion / The Gate Function | 完了宣言の前に検証を実行し結果を確認 | 実装側の完了報告や過去の合格だけで統合完了としない |

完了スキルの選択肢提示は原則必須である。承認済み選択の再質問を省くのは、ユーザーの明示指示がスキルの既定手順に優先する範囲だけであり、設定値やAIの推奨でこの例外を作らない。外部スキルが処理中、または選択を提示済みなら、その進行へ戻す。

## Considered Alternatives

1. **既存工程の文言と分岐を補う（推奨）**: superpowers実装スキルの必須接続を優先し、`start-work`ではそれを経ない完了・終了依頼と未マージ状態の扱いを補う。独立した終了スキルや台帳の導入・保守は不要。会話からの承認・残作業の読み取りには引き続き依存する。
2. **Gitフックや終了スクリプトで統合まで自動化する**: 機械的な未マージ判定は可能だが、調査完了・作業中断・統合の承認をGit状態だけで判定できない。現行リポジトリの追跡対象に該当フック・ワークフローはなく、`core.hooksPath`も未設定。別の状態入力と維持が必要になる。版更新の検査は独立に検討できるためIssue-0129へ引き継ぐ。
3. **現状の案内規定の遵守だけで対処する**: 追加費用は最小でC03・C04には適切。ただしC08の未マージ分岐は定義されないまま残り、利用者が終了範囲を補う負担を受容することになる。

## Decision

1. **既存の必須接続を優先し、未接続時の判定をPhase 2で補う**。superpowersの実装スキルが完了スキルへ進む場合は、その経路を使う。そこを経ない実装完了、対策済みIssueのクローズ、作業を完了させる依頼では、今回合意した作業範囲・必要な検証とレビュー・完了スキルの進行状態を確認する。クローズだけでマージを決めず、ブランチ全体に残作業があればその作業へ戻る。完了処理の実行中・選択待ち・実行済みなら二重に起動せず、既存の進行から続ける。
2. **取り込み判断と実行を既存の完了スキルへ委譲する**。環境・対象確認、選択肢の意味、実行できる操作の範囲は同スキルの定義に従う。表示言語・推奨順位・質問形式は適用先の上位指示を優先し、表示の調整を理由に操作の選択肢を増減しない。同じ対象・方法に対するユーザーの明示承認が実在し、有効な範囲に限り、その指示を選択として引き継ぐ。対象変更・新たなリスクなどで承認範囲を外れる場合は必要な判断を求める。マージ方式設定や単なる作業継続指示は実行承認としない。方式確認・操作前レビューを参照し、検証・環境分岐・停止条件をこちらで再定義しない。完了スキル不在時は既存のインライン案内を使い、不在を理由に無確認実行しない。
3. **セッション終了処理に未マージ分岐を補う**。完成済みで未マージの作業は、取り込み要求が明示されていなくてもPhase 2の完了工程へ接続する。ただし、明示的な中断、調査のみ、不採用・重複によるクローズ、PRのレビュー待ち、取り込み保留は、その状態を記録して引き継ぐ。接続はマージの自動承認ではなく、未決ならDecision 2の選択肢提示へ進む。非Git環境や既定ブランチへの直接変更を自己マージへ誘導しない。
4. **実際に到達した状態で報告する**。実装・検証、ローカル統合、リモート反映のどこまで済んだか、未完了分があれば次手を示す。マージ直後は既存の`retrospective`へ接続し、同スキルのユーザー判断を経て引き継ぎへ進む。PR作成やブランチpushだけで統合済みとは扱わない。

変更の主対象は`skills/start-work/SKILL.md`。方式・操作承認・振り返り・引き継ぎの正本は維持する。Issue-0129の版更新条件はADR-0132で扱う。

期待検出量: 導入後の次の3実装サイクルについて、完了・終了場面を各サイクル1件の評価機会として見込む。既存のhandoffとgit履歴から復元できる範囲で統合状態と残作業を確認する。ユーザーへの次手提示の有無は、利用可能な会話記録や明示された選択記録がある場面だけを数える。未マージで記録がない場合は原因不明であり、無案内終了とも正常な保留とも判定しない。評価時は確認できた件数と不明件数を分ける。この定義は評価機会に既存資料を使うもので、新しい定期監視・必須保存欄・台帳は設けない。

## Consequences

- 実装後に利用者がマージ・振り返り・引き継ぎを一つずつ催促する経路を減らす。スキルを読まずに停止する実行漏れまで、この変更で解消したとは主張しない。
- 既存の工程を補うため、新しい状態モデルや環境設定は不要。承認済み範囲の取り違えと、単なる中断を作業完了と解釈する誤りを重点的に検証する。
- 当プロジェクトの「pushは実行ごとに確認する」という明示要件は継続する。マージ方針や過去のpush承認を流用しない。配布する汎用手順では既存の操作承認とプロジェクトの指示を参照する。
- ADR-0116の正本配置を変更せず、外部プラグインやインストール済みキャッシュは改定対象としない。

## 検証するケース

| 入力となる状況 | 期待する次手 |
|---|---|
| executing-plansまたはsubagent-driven-developmentから完了スキルへ到達済み | 既存の呼び出しを使い、start-workへ戻った際に再起動・再質問しない |
| subagent-driven-developmentの最終レビューが未完了 | 単なる実装・テスト完了から統合へ飛ばず、元スキルのレビューを完了させる |
| detached HEADの管理された作業領域 | 完了スキルの環境別選択肢に従い、ローカルマージを提示しない |
| 日本語・推奨先頭・テキスト質問を要求する適用先で取り込み方法が未定 | 選択肢の意味と環境分岐を保ち、表示は上位指示に合わせる |
| 合意範囲の実装・検証済み、対象ブランチのローカル統合を承認済み | 同じ選択を再質問せず統合工程へ進み、マージ後の振り返りへ接続 |
| 実装・検証済み、取り込み方法が未定 | 対象と推奨を示して必要な判断を求める |
| 既存の実装経路を経ず完成済み・未マージで終了処理へ到達し、取り込み要求も保留・中断指定もない | Phase 2へ接続して取り込み方法を提示する。実行は承認後 |
| 複数Issueのうち1件のみクローズ | ブランチ全体の残作業を継続 |
| 調査終了、不採用・重複によるクローズ | 変更の有無と合意した成果に応じて引き継ぎ。クローズだけでマージしない |
| 「ここまで」「続きは別セッション」と明示 | 中断状態を保存。完了させる依頼と混同しない |
| PR作成済みでレビュー待ち | 未統合と次手を記録し、作業全体の統合完了とは報告しない |
| 検証失敗、または取り込み中に競合 | 元スキルの停止条件を守り、失敗した状態で統合・公開・削除へ進まない。障害と対応の次手を提示 |
| 既定ブランチでの作業、または非Git環境 | 不要な自己マージをせず、該当する検証・記録へ進む |
| ローカル統合済みでpush未承認 | ローカル作業を整え、宛先・ブランチ・送信差分を示して当該pushの承認を求める |
| 導入後評価で未マージ状態しか復元できず、次手提示・保留選択の証拠がない | 提示の成否は不明とし、無案内終了や成功の件数へ換算しない |

検証は上表と変更後の手順の照合、両配布生成器の`-Check`、生成された手順の読み直しで行う。ケース照合は実エージェントの継続挙動を実測した試験とは区別する。

## 過剰適合点検（ADR-0079）

| 観点 | 判定 | 根拠 |
|---|---|---|
| 出所の偏り | 要是正→観測可能な発動条件でゲート | 出所は1プロジェクト・1セッションの照合記録、対象はC07・C08の2場面。記録本文にモデル世代の明記がなく、世代数は不明。実装範囲・検証結果・明示された中断や承認を条件とし、一般的な再発率を推定しない |
| システム種別依存性 | 問題なし | Gitブランチの統合は対象ブランチがある場合だけ。引き写し箇所: merge-practiceの既定ブランチ・方式判定は参照で維持、retrospectiveのマージ直後という条件とsession-handoffの中断・完了の区別を維持 |
| AIモデル/ツール依存性 | 問題なし | 特定モデルの癖やCodex固有APIを条件にしない。引き写し箇所: 実装側2スキルの必須接続・最終レビューを優先し、finishing-a-development-branchの選択肢の意味・環境分岐・前後検証・停止条件を維持。表示は適用先の上位指示へ従う。利用者の明示指示だけを再確認省略の根拠とする。未導入時は既存フォールバック、操作承認は既存正本へ従う |
| 規範の廃止条件 | 定義済み | 外部の完了スキルまたは既存の作業フローが、上表の完了・中断・保留の分岐と自動接続を担い、本追記を外しても全ケースの期待結果が保たれることを確認できたら重複部分の廃止を提案する。未マージの無案内終了が残る場合は存置側 |
