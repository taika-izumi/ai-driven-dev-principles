# ADR-0133: 自動進行は初期設計で合意した判断の分担と変更の影響で決める

- **Status**: Accepted
- **Date**: 2026-09-07

## Context

Issue-0122は、レビュー指摘の採否・反復・ADR承認での回答待ちの削減を扱う。元案は推奨が全件採用・承認・継続で一致するときの事前許可だった。配布先LoopForAlphaの先行運用は第131回の引き継ぎで宣言なし・計測0サイクルであり、効果は未検証。

本セッションでユーザーは、初期設計の全体方向には関与するが、その後は多くの推奨を採用していると説明した。一方、計画・実装中に根幹に関わる落とし穴も発見される。補助的な機能では当初仕様からの逸脱も任せたいという要件から、フェーズや仕様変更の有無だけでは相談の境界にならない。2026-09-07、初期設計で相談事項・委任範囲・裁量の限度を合意するワークフロー案をユーザーが承認した。

## Considered Alternatives

- 推奨の一致を基準にする: 判定は簡単だが、重要な設計判断まで自動化し、一部不採用を含む局所判断では停止する。ユーザーの関与したい範囲と一致しない。
- 当初設計から逸脱しない場合だけ自動化する: 合意の保護は説明しやすいが、任せたい局所仕様の変更まで確認が必要になる。
- 既存手順のまま個別に「推奨で進める」と指示する: 追加機構・保守費は小さいが、判断の分担を毎回解釈する負担と回答待ちが残る。
- 判断の分担と影響で決める: 初期設計で短い合意を作る負担と、後続で影響を判定する費用が生じる。既存の設計・レビュー・逸脱記録を使い、新しい承認台帳や毎変更の通知を設けず運用費を抑える。影響の過小評価は残り、既存レビューと実例検証で検出する。

## Decision

初期設計で「変更前に相談する事項」「AIに任せる範囲」「裁量の限度」をAIが整理し、設計承認と合わせてユーザーの許可を得る。これを後続の計画・レビュー・実装・記録の判断に用いる。仕様の変更を伴うか、推奨が全件一致するかだけでは自動進行を決めない。

委任範囲内で相談事項と限度を守る変更は、採否・代替案・必要な検証をAIが判断して進める。範囲を越える変更は適用前に相談する。影響が分からない場合はまず調査し、解消しなければ相談する。影響は最後にユーザーが承認した設計からの累積で判断し、AI自身の局所変更で相談の境界を広げない。

レビューの採否・反復とADR確定にも同じ判断の分担を適用する。記録・検証・レビューの要件は維持し、委任範囲内の判断は許可の根拠を残す。ユーザーの個別承認と委任による確定を区別し、同じ判断への回答を別工程で繰り返し求めない。

相談が必要な場合は、判明した事実・合意への影響・選択肢と推奨を示す。その判断に依存する変更を止め、独立した作業は続ける。許可の変更・撤回に対応し、次セッションでは許可の根拠と適用範囲を読み直す。通知は既存の節目へ、記録は既存の設計・ADR・計画へまとめる。

## Consequences

重要な設計判断をユーザーに残しながら、局所的な仕様調整まで自動進行に含められる。既存の計画逸脱規範・反復規範・ADR承認手順には、妥当性と判断権限を分ける接続が必要になる。既存の不可逆操作の権限はこの許可だけでは拡張しない。

本ADRはユーザーの個別承認を得た方針である。仕様の独立レビュー、実装、変更前後の模擬判断、独立実装レビューと指摘修正、サイクル全体整合検査を終え、2026-09-07にAcceptedへ昇格した。ADR-0072・0080・0107・0119への部分修正を記録済み。配布予定版は0.1.23。検証はdocs/records/minutes/2026-09-07-issue-0122-implementation-verification.mdを参照。

導入後最初の対象作業1サイクルで、既存のレビュー対応表・逸脱記録・ADRから復元できる委任判断と差し戻しを確認する。捕捉したい欠陥は、相談事項を越えた自動進行と、委任済み判断への不要な再確認。不要な再確認が減らず整理負担だけ増える、または境界超過を見逃す場合は、適用範囲の縮小・簡素化・撤回を検討する。記録不足は成功と数えず、事前試行の実績がないため効果量や率の閾値は設定しない。
