# ADR-0134: 文書の作成・編集を委譲するときに表現のルールと置き換え表の所在を渡す

- **Status**: Accepted
- **Date**: 2026-09-07

## Context

Issue-0125への着手は、2026-09-07のユーザー回答「OKです。では、Issue0125に着手しましょう」で承認された。同日の将来費用に関する比較への回答「OKです。この方針で進めましょう」により、既存ルールの伝達経路だけを追加する方針が承認された。承認内容の保存先はIssue-0125の「2026-09-07 方針の承認」。計画レビュー後の回答「１で」で指摘不採用・計画確定・実装移行を承認され、実装・独立レビュー・配布検証とサイクル全体整合検査の完了後にAcceptedとした。

変更前の `skills/subagent-dispatch/SKILL.md` は条件発火の6行に文書表現の項目を持たない。Issue-0125には、文書編集の委譲12回で置き換え表の内容を手渡しした記録がある。これは1プロジェクトの記録で、観測モデル世代は同Issueに記載がない。今回、全ツールでサブエージェントがAGENTS.mdを読まないという一般命題は検証しておらず、既存の委譲手順に明示的な伝達経路がないことを対策対象とする。

`docs/overview/wording-replacements.md` は `template.manifest` の配布対象であり、ガイドライン配信元だけの非配布文書を参照させる必要はない。既存規範の適用対象と記録型文書の本文除外を維持する。

## Considered Alternatives

1. **設定・フックによる自動注入**: Issue-0047にはClaude Codeの入力変更フックの調査記録があるが、複数ツールへの適用と規範との二重管理は未解決。今回の伝達漏れだけのためにツール別の実装・配布・検証を増やす案は採らない。現在の各ツールで利用不能と断定するものではない。
2. **既存の条件発火表へ文書作成・編集の行を追加する**: 既存の全行判定と項目展開を使え、必要な作業だけにルールを渡せる。条件判定と参照読み込みの負担は増えるが、置き換え表の複写・新スキル・自動検査は不要。採用案。
3. **常時適用に追加する、または手渡しを継続する**: 前者は文書を扱わない委譲にも読み込みを課し、ADR-0066の作業量による分離に反する。後者は最小変更だが、表の写し間違いと伝達漏れを受容することになる。

## Decision

文書の作成・編集を委譲するときに、既存の表現のルールを条件付きで渡す。ルールの内容を増やすのではなく、委譲先への伝達経路を追加する。

- `subagent-dispatch` の条件発火表に1行を追加し、判定行の例とスキル説明の条件数を揃える。常時適用の4件は変更しない。
- 条件は、今後も書き換える文書の作成・編集、または記録型文書のタイトルの作成・編集を含む委譲とする。記録型文書の本文だけの作業、文書を成果物にしないコード変更・読み取りだけの調査には、この追加項目を課さない。
- 委譲元は対象プロジェクトの `docs/overview/wording-replacements.md` の所在と既存規範の適用範囲を渡す。委譲先は同表を参照して担当する新規・変更部分を既存基準に合わせ、編集後の確認も既存の成果物検証に含める。置き換え表や語彙基準をプロンプト・スキルへ複写しない。
- 参照先の欠落や担当範囲外で見つけた語は、常時適用の実態優先・報告義務・範囲外作業の禁止で扱う。語彙専用の停止・代替・報告分岐を追加せず、編集権限やタスク範囲も広げない。記録型文書の本文除外とタイトルの対象化は既存の適用範囲を維持する。
- Issue-0123の5種類の対策、フック注入、語彙表の増補、自動検査、全資料の一括置換は含めない。ADR-0066の常時・条件付きの分離とADR-0123の語彙規範を維持した追加であり、両ADR全体は置換しない。

## Consequences

必要な参照先を明示でき、委譲元による表の手渡しを減らせる。一方、条件の判断と表の読み込みは増え、指示による伝達のため遵守や読みやすさの改善を保証しない。表の更新は従来の1ファイルで行い、専用の監視台帳・定期作業は増やさない。

変更対象は既存スキルの伝達機能1つで、新しいモジュールは設けないため、feature-block-designの分割しきい値には該当しない。設計は本ADRへまとめ、実装時に既存の関連仕様を更新する。独立した差分仕様書は作らない。

導入時には、現用文書の作成・編集、記録タイトル、記録本文だけ、コードだけ、参照先欠落の各ケースで判定・出力を照合し、旧手順では伝達項目が欠けることも確認する。ソースと生成後の配布本文を読み直し、両生成器のCheckを行う。これは手順の検証であり、利用環境へ新版が導入されたことや長期効果の実証とは区別する。

期待する検出機会は導入サイクル内の上記ケースで数え、捕捉対象は参照先・適用範囲・除外条件の渡し漏れと不要な適用である。導入後の評価は既存の委譲記録で確認できる範囲に限る。新たな利用者作業や配布先での測定を必須にしない。

実装・検証結果とサイクル全体整合検査は `docs/working/plans/2026-09-07-issue-0125-wording-dispatch.md` のTask 3・4に記録した。7ケースは実装者と独立レビュアーの判定が一致し、実装レビューの指摘は0件。0.1.24の配布物をローカル生成して両Checkを通過した。コミット・統合・公開・利用環境更新は別の操作承認を要し、今回のAccepted化をその完了と扱わない。
