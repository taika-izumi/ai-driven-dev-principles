# ADR-0138: 問い直しの事例は既存のworklogに蓄積しIssue-0132再着手時に確認する

- **Status**: Accepted
- **Date**: 2026-09-08

## Context

Issue-0132の小規模比較では、問い直し後に改善点と誤指摘が混在した。具体的な問いの固有効果と再現性は未確定で、ユーザーは追加の検証費用を抑える方針を希望した。既存の事前指示を維持し、必要な実作業で問い直しを使い、変更の根拠を確認する方針を承認した。

2026-09-08の会話で「Issue-0132に記録方針を残す／日々の作業は既存worklogの条件でAIが記録する／再着手時にログを確認する／全件記録ではないため成功率を算出しない」と説明した後、ユーザーが「Okです。ではその方針で進めましょう」と回答した。記録と再着手時の確認に対する個別承認である。

## Considered Alternatives

- 既存のworklogを使う: 日々の記録手順を増やさず、実作業の改善・副作用・負担を判断材料にできる。全件観測や分母の確保はできない。
- 問い直しの全件記録や専用の計測を追加する: 成功率等を調べやすくなるが、今回は必要性の裏付けが不足し、記録・保守の負担が増える。
- 直ちに追加実験や必須手順化へ進む: 固有効果・再現性が未確定の段階で費用と運用負担が増える。

## Decision

問い直しの事例は既存の `start-work` / `worklog-record` の発火点と記録条件に従って蓄積し、Issue-0132への再着手時に関係する記録を確認する。問い直し前後の設計、与えた問い、根拠のある改善、副作用、確認負担を、記録されている範囲で整理する。Issueへの毎回の転載は要求しない。

既存の事前指示は維持し、実作業で必要なときに問い直しを使う。Issue-0132はopenのまま観測待ちとし、追加実験と必須ルール化は行わない。再着手の判断はユーザーが行う。これは既存手順の利用方針で、スキルやAGENTS.mdの変更、記録条件の拡張、自動監視の新設を含まない。

## Consequences

ユーザーが毎回記録を指示する負担を増やさず、後続判断の材料を蓄積できる。記録されない事例もあるため、記録の件数から成功率・発生率を算出せず、記録がないことを効果や副作用がない証拠にしない。別プロジェクトの事例は作業ログのプロジェクト情報と出所を保って扱う。

再着手時の確認事項と検索の手掛かりは `docs/working/issues/flow/0132-post-proposal-design-reconsideration-effect.md` に記載する。Issue本文は記録を自動実行する仕組みではなく、再開時の引き継ぎ先として使う。
