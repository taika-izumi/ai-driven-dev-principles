# ADR-0139: AI組織の実証は公式実行基盤を利用し、開発手順と必要な接続だけを整備する

- **Status**: Proposed
- **Date**: 2026-09-08

## Context

ユーザーは、ループエンジニアリングとAI組織による開発へ進むロードマップを、公式ツールの利用・組み込み可能性を検討してから作るよう依頼した。調査・文書作成の依頼であり、基盤の採用確定・有料実行・導入への承認ではない。本ADRは採用候補を記録したドラフトである。

公式資料ではClaude CodeとCodexに専門担当への委譲機能があり、SDKによるプログラムからの利用も案内されている。一方、案件の終了基準、記録体系、委任の境界は利用側が定義する必要がある。調査根拠と制限は[公式ツールの調査](../../reference/ai-team-tooling.md)にまとめる。

ADR-0043の実証先行と、実証後に配布構成を決める条件を維持する。本ADRはその実証方法の補足案であり、既存ガイドラインや戦略探索ループを直ちに置換しない。

## Considered Alternatives

| 案 | 利益 | 費用・制限 |
|---|---|---|
| 公式機能を使い、必要な手順と接続を補う（推奨案） | 起動・委譲・モデル呼び出しを再実装せず試せる | 製品ごとの権限・設定読み込み・中断挙動を確認する負担が残る |
| 自前の汎用AI組織基盤を先に作る | 任意の制御を設計できる | 公式機能との重複、API変更への追随、障害復旧・課金管理の保守を実証前に抱える |
| 既存の対話手順だけを改善し続ける | 新しい実行基盤の負担がない | 人が常時見ない場合の停止・再開・記録の成立を確認できない |

## Decision

採用案は、公式実行基盤の再利用を先に検証し、ガイドラインは役割・終了基準・権限・記録・検証の要求を持つ構成とする。既存機能の設定で不足が解消するなら、追加コードを作らない。

最初の候補はLoopForAlphaで利用中のClaude Codeとサブエージェントとし、取りまとめ・実装・独立検査の小構成を対象にする。必要な結果回収・停止・再開をその環境で扱えないことが確認された場合にClaude Agent SDK等の接続を検討する。相互通信が必要になった場合のAgent teams、運用場所の変更が必要になった場合のManaged Agentsは別候補として比較する。いずれも実測なしに標準基盤とはしない。

Codexの確認は同じ役割・報告要件で行い、組み込みにはCodex SDK／App Serverを候補とする。公式資料で非推奨とされる `codex mcp-server` を新規構成の前提にしない。異なる提供元のモデル混在は、単一提供元での実証とは分け、必要性が確認されたときに接続を追加する。

## Consequences

- **部分修正（ADR-0166）**: 2026-09-10、固定の取りまとめ・実装・独立検査構成を具体化する前に、モデルに進め方を任せる条件との比較を行う順序へ変更した。公式実行基盤の再利用方針は維持する。本ADRはProposedのままとし、最新の実行順序はロードマップ4.0節を参照する。

最初の成果物は案件ごとの設定・役割指示・検証手順であり、汎用ランタイムを新設しない。接続コードが必要な場合も実証側に置き、有効性の確認後に共有範囲を決める。認証設定、実行環境、利用上限への対応はユーザーの作業を伴い得るため、実証開始前に具体化する。

既存の規範への注意書きだけでは、停止時に子処理が残ることや保護対象への書き込みを構造的には防げない。最初の実行確認と開発実証で、設定の反映・書き込み境界・停止・再開を記録する。確認機会は[ロードマップ](../../current/development-roadmap.md)の段階2・3で実行した案件数と中断試験数から数え、未確認を成功と数えない。公式機能だけで要件を満たす場合は接続コードを追加せず、追加コードが確認可能な利益を生まず維持費だけを増やす場合は撤回する。

## 過剰適合点検（ADR-0079）

| 観点 | 判定 | 根拠 |
|---|---|---|
| 出所の偏り | 要是正→実証案に限定 | 運用前提はLoopForAlphaの1プロジェクト。公式機能は2提供元の文書調査であり、組み込みの実測・モデル世代比較は0件。一般的な性能向上を主張しない |
| システム種別依存性 | 要是正→対象限定 | 初回はローカルの限定的なソフトウェア改修。戦略探索での成績を開発手順の成功に換算しない。引き写し箇所: ADR-0043の実証後抽出という条件を維持 |
| AIモデル/ツール依存性 | 要是正→導入前確認 | Claude Code先行は既存環境を使う実証上の選択。能力、設定形式、認証は調査文書の確認日と実証時の版で扱う。引き写し箇所: ADR-0133の委任は操作権限を広げない条件を維持 |
| 規範の廃止条件 | 定義済み | 公式機能で要求が充足されれば独自接続を不要と判断する。既存対話手順より負担だけ増える実測なら構成を縮小し、ユーザーが継続・撤回を決める |
