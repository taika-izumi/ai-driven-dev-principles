# ADR-0141: 検査委譲の保護条件を共通化し、対応可否はツール別の実行経路で確認する

- **Status**: Proposed
- **Date**: 2026-09-08

## Context

Issue-0136では、検査委譲に含まれる変更実験の保護漏れ、リポジトリ外への書き込み、後片付けによる既存記録の削除が起きた。CodexのWindowsサンドボックスでは試験専用ファイルの親子の書き込み拒否と実検査の成功を確認したが、Claude Codeから同じ条件が成立することは未確認である。調査と測定値は `docs/reference/inspection-isolation-costs.md` を参照する。

2026-09-08のユーザー発言「本ガイドラインはclaude codeからも利用することを想定しています」「次に進みましょう」を受け、Claude Codeを含む設計へ進む。同日11:39の「1で」で設計と分担の承認を受領し、初回レビュー後の「1で」（12:07に反映着手）でF-01の修正案と新規1担当4観点の再レビューを承認された。承認基準と追加承認はIssue-0136の設計ノート「承認記録」に保存する。特定の接続方式・新しい必須依存・環境移行の承認とは解釈しない。第2回レビューは新規指摘なしで設計を確定した。実装を伴う決定のため、実装・検証完了までProposedを維持する。レビュー結果は `docs/records/reviews/2026-09-08-issue-0136-design-r2.md`。

## Considered Alternatives

| 案 | 利益 | 導入・運用・維持の負担と限界 |
|---|---|---|
| 共通の保護条件とツール別の実行経路を分ける（提案） | ツールの選択を保ち、実行時に保護が届くかを確認できる | ツール・OS・起動方法ごとに初回確認が必要。参照手順の更新も必要 |
| Codex経由の検証を全環境で必須にする | 今回の実測を利用しやすい | Claude Codeだけを使う利用者にも別ツールの導入を求める。今回のWindows単一環境の実測から汎用要件へ拡大し過ぎる |
| 既存の注意書きを強化し、環境制限を確認しない | 変更量と導入負担が小さい | 指示外の実験や絶対パスの誤解決による破損経路を残す。Issue-0136の実害に対する根拠が弱い |

## Decision

方針は、検査委譲で守る対象・書き込み範囲・既存物の扱いを共通条件として定め、その実現方法と確認済み範囲をツール別に扱うことである。Codexの導入をClaude Code利用者の一律の前提にしない。改定の正本は既存 `subagent-dispatch` の判定・引き渡し手順とし、環境別の詳細は条件に応じて読む参照へ置く。

`subagent-dispatch` が定める確認に従い、委譲元が既存の起動・権限設定機能で検査担当の実行経路を準備する。起動前に、担当全体を狭い権限で実行できるか、書き込み可能な操作がすべて保護された経路だけを通ることを確認する。シェル・ファイル編集・MCP等の直接操作が保護対象へ届く場合、狭いコマンドを使うよう指示しただけでは成立としない。確認不能・制限不能なら、書き込み可能な操作を持たない静的確認へ限定するか、実行を伴う委譲を止めて相談する。新しい常設起動基盤をこの改定で暗黙に新設しない。

対応確認は、委譲元から実際に使う経路について、許可された処理の成功、保護対象への書き込み拒否、子プロセスへの制限の継承、既存記録の保全、検証結果の回収を確認する。Codexだけの試験をClaude Code対応の証拠にしない。Claude Codeについても具体的な経路を少なくとも1つ実証し、ツール・OS・必要条件を明示して対応と報告する。

受け取り時の委譲元確認は、破壊的検証を明示した場合に限らず、実行を伴う検査委譲にも接続する。起動時の経路・保護範囲と実際の実行・結果を照合し、既存の対象を絞った前後比較を用いる。静的確認をこの実行確認の対象には含めない。

既存のコピー・絶対パス・状態比較は保護の補助として維持し、コピーを用意しただけで権限が制限されたとは扱わない。ADR-0093を全面置換する案ではなく、その発火条件と確認対象を補う。詳細案と未決の経路はIssue-0136の検討ノートに置く。

## Consequences

利用者は必要な場合に、検証用領域と実行環境の初期設定を行う。追加インストール、WindowsからWSLへの移行、認証の追加を伴う経路は、その作業を具体化してから選ぶ。試行は16GBでの直列検証から始める案とし、全環境に固定のメモリ上限や担当者数を配布しない。

今回の実装検証ではCodex・Claude Codeの各経路で保護条件ごとの成否と未確認を数える。既存設定の引き継ぎだけで全条件を満たすと確認された項目は追加手順を省略する候補にする。追加手順が固有の欠陥を捕捉せず、既存機能と同じ確認を繰り返すだけと実測された場合は縮小・削除側へ見直す。確認機会がないことを不要の根拠にしない。
