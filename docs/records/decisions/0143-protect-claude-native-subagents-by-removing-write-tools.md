# ADR-0143: Claude標準サブエージェントの保護は書き込み系ツールの除去で成立させ権限モードに依存しない

- **Status**: Accepted
- **Date**: 2026-09-08

## Context

Issue-0136では検査委譲の共通保護条件（ADR-0141）を定め、Claude Code側はCLIを別プロセスとして起動し固定検査MCPだけを公開する構成で実証した（ADR-0142）。標準のAgent/Task機構から起動する子AIについては、ツール制限・権限継承・実行を伴う検査・再委譲が未確認のまま残っていた。

2026-09-08、Claude Code 2.1.263・Windows 11で、親に `Bash, Edit, Read, Write` を持たせた状態から標準のAgent/Taskで子を起動する実測を行った（実行記録: `docs/records/experiments/2026-09-08-claude-native-subagent.json`）。子の利用可能ツールを許可リストで絞った構成では、Bash・PowerShell・Write・Editがいずれも `No such tool available` で不発だった。一方、親を `acceptEdits` にして子に `Write` を渡した構成では、子が保護対象の代用品を実際に上書きし、作業ディレクトリ外への書き込みだけが拒否された。固定検査1操作だけを渡した構成では、正常1成功・変異1失敗・復元1成功と保護代用品4件の拒否を確認した。

ユーザーは実測結果の提示に対し、未確認事項は次セッションへ引き継ぎ、確定した範囲の反映を今行う案を選択した（2026-09-08、「1で」）。

## Considered Alternatives

- **権限モードで子を制御する**: 追加設定なしで扱えるが、実測では `acceptEdits` の親から起動した子が作業ディレクトリ内の保護対象を上書きできた。パス単位の保護にならず、既存の共通条件（全操作経路の制限）を満たさない。
- **子の利用可能ツールから書き込み可能な内蔵ツールを外す**: 実測で書き込み・編集・シェルのすべてが不発になり、親が同じツールを保持していても子へ渡らなかった。設定は起動時のエージェント定義または起動引数で行うため、既存機能の範囲で足りる。
- **実測を記録するだけで規範へ反映しない**: 変更量は最小だが、次に標準サブエージェントへ検査を委譲するたび同じ確認を繰り返し、確認済みの構成と未確認の構成を取り違える経路が残る。
- **標準サブエージェントを実行を伴う検査の対象外と決める**: 判断は単純になるが、固定した1操作だけを渡す構成が実際に成立したため、成立する経路を捨てることになる。

## Decision

Claude Code標準のAgent/Task機構で実行を伴う検査を委譲するとき、保護の成立条件は**子の利用可能ツールから書き込み可能な内蔵ツール（シェル・ファイル編集・ファイル作成）を外すこと**とする。権限モードの指定はこの条件の代替にしない。

実行が必要な検査は、あらかじめ固定した1操作だけを子へ渡す構成で行う。今回の実証ではセッション側に公開した固定検査MCPを子のツール許可リストで1操作に限定し、実行そのものは既存Codexのサンドボックス内で行った（ADR-0142の構成を子へ付け替えた形であり、CodexをClaude Code利用者の必須依存にする決定ではない）。

再委譲は既定で可能なため、不要な場合は子の許可リストからAgent（Task）を外す。孫まで起動した場合も、孫の許可リストによる制限は保たれた。

確認済み範囲はClaude Code 2.1.263・Windows 11・`--print` 実行に限る。対話セッション（autoモード）での挙動、エージェント定義ファイルのfrontmatterによるMCP限定公開・拒否リスト、親が `bypassPermissions` の場合、別OS・別版は未確認とし、既存の限定構成の成功をこれらへ読み替えない。

## Consequences

標準サブエージェントへ検査を委譲する経路が、確認済みの構成として使えるようになる。委譲元は起動前にツール許可リストを確認する作業が増えるが、確認は開始イベントの実ツール一覧で足りる。

権限モードでは保護できないことを明記するため、`acceptEdits` や自動承認の運用で子へ書き込み系ツールを渡している場合は、保護対象を作業ディレクトリの外へ置くか、ツールを外す必要がある。

エージェント定義ファイルは起動時に読み込まれるため、実行中のセッションで定義を足しても使えない。委譲元が新しい制限構成を使うには新しいセッションを起動する必要がある。

未確認範囲を明示したため、対話セッションでの実挙動と定義ファイル側の限定公開はIssue-0136の追加検証として次サイクルへ残る。
