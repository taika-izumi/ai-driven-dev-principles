# ADR-0144: Claude標準サブエージェントの書き込み系ツールの除去は許可リスト方式で行い拒否リスト方式を用いない

- **Status**: Proposed
- **Date**: 2026-09-09

## Context

ADR-0143 は、Claude Code 標準のサブエージェント機能で子を起動する場合の保護を「子の利用可能ツールから書き込み可能な内蔵ツール（シェル・ファイル編集・ファイル作成）を外すこと」で成立させた。ただし、外し方を許可リストと拒否リストのどちらでもよいと明言しているのは同 ADR の Decision ではなく、`skills/subagent-dispatch/references/inspection-isolation.md` の対応表（37 行目）である。ADR-0143 の Decision で「どちらでも」と書かれているのは再委譲（Agent の外し方）の1箇所に限られ、さらに同 Decision は末尾で確認済み範囲を Claude Code 2.1.263・Windows 11・`--print` 実行に限り、対話セッション（autoモード）での挙動を未確認としている。つまり対応表の「どちらでもよい」は、ADR-0143 が自ら限定した確認済み射程より広く一般化されていた。この等価性の根拠にあたる実測は、拒否リスト（`disallowedTools`）で Write・Edit・Bash・PowerShell・Agent を外した子がその5ツールを呼び出せなかったという `--print` 実行の結果である。

2026-09-09、Claude Code 2.1.263・Windows 11 の対話セッション（autoモード）で追加検証したところ、同じ拒否リスト定義の子に書き換え能力を持つツールが残っていた。子が実際に見えていたのは、すぐ呼べるもの6件（Artifact, Glob, Grep, Read, Skill, ToolSearch）と、検索して取得できる遅延ツール14件（EnterWorktree, ExitWorktree, Monitor, NotebookEdit, SendMessage, TaskStop, WebFetch, WebSearch、および外部サービス認証6件）である。このうち NotebookEdit を実際に使わせたところ、保護対象として置いた代用ノートブックを承認要求なしで上書きした（実行記録: `docs/records/experiments/2026-09-09-claude-native-subagent-interactive.json`）。同じ試験で、許可リスト方式（`tools: Read`）の子は5ツールすべてが `No such tool available` となり、代用品は無変更だった。対称的な反証として、許可リスト方式の子に ToolSearch と NotebookEdit を実際に呼び出させたところ、いずれも同じく `No such tool available` で拒否され、保護側の代用ノートブックは無変更だった（同記録の run i4）。許可リストに載っていないツールを子が後から取得する経路は確認されていない。上書き・無変更の確認はいずれも子の報告ではなく委譲元のハッシュ照合で行い、変異させた代用品は復元して基準値と一致させた。

前サイクルの測定が5ツールだけを試したため、この残存は見えていなかった。NotebookEdit はファイルを書き換える内蔵ツールであり、ADR-0143 の「書き込み可能な内蔵ツール」の列挙（シェル・ファイル編集・ファイル作成）から漏れていた。これは対話セッション固有の差ではなく列挙の不完全性である（`--print` 実行での残存集合は未測定）。

## Considered Alternatives

1. **拒否リストの列挙を増やす**（NotebookEdit・Artifact・SendMessage 等を追記する）: 今回の穴は閉じる。ただし版が上がるたびに新しい書き込み可能ツールが増え、そのつど列挙を追わないと保護が破れる。列挙漏れがそのまま書き込みになる構造は変わらない。維持費は版追随として恒久的に続く。これは Issue-0139（`inspection-isolation.md` の確認表の行が版・起動方式ごとに増え、古くなった行を落とす基準が無いという文書構造の課題）と同種の構造（版追随の恒久化）を持つ。ただし Issue-0139 が扱うのは表の維持負担であり、こちらは列挙漏れがそのまま保護の破れになる運用上の懸念で、負担の性質は異なる。
2. **権限モードや作業ディレクトリの境界で補う**: ADR-0143 で不成立が実測されている（`acceptEdits` でも `bypassPermissions` でも子は保護対象を上書きでき、後者では作業ディレクトリ外への書き込みも通った）。
3. **採用案: 許可リスト方式に限定する**: 許可する側を列挙するため、未知・新規のツールは既定で子へ渡らない。版追随の維持費が発生しない。運用作業も増えない（ADR-0143 が既に起動前のツール一覧確認を求めており、許可リスト方式ではその確認対象がそのまま許可列挙になる）。
4. **リスクを受容して現行の「どちらでもよい」を維持する**: 承認要求なしで保護対象が実際に書き換わる経路が実測されたため受容しない。

新設の評価可能性の適用判定: 本決定は既存規範の選択肢を狭める文言強化であり、新しい規範・手順・観点の新設を含まないため、`CONTRIBUTING.md`「全シナリオ共通: 新設の評価可能性」の記載要件の適用対象外と判定した。上記の比較は判定の根拠として残す。

## Decision

Claude Code 標準のサブエージェント機能で子を起動するときの保護は、子の利用可能ツールを許可リストで明示列挙する方式で行う。拒否リスト方式（`disallowedTools`）は保護手段として用いない。

理由は、拒否リスト方式が列挙した分しか外さず、列挙漏れがそのまま書き込みになるためである。実測では、拒否リストで外した子に残った NotebookEdit が保護対象の代用ノートブックを承認要求なしで上書きした。許可リスト方式では許可する側を列挙するため、未知のツールは既定で渡らない。

適用範囲は Claude Code 標準のサブエージェント機能（Agent/Task ツールから子の担当を起動する仕組み）であり、確認済みの版は Claude Code CLI 2.1.263・Windows 11 である。ADR-0143 の骨格（書き込み系ツールの除去で保護を成立させ、権限モードを保護の代わりにしない）は維持する。本決定が改めるのは次の2点のみである（部分修正）。第一に、ADR-0143 の Decision が保護の成立条件として挙げた「書き込み可能な内蔵ツール（シェル・ファイル編集・ファイル作成）」という列挙は不完全であり、NotebookEdit のような列挙外の書き込み可能ツールが存在する。第二に、`inspection-isolation.md` の対応表にある「外し方は許可リストと拒否リストのどちらでもよい」は成立しない。列挙を完全にすることではなく、許可する側を列挙する方式へ寄せることでこの2点に対処する。

拒否リスト方式を保護以外の目的で使うこと（利用者の利便のために不要なツールを隠すなど、破られても損害が出ない用途）は禁じない。

## Consequences

- 委譲元は子の定義に許可リスト（`tools`）を書く。拒否リストだけで保護している既存の定義があれば許可リストへ書き換える。現時点でこのリポジトリにあるのは試験用の `.claude/agents/issue0136-nowrite.md`（未追跡の使い捨て）だけである。
- 子に必要なツールを列挙する作業は委譲元に残る。ADR-0143 が既に起動前のツール一覧確認を求めているため、工程は増えない。
- 版が上がって新しい書き込み可能ツールが増えても、許可リスト方式では既定で子へ渡らないため、規範側の版追随が不要になる。
- 外向き操作（Artifact による公開、SendMessage による他セッションへの送信）は、ファイル書き込みとは別種の副作用として名前の残存を確認したが、実効性は測っていない。許可リスト方式では既定で渡らないため本決定の範囲では対処されるが、拒否リスト方式を利便目的で使う場合は残る。
- 未確認として残るもの: `--print` 実行での残存ツール集合、別OS・別版、Artifact と SendMessage の実効性、状態を変える残存ツール（EnterWorktree・ExitWorktree・TaskStop）の実効性、および固定検査の接続を子だけに渡す構成の対話セッションでの実行（前サイクルの試験領域へ書き込みが入るためユーザー判断を待って保留した。本決定の論点は書き込み系ツールの外し方であり、固定検査の成立可否は ADR-0143 の範囲に属する）。今回の結論をこれらへ読み替えない。
