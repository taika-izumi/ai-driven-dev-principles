# ADR-0145: 検証担当が隔離範囲内で追加テストを作成・実行できる構成を目指す

- **Status**: Accepted
- **Date**: 2026-09-09

## Context

設計の確定: 2026-09-09、ユーザーが差分再確認と軽微修正の機械確認の報告後に「仕様を確定し、実装計画へ進む」を「1で」と選択した。採否案を含むこの版を設計として承認し、実装と実経路の検証は後続とする。

隔離環境の構築方針を検討するにあたり、検証担当へ任せる作業範囲を確認した。既存の実測では、読み取り専用のClaude標準サブエージェント、ClaudeからCodexへ固定検査を渡す経路、書き込み先を狭めた別のCodex実行と副担当への制限継承が確認されている（`docs/reference/inspection-isolation-costs.md` 第8〜10節）。

ユーザーの個別承認: 本セッションで「検証担当にどこまで自律的に作業してほしいか」という質問に対し、選択肢1「隔離した範囲内では、追加テストの作成・実行まで任せたい」を「1で」と選択した（2026-09-09）。本記録はこの作業範囲の選択を保存するために作成する。

## Considered Alternatives

1. **隔離範囲内で追加テストの作成・実行まで任せる（採用）**: 検査で得た知見に応じて担当が検証を追加でき、人が検査ごとに実行内容を用意する負担を抑えられる。一方、追加したコードや子プロセスも含めた操作範囲の制限が必要になる。
2. **用意済みの検査だけ実行させる**: 公開する操作を限定しやすいが、新しい検査を追加するたびに接続側の整備が必要になる。
3. **当面は読み取り・検索によるレビューを優先する**: 実行環境の準備を抑えられるが、実行を通した検証には別の担当や工程が必要になる。

## Decision

今回の隔離環境の構築方針では、検証担当が隔離した範囲内で追加テストを作成・実行できる構成を目指す。検証内容を固定検査だけに限定せず、検査ごとの利用者の準備負担を抑える。

この選択は今回検討する構成の要求であり、全プロジェクトへの新しい義務ではない。既存の保護条件（ADR-0141）と、Claude標準サブエージェントに関する決定（ADR-0143・0144）は変更しない。

## Consequences

- 構成案は、検証用の書き込みを許しつつ、原本・共有ツール・既存記録への変更を防ぐ条件で比較する。
- テスト作成・実行の自由度と、導入・運用・維持の負担を合わせて評価する。
- 本承認は検討する要求の選択に限る。実環境の構築、追加依存の導入、公開の操作承認を含まない。
