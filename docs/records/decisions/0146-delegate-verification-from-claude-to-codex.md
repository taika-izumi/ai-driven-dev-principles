# ADR-0146: 開発の主担当を維持し、Claude CodeとCodexから共通の検証担当を呼ぶ

- **Status**: Accepted
- **Date**: 2026-09-09

## Context

設計の確定: 2026-09-09、ユーザーが差分再確認と軽微修正の機械確認の報告後に「仕様を確定し、実装計画へ進む」を「1で」と選択した。採否案を含むこの版を設計として承認し、実装と実経路の検証は後続とする。

ADR-0145では、隔離範囲内で検証担当が追加テストを作成・実行できる構成を要求として選択した。初回の対応ツールについて、Codex、Claude、両方を比較した。

ユーザーの個別承認は2026-09-09の回答「現在、claude codeでメインの開発を行なっています。もしclaude codeからcodexを呼び出して検証依頼出来たりするのであれば、1で良いです。」である。選択肢1は「まずCodexを検証担当にする」であり、Claude Codeから依頼できることが選択の条件である。

この条件には、Codexの非対話CLIを接続から呼び出す構成が対応する。2026-09-09に、このPCの `codex-cli 0.153.4` の `codex exec --help` で、標準入力からの依頼受け取り、作業ディレクトリ指定、JSONLイベント、最終応答のJSON Schema指定とファイル出力を確認した。[OpenAIの非対話モード公式資料](https://learn.chatgpt.com/docs/non-interactive-mode)でもスクリプトからの起動と結果回収が説明されている。

前回のClaudeからの接続実測は固定Pester検査の起動であり、CodexのAIへ追加テスト作成を依頼した実証ではない（`scripts/experiments/inspection-dispatch/limited-execution/README.md`）。別のCodex実行での制限継承の実測は `docs/records/experiments/2026-09-08-codex-subagent-inheritance.json` にある。これらと公式機能は接続構成の実現根拠とするが、今回の一連の経路の実証完了とは扱わない。

後続の個別承認: ユーザーは本ガイドラインをCodex中心で開発していると説明した。AIが「ClaudeとCodexのどちらからも依頼できる共通の起動処理」を提示したところ、ユーザーは「OKです。とりあえずそれで進めましょう」と承認した（2026-09-09）。依頼元を両方へ広げ、検証担当は引き続きCodexとする。以下の比較でいう「両方を検証担当にする」とは異なる。

## Considered Alternatives

1. **Claudeを主担当に残し、Codexへ検証を依頼する（採用）**: 現在の開発環境を維持し、Windowsでの既存実測を活用できる。依頼の受け渡し・起動・結果回収をつなぐ補助と、その動作確認が必要になる。
2. **初回からClaudeを検証担当にする**: 主担当と同じツールを使えるが、追加テストの作成・実行を含む担当全体の隔離構成を別に整備・確認する必要がある。
3. **初回から両方を検証担当として選べるようにする**: 選択の自由度は上がるが、二つの起動経路と対応環境を準備・検証・維持する負担が生じる。

## Decision

初回は現在のWindows環境で、開発の主担当を維持したまま、Claude CodeとCodexのどちらからも共通の起動処理へ検証を依頼し、結果を依頼元へ戻す構成を具体化する。検証担当は、書き込み先を検証用コピーへ狭めた別実行のCodexとし、ADR-0145に従って追加テストを作成・実行する。原本を編集できる主担当から通常の副担当を起動するだけでは、原本の保護が成立したとは扱わない。

Codexへ主担当を移すことや、人が毎回依頼と結果を転記する運用を前提にしない。既存のClaude標準サブエージェントの保護方式（ADR-0143・0144）は変更せず、今回の構成は別の起動経路として扱う。

## Consequences

- 利用者は各プロジェクトの主担当を維持できる。検証のAI利用分はCodex側にも発生する。
- 導入時にはCodexの認証・実行環境と、Claude側から使う接続の設定を確認する必要がある。依頼のたびの手動転記を不要にすることを設計条件とする。
- 採用は初回の構成対象の選択であり、一連の経路の動作保証や構築完了ではない。導入可能と判定する前に、Claudeからの依頼、Codexによる追加テスト作成・実行、保護範囲外への書き込み拒否、結果回収を通して確認する。
- 本決定は初回構成のスコープであり、全Claude利用者へのCodex必須化、全プロジェクトへの規範追加、公開・導入の操作承認ではない。
