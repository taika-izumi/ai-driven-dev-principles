# ADR-0147: 検証の共通入口をCLIに置き、準備・実行・回収の責務を分ける

- **Status**: Accepted
- **Date**: 2026-09-09

## Context

設計の確定: 2026-09-09、ユーザーが差分再確認と軽微修正の機械確認の報告後に「仕様を確定し、実装計画へ進む」を「1で」と選択した。採否案を含むこの版を設計として承認し、実装と実経路の検証は後続とする。

ADR-0145・0146により、Claude CodeとCodexの両方から、隔離したCodexへ追加テスト作成・実行を依頼する方針が承認された。承認済みの処理順は、検証用コピーの準備、制限付きCodexの実行、結果回収である。既存の `scripts/experiments/inspection-dispatch/limited-execution/server.ps1` は固定検査専用の実験コードで、任意の検証依頼を受ける運用部品ではない。

接続方式の詳細を含む構成は、上記の仕様確定時に承認された。

## Considered Alternatives

1. **共通CLIを両方の主担当から呼ぶ（採用）**: 既存のPowerShellとCodex CLIを利用する。依頼用JSONをファイルで渡し、JSONの結果を返す。常設サーバーの接続登録・更新は不要だが、各主担当からのコマンド起動権限を確認する必要がある。
2. **初回からMCP接続にする**: 両方からツールとして発見・呼び出せるが、長時間実行・切断・再接続の扱いと、両クライアントへの登録が加わる。既存の試験MCPをそのまま常設化できるとは扱わない。
3. **依頼元ごとに別の起動処理を作る**: 個別に調整できるが、コピー・権限制限・結果判定の重複実装と維持が発生する。

既存の注意書きだけでは権限継承による原本変更を防げない。これを受容する案はADR-0141・0145の保護要求を満たさない。CLIは継続して維持する小さな実行補助とし、引数検査・プロセス終了・版対応の保守負担を持つ。初回はローカルの検証経路として実証し、プラグインへの通常配布を既成事実にしない。

## Decision

構成は、共通CLIを入口とし、依頼受付とコピー準備、Codexの制限付き実行、結果の回収と照合の3責務に分割する。依頼元固有の違いは呼び出し手順と起動確認へ限定する。依頼の文章をコマンド文字列へ展開せず、Codexの標準入力へデータとして渡す。

## Consequences

- 各ブロックをAIの実呼び出しなしで検証し、最後に両方の依頼元から実経路を確認できる。
- 初回に共通CLIの配置と起動許可・認証を確認する。依頼ごとの手動転記は不要にする。
- 依頼元の承認制約で起動できない場合は理由を返す。制限解除や別経路への自動切り替えを実装しない。
- 次の初回実証で両依頼元から各1件の依頼を数え、追加テスト作成・結果回収と原本保護の成立を確認する。CLI共通化が両方で成立せず固有処理の重複を残す場合は、共通入口の方式を見直す。
