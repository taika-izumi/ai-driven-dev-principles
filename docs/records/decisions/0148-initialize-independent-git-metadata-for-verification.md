# ADR-0148: 検証用コピーに独立したGit管理領域を作る

- **Status**: Accepted
- **Date**: 2026-09-09

## Context

設計の確定: 2026-09-09、ユーザーが差分再確認と軽微修正の機械確認の報告後に「仕様を確定し、実装計画へ進む」を「1で」と選択した。採否案を含むこの版を設計として承認し、実装と実経路の検証は後続とする。

隔離検証の仕様は原本の`.git`を複製せず、検証領域を原本配下にも置ける構成だった。独立レビューR2が非Git領域でのCodex起動条件の不足を指摘した。委譲元の無害な試験では、原本配下に作った`.git`のないコピーから`git rev-parse --show-toplevel`を呼ぶと原本が返った。次に新しい試験フォルダへ空のGit管理領域を作ると、そのフォルダ自身が返った。実出力は`.tmp/isolated-verification-review-20260909-01/git-probe-result.json`と`git-independent-probe-result.json`。

レビューに基づくこの修正は、上記の仕様確定時に採用された。権限制限の突破を実証した記録ではなく、検証の対象版と作業範囲を取り違える経路の修正である。

## Considered Alternatives

1. **非Git領域の許可フラグだけを付ける**: Codexの起動チェックは回避できるが、親リポジトリへ遡るGitの探索を止めるものではない。
2. **原本のGit管理領域をコピーする**: 履歴等を使える一方、原本の設定・フック・外部参照を持ち込む。今回のファイルコピーを対象にする要求には不要で、確認と維持の負担が増える。
3. **コピーに独立したGit管理領域を作る（採用）**: 既存のGitを使ってコピー自身を作業単位にできる。初期化と探索先の確認を追加するが、原本の履歴・設定・フックを持ち込まない。

## Decision

コピー完了後に、空のテンプレートを指定して`work/`へ新しいGit管理領域を作り、Gitが返す最上位ディレクトリとGit管理領域のパスがともにコピー内を指すことを確認する。検証担当の起動前に行い、原本の`.git`を複製・共有しない。作成した管理領域は検証担当から書き込み不可にする。

## Consequences

- Codexの非Git許可フラグを、コピーと原本の区別の代わりにしない。
- コピーには原本のコミット履歴・インデックス状態を再現しない。それらに依存する検査は未検証として報告する。ファイル内容・対象版は従来どおりsourceManifestで対応付ける。
- 既存の準備ブロックに初期化と確認を追加するだけで、新しい常駐処理・依存は作らない。初回実証の両依頼元各1件で、Gitが原本へ遡らないことを確認する。
- 上位リポジトリを参照せず検証を行える別の公式機構が実測で成立し、Git管理領域の初期化が不要になれば削除・置換を検討する。
