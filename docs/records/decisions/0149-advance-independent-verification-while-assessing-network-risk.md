# ADR-0149: 通信リスクを評価しながら独立した検証を先に進める

- **Status**: Accepted
- **Date**: 2026-09-09

## Context

共通CLIのタスク0でファイル書き込み保護を確認したが、通信拒否は未達。WFPのフィルター・トークン条件・既存イベントを調査しても原因確定には至らなかった。実測はIssue-0136の`0136-note-common-cli-runtime.md`と`0136-note-wfp-loopback-diagnostic.md`。

ユーザーは「リスク評価＋独立した検証を進める」を2026-09-09の回答「1で」で個別承認した。既存計画の全タスク停止条件を変更し、合格基準と通常導入の条件は維持する。

## Considered Alternatives

1. 通信拒否の内部原因を特定するまで全実装を止める: 追加調査の見通しが薄く、独立した機能の検証も進まない。
2. 通信リスクの評価だけを先に行う: 実装投資を抑えられるが、方式によらず必要なコピー・結果検査を進められない。
3. 通信遮断を必須として別方式へ移る: 強い隔離を求められるが、導入・維持の負担を比較する材料が不足している。
4. リスク評価と独立した検証を進める（採用）: 実用性・安全性の判断材料を増やし、既存成果を活用できる。

## Decision

通信の内部原因追跡をいったん区切り、通信の実態・読み取り範囲・影響を限定した試験と分析で整理する。同時に、AIなしで検証できるコピー準備、結果照合、プロセス停止を先に実装・検証する。

通信条件が未達の間も上記部分は進めてよい。実エージェントの自律実行、未検証の権限設定の採用、両依頼元からの通常利用、導入・公開はこの承認に含めない。通信を許容する判断や別の隔離方式の採用は、評価後の個別判断とする。

## Consequences

- 実装計画のタスク0を全後続の一律前提から、実エージェントの起動と導入の前提へ変更する。既存の成功条件は下げない。
- タスク1、タスク2のAIなしプロセス管理部分、タスク3の結果照合部分を先行する。起動設定への依存が強い部分とタスク4は保留する。
- 別方式を選ぶ場合に作り直しが少なくなるよう、既存仕様の3責務の分割を維持する。
- リスク評価は受容の決定ではない。評価資料はIssue-0136の検討ノートへ置き、ADRには採用済みの進行方針だけを記録する。
- 2026-09-09、承認済みの進行方針を計画へ反映し、リスク評価とAIなし3群の検証を実施したチェックポイントで確定。整合確認は実装計画「先行範囲の整合確認」。全体完成や通信受容の認定ではない。
