# ADR-0150: 検証担当へリポジトリのファイルとGit履歴をスクリプトで渡す

- **Status**: Accepted
- **Date**: 2026-09-09

## Context

ユーザーは、取りまとめ役が関連資料を事前選択することで子の探索が妨げられることと、本文の転記による出力トークン増加を懸念した。2026-09-09の本会話で、スクリプトによるコピーを確認したうえで「子セッションでもGit履歴が確認できれば、子セッションの参照可能データについては何も不満はありません。作業を進めましょう」と指示した。ファイルと履歴の提供はこの個別承認による。

## Considered Alternatives

1. 親が資料本文を出力して渡す: 転記費用が増え、子による資料探索を制限する。
2. ファイルを広く複製するが履歴を渡さない: 現行ADR-0148の構成。履歴を調べたいという要求を満たさない。
3. ファイルと履歴をスクリプトで独立した領域へ複製する: 親の全文出力を不要にし、子が必要な資料と履歴を探索できる。

## Decision

案3を採用する。現行のファイル列挙・コピーにGit履歴の参照を加える。原本のGit管理領域を共有しないというADR-0148の境界は維持し、「原本のコミット履歴を再現しない」という範囲を部分変更する。親は目的・基準・参照の入口を短く渡し、本文転記を通常手順にしない。

具体化にはGit bundleによる履歴データの移送を用いる。原本の`.git`の直接コピーやworktreeによる共有と異なり、設定・フック・外部オブジェクト参照を持ち込まず、既存のファイルコピーへ追加できるため。合成データとコピー準備の部品テストで、履歴参照と未コミット内容の保持を確認した。全参照と入力worktreeのHEADから到達できる履歴を提供し、他worktreeだけのHEAD・reflogだけの履歴は含めない。

## Consequences

- 子が読んだ資料・履歴の入力トークンは必要だが、親による全文再出力は不要になる。
- 履歴の複製にはディスク容量とコピー時間が必要。履歴中の過去のファイルも子から参照可能になる。
- 作業中の未コミット内容と履歴の基準を区別し、原本の設定・フックを実行設定として持ち込まない。
- HEADのブランチ名またはdetached状態も保持し、同じコミットを指すブランチへの切り替えを対象版の変更として検出する。
- 変更は検証用コピーの準備が対象。Docker採用・Linux先行・実エージェント起動・公開の承認は含まない。
- 2026-09-09、個別承認済みの要求に対する実装と独立レビューを完了。指摘の再現・訂正と4テスト群の成功を確認し、履歴変更の整合検査を経て確定。正本は`docs/records/reviews/2026-09-09-history-copy.md`。隔離環境全体の完成を認定するものではない。
