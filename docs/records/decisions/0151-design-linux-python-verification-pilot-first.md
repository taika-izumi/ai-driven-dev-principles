# ADR-0151: 隔離検証はLinux・Python対象の小さな試作設計を先行する

- **Status**: Accepted
- **Date**: 2026-09-09

## Context

Windows側の通信制限が未成立のため、既存Docker方式の再利用差分を調べた。Git履歴コピーはADR-0150の実装・レビューまで完了している。ユーザーへ「Linux・Python対象の小さな試作設計」と「Windows対象の検証を優先」の2案を提示し、本会話の2026-09-09の回答「１で」により前者が選択された。

## Considered Alternatives

1. Linux・Python対象で既存Docker方式を活かす試作設計を先行する: 保護と担当間の往復を小さな題材で具体化できる。
2. Windows対象を優先して代替環境を比較する: 現行OS範囲を維持できるが、Windows固有の保護条件の解決を先に要する。

## Decision

案1を選ぶ。既存Docker方式を参考に、資料・Git履歴の独立コピー、隔離したテスト実行、結果の回収、修正後の再検証をつなぐLinux・Python対象の試作を設計する。既存のコピー準備を活かし、ホスト上のAIの操作範囲とコンテナ内の実行範囲を別々に確認する。

## Consequences

- Windows固有の動作検証を完了したとは扱わない。先行順序の選択であり、既存Windows部品の撤去を含まない。
- 今回の承認は試作設計の先行。既存LoopForAlpha環境の変更、実エージェント起動、外部送信、通常導入・公開の承認へ拡張しない。
- 方式の詳細と実行可能性の確認事項はIssue-0136の検討ノートで扱い、設計案に利用者の準備作業と判断の分担を含める。
- 2026-09-09、ユーザーが選択した機械検証16項目で追加修正なく詳細仕様を確定したチェックポイントでAcceptedへ昇格。実装前の設計確定であり、隔離動作の成功を意味しない。記録は`docs/records/reviews/2026-09-09-linux-pilot-spec-final.md`。
