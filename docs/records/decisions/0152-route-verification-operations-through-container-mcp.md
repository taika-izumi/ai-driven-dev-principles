# ADR-0152: ホスト上の検証担当の操作を専用MCP接続でコンテナへ限定する

- **Status**: Accepted
- **Date**: 2026-09-09

## Context

Linux試作先行はADR-0151、資料と履歴の独立コピーはADR-0150による。ユーザーは、子AIがDocker外にいるとホストを操作できるのではないかと確認した。専用接続以外の操作手段を制限する必要があり、その実効性は未確認であることを説明した後、「なるほど。理解しました。一旦この案で進めましょう」と回答した。本会話のこの回答を、子AIはホストで動き操作はDocker内へ限定する構成への個別承認とする。

承認時の構成・分担案はIssue-0136の`0136-note-linux-python-pilot.md`（SHA256: `EE029F6786850AF0BEF2031E2B7F3EDB2A0FC6A097E6BA249F1D5220C03A4D27`）。詳細仕様作成までの補助設計をAIが進め、主要な変更・新たな必須依存・保護の緩和・実起動と送信等は相談するという範囲を維持する。

## Considered Alternatives

1. 通常のホストシェルを持つ子からDockerラッパーを呼ぶ: ラッパーを迂回する操作が残る。
2. ホストの子には専用MCP接続を渡し、操作先を固定したコンテナへ限定する: 既存の認証とコピー準備を活かせるが、全操作経路の実効制限が必要。
3. 子AI本体も別環境へ移す: ホストからさらに分離できるが、モデル通信と認証の準備・維持が増える。

## Decision

案2でLinux・Python試作を設計する。既存の準備・実行・回収の3ブロックを維持し、実行ブロックに実行単位のSTDIO MCP接続とDocker管理を置く。子はコンテナ内で検索・編集・テストを行い、ホスト側の信頼する処理が操作記録・結果・停止状態を確認する。

## Consequences

- ADR-0147の共通CLIと3責務を維持し、MCP登録を初回必須にしない範囲を部分変更する。恒久登録は行わず実行ごとの接続にする。
- 原本・機密ファイル・ホストサービスを守るには、コンテナの隔離に加え、子のホスト操作手段が制限されている必要がある。設定受理だけで成立としない。
- 検証担当はCodex、主担当はClaude CodeまたはCodexを維持する。これらの変更を暗黙に行わない。
- Windows上の既存プロセス管理はホスト側に残るが、コンテナ内プロセスの停止確認を代替しない。
- 承認は構成と詳細仕様作成の範囲。保護の実証・運用成功・外部送信や導入の承認を意味しない。
- 2026-09-09、フルレビュー・差分再確認後の採否案と機械検証の選択に対するユーザー回答「１で」を受け、16項目の一致を確認して仕様を確定。実装前のAccepted昇格であり、全体の実装完了時には整合検査と動的実証を行う。記録は`docs/records/reviews/2026-09-09-linux-pilot-spec-final.md`。
