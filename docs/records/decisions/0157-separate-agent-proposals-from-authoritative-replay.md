# ADR-0157: Codexの提案作成と採否用の再実行を分離する

- **Status**: Accepted
- **Date**: 2026-09-09

## Context

sbxのAIなし搬入・回収・停止試験は成功したが、VM内でsudoを持つ子の全操作を制限する旧仕様とは保護境界が異なる。Issue-0136の`0136-note-sbx-after-smoke-design-options.md`に2案を提示し、ユーザーへ処理の流れと旧案との比較表を説明した。ユーザーは「なるほど。案１で行きましょうか。」と回答した。これを案1の基本方針への個別承認とする。詳細仕様と実モデルの起動承認ではない。

## Considered Alternatives

1. Codexの提案と採否用再実行を分離する。子の全試行の制御への依存を減らし、原本と外側の検証を守る。
2. 旧仕様の強制条件をすべて維持し、全操作の外側記録・コピー内Git保護・通信なしを制御する基盤を追加検討する。成立する配置の調査と実装負担が大きい。

## Decision

案1で詳細設計を進める。Codexはsbx内の独立コピーで探索・編集・試行し、提案を返す。ホスト側に原本と基準Gitを保全する。提案されたファイルを検査して回収し、別の通信なし実行環境へ基準版とともに渡す。外側が採否用の再実行・出力・終了・停止を記録する。主担当はClaude CodeまたはCodex、日常の本文転記不要という要求を維持する。

ADR-0152のホスト上の子を専用MCP接続へ限定する構成を置き換える。旧仕様の「子の全試行を通信なし・外側記録」および「子に渡したGitコピーの変更禁止」は採用しない。代わりに「採否用の再実行は通信なし・外側記録」「基準Gitを外側に保全し子のコピーと自己申告ログを信頼しない」を要求する。ADR-0150のファイル・履歴コピーは維持する。

ADR-0148の子のGitコピーを書き込み不可にする部分を変更する。独立したGit管理領域と原本の設定・フック非共有は維持する。

## Consequences

- 子の提案だけで合格にしない。同じテストで修正前の再現と修正後の解消を確認するが、テスト内容の十分性は別に評価する。
- 第2実行環境と回収検査・再実行処理が必要になり、資源消費・実行時間が増える。
- 新たな実行基盤、認証方式、モデル利用費、実送信対象、追加ホスト接続の保護は詳細化して確認する。実モデル起動やホスト保護の追加緩和へ承認を広げない。
- 旧v2仕様・計画は新構成の詳細確定までは保留資料。現時点の実装仕様として再開しない。基本方針は承認済み、ADRの昇格は詳細設計チェックポイントで整合確認する。
- 2026-09-09、ユーザー選択の差分再確認で残指摘0件を確認して詳細仕様を確定し、設計としてAcceptedへ昇格。実装前のため全体整合検査・動的実証は実装工程で行う。確定記録は2026-09-09-proposal-replay-spec-r3.md。
