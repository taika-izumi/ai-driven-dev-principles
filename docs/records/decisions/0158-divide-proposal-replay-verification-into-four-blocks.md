# ADR-0158: 提案と再実行の検証を4つの責務に分割する

- **Status**: Accepted
- **Date**: 2026-09-09

## Context

ADR-0157の基本方針を詳細化するため、既存RequestCopy・Execution・Resultの実体を読み、4機能の分割案を提示した。ユーザーは「１で」と回答し、下記分割と補助設計の分担を承認した。承認基準はIssue-0136の`0136-note-sbx-after-smoke-design-options.md`「基本方針承認後の機能分割案」と本記録に保持する。

## Considered Alternatives

1. 依頼・基準版準備、提案作成・回収、通信なし再実行、結果照合の4責務に分ける。信頼境界と検証責務が明確になる。
2. 提案と再実行を旧実行ブロックへまとめる。ファイル数は少ないが、子の報告と外側の証拠の区別が内部に埋もれる。

## Decision

案1を採用して詳細設計する。準備から再実行へ基準版を直接渡し、提案側に基準版を更新させない。回収検査に通った提案だけを再実行へ渡す。結果照合が原本の状態と実行・停止の証拠を確認する。

今回の詳細設計では、基本方針と4責務を維持する補助的なデータ形式・内部構造・検証手順をAIが作成し、仕様をまとめて提示する。保護の追加緩和、新たな必須基盤や利用者作業、モデル認証・利用費・送信範囲、既存物の削除、公開は個別相談する。レビューの実施や新しい外部送信をこの分担だけで承認済みにしない。

## Consequences

- ADR-0147の共通CLI・準備・実行・回収という全体方針を維持しつつ、実行の責務を提案と再実行に分ける部分変更。
- schemaVersion=3で新構成を識別する。実装済みv1部品と保留中v2構成の成功を新構成の成功に読み替えない。
- 初回は依存取得不要の小さなLinux・Python題材。第2実行環境の具体設定と追加ホスト経路の保護は成立確認が必要。未実証の要件は起動前条件として明記する。
- 詳細仕様を自己確認し、確定前レビューの判断点へ提示する。新構成の実装・認証・モデル起動は未実施。
- 2026-09-09、静的フル1回・差分再確認2回の後、残指摘0件で詳細仕様を確定し、設計としてAcceptedへ昇格。実装前のため全体整合検査は実装完了時に行う。確定記録は2026-09-09-proposal-replay-spec-r3.md。
