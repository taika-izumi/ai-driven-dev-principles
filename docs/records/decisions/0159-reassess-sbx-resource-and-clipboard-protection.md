# ADR-0159: sbxの資源保護とクリップボード条件を目的から再検討する

- **Status**: Accepted
- **Date**: 2026-09-09

## Context

v3実装前の読み取り確認で、sbxのclipboard文字列書込拒否とpids外側強制を確認できなかった。現仕様は起動前条件が不成立ならblockedとする。主担当が「この2条件の保護目的と実現手段を見直す」と「現仕様を維持し提供元に確認する」を提示し、ユーザーは「1で」と回答した。

## Considered Alternatives

1. 保護目的と既製機能を照合して代替手段と残余リスクを具体化する。原本・認証・外側記録など、維持する保護を分けて判断できる。
2. 現仕様の数値・条件を維持し、提供元へ機能の有無を確認する。回答待ちと、対応機能がない可能性がある。

## Decision

案1の再検討を行う。変更案と失う保護、利用者に増える作業を提示してから採否を判断する。この回答はpids128の撤去やclipboard書込許容の承認ではない。

## Consequences

- 確定v3仕様と実機設定はまだ変更しない。詳細な比較はIssue-0136の0136-note-v3-capability-gaps.mdに保存する。
- クリップボード書込は、画像読取禁止やファイル非共有で代替できたと扱わない。
- CPU・メモリの割当とプロセス数の上限を同じ保証と扱わない。変える場合は新たな採否と実証条件を定義する。
- 原本・基準Git・外側記録・認証の保全、通信なし採否用再実行は維持する。新規基盤・外部送信・設定変更は含めない。
- 2026-09-10、再検討を経たADR-0160/0161の条件改訂確定に合わせ、本検討方針を確定。具体的な保護変更の承認根拠は両ADRに分離して保持する。
