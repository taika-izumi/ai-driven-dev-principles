# ADR-0160: 合成題材の試作ではVM資源割当と外側停止を資源保護の基準にする

- **Status**: Accepted
- **Date**: 2026-09-10

## Context

sbx 0.42.1ではpids128を子が緩和できない形で設定する手段を確認できなかった。ADR-0159に基づく再検討で、厳密なプロセス数上限を外し、VMのCPU・メモリ割当、直列実行、時間制限と外側停止を維持する案を提示した。ユーザーは試作限定の意味とclipboard例外を確認した後、「OKです。では推奨案で進めましょう」と回答した。これは小さな合成題材での本変更への個別承認。

## Considered Alternatives

1. pids128の必須条件を維持し、提供元の機能確認や別基盤を待つ。
2. 合成題材の試作に限り、VM資源割当と外側停止の実証を基準にする。ホストの完全な無影響やVM内の応答性は保証しない。

## Decision

案2を採用。vCPU2・ゲストメモリ2048MiB、同時稼働1VM、既存の全体/各実行の制限時間、停止猶予、出力容量制限を維持し、厳密なpids128を起動条件から外す。VM内のプロセス数上限は保証しない。負荷を限定した試験で外側から停止できることを実証するまで、runtimeをverifiedにしない。

## Consequences

- 仕様の数値上限と実行前条件を部分変更する。VM内資源枯渇は失敗として扱い、原本・基準Git・認証・外側記録・通信なし再実行の保護は維持する。
- ゲスト割当の2GiBにホストのdaemon/プロキシ/仮想化の全オーバーヘッドが収まるとは主張しない。
- 対象は名指しで確認した小さな合成題材のみ。実プロジェクトや通常運用への拡張、負荷試験・モデル起動・設定変更は別に具体化する。
- 2026-09-10、差分再確認2回で残指摘0件を確認し、設計としてAcceptedへ昇格。実装・負荷中停止の実証は後続。確定記録は2026-09-10-synthetic-pilot-scope-r2.md。
