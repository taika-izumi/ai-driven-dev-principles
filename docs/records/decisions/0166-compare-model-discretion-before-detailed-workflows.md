# ADR-0166: 独自の開発手順を詳細化する前にモデルへ進め方を任せる比較を行う

- **Status**: Accepted
- **Date**: 2026-09-10

## Context

ユーザーは高性能モデルがタスク分割・委譲を判断できるなら詳細なガイドライン整備に価値があるかを問い、回答後に「その可能性を先に確かめるにはどうすればよいか考えてロードマップに反映してほしい」と依頼した。本依頼による委任は、比較方法・結果による進路の検討とロードマップへの反映まで。実験の起動、利用環境の変更、現行規範の撤去、個別Issueの実装・公開へは拡張しない。

現行ロードマップは公式基盤の再利用と最小構成との比較を含むが、組織運用の先行調査と役割設計が先にあり、進め方をモデルに任せる比較条件が明確でない。独自手順の有用性を測る前に、その手順の整備費用を積み上げる経路がある。Issue-0140・0124の対策と0.1.26公開は完了済みで、運用効果は未評価である。

同日の追加要件として、ユーザーは高性能モデルだけでなくClaude Opusなど他の利用予定モデルでも成果を出せるガイドラインを求めた。これを比較対象と採否条件へ反映する。製品名から固定した性能順位を推定する依頼とは扱わない。

2026-09-10の終了指示「あなたの目でざっと見直し」「次セッションから、またロードマップに沿って…進めていきましょう」と、それ以前の文書改訂の委任に基づき、主担当の自己点検後に比較を先行する方針を確定した。Acceptedはロードマップの方向を対象とし、具体的な実行案・利用上限・操作の承認や比較結果の確定を意味しない。

## Considered Alternatives

1. 既存案の比較の文言だけを補い、先行調査・役割設計を継続する。編集量は少ないが、比較前に詳細化へ投資する順序は変わらない。
2. モデルに進め方を任せる条件と既存ガイドラインを使う条件を、小さな同一課題で先に比較する。準備・実行・採点の費用は必要だが、新たな組織や専用基盤を作らず、追加手順の要否を判断できる。
3. 高性能モデルへ全面的に任せ、比較せず規範を削減する。整備費用を抑えられるが、本プロジェクトでの品質・継続性・権限の充足は未実証で、既知の失敗を受容する根拠が不足する。

## Decision

案2を、独自手順の詳細化に先立つロードマップの次段階として記載する。目的・製品知識・権限・合格条件を共通にし、各モデル内の対比較では同じモデルと実行基盤を使う。モデル裁量の条件では工程・役割数・委譲順序を指定しない。両条件で公式の委譲機能を同様に利用可能にし、委譲しない判断も認める。詳細はロードマップ2節・4.0節を正本とする。

初回候補は不具合修正と小機能追加の2題材、各条件1回ずつ、1モデル計4実行とする。代表2モデルでは計8実行を候補とする。実行前に題材・合格条件・上限を具体化し、小さな対比較から始める。試験条件を分離できない場合はその制約を記録し、無指示のモデル能力を測ったと扱わない。合格条件は実行前に固定し、共通の外部検査で成果物と引き継ぎに必要な情報を確認する。

品質条件を満たす最小構成を起点に、確認された不足だけを既存設定、短い指示、必要な実装の順で検討する。差が不明なときは独自整備の便益を確定せず、判断を変え得る追加確認に限って再試行する。詳細手順の追加を見送る結論も成功とする。

初期評価に高性能モデルと他の利用予定モデルの代表を含め、各モデル内で手順の有無を比較する。共通手順の削減は高性能モデルだけの成功を根拠にしない。必要な品質は共通に保ち、他のモデルで欠落を補える手順は便益として評価する。必要性に応じた追加支援を候補とし、利用モデルをAIだけで除外したり、品質条件を下げたりしない。

## Consequences

- ADR-0139の固定した役割候補への着手、ADR-0140の段階2以降の順序、ADR-0163の直近の次手を部分修正する。公式基盤の再利用、現行利用の保全、実証後の汎用化、操作承認の境界は維持する。旧ADR全体の置換ではない。
- 比較はモデル単体の性能ではなく、指定したモデル・実行基盤・指示構成の比較となる。少数の成功を長期自律運用・別モデル・別案件へ一般化しない。
- 観測機会は初期評価の2モデル×2題材×2条件の実行記録で数える。捕捉したい問題は、必要な品質・継続情報の欠落と、追加手順が便益なしに確認・記録・費用を増やすことである。現時点の実測は0件。
- 今回限りの比較準備と各方式の運用費用を分けて示し、専用の常設計測基盤は作らない。当該モデル・題材でモデル裁量が条件を満たし追加手順の便益が確認できない場合は、その範囲の詳細化を見送り、比較不能なら原因を直せる範囲へ縮小する。広い調査や恒久的な比較工程を維持する前提にしない。

## 過剰適合点検（ADR-0079）

| 観点 | 判定 | 根拠 |
|---|---|---|
| 出所の偏り | 該当なし | 今回の比較実測は0件、対象プロジェクト数・モデル世代数も0。ユーザーの仮説を確かめる本ロードマップ限定の比較案で、特定方式の優位や一般規範の妥当性は主張しない |
| システム種別依存性 | 対象限定 | 小規模なソフトウェア改修を初回対象とする。引き写し箇所: ADR-0140の実証後の汎用化・限定試用と通常配布の分離条件を維持する |
| AIモデル/ツール依存性 | 実行時に条件を特定 | 初期評価に他の利用予定モデルも含め、高性能モデルだけの成功で共通手順を削減しない。モデル名だけで能力・委譲権限を推定しない。引き写し箇所: ADR-0139の公式基盤再利用と導入前の確認、ADR-0133の委任と操作権限の区別を維持する |
| 規範の廃止条件 | 定義済み | 初回比較で目的を満たす構成を選べれば比較準備を終了する。追加手順に便益がなく負担のみ増える結果なら詳細化を見送る。判断を変え得る問いがない追加測定は行わない |
