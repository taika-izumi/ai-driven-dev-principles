# ADR-0168: 初期比較はログ解析の2題材を代表2モデルで段階実行する

- **Status**: Accepted
- **Date**: 2026-09-10

## Context

ADR-0166の比較方針を具体化し、`docs/reference/model-discretion-comparison-preparation.md` の「設計として提示する案」を提示した。ユーザーは2026-09-10、本会話の「この設計案で詳細化する」に「1で」と回答した。承認対象は同案の題材・モデル・合格条件・回数・時間上限・判断の分担で、実験起動は具体的な操作と事前確認結果を示してから判断する。

承認時の基準は、ログ解析ツールの切り出し、日時処理修正と対象セッション指定、GPT-6-Astra/mediumとClaude Opus 5/high、2条件ずつ計8実行、各30分・準備と採点を含め計300分の上限である。人工ログ・固定検査・配置・記録様式・起動手順の詳細化はAIへ委ね、題材・モデル・合格条件・上限の変更、通常環境への影響、追加課金、保護の縮小、比較不能時の進路は相談する。

## Considered Alternatives

1. LoopForAlphaの開発用ログ解析ツールを必要な説明とともに切り出す。人工ログで検査でき、実案件に存在する複数ファイルの改修を比較できる。結果の適用範囲は開発用ツールの小改修に限られる。
2. LoopForAlpha全体の開発用コピーを使う。製品全体に近いが、製品情報と工程指示の分離、入力の選別、実行条件の確認に負担が増える。
3. 新しい無害な小規模リポジトリを使う。準備を抑えやすいが、実案件への対応が弱くなる。

## Decision

案1を採用し、上記2題材・2モデル・2条件の計8実行を初期比較の設計とする。モデルID候補は `gpt-6-astra` と `claude-opus-5[1m]`、推論設定はそれぞれmediumとhigh。まずCodexの不具合題材の対比較で入力・採点・記録回収を確認し、成立時に残りへ進む。各実行30分、作成側240分と準備・採点60分の合計300分を実行段階の上限とする。子と再開は同じ実行の上限を共有する。

同じ合格条件を全条件へ事前に提示し、小機能では共通の2段階の依頼と新規セッションで継続情報を検査する。通常環境と固定検査の保護を実測し、成立しない場合は実験を保留する。比較の入力・実行管理・採点を独立して確認できる3ブロックに分け、人工ログ・成果物・結果JSONで受け渡す。常設基盤を新設する決定ではない。

## Consequences

- **部分修正（ADR-0180）**: 2026-09-11ユーザーの個別指示により、初期比較をAstraとSolの2モデル・2題材・2条件・8実行（各30分、作成側240分）へ変更。モデルによる必要な支援の違いを調べる目的を維持し、Claudeと今回比較のためのsbx整備は保留する。比較の問い・入力・検査・保護と既存記録は維持する。

- **部分修正（ADR-0169）**: 準備60分の到達だけで残作業を止めず、必要性と進捗を条件に次セッションで続行する許可を受けた。新たな90分・330分の数値枠は採用せず、比較本体の各30分・計240分と他の承認境界は維持する。
- 既存実装に対応した小規模な比較となり、必要な品質と継続情報の欠落を共通検査で比較できる。
- 2題材は同じツールに由来するため、モデル全般や製品全体、長期開発への一般化はしない。8実行で統計的な優位を主張しない。
- 所要時間上限は利用量の保証ではない。既存契約枠の扱いはADR-0167に従う。
- 観測は初期8実行を対象とし、条件が成立しなければ後続起動を止める。追加確認は採否を変え得る問いに限る。比較が終われば準備工程を常設化せず、結果から手順の維持・縮小・追加支援を判断する。
- 承認済みの詳細化は繰り返し確認しない。実験起動と、承認基準を変える判断はユーザーへ戻す。ADR-0166を具体化するもので、同ADRと中断中のIssue-0136を置換しない。
