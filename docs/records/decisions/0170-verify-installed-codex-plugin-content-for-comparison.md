# ADR-0170: 比較用Codexプラグインは内容一致を条件に導入済みキャッシュから読む

- **Status**: Accepted
- **Date**: 2026-09-10

## Context

ADR-0168に基づく比較計画Task 2は、固定したプラグインの複製先を実際の読み込み元に指定する。Task 1の診断ではCodexが導入済みキャッシュを参照した。CLIヘルプと公式設定スキーマのPluginConfigには、プラグイン単位の読み込みパス指定がない。これは他の公式経路の不存在を証明するものではない。

2026-09-10、ユーザーは「この案を採用して準備を続ける」に「1で」と回答した。この回答は直前に提示した本ドラフトの案1への個別承認であり、モデル起動の承認は含まない。

## Considered Alternatives

1. 保存済みmanifest・複製・導入済みキャッシュのファイル集合とSHA256が一致する場合だけ、Codexの既存読み込み経路を利用する。内容の固定を維持し、専用導入環境の追加を避ける。
2. 複製先からの直接読み込みを必須のまま保ち、別の公式経路を調べる。現時点で成立済みの方法はなく、追加調査が必要になる。

## Decision

案1を採用する。対象はai-driven-dev-principles 0.1.26とsuperpowers 6.3.0のみ。各実行の前後に保存済みmanifest、複製、実ロード先の全ファイル集合とSHA256を照合する。不一致・ロード先不明・確認不能なら当該実行を比較不能とし、後続起動を止める。作成側からキャッシュへの書き込みを許可しない。Claudeは複製先を指定する既存案を維持する。

## Consequences

- 仕様01と計画Task 2の読み込み元指定だけを修正する。ADR-0168の比較条件を全体置換しない。
- 通常設定・導入内容・認証情報は変更しない。モデル・題材・時間・合格条件・起動承認を維持する。
- 実行中に別プロセスがキャッシュを変更する可能性が残るため、終了後の一致確認まで比較成立を確定しない。
- 実際のモデルによる指示継承と保護の成立は、Task 4の承認後の実測で判断する。
