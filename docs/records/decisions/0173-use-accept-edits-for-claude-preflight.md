# ADR-0173: Claudeの限定事前確認で親子の編集モードをacceptEditsにする

- **Status**: Accepted
- **Date**: 2026-09-10

## Context

Claude・既存手順条件はdontAskで親子の内蔵Writeが拒否された。更新後の登録版0.1.26／6.3.0を確認し、既存候補との差分が親子のpermissionModeだけであることを照合した。2026-09-10、本会話の「変更を採用し、限定再試行を実行する」へユーザーが「1で」と回答した。承認対象の具体的な操作は `docs/records/experiments/2026-09-10-model-discretion-preflight-results.md` の「更新後の確認と追加起動案」に保持する。

## Considered Alternatives

1. 試験用の親子をacceptEditsへ変更し、失敗した条件を1回だけ確認する。許可内編集の成立を直接観測できる。
2. 変更・起動を保留する。利用枠は消費しないが、編集経路の未成立が残る。

## Decision

ユーザーの個別承認により案1を採用する。Claude・既存手順の親CLI1回と定義済みの子1体に限定し、親子ともclaude-opus-5[1m]／highを使う。許可内ファイル作成、専用保護代用品への拒否、子のSkill実応答の読み込み元を確認する。OS保護、公開資料だけの送信範囲、通常設定、固定版を維持する。失敗・不明なら追加起動を止める。

## Consequences

既存契約枠と5〜10分程度の概算時間を消費する。送信・消費は取り消せない。設定差分は戻せるが、成功は実測結果で判定する。本比較の起動・非公開コード送信・全条件の再実行への承認には拡張しない。既存の比較設計ADR-0168のモデル・題材・採点・時間上限を変更しない。
