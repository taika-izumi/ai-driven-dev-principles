# ADR-0174: Claudeの編集拒否を同じ作業場所でプラグイン有無の2回診断により切り分ける

- **Status**: Accepted
- **Date**: 2026-09-10

## Context

ADR-0173の限定試行は編集拒否となった。既存成功例とは作業場所なども異なるため、同一条件でプラグイン指定の有無を比較する候補を保存した。2026-09-10、本会話の操作前レビュー「この2回の診断を実行する」へユーザーが「1で」と回答し、個別承認した。具体的な操作は `docs/records/experiments/2026-09-10-model-discretion-preflight-results.md` の「同じ作業場所でのプラグイン有無診断案」、起動引数は `.tmp/model-discretion-execution/plugin-diagnostic/launch-candidate.json` に保持する。

## Considered Alternatives

1. 同じ作業場所・文字列・Read/Write依頼でプラグインなし、ありの順に2回診断する。既存試行の条件差を減らせる。
2. 起動を保留する。利用枠を消費しないが、編集拒否との関係は未確認のままとなる。

## Decision

ユーザーの個別承認により案1を採用する。Claude Opus 5／high、acceptEdits、親CLI2回、子なし。管理側で無害な試験ファイルを新規作成し、各回はRead1回と同内容のWrite1回だけを依頼する。プラグイン指定とログ保存先以外の引数一致を確認済み。既存ファイルへの同内容書き戻しであり、新規作成拒否の直接再現とは区別する。

公開指示・公開手順・無害な文字列と操作結果のみを送信し、既存のOS保護を維持する。指定外操作・想定外の変更・モデル不一致・起動失敗・Read/Write未実行は後続停止。編集拒否自体は診断結果として2回目へ進める。2回終了後の追加起動は行わない。

## Consequences

概算2〜5分と既存契約枠を消費する。送信済み入力と消費済み利用枠は取り消せない。結果・対象ハッシュ・公式イベント・詳細ログを保存する。通常設定変更、比較本体の起動、非公開コード送信、追加購入、利用枠リセットへの承認には拡張しない。ADR-0168・0169の比較設計と進捗条件を維持し、実施済みADR-0173を置換しない。
