# ADR-0175: フック起動準備は通信を禁止した試験専用設定領域で確認する

- **Status**: Accepted
- **Date**: 2026-09-10

## Context

ADR-0174の診断でSuperpowersの起動フックが通常の.claude/session-env作成時にEPERMとなった。静的調査後、ユーザーは「起動準備だけを確かめる実行検証」という次手へ「OKです。このまま進めましょう」と回答した。今回の対象はinit-onlyによるローカルのフック起動確認であり、追加モデル試行ではない。通常設定を保護し、試験の配置・記録を具体化する既存の委任範囲で以下を選ぶ。

## Considered Alternatives

1. 今回だけ空の試験用CLAUDE_CONFIG_DIRを指定する。通常の設定領域を変更せず、フック用の実行時領域がそこで作られるか観測できる。
2. 通常の.claude/session-envへ書き込みを許す。通常領域への影響を伴うため、今回の起動準備確認では採らない。

## Decision

案1を採用する。元の作業場所・固定プラグインを保持し、そのruntime-temp/init-only-1配下に空の設定領域とログを作る。認証情報・既存設定をコピーしない。CLAUDE_CONFIG_DIRの変更は試験プロセス内だけとし、既存のread-only基底と製品・採点原本の拒否を維持する。ネットワークを禁止し、固定SuperpowersのSessionStartを公式init-onlyで1回起動する。60秒で未終了なら当該プロセスツリーを停止する。失敗時に追加試行は行わない。

## Consequences

Claudeが試験領域に設定・実行時ファイルを作る可能性がある。モデルに依頼を送らず、ログ・終了コード・フック応答・session-envの実体で成否を判定する。通常設定や認証を使う本比較の条件とは異なり、成功してもWrite拒否の解消や本比較成立とはしない。公式資料にあるinit-onlyが実版2.1.267のヘルプに出ていないため、対応有無も結果で確認する。証拠は保存し自動削除しない。
