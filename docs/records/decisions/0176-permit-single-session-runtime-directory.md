# ADR-0176: 通常認証を保つ起動確認では指定セッションの実行時領域だけを書き込み可能にする

- **Status**: Accepted
- **Date**: 2026-09-11

## Context

ADR-0175の空設定領域ではフック起動が成功したが、既存Max認証は参照されなかった。通常設定先では通信禁止のauth statusがclaude.ai・Maxを示した。1セッション領域だけをwriteとするinit-only候補を提示し、ユーザーは「OKです。検証準備段階をこのままやり切ってしまいましょう。」と回答した。提示した限定検証への個別承認と、必要な準備を継続する指示として扱う。本比較の起動まで承認されたとは扱わない。

## Considered Alternatives

1. 通常認証の参照先を維持し、指定セッションのsession-envだけをwriteにする。認証コピーなしで起動準備を確認できる。
2. 空の設定領域を継続使用する。フックは動くが認証情報の移設等が必要になるため、今回の条件では採らない。

## Decision

案1を個別承認に基づき採用する。許可先は `C:/Users/d12an/.claude/session-env/298b62c9-3d37-48aa-8a04-420b5d049e60` の1件。通常設定・認証ファイル・固定プラグインはread-onlyを維持し、通信禁止のinit-onlyを1回実行する。認証情報・設定をコピーしない。既存の保存先やセッション領域があれば停止し、最大60秒で当該プロセスツリーを止める。

初回の未作成先へのmkdir拒否を受け、ユーザーの準備完了指示の範囲で、同じ承認済み領域を管理側で先に作成する補正を採用した。権限範囲を広げず、新しい結果保存先で追加のinit-only1回を実施した。通常設定・通信禁止・モデル依頼なしを維持し、初回の失敗記録を残した。この補正は事前作成の有無による実行時領域の成立を確認するもので、同じ条件の無変更再試行ではない。

## Consequences

通常領域に今回の実行時ディレクトリが残る。通常の設定ファイルは変更せず、作成物と証拠は保存する。起動スクリプトは `.tmp/model-discretion-execution/run-init-only-normal-auth-candidate.ps1`、許可候補は同所のinit-only-normal-auth-candidate.json。フックの正常起動とモデルWriteの成功は別に確認する。必要な後続準備は継続するが、未提示の保護縮小・通常設定変更・非公開コード送信・本比較起動の許可へ拡張しない。
