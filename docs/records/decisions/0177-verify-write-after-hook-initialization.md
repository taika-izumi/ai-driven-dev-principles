# ADR-0177: フック起動準備を整えた条件で無害な同内容Writeを1回確認する

- **Status**: Accepted
- **Date**: 2026-09-11

## Context

ADR-0176で通常認証先を維持したフック起動準備が成立した。ユーザーは公開指示・公開手順・無害な操作結果の送信、Max枠消費、Opus 5/high・子なし・1回という操作前提示の「このWrite確認を実行する」に「1で」と回答し個別承認した。

## Considered Alternatives

1. 起動準備成立後の同条件でRead1回・同内容Write1回を確認する。フック起動とWrite拒否の関係を追加の事実で判断できる。
2. 保留する。利用枠を消費しないが、Write拒否の解消は未確認のまま残る。

## Decision

案1を採用する。起動条件は `.tmp/model-discretion-execution/launch-runtime-ready-write-candidate.json` の1件。通常の認証先を維持し、ADR-0176の指定session-envだけのwrite許可と固定セッションIDを使う。既存の無害ファイルをReadで1回読み、同内容をWriteで1回書く。モデルはOpus 5/high、子なし。追加起動なし、指定外操作・保護対象変化・モデル不一致は停止する。

起動実施時はClaude開始前のWindowsエラー1783となった。空のモデルログと起動エラーを照合したうえで、同じ承認済みモデル依頼を成立させるため起動処理だけを1度再実行したが同じエラーだった。モデル開始は0回のままで、以後の反復を停止した。起動試行2回とモデル依頼の実行数を区別して記録する。

その後の非モデル調査で、同じサンドボックス内のPythonから元の引数を渡す経路はヘルプ表示に成功した。モデル・権限・依頼本文の同一性を照合し、この経路で承認済みモデル依頼を1回実行した。フック成功・Read成功・Write拒否を記録し、追加モデル実行は行わない。

## Consequences

公開した試験指示・固定手順・無害な文字列と操作結果を送信し、既存Max枠を消費する。送信・消費は取り消せない。通常設定・認証・固定資材の保護は維持する。本比較、非公開コード送信、追加試行や親子の包括検証への承認には拡張しない。成功と拒否を実応答で判定し、結果・利用量・実体比較を保存する。
