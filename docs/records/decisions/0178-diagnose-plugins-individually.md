# ADR-0178: Write拒否を固定プラグインの個別読み込み2回で切り分ける

- **Status**: Accepted
- **Date**: 2026-09-11

## Context

フック成功後もWrite拒否が残り、静的調査では内部原因を確定できなかった。ユーザーは「この2回を実行する」へ「1で」と回答した。承認対象は `.tmp/model-discretion-execution/single-plugin-diagnostic-proposal-20260911.json` の2条件、公開手順・無害文字列と結果の送信、既存Max枠消費、指定session-env2件の事前作成である。

## Considered Alternatives

1. プラグインを1つずつ読み込んで2回診断する。個別条件と拒否の対応を追加の証拠で判断できる。
2. 保留する。追加消費はないが切り分けは進まない。

## Decision

案1を採用する。固定版ai-driven-dev-principlesとsuperpowersを各1回、Opus 5/high・子なしで読み込み、同じ既存txtをRead1回・同内容Write1回。通常認証と既存OS保護を維持し、候補に記載した新規session-env2件だけを事前作成する。各60秒で親と捕捉子孫を停止し、起動失敗・指定外操作・保護変化・終了不明なら後続を止める。通常のWrite拒否は診断結果として次条件へ進める。起動経路は前回成立した同一sandbox内Python中継を使う。

## Consequences

送信とMax枠消費は取消不能。内部原因の確定、本比較、追加試行、保護縮小への承認ではない。結果がどちらでも自動で追加起動しない。既存ADRの置換はなく、ADR-0177とは別の実行承認を記録する。

2回を実施し、どちらもRead成功・Write拒否。通常設定・固定プラグイン・対象txt・保護マーカーは不変、親と捕捉子孫は終了した。候補の古い`-C`値は前回成功経路どおり作業ディレクトリへ補正し、Claude引数・依頼・権限設定を照合して起動した。詳細は事前確認結果の「個別プラグイン診断の結果（2026-09-11）」を参照。
