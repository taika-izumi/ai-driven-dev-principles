# ADR-0179: 通常ユーザー権限で同じClaude条件の対照診断を1回行う

- **Status**: Accepted
- **Date**: 2026-09-11

## Context

ADR-0178で両プラグイン単独でもWrite拒否が再現した。ユーザーは具体化を選択後、前回のOS保護を適用しないこと、通常.claude領域への実行時保存、公開手順・無害な操作結果の送信、Max枠消費を明示した「この条件で1回実行する」に「１で」と回答した。候補launch-candidate.jsonの1回を個別承認したものとして記録する。

## Considered Alternatives

1. 通常ユーザー権限で同じCLI条件を動かす対照診断を具体化する。現在の外側サンドボックスとの組み合わせを切り分けられる。
2. 比較を保留する。追加の準備・利用枠消費を避けるが原因確認は進まない。
3. 同じ構成で内部原因を追い続ける。比較開始に至る見通しが弱い。

## Decision

案1を採用する。起動条件は `.tmp/model-discretion-execution/normal-user-diagnostic-20260911/launch-candidate.json`。同じCLI・Opus 5/high・固定プラグイン2件・Read/Write依頼・対象txtを用い、前回と同じコードのPython中継から通常ユーザー権限で1回起動する。外側のcodex sandboxは起動しない。セッションID・記録先・中継の配置は新規とする。

## Consequences

ClaudeのacceptEditsとRead/Writeだけのツール指定は維持するが、前回の試験専用OS保護は適用されない。通常の.claude.json・.claude配下へCLIが実行時情報を保存し得る。依頼が無害でも通常領域の不変や同等の隔離を保証しない。差分・送信・Max枠消費を明示した個別承認に基づく1回に限る。本比較の保護条件は変更しない。

利用者の端末操作や環境構築を必要としない候補を作成した。実行時の自動承認レビューで拒否された場合は無理に実行せず報告する。実行案は1回・60秒停止・追加試行なし。設定変化があっても自動で復元しない。結果は実行環境の関与を判断する材料であり、内部原因や本比較成立の証明とはしない。

1回実施しRead/Write成功、拒否0件。通常settings.jsonは不変、.claude.jsonは9項目で変化し、指定session-envが作成された。詳細と観測の限界は事前確認結果の「通常ユーザー権限での対照診断結果（2026-09-11）」に記録。追加起動は行っていない。
