# ADR-0185: 独立レビューでプロジェクト全体の目的・方針との整合を確認する

- **Status**: Accepted
- **Date**: 2026-09-11

## Context

各種開発に使うガイドラインの改善で、作成側が比較検証の準備長期化に着目し、準備だけに適用する案を設計・編集した。ユーザーが目的に比べて適用範囲が狭い点を指摘し、中断した（ADR-0184）。独立レビュー前の発見であり、現行の独立レビューが見逃した実測ではない。

2026-09-11、本会話でユーザーは「独立レビューの観点として『プロジェクトのそもそもの方針や目的に沿っているか』を明示するように改善」と指示した。この個別指示に基づき、以下の文言・接続を具体化する。目的を作成側の局所的な要約に閉じず、必要な原文と考え方を絞って渡すことを設計理由とする。LLM全般の能力限界や費用削減効果を実証済みとは扱わない。

## Considered Alternatives

1. 既存の仕様適合観点とレビュー委譲に、プロジェクト全体の目的・方針との整合と根拠の受け渡しを明示する。既存工程を使い、目的と局所仕様の食い違いを検査できる。参照確認の追加費用はあるため、関係する原文の所在と節を絞る。
2. 現行の「上流の要求」とレビュアーの自発的探索に任せる。変更費用はないが、作成側が狭めた設計を上流要求として渡すと、その範囲内の整合だけで終わる経路が残る。
3. 目的確認の専用担当・第5観点・全資料の一律読破を追加する。読解・重複確認・集約・維持の負担が増え、必要範囲の原文を渡す既存レビューへの補足で扱えるため採らない。

## Decision

案1を採用する。設計・計画・実装の独立レビューでは、直接の要求との一致に加え、成果物とそのスコープがプロジェクト全体の目的・方針に沿うかを確認する。直近のspec・Issue・ADRや作成者の要約だけで全体目的を代替しない。

委譲元は関連する目的・方針の正本のパスと節、今回の要求・範囲、承認済みの限定理由がある場合はその根拠を渡す。既存資料から特定できる範囲を使い、目的確認のためだけの全資料走査・新規文書作成を要求しない。レビュアーは原文を確認し、局所的な問題への対策が必要な適用範囲を取りこぼしていないか、目的を超える負担を加えていないかを見る。根拠が不足・矛盾している場合は確認できない点を報告し、整合済みとしない。

正当に限定された段階・作業は、その理由と全体目的へのつながりから評価する。全体目的との照合を、今回すべての目的を実装する要求や自動的な範囲拡大へ転用しない。結果は既存のレビュー報告へ根拠箇所とともに残す。

目的整合の定義と入力は`skills/pre-finalization-review/references/review-criteria.md`、実施は`review-procedure.md`を正本とし、`skills/subagent-dispatch/SKILL.md`から確定前レビュー以外の独立レビューにも接続する。正本の分割は、後続の観点整理指示を具体化したADR-0186に従う。4観点、人数・実施判断・保護・指摘採否の既存規定は維持する。

## Consequences

2026-09-11、フルレビュー1回・差分再確認1回と指摘反映を経て、ユーザーが「この内容で確定する」に「念のために1で」と回答した。検証・終了判断は`docs/records/reviews/2026-09-11-review-criteria-finalization.md`を参照。公開は別途判断とする。

上流確認を一段明確にし、確認対象を選ぶ責任と原文で検査する責任を委譲元・レビュアーに分担する。ADR-0133の許可範囲とADR-0165の採否・費用比較は維持し、過去の決定の置換はない。準備継続案の一般化や採用は別の判断として保留する。

今回の誤った限定、承認済みの段階的な限定、根拠不足、目的を超える増設を文書照合の検証例にする。効果の新規モデル試験・独立レビュー実行・公開を、規範改定の指示だけから自動起動しない。

導入後の最初の3件の独立レビューで、既存報告から目的・範囲の不整合の検出と必要な参照負担を確認する。捕捉対象は「局所要求には一致するが全体目的に必要な対象を落とす、または全体目的を口実に承認範囲を広げる」設計。機会・記録が無ければ未評価。既存の要求照合と全件重複し固有の検出がなく、追加読解・記録負担だけが確認された場合は補足の簡素化・撤回を提案する。専用台帳は作らない。
