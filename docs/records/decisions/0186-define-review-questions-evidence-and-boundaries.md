# ADR-0186: レビュー観点を問い・根拠・境界で定義し共通の委譲資料にする

- **Status**: Accepted
- **Date**: 2026-09-11

## Context

ADR-0185の全体目的との整合を追加した後、ユーザーから仕様適合と前提実在の違いを問われた。作成側の説明では、前提実在が根拠・必要性まで扱うこと、仕様適合に追加した負担の確認と採否時の費用比較の境界が十分に伝わらなかった。

ユーザーは本会話で「このタイミングで、レビュー観点の整理をしたい」「コンテキストを持たないAIエージェントでも、レビュー観点を誤解なく理解してレビュー実施出来るように」と指示した。以下は、この指示に基づく文言・参照・例の具体化である。独立レビューの実施許可や、理解可能性の実証済みという意味にはしない。

## Considered Alternatives

1. 既存4観点の名称と検査範囲を維持し、問い・照合対象・指摘根拠・境界例・報告形式を共通文書で定義する。既存参照を保ち、会話に依存する解釈を減らす。参照文書1件の維持・読解費用が加わる。
2. 現行の短い定義へ注意書きを追加し続ける。変更は局所的だが、観点・委譲入力・判断責任が長い実施手順に混在したままで、文脈のない担当へ必要情報を渡しにくい。
3. 観点を全面的に改名・再編し、目的・費用等の担当を増やす。問いの整理はできるが、過去の4観点との対応・各工程の参照・担当分割を変更する費用が増す。現在の検査範囲を説明する目的には不要。

## Decision

案1を採用する。`skills/pre-finalization-review/references/review-criteria.md`を、独立レビューに渡す入力、4観点の定義、重なり・未確認・報告の扱いの正本とする。実施手順は正本へ接続し、サブエージェント委譲には定義の所在と担当範囲を渡す。確定前レビューは4観点を維持し、他の独立レビューは呼び出し側が定めた担当範囲に、全体目的との整合確認を含める。

仕様適合は目的・要求・制約との比較、前提実在は設計理由として使われる事実・問題・保護対象と機構の必要性、実装整合性は実際の接続先・既存の契約・状態との比較、敵対的は失敗条件と到達経路を探す観点として定義する。敵対的は他の観点でも使える検査方法であり、4観点を排他的分類とはしない。同一欠陥は1件へまとめ、関係する観点を併記してよい。

判断の根拠が足りない場合は未確認として不足を示し、問題なし・不要へ換算しない。前提実在の既存5判定（必要・不要・重複・欠落・前提誤り）は根拠を得た場合の分類として維持する。機構の必要性と費用を含む対策案の最終採否は分け、採否の正本とユーザーの権限を維持する。

仮定を置く検討では、与えられた条件内の結論と実環境の成立確認を区別する。これは理解確認で、明示された条件まで資料不足として扱う回答が観測されたための文言調整であり、実環境の安全性の検証を省く許可ではない。

目的・方針の原文と作成側の要約を区別し、正当な作業限定を全目的の同時実装へ読み替えない。レビュー担当が根拠を追える所在・版・関連節を渡すが、全資料の一律読破・各要求の専用台帳は追加しない。

ユーザーが追加で懸念した、把握中の狭い情報を全体方針として渡す経路に対し、入力欄で案内文書から所在をたどり文書の対象範囲を確認することを明記する。既に特定済みで有効な正本は再利用し、特定不能・矛盾は探した場所とともに報告する。正本の探索だけの独立した工程・台帳は作らない。

## Consequences

- **部分修正（ADR-0189、2026-09-12の設計確定）**: 観点を目的・要求、根拠・設計判断、動作・検証・運用、独立した反証へ整理し、品質項目の担当を明示する方針を採用。入力・原文・未確認・報告の趣旨は保持する。スキルへの反映は未実施であり、配布済み規範は従来の状態。StatusはAcceptedを維持する。

2026-09-11、ユーザーが「この内容で確定する」に「念のために1で」と回答し、指摘採否と改訂内容を確定した。終了状態は提示後確定（実質的な収束に至らず）。最終確認は`docs/records/reviews/2026-09-11-review-criteria-finalization.md`、差分回の結果はr2記録を参照。追加のモデル確認・公開は行わない。

ユーザーが理解確認と4観点レビュー、Claudeへの指定資料送信を承認し、Claude Opus 5・mediumで実施した。結果と7指摘の対応案は`docs/records/reviews/2026-09-11-review-criteria-r1.md`および同名JSON。主要な問題は識別できたが、与件の再確認と前提実在の判定に不足が残り、全件合格とはしない。修正後の理解確認は未実施。初回の指摘反映は文言・接続の具体化に収め、最終採否・確定は反復提示への回答で行う。

ADR-0185の目的整合と根拠の受け渡しを継続し、定義・入力の正本の配置を本決定で具体化する。ADR-0117の検査範囲と5判定、ADR-0165の採否順序を維持する。既存4観点の撤去・名前の一括置換・レビュー人数の固定・モデル試験の自動起動はしない。

定義には対比できる事例と、未確認を含む報告例を置く。文書照合と生成検査だけでは、別のAIが誤解しないことを保証できない。会話履歴を渡さずに既知の欠陥・正当な限定・根拠不足を判別できるかの確認案を用意し、実行は追加モデル利用の判断を受ける。

今後最初の3件の独立レビューで、既存報告から観点の混同による見落とし・重複と、必要な参照負担を確認する。理解の相違による再説明や分類のための重複作業だけが増え、検出・報告の改善が見られない場合は定義・例を簡素化する。該当機会・記録が無ければ未評価とし、専用の計数工程は設けない。
