# ADR-0187: レビュー観点の再評価と根拠を自力で探す経路を別課題として扱う

- **Status**: Accepted
- **Date**: 2026-09-11

## Context

ユーザーは、前提実在の名称と意図の伝達、旧意図を今もレビューへ含める必要性、委譲元の文脈理解に依存する資料選択、レビュアーの自由なファイル確認について分析し、Issue起票と対処の要否を判断するよう依頼した。

0.1.27の原意照合で対象列挙・範囲外の明示・適用例への参照の弱化が見つかった。今回の独立担当はツールなしで、渡した資料にADR-0117が無く、自分で追加資料を取得できなかった。過去の全レビュアーの理解不足や名称単独の因果は未検証。一方、既存Issue-0133には全資料を読んでも既存の判断に引っ張られた別の事例があり、全資料の一律読破が解決策とは言えない。

## Considered Alternatives

1. 検出すべき問題からの観点再評価と、独立した根拠探索の成立を別課題として起票する。既存Issue-0075・0112・0133・0136の素材と保護を再利用し、重複実装しない。
2. 前提実在の改名と旧文の復元だけで完了する。局所の明示は直せるが、元の意図が今も必要か、別観点と重複するか、資料不足が再発するかを判断できない。
3. 全資料読破・無制限ツール・新しい多段レビューを直ちに既定にする。閲覧の可能性と毎回の読解量を混同し、読解・集約費用や書き換えリスクが増える。実証前に採らない。

## Decision

ユーザーの判断委任に基づき案1を採用する。Issue-0143でレビュー全体が検出すべき欠陥と観点構成を、Issue-0144で委譲元が渡し忘れた根拠を担当自身が探せる情報アクセスを扱う。名称や原意の復元、観点数、具体的なツール構成の採否は決めない。単なる名称変更を十分な対処としない。

必要性は高く、次の整備対象とする。最初に0144の読み取り・検索だけの最小経路が既存機能で成立するか確認し、その範囲で0143の観点候補を検討する。0144全体や独自の隔離基盤の完成を、観点設計の開始条件にはしない。広い閲覧可能範囲と、目的に応じた限定的な読解を両立する方向を検討候補とする。

Issue-0075には今回の文書理解の事例を追記する。多層レビューの役割分担（0112）、既存判断への係留（0133）、実行保護（0136）とは責務を分け、これらの全体再開・拡張を今回の起票から自動実行しない。

## Consequences

旧意図は必要な検査を考える材料として使い、歴史上採用されたというだけで維持を確定しない。不要・重複・保護の欠落・根拠誤りを防ぐ必要が現在もあるか、どの観点・確認方法へ置くかを評価する。

「必要な情報だけ渡す」は、委譲元が必要性を正しく判断できることを保証しない。初期資料を絞ることと、追加根拠を独立に閲覧・検索できないことを分ける。全ファイルへアクセスできても必ず発見できるとはせず、閲覧・検索権限と書き換え・コマンド実行権限も分けて設計する。

今回は分析・起票・優先順の判断まで。規範改定・モデル試験・プロジェクト全体の外部送信・公開版更新は実施しない。後続で必要な実行条件と対象を具体化する。

確定根拠: ユーザーの「現在の状況を分析し、Issue起票して対処していくべきか判断してください」による判断委任。Issue索引・関連課題と中央作業ログの在庫を照合し、0075は初見の利用可能性、0112は層間の分担、0133は既存判断への係留、0136は操作保護であり、新規2件の一般形とは区別できることを確認した。観点・ツール構成の採用ではなく調査と課題管理の決定なので、規範実装のサイクル全体整合検査は非該当。課題の解決は未完了のためopenを維持する。
