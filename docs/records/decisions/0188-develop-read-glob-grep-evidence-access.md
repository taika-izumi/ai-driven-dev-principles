# ADR-0188: 根拠探索の最小候補としてRead・Glob・Grep構成を具体化する

- **Status**: Accepted
- **Date**: 2026-09-12

## Context

ADR-0187に沿うIssue-0144の調査で、Claude CLI 2.1.268の内蔵ツールをRead・Glob・Grepに限定する指定方法を確認した。調査記録は `docs/records/experiments/2026-09-12-review-evidence-access-investigation.md`。

ユーザーの「1で」を最小候補の具体化を進める指定として受け取り、その解釈を明示した。続いて、能力比較ではなく環境案の成立を検証する目的を説明し、ユーザーが「OK。進めましょう」と承認した。外部送信の自動承認拒否後、内部情報を含み得る275ファイルのClaude送信と実行を明記した選択肢1に対し、ユーザーが改めて「1で」と承認した（2026-09-12）。承認した起動条件と対象は `docs/records/experiments/2026-09-12-review-evidence-access-preparation.md`。

## Considered Alternatives

1. 既存CLIのRead・Glob・Grep構成を具体化する。文書の横断探索に必要な既存機能を利用できる。
2. 履歴取得用の限定接続を先に実装する。履歴への到達範囲は広がるが、接続の検証・保守が必要になる。
3. ツールなしで主担当が選んだ資料だけを渡す。今回調べる独立した根拠探索を試せない。

## Decision

案1を具体化し、Claude Opus 5・mediumの新規1実行、最大10分で環境の成立を検証する。対象版48c9a1cのskills・docs/overview・docs/current・docs/records/decisionsの275ファイルを複製し、Read・Glob・Grepだけを公開する。通常認証・実行時保存と、取得資料のAnthropicへの送信は上記の個別承認に基づく。今回の判断は実証候補の選択であり、常設運用・規範への採用ではない。既存CLIで指定可能な読み取り・検索機能から検討することで、独自基盤の構築を先行させない。

## Consequences

Read・Glob・Grepによるファイル探索とGit履歴へのアクセスは区別する。モデルが根拠を発見できること、公開ツールの実効制限、閲覧範囲の成立を別々に評価する必要がある。未解決の試験条件と履歴の扱いはIssue-0144の検討対象として維持する。

既存の操作保護規範は変更しない。追加実行・常設採用へ今回の1回の承認を拡張しない。個別承認と送信承認が揃ったためAcceptedとした。タイトルは最小構成の具体化という一つの問いに対応し、恒久的な新規範・仕様の変更はないためサイクル全体整合検査は非該当。
