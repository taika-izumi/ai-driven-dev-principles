# ADR-0190: プロジェクトの目的・方針の正本を開始・再開・委譲で参照する

- **Status**: Proposed
- **Date**: 2026-09-12
- **設計状態**: 2026-09-13確定（R3で実質的な収束）。実装・検証後にAcceptedへ昇格する。

## Context

本ガイドラインは、利用者が満足できる品質と保守・拡張に必要な記録・構造を維持し、AI利用費用・所要時間・将来の維持変更負担を抑える。品質・権限・継続情報の不足を速度で相殺せず、見積もりだけのために計測・帳票・確認会話を増やさない（ADR-0130・0183、ロードマップ）。

継続判断の検討で主担当が、準備に限定したADR-0184の中断を推薦時に拾わず、その後も目的関数の確認より利用者の感情の分析へ論点を寄せた。目的を記録した文書は既に存在していた。詳細は `docs/reference/stage-three-preparation-and-delegation.md` の2026-09-12再照合・対話補足を参照する。これを当時の全判断の単一原因とはしない。

現行start-workのPhase 1は今回の作業目的を扱うが、継続経路はPhase 0からPhase 2へ進む。handoffの目的は局所作業の目的である。ADR-0185・0189の全体目的入力は独立レビューを対象とし、開始・再開・レビュー以外の担当への到達を一律には定めていない。

2026-09-12、ユーザーはプロジェクトの現在の目的・方針を定義し、毎回の担当が把握できる仕組みを提起した。正本再利用・未定義時の草案、開始再開の共通処理、担当への受け渡し、変更と配布時の保全、判断を伴う確認を先行する提案に「OK。この案で進めていきましょう」と回答した。これを設計・改修への個別承認とする。継続判断そのものの規範とADR-0184の旧案は採用していない。

## Considered Alternatives

1. **既存正本を特定し、開始・再開・委譲で参照する**。参照と正本維持の負担は生じるが、既知目的の再質問・歴史資料の再探索・本文複写を減らす。既存の開始・引き継ぎ・委譲を補う。
2. **現行の作業意図確認とレビューだけで扱う**。追加負担はないが、局所目的だけで再開し、利用者の訂正に依存する経路が残る。今回の目的を毎回取得する要求を満たさない。
3. **全目的・履歴を常時指示へ列挙するか、共通の自動注入基盤を新設する**。常時入力、同期、提供元別実装の負担が増える。現行AGENTS→start-workで特定・参照を具体化できる範囲に対し、追加基盤の便益は未実証である。

## Decision

案1を採用する。詳細の正本は `docs/current/specs/2026-09-12-project-purpose-context/00-overview.md` と3つのブロック仕様に置く。本ADRは理由・採否・評価根拠を持ち、同じ詳細仕様を複写しない。

- プロジェクト固有の正本指定を優先し、未指定時は `docs/overview/project-purpose.md` を標準入口とする。既存の適切な文書・節を再利用できる。製品目的と、開発方法を選ぶ共通基準は区別して併用する。
- 目的の特定・確認・変更、ワークフローへの接続、導入更新・検証の3責務へ分ける。初稿は主要機能が一つであることから分割不要としたが、既存のstart-work・session-handoff・subagent-dispatch・pre-finalization-reviewにまたがる契約変更を含むため、現行しきい値に従い分割仕様へ訂正する。
- 新規・継続の分岐前に現在の正本と今回の依頼・承認範囲を照合する。目的の根拠を参照できなくなった場合も再取得する。目的の再承認・毎応答の全文再読・読了証明の専用ログは要求しない。
- 根拠の所在と参照した内容を識別できる形で渡す。目的変更の確定内容と正本の更新が分かれた場合は、未反映の変更と根拠を保全し、可読な旧正本を黙って最新版としない。全ファイルのハッシュ管理や新しい承認台帳は作らない。
- 未定義時は既存資料から確定事項と草案を分ける。正本・案内の永続化は今回の範囲・権限内で行い、読み取り専用作業に文書作成を強制しない。目的の不明が影響する判断だけを相談する。
- 子へ必要な目的・原文・出所を渡し、担当範囲との不一致は親へ報告させる。全体のstart-workは主担当が担い、子は必要な目的の特定・読取りと担当範囲の確認を行う。この分担をAGENTS・start-work・委譲の既存指示に揃え、子によるhandoff・ADRの重複作成や権限拡張を防ぐ。
- 本リポジトリの目的を既存の採用済み方針から蒸留し、ロードマップはその正本を参照する。固有の目的本文は配布物に含めず、既存利用側の固有指示・正本指定を保持して共通部を統合する更新手順を案内する。

## Consequences

目的に到達する責務が主担当・引き継ぎ・委譲でつながる。正本の維持・読み取り・更新時の整合に追加負担が生じるため、既存文書・既存記録を使い、問題のない再利用と限定作業を妨げない。目的が必ず記憶されるという技術的保証や判断改善の効果は未実証である。

ADR-0130の要求充足・概算、ADR-0133の許可境界、ADR-0185・0189の全体目的レビューは維持する。ADR-0184は中断・Proposedのままとする。Issue-0118の情報到達全体、Issue-0145の履歴調査十分性、継続・切替・保留の判断規範まで解決したとは扱わない。初回比較・Claude/sbx・Issue-0136は再開しない。

目的の不一致を隠すために目的を変える、全体目的を口実に範囲を広げる、既知目的を毎回問い直す挙動は後退として扱う。評価のための新たな環境整備を自動的に拡大しない。

## 新設の評価可能性

実装後の最初の3件の開始・再開を、既存handoff・会話・レビュー記録から復元できる範囲で確認する。開始か再開を各1回の機会とし、少なくとも1件の目的参照を見込む。捕捉対象は目的を未取得・旧版のまま判断し、要求に必要な条件を落とす、または不要な再質問をすること。専用の恒久台帳・監視は追加しない。

判断の改善がなく追加読解・確認だけが増えた観測は簡素化・撤回側、誤った目的や範囲拡大、正常な限定作業への妨害が残る観測は修正側の材料とする。機会・記録不足は未評価であり、不要の根拠にしない。改定後の判断比較と配布整合の検証範囲は仕様03に記載する。
