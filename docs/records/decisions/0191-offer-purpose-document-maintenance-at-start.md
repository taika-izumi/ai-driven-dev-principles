# ADR-0191: 正本を確認できない開始・再開では目的整備を作業候補に含める

- **Status**: Accepted
- **Date**: 2026-09-13

## Context

ADR-0190は目的の取得と未整備時の既存根拠の利用を定めたが、既存資料から目的を把握できれば、正本の整備が作業候補に現れない経路が残る。ユーザーは2026-09-13の本会話で、start-work実行時に正本を確認できなければ、毎回そのセッションの作業候補の一つとして整備を提案するよう明示した。整備の強制は求めていない。この個別指示と、Sol/high 1体のレビュー後に実装する選択「1で」を根拠とする。

## Considered Alternatives

1. 既存の目的取得と次手提示を補足する。取得結果を使って候補を一つ提示でき、追加の探索・台帳・工程は不要。継続運用の負担は未確認時の短い候補提示となる。
2. 現行のまま未整備を許容する。追加負担はないが、既存根拠を読めた場合に整備候補が出ないため、今回の要求を満たさない。
3. 正本作成を開始条件にする。整備は進むが、限定作業や読取り専用作業を止め、ユーザーの求める候補提示を超える。

## Decision

既存start-workの目的取得と作業候補提示を補足する。正本を確認できない場合は、新規・再開の双方で「プロジェクトの目的・方針の正本の整備」をそのセッションの作業候補に含める。前のセッションで見送った場合も、次回start-work実行時に未確認なら再提示する。同一実行中のPhase 2ループでは同じ候補を繰り返さない。

既存の特定手順を経ても正本が未定義・不存在・読取不能の場合を対象とし、指定先がある場合は参照先の確認・復旧を含む候補として示す。明示指定がなくても標準入口で確認できた場合や、適切な既存文書が正本として指定され確認できた場合は、整備候補を追加しない。正本未整備で既存合意だけ確認できた場合も、目的自体が未確定の場合も提示対象とする。

候補への掲載は着手の決定ではない。read-onlyでも候補を提示できるが、整備は既存の作業範囲・権限の条件に従う。不明が影響する判断だけを相談するADR-0190の扱いを維持する。

## Consequences

start-work本体の開始・再開と候補提示の接続、およびreferences/project-purpose.mdを変更し、現行仕様・READMEの説明を整合させる。session-handoff単独readや子への委譲へ候補提示義務を拡張しない。ADR-0190の目的参照機構を補足し、その判断全体を置換しない。

検証条件は現行仕様03の整備候補提示の表に置く。標準入口での確認成功と、正本・既存合意の双方がない状態も含める。公開・導入は今回の変更指示に含めない。

Sol/high 1体のフルレビューでMajorなし・Minor 1件（F01）。明示指定の不在と、標準入口まで調べた後の正本未確認の区別を採用した。条件と検証例の明確化はユーザーが承認した目的・範囲内であり、追加モデル呼出しは行わず、主担当による原文照合・机上経路確認と機械検査へ進める。独立再レビューによる収束とは扱わない。原報告・採否・限界は `docs/records/reviews/2026-09-13-purpose-maintenance-candidate.md`。

## 評価可能性

2026-09-13、実装・配布生成・機械検査と主担当の机上経路確認、固定5観点の全体整合検査を完了しAcceptedへ昇格。予定版0.1.29を維持し、公開・利用環境への導入は未実施。

導入後の最初の3件のstart-workを既存会話・handoffから確認できる範囲で調べ、正本未確認時の候補漏れを捕捉する。未確認の機会がなければ効果は未評価。候補提示が判断に役立たず反復負担だけになるとユーザーが評価した場合は、頻度の縮小・撤回を検討する。専用台帳は作らない。
