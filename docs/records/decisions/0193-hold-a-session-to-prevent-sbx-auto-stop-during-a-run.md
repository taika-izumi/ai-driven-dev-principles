# ADR-0193: 隔離検証の実行中はセッションを保持してsbxの自動停止を避ける

- **Status**: Accepted
- **Date**: 2026-09-15

## Context

sbx 0.42.1 のVMは、クライアント接続（`exec`・`cp` 等のセッション）が全部切れてから30秒で自動停止し、次の `exec`・`cp` が停止VMを自動起動する（`docs/reference/sbx-sandbox-runtime-facts.md`、2026-09-14の実測）。隔離検証の共通起動処理（仕様 `docs/current/specs/2026-09-09-isolated-verification/`）は、1つのVMに対して搬入→照合→実行→停止を順に行うため、コマンドの間隔が30秒を超えるとVMが再起動され、メモリ上の状態と実行中のプロセスが失われ、停止の証拠も分断される。仕様02は「停止中の自動再起動防止」を起動前確認の条件に挙げるが、実現手段は定めていない。

実装計画 `docs/working/plans/2026-09-14-isolated-verification-v3-implementation.md` の初回確定前レビュー（2026-09-14、claude-opus-5）は、計画が置いたセッション保持の機構を「実体合わせの調整」と分類したことを誤りと指摘し（M9）、保持を起動する手段が計画に無いこと（C2）も指摘した。ユーザーは2026-09-15に選択肢1「セッション保持方式を採り、実VM試験に約30分の連続保持で切れないかの確認を加える」を選び、「30分という値自体に意味はないが、長期稼働の試験をしないのは良くないので動作確認も行う」と述べた（ユーザーの個別承認）。

## Considered Alternatives

1. セッション保持方式。VM作成直後に `sbx exec <VM> sleep <停止猶予の期限までの秒数>` を背景プロセスとして起動し、停止直前に止める。搬入・照合は1回で済み、証拠が分断されない。
2. 再起動前提方式。保持せず、各コマンドの直前に自動停止の痕跡を確認し、あれば搬入と照合をやり直す。機構は減るが、30秒を超える間隔のたびに搬入が繰り返され、提案作成中の子プロセスが消える経路が残る。
3. 製品設定で自動停止の猶予を変えられるかを先に調べる。未確認であり、見つかっても設定変更は別承認になる。

## Decision

案1を採用する。SbxRuntime はVMの作成確認後に保持用の exec を背景起動して SandboxHandle に保持する。`Stop-VerificationSandbox` は保持を生かしたまま `sbx stop` を発行し、停止を確認してから保持プロセスを止める（保持を先に切ると30秒の自動停止猶予が始まり、`stop` の完了がそれより遅れた場合に自動停止の行だけが残って停止未確認になる経路があるため。実測の試験Cはこの順序で成立している）。保持プロセスは既存のジョブ機構の配下に置き、CLI本体が終了すればジョブごと止まる（その後は製品の30秒自動停止が働く）。保持プロセスの終了をVM停止の証拠にせず、停止確認は `ls --json` の同一ID・stopped と、stop発行後の daemon.log の行で行う。run途中に自動停止の痕跡（`auto-stopped runtime`）があれば当該runを失敗にする。

改訂記録: 2026-09-15、実装計画の第2回確定前レビュー（claude-opus-5）の指摘 m-2 を受け、停止時の順序を「保持を止める → `stop`」から「`stop` → 停止確認 → 保持を止める」へ改めた（ユーザーの個別選択。代替案は、順序を変えず自動停止による停止を第3の状態として記録する案で、判定の種類が増え停止の証拠が製品の自動停止に依存するため採らなかった）。

保持中の長時間挙動は未実測のため、実VM試験（計画のタスク8）で、設定上限に近い約30分の連続保持中にVMが停止・切断されないことを1回確認する。

## Consequences

- VMに割り当てた資源（試作では CPU 2・メモリ 2GiB）は、run の間（全体上限 totalSeconds＋停止猶予）占有され続ける。上限は道具の設定値であり、規範の値ではない。
- 保持は隔離の保護（別カーネルのVM・ホストのマウント無し・通信拒否）を変えない。製品の自動停止は資源回収の仕組みで、これを保持で満たすのは利用者が対話シェルを開き続けるのと同じ状態である。
- 背景起動と停止の操作（`Start-VerificationBackgroundProcess`／`Stop-VerificationBackgroundProcess`）を Execution 側に足す必要があり、計画のタスク2で試験する。
- 提案フェーズの子（Codex）には依頼文で残り時間を伝えるが、それは助言であり、強制は外側の時間上限で行う。時間超過の run は新しい run でやり直す（現行仕様の方針を変えない）。
- 本ADRは仕様02の実現手段の追加であり、ADR-0157/0158/0160〜0162 を置換しない。Proposedで個別承認を保存し、サイクル全体整合検査を伴う次の確定チェックポイントで昇格する。
