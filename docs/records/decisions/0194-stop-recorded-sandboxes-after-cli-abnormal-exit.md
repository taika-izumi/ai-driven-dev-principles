# ADR-0194: CLI異常終了後は記録済みIDだけを止める復旧操作で停止を確認する

- **Status**: Proposed
- **Date**: 2026-09-15

## Context

仕様 `docs/current/specs/2026-09-09-isolated-verification/00-overview.md` の成功基準V5は「出力超過・時間超過・CLI切断時の停止、対象外VMの継続、停止未確認時の失敗扱い」を求め、04は「CLI異常終了時は外側停止担当が記録済みIDだけを処理する」「CLIを終了させるだけでVM停止扱いしない」と定める。実装計画 `docs/working/plans/2026-09-14-isolated-verification-v3-implementation.md` の草案はこの2要素をどのタスクにも割り当てず、実VM試験からも除外していた。初回確定前レビュー（2026-09-14、claude-opus-5）はこれを根拠のない範囲の縮小と指摘した（M4）。

実測（`docs/reference/sbx-sandbox-runtime-facts.md`）では、CLIが落ちるとセッション保持のプロセス（ADR-0193）もジョブごと止まり、30秒後に製品の自動停止が働く。したがってVM自体は最悪でも止まるが、止まった事実と経緯が道具の記録に残らず、次のrunは「動いているVMがあれば新規作成を拒否する」設計のため、停止が働かなかった場合に全runがblockedになる。

ユーザーは2026-09-15に、用語（対照・利用者・記録の所在）を確認したうえで選択肢1「記録済みIDだけを止める復旧操作を設け、実VM試験でCLIの強制終了時の挙動も確認する」を選んだ（ユーザーの個別承認）。

## Considered Alternatives

1. `Stop-VerificationRecordedSandboxes` と CLI の入口 `-StopRecorded -RunRoot <path>` を設け、`control/runtime/*-sandbox.json` に記録されたIDだけを名指しで停止・確認して結果を残す。実VM試験で、実行中のCLIを強制終了し、保持プロセスの消失→30秒後の自動停止→復旧操作が記録済みIDだけを扱い既存VMに触れないことを確認する。
2. 適用外とし、製品の30秒自動停止に委ねる旨と残余リスクを計画に明記する。実装は減るが、切断後の停止が記録に残らずV5の当該項目は未実証のままになる。
3. 復旧操作は設けるが実機確認は行わず、偽sbxの試験だけで済ませる。自動停止との組み合わせが実機で確認されない。

## Decision

案1を採用する。復旧操作は次の条件で作る。

- 対象は指定した runRoot の `control/runtime/` にあるVMのIDと名前だけ。記録に無いVMには触れない（`ls --json` の同一IDで照合し、名前の接頭辞一致で選ばない）。
- 停止は `phase=cleanup` の予算で行い、`ls --json` の同一ID・stopped と daemon.log の行で確認して、結果を `control/runtime/recovery-<時刻>.json` に CreateNew で残す。
- 使うのは道具を呼び出した主担当のAIまたは利用者で、CLIの結果JSONが返らなかった後に限る。VM内の子には渡さない。
- CLIは開始時に runRoot を診断出力（stderr）へ表示し、結果が返らなくても復旧操作に必要なパスが分かるようにする。
- 実VM試験（計画のタスク8）で、CLIプロセスの強制終了後の自動停止と復旧操作の挙動、既存の試験VM2台の状態不変を1回確認する。電源断などホストごと失われる切断は対象にしない。

## Consequences

- 道具に入口が1つ増え、その誤用を防ぐ責任は「記録済みIDだけ」という実装と試験に依存する。偽sbxの試験で記録外VMへの stop が0件であることを検査する。
- 切断の瞬間にVMを止めるのは製品の自動停止であり、復旧操作はその後の確認と記録を担う。仕様の「CLIを終了させるだけでVM停止扱いしない」はこれで満たす。
- 実VM試験に、CLI強制終了の1回分（VM作成・30秒待機・復旧操作）の時間が加わる。
- 本ADRは仕様04の「外側停止担当」の実現手段の追加であり、ADR-0157/0158/0192/0193 を置換しない。Proposedで個別承認を保存し、サイクル全体整合検査を伴う次の確定チェックポイントで昇格する。
