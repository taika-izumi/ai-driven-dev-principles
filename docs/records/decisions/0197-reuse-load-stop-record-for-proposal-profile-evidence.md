# ADR-0197: 提案用実行設定の証拠は提案用VMで取り直し、負荷中の外側停止だけ再実行用の既存記録を使う

- **Status**: Accepted
- **Date**: 2026-09-15

## Context

仕様 `docs/current/specs/2026-09-09-isolated-verification/00-overview.md` は「提案用と再実行用は別の実行設定を持つ。同じ製品であっても保護条件を共用済みにしない」と定め、仕様02は verified とする実行設定の条件（ホスト経路の拒否、資源割当の実効値と負荷中の外側停止、通信・認証の条件など）を列挙する。再実行用（agent=shell、通信全拒否）の証拠は、2026-09-14 に実施した試験A〜C（SSH転送の拒否・資源実効値・負荷中の外側停止。`docs/records/experiments/2026-09-14-v3-capability-test-methods.md`）と実装計画のタスク8で揃う。

提案用（agent=codex、承認されたモデル接続先だけを許す通信）については、実装計画の第6回確定前レビュー（2026-09-15、claude-opus-5、MA-1）が、既存記録を「通信なしのVMの記録なので流用しない」とした一方で試験A〜Cの再実施を承認範囲に含めておらず、提案用の実行設定が verified になり得ないと指摘した。

ユーザーは2026-09-15に、案1（通信・認証以外の成分はすべて既存記録を流用）の懸念——agent 種別で VM 内の構成が変わりうるため「通信設定以外が同一なら結果は同じ」は未検証の仮定であること、仕様の読み替えが前例になること——の説明を受けたうえで、案3を選んだ（ユーザーの個別承認）。

## Considered Alternatives

1. 通信・認証に関わらない成分（SSH転送・ホスト経路の実体、資源割当の実効値、負荷中の外側停止）はすべて既存記録を役割非依存の証拠として使い、通信・認証の成分だけを提案用VMで取り直す。追加費用は最小だが、agent 種別による差異を未検証のまま「同一」と扱う。
2. 提案用VMで試験A〜Cをすべて再実施する。仕様どおり厳密だが、負荷試験を含む実施1回分（30分前後）と承認の提示内容が増える。
3. 数秒で取れる成分（SSH転送・ホスト経路の拒否、CPU・メモリの実効値）は提案用VMで取り直し、負荷投入を要する「負荷中の外側停止」だけ既存記録を使う。読み替えは「負荷中でも外側の停止が効くことはデーモン側の停止機構の性質で、VM内の agent 種別に依存しない」の1点に限る。

## Decision

案3を採用する。実装計画のタスク9で提案用の証拠取得VMを2台作り（1台目: 照会・対照・ゲスト側確認と外側からの停止確認、2台目: 外側CLI異常後の自動停止と復旧操作。自動停止で終わるVMでは外側停止を観測できないため台を分ける）、タスク8a と同じ照会に加えて、試験Aのゲスト側の否定確認（SSHエージェントのソケット不在、透過プロキシの中継ポートへの応答、policy log）と試験Bのゲスト側の実効値（`nproc`・メモリ量）を取り、提案用 profile の `hostPathIsolation`・`resourceAndOutsideStop` の証拠にする。負荷中の外側停止だけは既存記録（試験C）を証拠に使い、負荷なしの外側停止は1台目の提案用VMの停止で観測する。通信・認証の成分（`modelEndpointAllowOnly`・`credentialMethod`・通信拒否の範囲）は提案用VMで取る。外側CLI異常後の自動停止と復旧操作（`abnormalExitRecovery`）も提案用VMで1回取り、再実行用の記録を流用しない。

改訂記録: 2026-09-15、実装計画の第7回確定前レビュー（claude-opus-5）の指摘Bを受け、外側CLI異常後の自動停止と復旧操作を「提案用VMで取り直す」側に明記した（本決定の原則「数分で取れるものは提案用VMで取り直す」の適用であり、例外の拡張ではない）。同日、第8回レビューの指摘4を受け、証拠取得の提案用VMを1台から2台に訂正した。ユーザーへの当初の説明「追加のVMは増えない」は誤りで、訂正の説明（2台の利点は提案用設定に対する直接観測と原則との一貫性、費用はVM作成1回と自動停止待ち）を受けたうえでユーザーが2台を選んだ（ユーザーの個別承認）。

## Consequences

- 仕様00の「保護条件を共用済みにしない」に対する例外は「負荷中の外側停止」の1点で、対象は synthetic-pilot に限る。通常運用へ広げる場合は提案用VMでの負荷試験を別承認で行う。
- 追加費用は提案用VM 2台分（1台目は数本のコマンドと外側停止、2台目はVM作成1回・約30秒の自動停止待ち・復旧操作）で、いずれもAIが実行し利用者の作業は増えない。通信許可と資格情報の設定を持つVMが数分間余分に存在するが、モデルは呼ばない。タスク9の承認提示にVM名とこれらのコマンドを含める。
- agent 種別による VM 内構成の差異は、取り直す成分については実測で確認され、負荷中の停止については未確認のまま残る（その旨を実験記録と結果の未確認範囲に書く）。
- 本ADRは ADR-0157/0158/0192〜0196 を置換しない。Proposed で個別承認を保存し、サイクル全体整合検査を伴う次の確定チェックポイントで昇格する。
