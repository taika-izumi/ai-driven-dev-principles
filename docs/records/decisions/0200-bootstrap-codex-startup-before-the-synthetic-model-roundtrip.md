# ADR-0200: 最小のCodex起動確認を先に行い、同じ条件で合成題材を往復させる

- **Status**: Proposed
- **Date**: 2026-09-17

## Context

Task9の2台の証拠取得は完了したが、仕様02が要求する画像内Codexの版・絶対パス・非対話stdin/終了/出力の実証が残る。これがないままproposal profileを生成すると、未実証の起動方法をverifiedとして本番経路へ渡す循環になる。利用者の「進めてください」を受け、モデル往復の具体的な操作案を用意した。2026-09-17、利用者が具体的な操作案へ「1で」と回答し、モデル・送信範囲・新規最大5VMの個別承認を得た。Statusは全体整合検査までProposedを維持する。

## Considered Alternatives

- ホストCLIの起動argvからprofileを先に確定する: 画像内版での実証という仕様条件を満たさないため採らない。
- 小さな起動確認を先に行う: VM1台と短いCodex実行が増えるが、モデル側の不具合と公開CLIの統合不具合を切り分けられる。
- 共通CLIへ初回だけ検査を飛ばす経路を足す: 製品の保護条件を弱め、今回不要な実装・維持負担を増やすため採らない。

## Decision

起動確認を新規VM1台で先に実施し、画像内の版/パス/ヘルプと、固定stdin・マーカー生成・終了0・応答を実測してからprofileを生成する案を採る。モデル候補はホスト側で利用実績があるgpt-5.6-sol、推論強度medium。モデルの提供情報とOAuth経路の実測は区別する。

その後に同じモデルと起動条件でCodex主担当から合成題材1往復を行う。起動確認1台、候補比較3台、修正後recheck1台の最大5台・逐次実行。Claude Code主担当からの実証は除外せず後続に残す。具体的な送信内容・境界・時間上限は`docs/working/plans/2026-09-17-task9-model-roundtrip-approval.md`へ記載する。

## Consequences

製品のprofile検査を迂回しない。既存8台を起動せず保全できる一方、新規1台と短い起動確認が追加される。モデルやヘルプが想定と違う場合は停止し、別モデル・更新・許可先追加・追加試行を自動で行わない。今回の順序はTask9全体のスコープ削減を意味しない。今回の個別承認の範囲内で実施し、追加試行・範囲拡張は別の判断とする。

## 実施時の前提不一致

2026-09-17、新規1台ab0a2b42の起動前確認で、固定digestがshell版でCodex未収録と判明した。停止・元の8台保全を確認し、モデルは未送信。Issue-0151へ分離し、公式codex画像への変更と証拠の取り直しを含む新規最大6台を別案として提示する。本ADRの最大5台の承認を画像変更へ流用しない。
