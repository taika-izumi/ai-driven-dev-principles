# ADR-0201: 提案用にはCodex収録済みの固定テンプレートを使う

- **Status**: Accepted
- **Date**: 2026-09-17

## Context

Task9の起動前確認で、提案側にも使用していた固定digestがshell版でCodex未収録と判明した（Issue-0151）。公開レジストリのmanifest/configと実VMのcommand -vの失敗を照合し、公式codex版の固定digest・取得量・条件の取り直し・新規最大6台を具体的に提示した。利用者は「画像」が実行環境テンプレートを意味すると確認したうえで「1で」と回答し、この変更を承認した。

## Considered Alternatives

- 公式codex版の固定digestを提案側で使用する: 導入済みバイナリを画像とまとめて固定でき、実行中のパッケージ取得も不要。
- shell版へ毎回Codexを追加する: パッケージ取得先の許可や搬入・導入処理が増え、固定画像に対する証拠と実行時の環境が分かれるため採らない。
- codex-docker版を使う: 今回の小さなPython題材にDocker Engineは不要なので採らない。

## Decision

提案用だけ`docker.io/docker/sandbox-templates@sha256:b387e913db629ca4370970076162d5bc06d1073059940f2f6326448c47143183`へ変更し、replayは既存のshell digest 16a88c...を維持する。2ホスト443番限定・OAuth・資源・共有/SSH拒否は維持する。新画像で保護条件と最小起動の確認を同じVMで取り、別VMで異常終了後の復旧を確認してからprofileを生成する。

具体的な操作範囲は2026-09-17-task9-codex-template-amendment.md。これから最大6台、同時1台。Codex実行最大2セッション、gpt-5.6-sol/mediumと送信内容は前案どおり。既存9台は停止保全し、未知の画像・モデル・許可先へ自動変更しない。

## Consequences

旧shell画像での提案側の能力証拠を、新画像のverifiedへ流用しない。旧画像の試験記録は経緯として保全する。画像取得は圧縮合計約795MBで、共有レイヤーによる削減と展開後使用量は未確定。追加試験と画像取得の負担は利用者へ提示して承認済み。

ADR-0200の「最小起動確認を先に行う」という順序は維持し、台数だけは本決定の承認済み変更案を優先する。起動条件が成立しなければ停止・記録し、利用者承認のない再試行は行わない。Task9全体完了とAccepted昇格は後続の全体整合検査で扱う。
