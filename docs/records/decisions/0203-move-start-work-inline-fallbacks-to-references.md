# ADR-0203: start-workのインラインフォールバックの内容をreferencesへ移す

- **Status**: Accepted
- **Date**: 2026-09-19

## Context

ADR-0202 の実装（`docs/working/plans/2026-09-19-worktree-start-detection.md` Task 1）で、`skills/start-work/SKILL.md` の Phase 0 に1句（約270バイト）を足したところ、`scripts/build-dist.ps1` のサイズ警告が発火した（19,961 → 20,233 バイト、目安値 20,000 バイト）。CONTRIBUTING.md「全シナリオ共通: SKILL.md のサイズと分割」は、警告発火時に責務帰属型 → references 型 → 例外登録の順で検討することを求める（ADR-0121）。

足した1句は Phase 0 の案内であり start-work 自身の責務のため、責務帰属型は当たらない。本文末尾の「インラインフォールバックの内容」（約1.4KB）は、Phase -1 で superpowers の該当スキルが見つからなかった環境でだけ読まれる条件発火の内容である。本文中でこの節を節名で参照する箇所は無い（2026-09-19 に `skills/` を検索して確認）。

## Considered Alternatives

1. **例外登録（承認済みサイズを約20.3KBにする）**: 変更が最小だが、毎回全文が読み込まれる量は減らない。規範の順序（references 型を先に検討する）にも反する。
2. **今回は警告を受容し、課題として起票する**: 実装を止めずに済むが、警告が常時出る状態が続き、次の追記で判断が先送りされる。
3. **インラインフォールバックの内容を references へ移す（採用）**: superpowers がある環境（通常の利用）では読まれない条件発火の内容であり、references 型の条件（発火時に毎回必要な内容の退避は認めない）を満たす。

## Decision

案3を採用する（利用者の個別承認、2026-09-19「1で」）。「インラインフォールバックの内容」の4小節（要件明確化・計画・実装・デバッグ）を、内容を変えずに `skills/start-work/references/inline-fallbacks.md` へ移す。本文には同じ見出しと、superpowers の該当スキルが無い環境ではそのフェーズで当該ファイルを読む旨の1文だけを残す（条文は複写しない）。

## Consequences

- `skills/start-work/SKILL.md` は 18,992 バイトになり、目安値を下回る。以後の追記に約1KBの余裕ができる。
- superpowers が無い環境では、フォールバックの手順を読むのに1ファイル分の読み取りが増える。
- 規範の内容は変えず置き場所だけを移すため、過剰適合の点検の対象外とする（CONTRIBUTING.md「全シナリオ共通: 過剰適合の点検」の適用対象は、規範・手順・観点の追加または強化であり、同一スキル内の references への移動で内容を変えないものは含まない）。
