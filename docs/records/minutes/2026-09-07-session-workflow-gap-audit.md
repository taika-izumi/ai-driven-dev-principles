# セッションの手順照合記録（2026-09-07）

## 目的と照合範囲

ユーザーの依頼に基づき、本セッションでAIが停止し、その後ユーザーが確認・続行指示を出した場面を、当時のスキル定義と照合した。対象は本会話の見えている履歴であり、他セッションや一般的なAI挙動の監査ではない。対策案の採用やスキル改定は行わず、原因を記録する。

比較する三者は、スキルの要求、実際のAIの行動、ユーザーの発言から確認できる期待である。「ユーザーが質問した」という事実だけで、直前の停止を不適切とは断定しない。推測による因果を実証として扱わない。

## 参照した定義

- `skills/start-work/SKILL.md`: Phase 0の継続確認、Phase 2の次手確認、節目の確認4「Phase 2へ戻る」、セッション終了処理1〜6。開始時点の153d47cと現在の本文を照合し、これらの接続・終了規定は今回の改定前にも存在していたことを確認した。
- `skills/session-handoff/references/op-finalize.md`: 次セッションのアクション・状態・コミット。マージやpushの実行を定める手順ではない。
- `skills/decision-log/references/adr-authoring.md`: 探索中のドラフトは保留を既定とするが、作業全体を終了する規定ではない。
- `skills/pre-finalization-review/SKILL.md`と`references/iteration-norms.md`: レビューの実施はユーザー指示時、修正後は再確認方法を提示し、指摘なしなら反復提示を省いて確定へ進める。
- `skills/extend-guidelines/SKILL.md`手順6、CONTRIBUTING.mdの生成手順、`scripts/build-dist.ps1`: 配布物生成・一致検査を定めるが、変更に伴うversion引上げの実施条件を明示していない。
- `skills/pre-action-review/SKILL.md`: 外部書込みの承認。別プラグインsuperpowers 6.3.0のfinishing-a-development-branchは統合方法の選択肢を定める。今回の配布スキルとは所有が異なるため、同一スキルの欠陥と混同しない。

## 定義側の問題として記録するもの

1. **Issue-0128**: クローズ・実装完了から統合工程への具体的な接続と、セッション終了時の未マージ分岐の不足。一般的な「次手を示す」規定は実在するため、無提案の停止すべてをこれだけで説明しない。
2. **Issue-0129**: 配布対象変更時のversion更新の実施条件・タイミングの不足。生成物が同期していても版据置きを検出しない。

今回の追加照合では、この2件以外に、実際の停止を引き起こしたと確認できる新しい定義欠陥は特定できなかった。C03・C04の無提案終了は、定義の欠如として新規起票せず、実行漏れの証拠としてIssue-0128から参照する。自動的に進める新規則を増やせば解決するとは結論しない。

参考: ADR-0130の初回レビューで見つかったbrainstorming不在時の再質問経路は定義上の欠陥として修正済みだが、今回その代替経路を実行してユーザーが催促した事実はない。今回の「実際に止まった事例」には数えない。

## pushに関する今回の明示要件

Issue-0128・0129の対策後も、**pushは実行するたびに利用者へ確認する**。過去のpush承認を次のpushへ持ち越さない。宛先・対象ブランチ・送信する変更を示し、ローカルの作業を完了させてから承認を求める。マージやバージョン更新の承認をpush承認と同一視しない。

これは今回明示された以後の要件であり、以前の発言が最初から毎回確認を意味していたと遡って断定しない。Gitタグ・GitHub Release・インストール済みキャッシュ更新までの自動実施も、本照合では要求として追加しない。
