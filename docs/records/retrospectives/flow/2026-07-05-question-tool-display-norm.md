## 開発フロー/ガイドライン課題

各課題は抽出と分類までにとどめる。**対策の設計・採否判断・ADR 化は行わない**（次サイクルでユーザーが対策要と判断した時点で着手。ADR-0021）。

- **課題 #1**: 規範・ADR の「エージェントによる実行可能性」を確認する観点が定式化されていない
  - **事象**: ADR-0029 の撤去基準を、エージェントには判定不能な条件（「事象が発生しないモデルの利用が常態化した時点」）で一度起草し、ユーザー指摘を受けて「ユーザーが判断し撤去を指示した時点」に書き直した
  - **原因**: 規範・ルールを起草する際に「その判定条件・動作をエージェントが実際に観測・実行できるか」をチェックする観点が、decision-log スキルの手順にも CONTRIBUTING のチェックリストにもない
  - **影響**: 実行不能な規範が混入すると形骸化した指示が残り続けるリスクがある。今回はユーザーレビューで捕捉されたが、捕捉がレビュー頼みになっている
  - **なぜフロー課題か**: 特定システムではなく、ADR・規範の起草プロセス（decision-log スキル / CONTRIBUTING のチェックリスト）の問題であるため
  - **関連**: ADR-0029、decision-log スキル、CONTRIBUTING.md「ADRを記録するとき」「CLAUDE.md を更新するとき」
