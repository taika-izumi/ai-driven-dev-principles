## 開発フロー/ガイドライン課題

各課題は抽出と分類までにとどめる。**対策の設計・採否判断・ADR 化は行わない**（次サイクルでユーザーが対策要と判断した時点で着手。ADR-0021）。

- **課題 #1**: ADR ドラフトの起票タイミングが「即時」ルールと議論の収束度で緊張する
  - **事象**: 選択肢の決定直後に「検出→即ドラフト」（ADR-0006）に従い ADR-0028 をコミットしようとしたが、ユーザーの懸念（配布先でのシステム固有課題の判別性）が未解消でコミットを中断された。その後フォルダ分割の決定を受けて ADR を書き直した
  - **原因**: 即時起票規範が、brainstorming 中の関連論点がまだ動いている段階でも起票・コミットまで促す。「ドラフト作成」と「コミット」の区別や、関連論点の収束確認が規範に含まれていない
  - **影響**: コミット中断と ADR の書き直しという手戻り（今回は未コミットだったため軽微）
  - **なぜフロー課題か**: ADR-0006 の継続検出ルールと ADR-0019 の記述規律という、ガイドラインの意思決定記録プロセス自体の問題であるため
  - **関連**: ADR-0006、ADR-0019、decision-log スキル
  - **起票**: Issue-0009（`../../working/issues/flow/0009-adr-draft-timing.md`）
- **課題 #2**: 既存 open 課題が再発した場合の記録方法が未定義
  - **事象**: Issue-0004（質問ツールの表示特性）の再発を、エージェントの判断で issue ファイルの「検討状況」に追記したが、この運用はどこにも定義されていない。同サイクルで Issue-0002・0006 の再発・再確認もあり、それらは振り返りファイルにのみ記録した
  - **原因**: ADR-0028 で起票フロー（新規課題）は定義したが、既存 open 課題の再発・進展情報の記録ルールはスコープ外だった
  - **影響**: 再発情報の記録場所（issue の検討状況 / 振り返りファイル / 両方）が実施者依存になり、課題の深刻度（再発頻度）の追跡可能性が下がる恐れ
  - **なぜフロー課題か**: 課題管理の運用ルール（ガイドラインの一部）の未定義領域であるため
  - **関連**: ADR-0028、docs/overview/folder-structure.md §7、retrospective スキル
  - **起票**: Issue-0010（`../../working/issues/flow/0010-issue-recurrence-recording.md`）
