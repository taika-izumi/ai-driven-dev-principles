## 開発フロー/ガイドライン課題

- **課題 #1**: 規範文書へ実測を追記するだけの小さな改訂でも確定点が立ち、確認工程の費用が主作業の費用を上回った
  - **事象**: 同一サイクルで確定前レビューが3回発火した（フル実施1回・差分再確認2回）。費用は CLI 表示で $1.33 + $1.40 + $1.23 = $3.95。一方、結論の根拠になった実測 run 13件の合計は $0.66 だった。3回のうち2回目・3回目の指摘は0件で、1回目の指摘1件も引用元の誤りという周辺レイヤだった。
  - **原因**: 確定点の推奨判定が「未レビューの規範・手順内容を含むか」で決まるため、既存の決定を変えない事実の追記でも規範改定型として毎回フル実施が推奨側に置かれる。加えて、実測 → 反映 → さらに実測、と作業を刻むと確定点がその回数だけ立つ。
  - **影響**: 小さな追記ほど確認費用の比率が上がる。今回はユーザーが2回とも差分再確認を選んで抑えたが、規定の推奨に従えばフル実施3回で $4 前後になっていた。作業を刻むほど費用が増える形は、実測を小分けに進める作業様式と噛み合わない。
  - **なぜフロー課題か**: 対象システム固有ではなく、確定点の定義と推奨判定という確定前レビューの規範そのものの問題である。
  - **振り分け判定**: 構造観察型（1回の躓きではなく、確定点が3回立った結果として費用比が見えた）
  - **関連**: `skills/pre-finalization-review/SKILL.md`「確定点での提示（提示規則）」の推奨判定と 2 型分類 / 同 `references/iteration-norms.md` / Issue-0124（足した機構の費用側評価。射程は機構の増加であり、本課題は確認工程自体の粒度と費用）/ Issue-0117 系のレビュー効用の実測
