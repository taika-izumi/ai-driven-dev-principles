## 3. Struggled（苦労したこと・手戻り）

- **事象**: 最初のコミットでメッセージ先頭・末尾に `@` が混入した（`[... ] @ feat: ...`）
  - **原因**: Bash ツール（POSIX sh / Git Bash）に対し、PowerShell 形式の here-string `@'...'@` を渡した。POSIX sh では `@'` `'@` がリテラルとして扱われる
  - **影響**: 軽微。未 push・未 merge の feature ブランチ上で `git commit --amend -F <file>` により修正、実害なし（手戻り1回）
  - **対処**: コミットメッセージをファイルに書き出し `git commit --amend -F` で確実に差し替え

## 4. Tech Notes（古びない技術知見）

- **タイトル**: マルチライン文字列はツールのシェル種別に合わせて渡す
  - **コンテキスト**: 複数行のコミットメッセージ等を CLI へ渡すとき。Bash ツール（POSIX sh）と PowerShell ツールで正しい構文が異なる
  - **知見**: PowerShell here-string `@'...'@` は POSIX sh では機能せず、`@` がリテラル混入する。逆に PowerShell ツールでは `@'...'@` が正しく機能する。どちらのツールを使っているかで書き分ける
  - **回避策・代替**: POSIX 側で複数行メッセージを渡すなら (a) メッセージをファイルに書いて `git commit -F <file>`、または (b) POSIX heredoc（`git commit -F - <<'EOF' ... EOF`）を使う。ツール非依存で最も確実なのは (a)
  - **一般化**: ツール名（Bash / PowerShell）は実行環境固有だが、核心は「利用中の CLI ツールのシェル種別に合わせて構文を選ぶ」という古びない原則である
  - **参照**: 本サイクルのコミット e061fb5（amend による修正）
