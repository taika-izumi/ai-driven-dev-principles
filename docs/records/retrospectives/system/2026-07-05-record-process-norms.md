## 3. Struggled（苦労したこと・手戻り）

- **事象**: AskUserQuestion の60秒無応答タイムアウトが2回発生し（実行方式確認・統合方法確認）、エージェントが推奨案で自走した（merge 実行を含む）
  - **原因**: ユーザー不在時のツール挙動（タイムアウト＋「ベストジャッジで進めよ」指示）に対し、操作の重要度に応じた自走可否の基準がガイドラインにない
  - **影響**: 今回は推奨案どおりで実害なし。構造的リスクは Issues へ（flow 課題 #1）
  - **対処**: 推奨案（インライン実行・ローカル merge）で自走し、事後にユーザーへ経緯を明示報告
- **事象**: plan Task 6 の検証 grep 期待値（6ファイルに ADR 参照）が、CLAUDE.md の編集文面（意図的に ADR 番号を書かない）と矛盾していた
  - **原因**: plan セルフレビューの観点に「検証ステップの期待値と各タスクの編集内容の突合」がない
  - **影響**: 軽微（実行時に5ファイル＋文言確認で吸収）。構造的リスクは Issues へ（flow 課題 #2）
  - **対処**: 検証時に矛盾へ気づき、CLAUDE.md は規範文言の存在確認（Task 1 で実施済み）で代替
- **事象**: CONTRIBUTING.md への Edit で置換文字列不一致が1回発生
  - **原因**: 原文を記憶から転記した際の微妙な差異（読点・強調位置）
  - **影響**: 軽微（即時に原文コピーで再実行）
  - **対処**: 直前の Read 結果からの正確なコピーで解消（Tech Notes 参照）

## 4. Tech Notes（古びない技術知見）

> **スコープ（ADR-0021 / ADR-0012）**
> - **含める**: ツール挙動・環境の罠・回避策・推奨手順など、開発フローやプロジェクトに依存せず古びない汎用技術知見
> - **除外**: 開発対象システムの仕様・ドメイン知識（ビジネスルール・用語・業務制約など）。これらは当該システムの仕様書に記載すること

- **タイトル**: 構造化質問ツールの無応答タイムアウト挙動
  - **コンテキスト**: Claude Code の AskUserQuestion をユーザー不在時に呼んだ場合
  - **知見**: 約60秒無応答で「ベストジャッジで進めよ」という指示付きのタイムアウトが返り、確認プロセスが実質スキップされる（2026-07-05 時点の Claude Code / Claude Fable 5 で確認。実装依存の観測値であり将来のバージョンで変わり得る）
  - **回避策・代替**: 節目の確認（merge 等）は、応答があるまで待てる形式（テキストで選択肢を提示してターンを終える）と使い分ける
  - **参照**: Issue-0012（`../../working/issues/flow/0012-question-tool-timeout-autonomy.md`）
- **タイトル**: 完全一致置換ツールでの編集は「記憶からの転記」を避ける
  - **コンテキスト**: Edit 等、原文の完全一致を要求する編集ツールを使うとき
  - **知見**: 会話履歴や記憶から原文を再構成すると、読点・強調・語順の微差で不一致になる
  - **回避策・代替**: 直前に Read した実ファイル内容から原文をコピーして渡す
  - **参照**: CONTRIBUTING.md 編集時の不一致（本サイクル Task 3）
