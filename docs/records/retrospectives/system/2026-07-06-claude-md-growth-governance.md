## 3. Struggled（苦労したこと・手戻り）

- **事象**: plan 初稿に期待値誤り3件（検証コマンドのシェル種別混在: `$LASTEXITCODE` を Bash で参照 / シナリオ数の期待値 9→正 10 / grep 件数の数え漏れ: ADR-0040 参照 2→正 3）
  - **原因**: 挿入予定テキスト内の参照回数を暗算で数えたこと、検証コマンドの実行シェルを明示せず書いたこと
  - **影響**: 軽微（実行前のセルフレビュー＝ADR-0034 の突合で全件修正。実行時の手戻りゼロ）
- **事象**: 設計提示で「計測スクリプトの2つの実行タイミング」の意図が伝わらず質問2往復が発生
  - **原因**: セクション1（監視）とセクション2（事前判定）を分割提示したことで、同一スクリプトが2側面で使い回される全体像を最初に示していなかった
  - **影響**: 軽微（質問2往復で解消。設計変更なし。むしろ役割分担の言語化につながった）
- **事象**: ADR-0040 の初回コミット（8a0f0a7）に、事前ステージ済みだった handoff 新規ファイルが意図せず同乗（コミットメッセージに handoff への言及なし）
  - **原因**: コミット前の read-back（ADR-0038）を「ファイル内容」に対して行い、ステージング状態（`git status` / `git diff --staged`）の確認を省いた
  - **影響**: 軽微（handoff はいずれコミット予定のファイルで実害なし。ただしコミット単位の意図とメッセージが不一致）

## 4. Tech Notes（古びない技術知見）

- **タイトル**: 常時ロード指示ファイルの閾値は「実測値＋既知の劣化域からの安全マージン」で決め、性格を正直に記録する
  - **コンテキスト**: AI エージェントの常時指示ファイル（CLAUDE.md 等）にサイズ・件数の閾値を設けるとき
  - **知見**: 数千トークン規模での精度影響を直接測ったデータは存在しない（2026-07 時点）。指示数による劣化開始は 150 件前後（IFScale）、入力長による劣化は数万トークン規模（Chroma "Context Rot"）で観測されており、その手前に置く閾値は「測定された危険水域」ではなく「管理上のトリップワイヤー」。決定記録にはその性格を明記し、根拠を過大に見せない。具体的な劣化開始点はモデル世代で変わるため、閾値見直し時は最新の測定を参照する
  - **参照**: ADR-0040 Context、arXiv 2507.11538、research.trychroma.com/context-rot
- **タイトル**: PowerShell の `exit` は `&` 呼び出しなら呼び出し元を殺さない
  - **コンテキスト**: PowerShell スクリプトから別スクリプトを呼び出して連結するとき
  - **知見**: `& script.ps1` で呼んだ子スクリプト内の `exit N` は子スクリプトだけを終了し、呼び出し元には `$LASTEXITCODE` として返る。ドットソース（`. script.ps1`）だと呼び出し元のスコープごと終了する（呼び出し元がスクリプトならそのスクリプトが、対話セッションから直接ドットソースした場合はセッション自体が終了する）。スクリプト連結時はこの使い分けに注意する
  - **参照**: `sync-template.ps1` からの `check-claude-md-size.ps1` 呼び出し実装
- **タイトル**: 検証コマンドには実行シェルを明示する
  - **コンテキスト**: PowerShell と Bash（POSIX sh）が併存する環境で、plan に検証コマンドと期待値を書くとき
  - **知見**: 終了コード参照（PowerShell `$LASTEXITCODE` vs Bash `$?`）のような同目的・別構文は、実行シェルが曖昧だと静かに間違う。plan の検証ステップには「どのツール（シェル）で実行するか」を明記する
  - **参照**: 本サイクル plan の Task 1 検証ステップ（セルフレビューで「Run（Bash ツール）」表記へ修正）
