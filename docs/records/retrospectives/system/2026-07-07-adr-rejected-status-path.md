## 3. Struggled（苦労したこと・手戻り）

- **事象**: ADR-0041 の初版に「Rejected 経路」「置換特定と監査」「本サイクル実施項目」という複数の独立した決定・計画を束ねて起票し、ユーザーレビューで分割となった
  - **原因**: 「1サイクル=1ADR」という暗黙の慣性で、起票時に1決定=1ADR の粒度検討をしなかった
  - **影響**: ADR の書き直しと再コミット1回（軽微）。レビューがなければ「部分修正あり」注記が増えやすい大型 ADR が台帳に残った
  - **対処**: 2分割（0041/0042）し、実行計画の内容は plan へ移した
- **事象**: ADR 初回コミットで、未追跡ファイルへのパス指定 `git commit -- <path>` が失敗（`git add` 前）し、不要な変数参照の混入もあり1往復ロス
  - **原因**: ステージングとパス指定コミットの挙動の混同
  - **影響**: 軽微（即修正）
  - **対処**: `git add` → パス指定コミットの順に修正。Tech Notes に知見化
- **事象**: plan Task 4 の grep 期待値が2箇所ずれた（README の "Superseded" が ADR-0042 自身のタイトルにヒット、「一部改定」が改定する側の 0021 本文にもヒット）
  - **原因**: 期待値算定時に「検索語が新規 ADR のタイトルや既存本文にも現れる」ことを織り込まなかった
  - **影響**: 実行時に grep -n で原因特定して吸収（良性と判定）。逆方向（誤って通る）のリスクは残る
  - **対処**: ずれ2件とも行を特定し、ステータス列ではないことを確認してから通過

## 4. Tech Notes（古びない技術知見）

> **スコープ（ADR-0021 / ADR-0012）**
> - **含める**: ツール挙動・環境の罠・回避策・推奨手順など、開発フローやプロジェクトに依存せず古びない汎用技術知見
> - **除外**: 開発対象システムの仕様・ドメイン知識（ビジネスルール・用語・業務制約など）。これらは当該システムの仕様書に記載すること

- **`git commit -- <pathspec>` は未追跡ファイルに使えない**
  - **コンテキスト**: 複数の変更が混在するワークツリーで、特定ファイルだけをコミットしたいとき
  - **知見**: パス指定コミットは追跡済みファイルの作業ツリー状態を拾う仕組みで、未追跡ファイルには `error: pathspec ... did not match any file(s) known to git` で失敗する。先に `git add` が必要。逆に追跡済みなら、他にステージ済みの変更が残っていてもパス指定分だけをコミットできる（ステージ済みファイルの温存に有効）
  - **参照**: コミット 0c62152 の前段の失敗と修正
- **`grep -c` は「一致した行数」であり出現回数ではない**
  - **コンテキスト**: grep を検証の期待値に使うとき
  - **知見**: 1行に複数回出現しても1と数える。期待値は「行数」で設計する。出現回数が必要なら `grep -o | wc -l`
- **grep 検証の期待値には「検索語が別文脈に現れる可能性」を織り込む**
  - **コンテキスト**: ステータス語・一般語（"Superseded" 等）を件数検証に使うとき
  - **知見**: タイトル・本文の言及・自己参照（検証対象自身が検索語を含む）にヒットしうる。期待値とずれたら `grep -n` で行を特定し、良性（別文脈）かを判定してから通す
  - **参照**: 本サイクル Task 4 の検証（ずれ2件とも良性）
