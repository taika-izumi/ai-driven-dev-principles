## 2. 課題（対象システム固有）

課題の抽出と分類まで（対策の設計・採否判断・ADR化は次サイクル。ADR-0021）。

- **課題 #1**: 点検ブロックの見出しレベルが記録先ごとに 2 通りあり、存在確認を単一 grep で書けない
  - **事象**: ADR-0079 が定めた点検ブロックの見出しが、CONTRIBUTING.md の雛形では `### 過剰適合点検（ADR-0079）`（インデントコードブロック内）、ADR 記録先の規定では `## 過剰適合点検（ADR-0079）`、spec のドッグフーディング実例でも `##` と、レベルが揃っていない
  - **原因**: 記録先（spec の節 / ADR 末尾の独立節）ごとに見出しレベルを揃える検討をしないまま雛形を確定した。確定前レビューは記録義務の内容（記録先の固定・ADR-0019 との整合）を厚く検査したが、見出しレベルの粒度までは踏み込まなかった
  - **影響**: ADR-0079 自身が定めた執行点「拡張 spec / 拡張 ADR をコミットする直前に点検ブロックの存在を確認する」を、単一の grep パターンで機械化できない。Issue-0047（A 群制約のフック機械注入）と同種の将来の自動化を試みる際の直接の障害になる
  - **起票**: Issue-0064（`../../working/issues/system/0064-check-block-heading-level-inconsistent.md`）
