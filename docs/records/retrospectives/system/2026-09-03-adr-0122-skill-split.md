## 2. 課題（対象システム固有）

課題の抽出と分類まで（対策の設計・採否判断・ADR化は次サイクル）。

- **課題 #1**: references 型分割の完了基準に「参照表の各行の到達元の実在確認」が無い
  - **事象**: 分割で `session-handoff/SKILL.md` へ横断規範の参照表（4 行）を新設したが、うち 1 行（`references/section-volume-norms.md`）はどの操作ファイルからも名指しされておらず（操作 5 ファイル中 0 件）、表の導入文が定めた発動条件「操作ファイルが名指しした時点」が恒常的に偽になっていた。分割前は同一ファイル内の節で常時利用可能だったため、分割が持ち込んだ到達不能である。Accepted 昇格時のサイクル全体整合検査 観点 4 が検出し、導入文へ「または下表の「読むとき」に当たった時点」を足して昇格前に修正した（db565f2）
  - **原因**: `CONTRIBUTING.md`「全シナリオ共通: SKILL.md のサイズと分割」の references 型の手順にも、`decision-log` の `references/cycle-consistency-check.md` 観点 4 の完了基準にも、「参照表の各行について到達元を数える」検査が無い。分割の完了基準が本文サイズ（ADR-0121）と実読み込み量（ADR-0122 決定 1）に寄っており、到達可能性は明示の検査対象になっていなかった
  - **影響**: 分割のたびに同型の到達不能が入りうる。本サイクルでは確定前レビュー 4 巡（claude-opus-5）とタスク単位の diff／grep 検証がいずれも素通りした——いずれも「書いたものが正しいか」を見ており、「書いた発動条件に到達元が実在するか」は見ていない。昇格チェックポイントに整合検査を置かないプロジェクトでは欠陥が確定する
  - **起票**: Issue-0117（`../../working/issues/system/0117-split-completion-criteria-lacks-reachability-check.md`）

> 開発フロー課題の起票は 0 件のため `flow/` ファイルは作成しない。worklog 送りとした delta 型候補は 3 件（起票なし。振り分け規則による）——(1) 確定済み計画の Expected が実体とずれたときの是正方式（本文書き換え / 読み替え）の既定が `plan-deviation-defaults.md` に無い〈`MakeAiInstructions-2026-09-03-04`。本サイクルで 3 回発生〉、(2)「実測値」というラベルが確定前レビューの検査対象から当該値を外す効果を持つ〈同 `-05`〉、(3) 計画内の同型規則がタスク間で適用漏れになる〈同 `-03`〉。
