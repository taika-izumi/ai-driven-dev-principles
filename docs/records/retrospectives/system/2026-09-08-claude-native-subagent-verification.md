## 1. 達成サマリ

- 親が広い権限を持つ状態から標準のサブエージェント機能で子を起動し、子の許可リストから書き込み可能な内蔵ツールを外す構成で保護が成立することを実測した（d98b47b）。権限モードは保護の代わりにならないこと（親 acceptEdits の子が作業ディレクトリ内の保護代用品を上書き）も同時に確認した。
- 固定検査1操作だけを子へ渡す構成で、実行を伴う検査が成立することを確認した（正常1成功・変異1失敗・復元1成功、保護代用品4件の拒否）。実行は既存 Codex のサンドボックス内。
- エージェント定義ファイルの拒否リストと接続の限定公開も実測し、後者が明示接続だけを使う起動オプションと併用できないことまで確定した（cf46d94）。
- 親の権限チェックを無効にした起動では作業ディレクトリの境界も保護にならないことを確認し、保護対象を外へ置く回避策が成立しないことを記録した（d0a83ef）。
- 実測は run 13件、確定前レビューはフル実施1回・差分再確認2回（いずれも書き込み可能なツールを持たない独立レビュアー）。記録は `docs/records/experiments/2026-09-08-claude-native-subagent.json`。

## 2. 課題（対象システム固有）

- **課題 #1**: 規範の「ツール別に確認する条件」の表が、ツール・版・起動方式の組み合わせごとに行と確認例の節を増やす構造になっている
  - **事象**: 本サイクルで表に1行、確認例に1節を追加した。追加した行のセルは約180字で、既存2行と合わせて3行になった。確認例の節も2節になった。
  - **原因**: 表の主キーが「ツールと版」であり、同じツールでも起動方式（別プロセス＋固定接続／標準のサブエージェント機能）が変われば新しい行になる。版が上がるたびに行が増える一方、古い行を落とす判断基準が無い。
  - **影響**: 読み手が自分の構成に該当する行を選びにくくなる。今回は3行で済んでいるが、OS・版・起動方式の組み合わせが増えると、委譲元が起動前に読む分量と選択の誤りが増える。
  - **起票**: Issue-0139（`../../working/issues/system/0139-tool-condition-matrix-grows-per-version-without-pruning-rule.md`）
