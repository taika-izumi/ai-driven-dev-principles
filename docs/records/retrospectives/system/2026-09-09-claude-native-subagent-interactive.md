## 1. 達成サマリ

- 対話セッション（autoモード）で子を4通り起動し、許可リスト方式（`tools: Read`）の子は書き込み系5ツールと ToolSearch・NotebookEdit を実際に呼び出しても全て拒否され、保護代用品が無変更であることを確認した（実行記録 `docs/records/experiments/2026-09-09-claude-native-subagent-interactive.json` の run i1・i4）
- 拒否リスト方式（`disallowedTools`）の子には列挙外のツールが20件残り、うち NotebookEdit が保護対象の代用ノートブックを承認要求なしで上書きした（run i2・i3）。前サイクルの測定が5ツールだけを試したことによる列挙の不完全性であり、対話セッション固有の差ではない
- 上記により規範の等価性の記述（`skills/subagent-dispatch/references/inspection-isolation.md` の「外し方は許可リストと拒否リストのどちらでもよい」）を否定し、ADR-0144 として決定した（40068bc）
- 規範本文と参照知識（`docs/reference/inspection-isolation-costs.md` 第10節）を改定し、配布物を再生成して ADR-0144 を Accepted へ昇格した（951e3fd）

## 2. 課題（対象システム固有）

課題の抽出と分類まで（対策の設計・採否判断・ADR化は次サイクル）。開発フロー/ガイドライン課題は `flow/2026-09-09-claude-native-subagent-interactive.md` に記載する。

- **課題 #1**: ADR-0144 の方式に沿った読み取り専用の担当を立てる常設の定義が無く、レビュアーが横断検索できない
  - **事象**: 確定前レビューを ADR-0144 の方式（許可リストで明示列挙）で回すため `.claude/agents/issue0136-static.md`（`tools: Read`）を使ったが、Grep/Glob を持たないため横断検索ができなかった。レビュアーは「同じ記述が他の箇所にも無いか」を独立に確認できず、委譲元が対象パスを全列挙した。差分再確認も同じ制約下で実施した
  - **原因**: 読み取りと検索だけを列挙した常設の許可リスト定義が無い。エージェント定義ファイルは起動時に読み込まれるため、必要と判明した時点のセッションでは作成しても認識されない
  - **影響**: 読み取り専用委譲で確認範囲を委譲元が決めることになり、走査の網羅性をレビュアー側で担保できない。今サイクルのレビュー2回がこの制約下で行われた
  - **起票**: 見送り。**本課題は「Claude 標準サブエージェントの許可リストで隔離を実現する」という現行方針を前提としている。隔離環境の構築方針は調査段階であり、方針が変われば課題の形も変わる。起票の要否は方針決定後に判断する**（ユーザー判断・2026-09-09）

> 開発フロー課題は `flow/2026-09-09-claude-native-subagent-interactive.md` 参照（起票1件・起票見送り1件）。worklog 送りとした delta 型候補1件（起票なし。振り分け規則による）。
