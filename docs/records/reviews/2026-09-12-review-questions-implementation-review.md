## 指摘の照合と対応

| 指摘 | 判断・対応 | 理由と既存の条件 |
|---|---|---|
| R1 descriptionの形式不一致（medium） | 採用し復元。提示・実施の2操作を新しい語彙で列挙する | start-work責務分割仕様の操作列挙型の要求・完了条件が実在。汎用writing-skillsの短いdescriptionの推奨へ合わせたことで、適用先の具体的な仕様から外れた。仕様を変えず実装を戻す |
| R2 版混同・根拠不足時の契約の脱落（medium） | 採用し復元。review-criteriaの共通入力と現行仕様へ、複数版の混同禁止、根拠不足・矛盾・版不明の確認可否、推測による補完禁止を明示 | 所在・版を渡すだけでは、元の禁止・未確認の条件の明示を保持しきれていなかった。計画の既存契約保持を満たすための修正 |
| R3 現行仕様の根拠索引（low） | 採用。根拠欄へADR-0189を追加 | 本文では示していたが索引でも到達可能にする。旧ADR-0117の導入時の観点名は歴史的説明として保持する |
| R4 仕様の二重化（low） | 不採用 | 仕様冒頭の「条件の正本を複写しない」は判断の分担の条件を指す。「条文を両方に複写しない」はSKILL.mdと反復側の責務境界。仕様全体の要約を禁止する規定ではない。今回の新節は定義全文の複写でなく、役割表と入力・境界・品質項目の要約。folder-structureの現行仕様が全体像を説明する要求と整合する。レビューの一部行番号は対象文書の行数外であり、そのまま根拠にしない |

| R6 旧名での廃止対象（low） | 採用。導入時の前提実在観点が、現在の根拠・設計判断領域の必要性・実在確認に対応すると注記 | 過去の実測・世代・件数を変えず、現行の縮小・廃止対象への到達性を補う |
| R7 入口の呼称（low） | 不採用 | 反例探索という方法と、別担当による独立した反証を区別する設計である。人数・独立性を選ぶ前の入口へ「独立した」を一律に付けると、兼務した探索まで独立と称する逆の誤読を招く。独立性の条件は本文に明記済み |

R1・R2は計画の意図・設計を変更せず、実装が既存仕様・保持要求を満たすように戻した。R3・R6は参照・対応の補足。新しい役割・工程・保護境界・評価起点は追加していない。関連して仕様の過去改定部分の「今回」という表現を、その改定の対象が分かる表現へ直した。

## 確認範囲と次の工程

主担当は採用箇所の元規定・修正後本文を読み直し、配布生成と両Check・差分検査で確認する。固定15題の変更前後確認とは役割が異なり、ケース確認だけで実装全体のレビュー済みとはしていない。独立レビュー後の上記復元・参照補足に追加モデルは起動していない。

反復・人数・採否の既存ルール、常時4制約・条件発火7条件、計画逸脱の採用基準、操作保護は保持した。実装レビューで必要と判定した修正を終えてから版更新へ進む。公開や利用側の更新は別途判断する。
