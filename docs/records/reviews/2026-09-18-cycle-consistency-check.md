## 観点4 経路の閉じ

サイクル中に新設した実行時の規則（Lease、復旧操作、セッション保持）について、到達経路を列挙した。

| 経路 | 発火する処理 | 記録のタイミング |
|---|---|---|
| 正常（提案→再実行→照合） | Lease取得 → 保持exec → stop → 停止確認 → 保持停止 → finallyでLease解放 | 停止確認の後に `control/result.json` を一度だけ保存 |
| recheck | Lease取得 → 提案VMなし → replay-after1台のみ | 同上（proposalStopped=null） |
| Lease競合・デーモン停止 | VMを作らずblocked | 型付きの失敗結果を照合へ |
| 期限到達でLease取得失敗 | Leaseなしで提案（timed_out）→ not_run → 照合（ADR-0198） | 照合後に保存。VM作成はLease検査で拒否 |
| CLI強制終了 | ジョブごと保持が消える → 30秒後に製品の自動停止 → 利用者または主担当が `-StopRecorded` | `recovery-<時刻>.json` をCreateNewで保存 |
| run途中の自動停止 | 各コマンド直前の検査で検知 → incomplete | 結果の unverified に残す |

同一内容への二重発火は見当たらなかった。復旧操作は結果JSONが返らなかった場合だけ使い、別runがLeaseを持つ間は何もしない。記録の書き込み順序（停止確認→結果保存）と値の確定順序も一致している。
