# Codexで選択肢が表示されない場合の設定

出所: Issue-0127、ADR-0127。2026-09-06の観測に基づく環境別の対処例。全利用者の必須設定ではない。

## 対象となる症状と確認範囲

AGENTS.mdに番号付き選択肢・推奨理由の指示があるのに、Codexでその形式が使われない場合の対処。モードに由来する開発者指示との競合が原因候補となる。

- Codex CLI 0.153.4: 設定をfalseにすると、`debug prompt-input`の生成入力からモード指示ブロックが除外されることをAIが実測。
- 同CLIの実際の応答: ユーザーが「意図した挙動になった」と報告。
- Codexアプリ: 共通設定後のrun5で、ユーザーが選択肢表示を確認。アプリ版・新規タスクか等の詳細は未報告。
- 作業継続の改善、他の版・モデル・全モードでの同等動作は未確認。

## CLIで一度だけ試す

```powershell
codex -c include_collaboration_mode_instructions=false
```

この起動に対する指定であり、設定ファイルは変更しない。元の設定で試す場合は、当該セッションを終了し、`-c`なしで新しく起動する。既に設定ファイルへfalseを保存している場合は、後述の復元手順も必要。

## ユーザー共通設定として保存する

1. `~/.codex/config.toml`をバックアップする。Windowsでは通常 `%USERPROFILE%\.codex\config.toml`。
2. 次の行をトップレベルに追加する。同名設定があればその値を変更し、重複させない。最初の`[セクション名]`より前に置き、`[features]`内には書かない。

```toml
include_collaboration_mode_instructions = false
```

3. 保存する。CLIでは新しく起動する。アプリでは作業を保存して完全終了・再起動し、新しいタスクで確認する。既存会話への遡及的な除去は前提にしない。
4. `start-work`など、判断が必要になる場面で説明・選択肢・推奨理由が表示されるか確認する。

この設定ファイルを使用するCodexの共通設定になる。別のCODEX_HOME、プロジェクト設定、起動時指定、管理された設定等により実効値が異なる場合がある。アプリとCLIで常に同一の反映になると保証するものではない。

## 設定の読み込みを確認する

CLI 0.153.4では次の診断コマンドが使用できる。

```powershell
codex debug prompt-input "設定確認"
```

生成入力内のモード指示の有無を確認できる。ただしCLIの診断結果は、アプリの実際の送信内容の証明にはならない。出力にはプロジェクトや個人の指示が含まれ得るため、外部共有する場合は内容を確認する。

## 影響範囲と元に戻す方法

この設定は選択肢禁止の一文だけではなく、collaboration modeの指示ブロック全体の注入を抑える。モードに応じた進め方にも影響する可能性がある。権限や承認設定の代わりにはならない。

戻す場合は追加した行を削除するか、変更前の値に戻し、新しく起動して確認する。他の設定変更が増えている場合、古いバックアップ全体の上書きより当該行だけを戻す。

将来の版で競合がなくなった場合や、モード指示の除外によって望ましくない動作が起きた場合は、この対処の継続を見直す。
