## 完了済みタスク

- [x] LoopForAlpha のハンドオフ実測調査（2026-08-13 完了）。結論: **原因の型は「策は展開・実行済みだが、策の設計が増加側を制御していない」**。実測の要点:
  - 対象は `docs/working/handoff/master.md` 1 ファイル（99KB / 289 行。1 行平均 340B・最長 2.5KB）
  - 防止策は動作している: リセット 2 回（2026-07-24 `fa7cba9` 手動刈り込み 154KB→6.9KB / 2026-08-06 `1880d6f` cycle-reset 211KB→23KB）、finalize の基準付き圧縮もセッション終了時に約 10% 縮小を実測（削除記録行あり）
  - しかし増加が約 10KB/日で圧縮を上回り、cycle-reset 後 7 日で 23KB→97KB
  - 増加の内訳（セクション別）: 進行中のタスク 31.5KB（申し送り・教訓の番号付きリスト 32 項目。「正本がここにしか無いもの」と明示した節あり）/ Post ラッパー消化記録 28KB（1 行平均 875B・最大 2.5KB。レビュー結果の詳細を行内に記載しつつ同じ行で正本を名指し＝重複）/ 次セッション開始時のアクション 11.5KB（スキル想定は 3 項目）/ ブロッカー 8.3KB / タイトル 3.4KB
  - 構造的原因 4 点: (A) cycle-reset の発火点（master マージ後）が LoopForAlpha の運用（master 直接開発・数週間の「段階」）と乖離し、サイクル内保護対象が数週間分蓄積 (B) ADR-0075 の「圧縮しないもの＝正本が handoff 以外にないもの」が、handoff を正本として書かれた申し送り群を上限なく保護（正本を外へ移す誘導が無い） (C) 消化記録の「1 行」に長さ・内容の規範が無く、正本参照と詳細記載が重複 (D) 「要点のみ」と称した抜粋自体が肥大。ほか細部（タイトルへの状態詰め込み、圧縮実施記録自体を handoff に残す＝ADR-0074 の「受け皿は git 履歴のみ」からの逸脱）
