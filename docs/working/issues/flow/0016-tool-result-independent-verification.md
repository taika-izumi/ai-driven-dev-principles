# Issue-0016: ツール適用結果を独立確認せず既遂とみなすと記録と実体が乖離する

- **Status**: closed
- **Opened**: 2026-07-05
- **Closed**: 2026-07-06
- **起票元**: Issue-0012 対策サイクルのセッション終了処理中に検出（retrospective は既にクローズ済みのため本 issue で一次記録）
- **関連**: 原則5（漸進的検証）、原則1（追跡可能性）、ADR-0034、Issue-0015

## 課題内容

エージェントが編集ツール（Edit 等）の適用結果を、戻り値とは独立した観測で確認せずに「既遂」とみなして後続の記録・判断を積み上げると、記録と実体が乖離する（要約。詳細は下記）。

- **事象**: Issue-0015 への追記 Edit が「成功」表示だったにもかかわらず実際にはファイル未変更で、後続の retrospective §6 が「Issue-0015 に追記済み」と記述され、実体と食い違った。コミット後の `git status` の staged 数の齟齬で偶然検出し、補完コミットで修正した
- **原因**: ツール適用結果を独立に観測せず既遂とみなしたこと。加えて今回はエージェントの応答内で tool_use ブロックの前に不正テキストが混入し、片方の Edit の発行/解釈が乱れた特殊要因もあった（原因が出力ミスか結果表示の齟齬かに依存せず、独立観測があれば捕捉できる問題）
- **影響**: 記録と実体の乖離＝追跡可能性の劣化。今回は捕捉・修正済みだが、確認手段がなければ乖離が残存しえた。特にドキュメント/ガイドライン系プロジェクトでは成果物＝記録の正確さのため影響が直接的

## 検討状況

- 2026-07-05: 対策の方向性（採否・設計は次サイクル）としてユーザーと以下を共有:
  - 核となる対策は **read-back verification**（変更後に Read/grep で実体を独立確認）。編集ツールの戻り値に依存せず実体を観測する
  - **リスク比例で発動条件を限定**する: 「後続の判断・記録がその変更の成否に依存する場合」＋「複数変更を節目で確定する直前」。全編集への一律適用は過剰
  - **git 非依存の表現にする**: 確認手段は Read/grep（VCS 非依存）。「節目」はコミットに限らず保存・エクスポート・送信・デプロイ等を含む一般語で書く
  - 実装層の候補は `CLAUDE.md`「検証」節への1項目追記（原則5・ADR-0034 の隣接）。ただし層・条件の確定は次サイクルの brainstorming で行う
  - ユーザーは 2026-07-05、本課題を起票し次サイクルで対策する方針に合意
- 2026-07-05: 本症状は Opus モデルでのみ観測（ユーザー報告、以前から時々発生、他モデル未確認）。Bash 実行自体をせず結果を捏造するケースも含む
- 2026-07-05: Issue-0014 対策サイクルで read-back verification を実践（renormalize 後の `git ls-files --eol` 確認、使い捨て CRLF ファイルでの実機検証。retrospectives/system/2026-07-05-gitattributes-eol-normalization.md 参照）。規範未整備のまま実践例が積み上がっている

## 結論

ADR-0038 として決定・実装（closed）。`CLAUDE.md`「検証」節に read-back verification の1箇条を追加（発動条件は「後続の判断・記録が依存する場合」「複数変更を節目で確定する直前」の2つに限定、確認手段・節目の表現は git 非依存）。原則5 は既存の抽象記述の具体化にあたるため改定せず。template 同期済み。
