# Issue-0018: CLAUDE.md 常時指示の肥大化を監視・棚卸しする仕組みがない

- **Status**: open
- **Opened**: 2026-07-05
- **起票元**: Issue-0016/0017 対策サイクルの設計議論（ユーザー指摘）
- **関連**: ADR-0038, ADR-0039, CONTRIBUTING.md「CLAUDE.md を更新するとき」、原則3（コンテキスト管理）

## 課題内容

CLAUDE.md はエージェントが毎セッション読み込む常時指示であり、template 経由で配布先全プロジェクトにも展開される。規範は対策サイクルのたびに単調増加している（2026-05〜07 で ADR-0029〜0039 の規範系が追加）が、以下の仕組みが存在しない:

- **肥大化の監視**: CLAUDE.md のサイズ・箇条数がどの水準にあるかを定期的に観測する機構
- **棚卸し**: 効かない・発動しない・古びた規範を検出し、削除または Layer 3（オンデマンドで読まれるスキル）へ退避する手順

個々の追加は小さくても（1箇条 50〜100 トークン程度）、累積すると「今の作業に無関係な指示への注意配分が増え、指示遵守・思考の精度が落ちる」「コンテキスト消費が増える」というリスクが配布先全プロジェクトへ波及する。追加の判定基準（CONTRIBUTING.md「CLAUDE.md を更新するとき」）はあるが、増える一方向のフローしかなく、減らす側のフローがない。

## 検討状況

- 2026-07-05: 起票と同サイクルで、規模拡大の抑制方針を初適用（Issue-0017 対策を CLAUDE.md ではなく CONTRIBUTING.md のみに配置。ADR-0039）
