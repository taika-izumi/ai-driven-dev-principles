## 課題内容

AI のデフォルト挙動は、「スキルが規定する自己レビュー（チェックリスト）を通したら、計画・仕様は確定してよい」と扱うことである。実際に必要だったのは、**コンテキストを持たない独立レビュアーに委譲し、かつ「計画中のコードをスクラッチで実際に実行せよ」まで課す**ことだった。

worklog の実測が示す自己レビューの限界:

- 自己レビューは**記載内容の誤り**は検出するが、**載せる項目の選定漏れ**と**既存コードとの相互作用**は 1 件も検出できていない
- `LoopForAlpha-2026-07-19-05` では、独立レビューが Critical 5 件を検出したのに対し、直前の自己レビューはその全数を取り逃していた
- 計画に書かれたテストコードは実装コードと同じだけ未検証である。写経して走らせるまで、スキャフォールドの構文もスコープも一度も評価されていない

現行のガイドライン・スキル体系では、コードには `requesting-code-review` があるが、**計画・仕様・設計文書という非コード成果物の確定前レビュー**に相当する工程がない。`writing-plans` / `feature-block-design` はいずれも自己レビューで完結する設計になっている。

根拠エントリ由来の運用ヒント: 独立レビューの観点は最低 3 つ（敵対的／実装整合性／仕様適合）を立て、**モデルは前工程のレビューと変える**。

## 検討状況

- 2026-07-31: `worklog-extract` 初回走査で採用（`processed.jsonl` へ `adopted` 追記済み）。`worklog-skillify` へ受け渡し予定
- 対策の方向として、(a) `requesting-code-review` の射程を非コード成果物へ広げる (b) `writing-plans` / `feature-block-design` の末尾に独立レビュー工程を必須ステップとして足す (c) 新規スキルを立てる、の 3 案がある。採否は次サイクルで判断する
- 3 世代のモデル（opus-4-8 / fable-5 / opus-5）にまたがって再発しており、モデル固有の躓きではない
- 2026-07-31: 本リポジトリ（MakeAiInstructions）の retrospective 再定義サイクルで同型が再発（ADR-0031）。brainstorming 中、AI が「構造観察型の課題は retrospective が受け皿になる」と設計しかけたが、ユーザーの「本当に retrospective で発見できるのか」という指摘で過去実績を調査したところ、retrospective が構造観察型を発見した実績は 0 件（実際の発見経路は作業中の随時起票）だった。**新工程に責務を割り当てる際、その工程が実際にその責務を果たせるかを実績データで検証していない**という形で、自己レビューが「載せる項目の選定」を検証できない本課題の症状が非コード成果物（設計）で現れた。対策設計時にこの角度（責務割り当ての実績検証）も観点に含めること

- 2026-08-05: 配布先からの申し送り（ADR-0061 / ADR-0063）。`LoopForAlpha#Issue-0054`（実装計画の成果物に「足場コード」を含めるべきかが未定義）は、本課題の代表エントリ `LoopForAlpha-2026-07-28-11` と**同一事象**である。第4段階フェーズ5 の計画に対する独立レビュー（実証検証担当）が計画中のテストコードを写経して実行し、**10 件すべてが `CommandNotFoundException` で 1 件も動かない**ことを検出した回のフォールアウトにあたる。あわせて配布先の課題本文には、対策設計に直接使える分析がある:
  - **誤りの種類によって計画の効き目が反転する** — 局所的・機械的な誤り（構文・スコープ・足場の配線）は直接実装なら最初の実行で数分で赤になるのに対し、計画に書くと検証が遅れるうえ偽の確信を生む。逆に構造的な誤り（タスクの順序・新旧の契約の食い違い・自分が足した制約が自分の検証工程を止める・境界の抜け）は計画でしか安く拾えない
  - したがって問うべきは「計画を作るか」ではなく「**計画に何を書くか**」である（配布先の課題も同じ結論に到達している）
  - 対策候補として「計画中のテストを前提確認タスクで実際に走らせる」が挙がっており、**重大3件のうち2件はこれで計画段階に自力検出できた計算**と実測されている
- 2026-08-05: 本サイクル内で同型を1件自力検出した。Issue-0032 の対処として健全性検査スクリプトを実装し、self-test が PASS し実ストアでも既知の欠陥を検出したため完成と見なしかけたが、**close 前に課題本文の要求と実装を突合したところ、本文が明記していた「中途 BOM」を検出できていなかった**（正の対照が先頭 BOM しか無かったため self-test も PASS していた）。自己レビューが「載せる項目の選定漏れ」を検出できないという本課題の症状が、検査の対照設計で現れた形（worklog `MakeAiInstructions-2026-08-05-02`）
