# Issue-0038: retrospective の Phase 3 で得た知見を記録へ反映する経路がない

- **Status**: open
- **Opened**: 2026-07-31
- **起票元**: `retrospectives/flow/2026-07-31-retrospective-mode-review.md` 課題#2（新形式の初回適用で検出）
- **関連**: ADR-0056（新4フェーズ構成・rubber-duck のオプション化）、ADR-0011（記録ファイルの上書き禁止）、ADR-0030（未コミットドラフトは書き直し自由）、`skills/retrospective/SKILL.md`（Phase 2 / Phase 3）

## 課題内容

ADR-0056 の新形式では、Phase 2（記録保存と起票）で記録ファイルを確定した後に Phase 3（仕上げ: オプションの rubber-duck レビュー / worklog 総ざらい / handoff 更新）を実行する。しかし Phase 3 は新事実を生みうる:

- **worklog 総ざらい**でサイクル全体を俯瞰した結果、Phase 2 では気づかなかった課題や既存課題の再発が判明する
- **rubber-duck レビュー**（実施時）の指摘で課題の追加・分類変更が生じる

ADR-0011 は記録ファイルを上書き禁止としているため、これらを記録へ反映する正規の経路がない。旧形式では Phase 3（rubber-duck）の結果を Phase 2 のドラフトへ反映する手順が明示されていたが、ADR-0056 で rubber-duck をオプション化した際にその反映経路の記述が失われた。

初回適用（2026-07-31、retrospective 再定義サイクル自身のドッグフーディング）で実際に再現した。Phase 3 の worklog 総ざらい中に Issue-0032 の再発（grep 系検出手段の誤判定、2例目）が判明したが、記録ファイルは Phase 2 で書き出し済みだった。暫定的に「未コミットのドラフトであるため ADR-0030 に準じて書き直し可」と解釈して追記したが、この扱いはスキルにも ADR にも書かれていない。

## 対処候補

- 記録ファイルの確定タイミングを「Phase 3 完了時（コミット時）」と明示し、それまではドラフトとして書き直し可能とする（ADR-0030 と同型の規約）
- あるいは Phase 2 と Phase 3 の順序を入れ替える（worklog 総ざらいを課題提示より前に置く）
- ADR-0011 の上書き禁止が「コミット後」に適用されることを明文化する

（対策の設計・採否は次サイクル。ADR-0021）
