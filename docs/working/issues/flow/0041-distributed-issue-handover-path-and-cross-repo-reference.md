# Issue-0041: 配布先からの申し送り経路と、クロスリポジトリの Issue 参照形式が未定義

- **Status**: closed
- **Opened**: 2026-08-05
- **Closed**: 2026-08-05
- **起票元**: 議論由来。LoopForAlpha の flow 課題 20 件の取り込み方針を検討する過程（ADR-0061 / ADR-0062）で検出
- **関連**: ADR-0061（配布先 flow 課題の取り込み経路）、`docs/overview/folder-structure.md` 7.2〜7.4、ADR-0056（delta 型と構造観察型の振り分け）、Issue-0040（`CONTRIBUTING.md` のテンプレート同期指示が現行構成と矛盾。本課題の修正先が同期対象のため前提になる）

## 課題内容

`docs/overview/folder-structure.md` 7.3 は「配布先プロジェクトの `flow/` 課題は、ガイドライン repo へ申し送り済み（または対応済み）で close する」と定めている。この規範は本リポジトリと配布先（LoopForAlpha）の両方に同一文で存在するが、**一度も適用されていない**。LoopForAlpha の flow 課題は 20 件すべてが open で、最古は 2026-07-11 である。規律違反ではなく、以下 3 点の未定義が原因である。

### (a) 起票経路に「配布先からの申し送り」が無い

7.2 が定める起票経路は「振り返り由来」「議論由来」の 2 つのみ。実践は先行しており、Issue-0033 / 0034 の起票元は `worklog-extract` 走査である。少なくとも「worklog-extract 走査由来」「配布先からの申し送り由来」の 2 経路が、規範に無いまま運用されている。

あわせて、取り込み時に**新規起票するか、既存 issue の「検討状況」へ追記するか**の判断基準も未定義である。一般形が既存 issue に吸収済みのものを新規起票すると重複する（実例: LoopForAlpha-0069 の対処は本リポジトリ Issue-0033 の定型項目リスト項目 8 に既に含まれている）。

### (b) クロスリポジトリの Issue 参照形式が未定義で、既に衝突している

Issue 番号はリポジトリ内で一意に採番される（7.2）。リポジトリ修飾のない `Issue-NNNN` 表記は、リポジトリをまたぐと別の課題を指す。

- **実例**: LoopForAlpha `flow/0034`（編集ツールが不可視文字のエスケープ表記を正規化する）と本リポジトリ `flow/0034`（計画・仕様など非コード成果物の確定前に実証を課した独立レビューを挟む工程がない）は、番号が同じで内容が異なる別課題である
- **worklog 台帳にも同じ穴がある**: `~/.ai-dev-worklog/processed.jsonl` の `ref` フィールドは `docs/working/issues/flow/0034-independent-review-with-proof-for-non-code-artifacts.md` というリポジトリ修飾なしの相対パスで記録されており、どちらのリポジトリを指すかは slug を読まなければ判別できない

### (c) worklog 経路では配布先を close するトリガーが発火しない

7.3 は「issue → issue」の申し送りを想定している。しかし実際に起きたのは「worklog エントリ → 本リポジトリの issue」であり、この経路には**配布先の issue を close する契機が誰にも割り当てられていない**。

LoopForAlpha-0069 と LoopForAlpha-0054 は、一般形が本リポジトリ Issue-0033 / 0034 として起票された時点で申し送り済みだが、配布先では open のまま残っている。ADR-0061 で delta 型を worklog 経路へ委ねると決めたため、この経路が主経路になる。**トリガーを定義しない限り、配布先の flow セクションはバックログではなく恒久的な駐車場として機能し続ける。**

## 検討状況

- 2026-08-05: 起票。ADR-0062 の Task 0 で対処する。修正先は `docs/overview/folder-structure.md` 7.2〜7.4 で、このファイルは `sync-template.ps1` の同期対象であるため、**Issue-0040 を先に片付ける必要がある**
- 対処の方向（未決）: (a) 起票経路の列挙に 2 経路を追加し、新規起票と既存 issue への追記の判断基準を書く / (b) クロスリポジトリ参照を `<repo>#Issue-NNNN` 等の修飾形式で定め、worklog 台帳の `ref` にも適用する / (c) close トリガーを `worklog-skillify` の手順か ADR-0061 の取り込み手順のいずれかへ割り当てる

## 結論

ADR-0063 と ADR-0068 の 2 本で対処した。

- **(a) 起票経路** と **(c) close トリガー** → ADR-0063（配布先からの申し送りを起票経路として定義し、受け皿の実在確認を close トリガーとする）。起票経路を 4 つへ拡張し、新規起票と既存課題への追記の使い分けを規定。close トリガーを受け皿の実在確認とし worklog 経路にも適用した
- **(b) クロスリポジトリの参照形式** → ADR-0068（他リポジトリの課題は `<repo>#Issue-NNNN` で修飾して参照する）。当初 ADR-0063 に含めていたが、答える問いが異なるため昇格前の粒度点検で分割した（ADR-0059 / ADR-0060）
