# Issue-0042: 検査・検出器の「検出力」を実証してから「守られている」と言う規律がない

- **Status**: open
- **Opened**: 2026-08-05
- **起票元**: `worklog-extract` 走査（2026-08-05、2回目）候補1。走査対象 118 件中 16 件が該当し、単一クラスタとして根拠数が最多
- **関連**: `superpowers:test-driven-development`（新規テストの RED 実測は義務化済み。既存検査の検出力は射程外）、`superpowers:verification-before-completion`（主張の前にコマンドを走らせるが、その検査が何を固定しているかは問わない）、`superpowers:requesting-code-review`、ADR-0064（本課題の一部を先行実装）、`LoopForAlpha#Issue-0084`（配布先での同一課題）、`LoopForAlpha#Issue-0081`（対象システム側の断面）、原則5（漸進的検証）

## 課題内容

AI のデフォルト挙動は「検査を書く → 緑（または本番 0 件）→ 完了」である。実際に必要だったのは、**その検査が RED になる変異が実在するかを毎回確かめる**ことだった。

本番で 0 件・全緑が出た状態は「**欠陥が無い**」と「**検出器が壊れている**」を区別できない。走査では、この区別が付かないまま「守られている」と報告する事象が 5 世代のモデルにまたがって 16 件再発している。

根拠エントリから、繰り返し要求された派生規律が 3 つ抽出できる:

1. **対策前の実装へ差し替えて落ちるか**を確かめる（`LoopForAlpha-2026-07-22-03`。`git show HEAD:<path>` で過去版を取り出して当てる）
2. **変異が no-op でないか**を、対象行を直接読んで確認する（`LoopForAlpha-2026-07-29-03`。等価変異は「検査に検出力が無い」ことの証明にならない）
3. **検出器には既知欠陥を含む入力を正の対照として同梱する**（`LoopForAlpha-2026-08-04-07`）。あわせて負の対照（正常入力を誤検出しない）で粒度を固定する

### 既存スキルとの境界

`test-driven-development` は新規テストについて「失敗を見てから書く」を義務化するが、**既存検査の検出力**と**等価変異の切り分け**は範囲外。`verification-before-completion` は「主張の前にコマンドを走らせる」ことを求めるが、その検査自体が何を固定しているか（書かれ方か、振る舞いか）は問わない。`requesting-code-review` のレビュアーテンプレートに変異・対照の要求はない。

**どのスキルにも無い面**: ミューテーションの全数走査 / 等価変異の切り分け / 検出器への正負対照の同梱 / 変異が実際に適用されたかの確認。
