# Issue-0045: 既存 open 課題の対策方針が実行可能かを点検する工程がない

- **Status**: open
- **Opened**: 2026-08-05
- **起票元**: `retrospectives/flow/2026-08-05-flow-issue-intake-and-worklog-pipeline.md` 課題#2
- **関連**: ADR-0069（汎用スキルの拡張先は自リポジトリに限る。本サイクルで決定）、ADR-0032（規範の判定条件はエージェントが観測・実行できる事実で書く。近縁だが対象が異なる）、`docs/overview/folder-structure.md` 7.2〜7.3、Issue-0033 / Issue-0034（実例）

## 課題内容

課題の対策方針は起票時・`worklog-extract` の採用時に書かれるが、その**実行可能性**（拡張先が自リポジトリに実在するか、編集が永続するか等）は着手時まで検証されない。起票と採用のどちらの工程にも確認ステップがない。

実例: Issue-0033 と Issue-0034 の対策方針は、いずれも superpowers プラグインのスキル拡張を前提にしていた。`worklog-skillify` を起動した段階で編集できないと判明し、方針を立て直すことになった。

ADR-0069 で今後の規範（対策方針を書く段階で拡張先が自リポジトリにあるか確認する）は定めたが、**既に起票済みの未着手課題に同種の見落としが潜在する**。

詳細（事象/原因/影響）は起票元の振り返りファイルが正。

## 検討状況

- 2026-08-05: 起票。ADR-0069 の Consequences に「同種の見落としが他の未着手課題にも潜在しうる」と記録した点を、独立した課題として切り出したもの
- 対処の方向（未決）: (a) 既存 open 課題の対策方針を一度棚卸しし、実行可能性を点検する（1 回限りの作業） (b) 着手時に対策方針の実行可能性を検証するステップをフローへ組み込む（恒久） (c) 起票時のフォーマットに「対策方針の前提が自リポジトリで成立するか」の欄を設ける。(a) と (b)(c) は排他ではない
