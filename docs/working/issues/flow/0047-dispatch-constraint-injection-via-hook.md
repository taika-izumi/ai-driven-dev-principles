# Issue-0047: サブエージェント委譲の常時制約を、規範文ではなくフックで機械注入できる

- **Status**: open
- **Opened**: 2026-08-05
- **起票元**: ADR-0070（A 群の実装方式を規範文に決めた際、繰り延べた代替手段）
- **関連**: ADR-0066（A 群 / B 群の分割）、ADR-0070（本課題を繰り延べた決定）、ADR-0039（環境・ツール設定による構造的解決の先行調査）、Issue-0033（定型項目の本体）、Issue-0039（ガイドライン遵守が不可視機構に依存しうる）

## 課題内容

ADR-0066 の A 群 4 件（実態優先の報告 / 既存ファイル削除の事前承認 / 範囲外作業の禁止 / 副エージェント起動の禁止）は**無条件適用**であり、タスクの型を判定せずに委譲プロンプトへ差し込める。ADR-0070 はこれを規範文として実装したが、遵守は AI が規範を読んで従うことに依存しており、取りこぼしうる。

Issue-0033 の根拠 10 件中 9 件が `friction`（人間の指摘を待たず AI が自力で踏んだ手戻り）である。つまりこの型の失敗は、**規範の不在ではなく規範の想起漏れ**として起きてきた。想起に依存しない手段があるなら、そちらのほうが構造的に強い。

## 調査済みの技術的事実

Claude Code 公式ドキュメント `code.claude.com/docs/en/hooks`（2026-08-05 取得）:

- `PreToolUse` フックは `Task`（サブエージェント委譲）を matcher に指定できる。フック入力の `tool_name` が `"Task"` になる
- `hookSpecificOutput.updatedInput` を返すと、ツール実行前に入力（委譲プロンプト）を書き換えられる
- フックはプラグインの `hooks/hooks.json` で配布できる。スクリプトのパスは `${CLAUDE_PLUGIN_ROOT}` で解決する。プラグインを有効化すると、利用者の user / project フックとマージされる
- `SubagentStart` / `SubagentStop` イベントも存在し、`agent_type` で matcher を書ける

つまり実装経路は存在する。着手時に再調査は要らない。

## 未解決の論点

- **ツール中立性**: フックは Claude Code 固有であり、GitHub Copilot CLI には同等の機構が確認されていない（未調査）。配布先が Copilot CLI の場合に何も効かなくなる状態をどう扱うか
- **二重管理**: 規範文（ADR-0070 で実装済み）とフックが同じ制約を持つと、片方だけ更新したときに実際に注入される文言と規範文が食い違う。実行中にどちらが効いているかを確認する手段がない
- **不可視性**: 効いている制約が設定ファイルの中にしか無い状態は Issue-0039 と同型である
- **検証手段**: フックが実際に発火して `updatedInput` が適用されたことを、どう観測して確かめるか（Issue-0044 と隣接）

## 着手判断の材料

ADR-0070 は効き目の測定方法を定めている: 本課題の起票後に「A 群の項目を渡し忘れた」型の delta が中央ストアへ再び現れるかを見る。現れれば規範文だけでは不足であることの実測になり、本課題へ着手する根拠になる。現れなければ規範文で足りている。
