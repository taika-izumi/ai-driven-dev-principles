## 課題内容

`session-handoff` はブランチごとの単一ファイルを時系列追記で運用しており、**完了した情報が落ちる仕組みがない**。削除規約があるのは「Post ラッパー消化記録」のみ（ADR-0057 の finalize 時削除）で、本文の各節（Current Phase / 既知のブロッカー / 次セッション開始時のアクション）には圧縮・剪定の規約がない。

あわせて、外部文書への参照が**節名・項番**で書かれており、参照先の構造が変わっても追随しない。

配布先での実測（LoopForAlpha、2026-08-05）:

- `docs/working/handoff/master.md` が **573 行・約 77KB** に達し、1 回の読み込みで読み切れず、セッション開始時に分割読みとセクション検索が必要になった（Phase 0 のハンドオフ読み込みがセッション開始時の最大消費になる）
- ハンドオフが案内していた**不可逆操作の手順書への参照が節名の取り違え**で誤っており、複数セッションにわたって残っていた（実害は正本への突き合わせで回避）

本リポジトリの `master.md` も 100 行前後で同型の兆候がある（ADR-0062 の Consequences で記録済み）。

## 留意（対処を設計するときに参照すること）

- **単純に短くする方向で解かないこと。** ハンドオフの記述の多くは「同じ罠を二度踏まないための実測済みの申し送り」であり、削ると再発する（配布先では複数の警告が後のセッションで踏みかけた罠を実際に防いでいる）
- 検討の切り口の候補: サブプロジェクト単位のアーカイブ / 「現在有効な申し送り」と「完了した経緯」の分離 / 外部参照を節名ではなく安定した識別子で書く規約
- Issue-0053（セッション再起動での素材消失）と交差する。ハンドオフは素材の主な担い手でもあるため、肥大と剪定はどちらもリスクを持つ
