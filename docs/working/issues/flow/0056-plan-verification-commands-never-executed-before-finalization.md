## 課題内容

ADR-0034 / Issue-0013 が定める plan の検証は「各検証ステップの**期待値**が、そのタスクの編集内容と矛盾しないか」という意味的な突合であり、「**検証コマンド自体が構文的に実行可能か**」は対象外になっている。計画の確定前にコマンドを一度も走らせない工程設計のため、実行不能なコマンドや、意図と違う対象を走査するコマンドが計画に残る。

振り分け判定: **構造観察型**（個々のコマンド誤りは delta として worklog に記録できるが、「確定前に実行可能性を検査する工程が無い」ことは体系の俯瞰で初めて見える欠落であり、delta の再発待ちでは捕捉できない）。

詳細（事象/原因/影響）は起票元の振り返りファイルが正。

- 2026-08-07（同日・次サイクル）: **対策を手動で先行適用し有効性を確認**（ADR-0079 サイクル）。計画確定前に検証コマンド 7 本を実行し、構文エラーゼロと現状値（未実装のため 0 件等）が期待値の前提と整合することを突合した。実行時エラーは 1 件も出ず、前サイクルの失敗は再発しなかった。**ただし限界も判明した**: 事前実行が担保するのは実行可能性までで、(a) 検出力（欠陥を入れたら落ちるか）は別問題として残り（Issue-0042）、(b) 出力形式が期待値の判定に足るかも別で、実際 `Group-Object Filename` が同名ファイル（`SKILL.md`）を併合してファイル別の期待値を判定できず、実行段階で個別実行へ切り替えた（worklog `MakeAiInstructions-2026-08-07-05`）。対策を設計する際は「実行できるか」だけでなく「出力が判定に使える形か」も検査対象に含めること
