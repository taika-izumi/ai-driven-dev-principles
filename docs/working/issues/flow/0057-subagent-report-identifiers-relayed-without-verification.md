# Issue-0057: サブエージェントの完了報告に含まれる識別子を検証せず後続へ転記する経路がある

- **Status**: open
- **Opened**: 2026-08-07
- **起票元**: `retrospectives/flow/2026-08-07-rename-to-ai-driven-dev-guideline.md` 課題#2
- **関連**: ADR-0038（変更の適用結果は実体の読み直しで確認する）、ADR-0066 / ADR-0071（`subagent-dispatch` の A 群・B 群）、worklog `MakeAiInstructions-2026-08-07-01`

## 課題内容

ADR-0038 の読み直し規範は「**自分の変更**の適用結果」を対象としており、「**委譲先が報告した事実**」の検証は明示されていない。委譲先の報告は自然言語であり、ツールの戻り値と違って構造的な検証点が無いため、報告に含まれる識別子（コミットハッシュ・ファイルパス・件数）を検証せずそのまま後続の委譲プロンプトや記録へ転記する経路が開いている。

`subagent-dispatch` が扱うのは「委譲プロンプトに**何を書くか**」であり、「委譲先の報告を**どう受け取るか**」は現行のどのスキルも扱っていない。

振り分け判定: **構造観察型**（個別事象は worklog に delta として記録済みだが、報告受領時の検証工程が体系に無いこと自体は構造の欠落で、`subagent-dispatch` の責務境界の外側に落ちている）。

詳細（事象/原因/影響）は起票元の振り返りファイルが正。

## 検討状況

- 2026-08-07: 起票。改名サイクル（ADR-0078）で実測。実装エージェントの完了報告に実在しないコミットハッシュ `21eb69c` が含まれ、検証せずレビュー委譲プロンプトへ転記した。レビューエージェントは存在しないオブジェクトを対象に起動したが、A 群 1（指示より実態を優先し報告）が働いて自力で異常を検知し正しいコミット `7ffcdab` を特定したため、被害はレビュー 1 回の空振りと訂正 1 往復にとどまった。異常に気づけたのは同一エージェントから 2 回目の通知が届き、1 回目と異なるハッシュを報告したためであり、通知が 1 回だけなら見逃していた
- 2026-08-07（同日・次サイクル）: **対策を手動で先行適用**（ADR-0079 サイクル）。委譲プロンプトへ「コミットハッシュは `git log -1 --format=%H` の実測値のみ報告すること。記憶で書かない」を明記したうえで、受け取った全ハッシュ 9 件をコントローラー側で `git cat-file -t` と `git show --stat` により実在・変更ファイルまで検証してから後続へ転記した。不一致は 0 件で、前サイクルのような空振りは発生しなかった。コストは 1 委譲あたりコマンド 1 本で、対策を設計する際の実行可能性の裏づけになる
- 2026-08-07（ADR-0080 サイクル）: **3 サイクル連続で有効性を確認、かつ検証対象の拡張が必要と判明**（ADR-0031）。11 回の委譲で報告された全コミットハッシュを `git cat-file -t` ＋ `git show --stat` で検証し、不一致 0 件。加えて本サイクルでは、サブエージェントが **`git reset --soft HEAD~1` による履歴の巻き戻しを申告**する事象が発生し、ハッシュの実在確認だけでは足りず `git reflog` で巻き戻しの経緯（誤コミット → reset → 再コミット）と作業内容の非損失まで裏取りする必要があった。**対策の検証対象は「報告された識別子の実在」に加えて「報告された操作が実際にその通り行われたか（履歴操作を含む）」へ広げるべき**という知見が加わった
