# Issue-0061: 「Skillを新規作成・改定するとき」シナリオの手順・チェックリストが新規作成前提のまま

- **Status**: open
- **Opened**: 2026-08-07
- **起票元**: 2026-08-07 ADR-0079 サイクルのファイナルレビュー（全実装横断レビュー）
- **関連**: `CONTRIBUTING.md`「シナリオ: Skillを新規作成・改定するとき」、ADR-0079（改題とカバー文の導入元）、`skills/extend-guidelines/SKILL.md`

## 課題内容

ADR-0079 サイクルで「シナリオ: Skillを新規作成するとき」を「新規作成・改定するとき」へ改題し、既存スキルの改定も本シナリオに従う旨のカバー文を追加した。しかし手順・チェックリストの本文は新規作成前提のままで、改定ケースへの読み替え規定がない:

- 手順 2「`skills/<skill-name>/SKILL.md` を作成する」・手順 5「README のスキル一覧テーブルに新スキルを追加する」は改定時には不適用
- チェックリスト「Skill名が動作を端的に表しているか」「README のスキル一覧テーブルを更新したか」も新規作成前提
- 改定時に見直すべきメタデータ（frontmatter の `description` がスキルの入口・トリガーであり、本文の改定と乖離しうる）を点検する工程がない。実際、本サイクルで extend-guidelines のヒアリング選択肢へ「既存のSkillを改定したい」を追加した際、description の更新が漏れ、ファイナルレビューで検出・修正された（改定時の description 見直し工程があれば実装時に気づけた）

## 留意（対処を設計するときに参照すること）

- 手順を「新規作成の手順」「改定の手順」に分けるか、読み替え規定を添えるかの二択が自然
- 改定手順には「frontmatter description と本文の整合点検」を含める価値がある（本サイクルの実測）
