# Issue-0063: 実装中に確定した文言を作業文書（plan）へ反映するかの規約が未定義

- **Status**: open
- **Opened**: 2026-08-07
- **起票元**: `retrospectives/flow/2026-08-07-overfitting-check-for-extensions.md` 課題#2
- **関連**: `superpowers:writing-plans`、ADR-0008（spec のスナップショット規約）、ADR-0011（記録の時系列追記型規約）、`CLAUDE.md` ドキュメント運用

## 課題内容

実装中にレビュー指摘などで確定文言が変わったとき、正本である spec は書き換え更新する規約（ADR-0008）があるが、実装計画（`docs/working/plans/`）に同じ変更を戻すかどうかの規約がない。

2026-08-07 の ADR-0079 サイクルでは、品質レビュー由来の文言修正（手順のラベル形式化・語尾の統一）で spec を同期した（`408d1bb` / `6670ea6`）一方、計画ファイルは旧文言のまま残った。「plan は時系列の作業記録だから戻さない」のか「同期漏れ」なのかを外形的に区別できず、計画を再読したときに突合コストが生じる。

## 留意（対処を設計するときに参照すること）

- 記録類には既に 2 つの相反する規約がある（spec = スナップショット書き換え / retrospective = 時系列追記の上書き禁止）。plan をどちらに寄せるかの判断であり、新しい第 3 の規約を作る必要は薄い
- plan は実行後に参照されることが少ないため、対処が「同期する」方向だと恒常コストに見合わない可能性がある。「戻さない」と明記して意図的な非同期であることを外形的に示す対処も候補
