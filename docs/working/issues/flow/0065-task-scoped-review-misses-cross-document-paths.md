# Issue-0065: タスク単位のレビューでは、複数文書にまたがる規範の「経路が閉じているか」を検出できない

- **Status**: open
- **Opened**: 2026-08-07
- **起票元**: `retrospectives/flow/2026-08-07-review-presentation-by-artifact-type.md` 課題#1
- **関連**: `superpowers:subagent-driven-development`（タスク単位の二段レビュー）、`skills/pre-finalization-review/SKILL.md`（適用例「文書間相互作用型」と同型）、ADR-0080、worklog `MakeAiInstructions-2026-08-07-11`

## 課題内容

`subagent-driven-development` で実装した全 8 タスクが個別に spec 準拠レビューと品質レビューを通過した後、実装全体の最終レビューが Major 4 件を検出した（要約。詳細は起票元参照）。うち 2 件は ADR-0080 の中核経路が空転する欠陥で、最終レビューを実施しなければそのまま確定していた。

原因は、タスク単位のレビューでは実装者もレビュアーも当該タスクの編集箇所しか読まないこと。「規範を実際に走らせたときに経路が閉じるか」「同じ規範への到達経路が複数あるとき全経路にフックがあるか」「記録の書き込み順序と値の確定順序が整合するか」は、タスクの外側にしか現れない。

## 留意（対処を設計するときに参照すること）

- **一次資料は起票元の振り返りファイル**にある。検出された 4 件の内訳（記録順序の逆転 / 確定点の重複発火と経路依存の発火条件 / フックの単一配置による迂回 / 引用元のゲートの脱落）が、それぞれどういう構造で個別レビューをすり抜けたかを記載している。対処を設計する前に必ず読むこと
- 本件の知見は単一サイクル・単一の成果物種別（複数スキルにまたがる規範）由来である。対処の設計時は ADR-0079 の過剰適合点検を適用すること（とくに観点 1「出所の偏り」）。**コード実装のサイクルで同じ死角が生じるかは未検証**であり、規範文書に限った話である可能性がある
- `subagent-driven-development` は superpowers プラグインのスキルで**本リポジトリの編集対象にならない**（ADR-0069 と同じ制約）。対処は本 repo 側のスキル（`start-work` の Post ラッパー、`pre-finalization-review` 等）か、委譲プロンプトの組み立て（`subagent-dispatch`）に置くことになる
- 本サイクルでは最終レビューを実施したため回避できた。したがって「最終レビューを必ず実施する」形の対処と、「タスク単位レビューの射程を広げる」形の対処が考えられる。前者は `subagent-driven-development` が既に最終レビューを規定しているため、規範の追加ではなく**実施の確実化**が論点になりうる
- 判定条件はエージェントが観測できる事実で書くこと（ADR-0032）。あわせて、本サイクルで判明した「発火条件をイベントで書くと経路依存になる」型（worklog `MakeAiInstructions-2026-08-07-11`）にも注意すること
