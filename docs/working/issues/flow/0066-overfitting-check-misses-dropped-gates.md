# Issue-0066: 過剰適合点検の観点 3 に、引用元の条件付き規範を無条件化する型を検出する手順がない

- **Status**: open
- **Opened**: 2026-08-07
- **起票元**: `retrospectives/flow/2026-08-07-review-presentation-by-artifact-type.md` 課題#2
- **関連**: ADR-0079（過剰適合点検）、`CONTRIBUTING.md`「全シナリオ共通: 過剰適合の点検」観点 3・是正パターン「観測可能な発動条件でゲート」、`CLAUDE.md`「ユーザーへの質問と意思決定要求」、ADR-0029、ADR-0080

## 課題内容

ADR-0080 の過剰適合点検で観点 3「AIモデル/ツール依存性」を「問題なし」と自己判定したが、その後の最終レビューが、モデル条件でゲートされた既存規範を**無条件規範として引き写している**箇所を検出した（要約。詳細は起票元参照）。

観点 3 の問いは「特定モデル・ツールの挙動を暗黙の前提にしていないか」であり、**引用元が持っていたゲートを引き継いだか**を確認する手順がない。ゲートを落とす方向の誤りは、観測すると「モデルに依存しない無条件規範」に見えるため、素朴な自己点検を通過する。

## 留意（対処を設計するときに参照すること）

- この型は過剰適合ではなく**過剰一般化**である。観点 3 の現行の問いは「前提を持ち込んでいないか」という縮小方向のみを見ており、「前提（ゲート）を落としていないか」という拡大方向を見ていない。同じ非対称が他の観点にもあるかを確認すること（観点 2「システム種別依存性」にも同型がありうる）
- 検出の手がかりは機械化しやすい可能性がある。**拡張が他文書の規範を参照・引用している箇所を列挙し、引用元にゲート（「〜の場合に限り」「確認済みモデル」等の条件節）があるかを突合する**、という形なら観測可能な手順になる（ADR-0032）
- 一方で、点検項目を増やすと点検自体が重くなる。ADR-0079 は「点検が形骸化しないこと」を設計の前提にしており、**観点の追加ではなく既存観点 3 の問いの書き換えで足りるか**を先に検討すること
- 本件の実測は単一サイクル 1 件（ADR-0080）である。対処の設計時は ADR-0079 の点検を自分自身に適用すること（観点 1「出所の偏り」）
- 発見経路は「文書間の突合」であり、点検の実施時点では見えなかった。したがって対処を点検手順に置くのか、独立レビューの観点に置くのか（Issue-0065 と同じ領域）で解が分かれうる。両者を同時に扱うと判断が一度で済む可能性がある
