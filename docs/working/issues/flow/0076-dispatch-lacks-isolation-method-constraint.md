# Issue-0076: 破壊的な検証を委譲するとき、隔離の作り方を指定する制約項目がない

- **Status**: closed
- **Opened**: 2026-08-08
- **Closed**: 2026-08-15
- **起票元**: `retrospectives/flow/2026-08-08-distributed-artifact-generation.md` 課題#4
- **関連**: ADR-0066（A 群 / B 群の分割）、ADR-0071（B 群の発火判定）、ADR-0073（根拠と退役経路）、`skills/subagent-dispatch/SKILL.md`

## 課題内容

委譲プロンプトへ「破壊的検証はスクラッチパッドの複製で行う」と明記し、委譲先も複製で実施したと報告したにもかかわらず、**実リポジトリのファイルが 2 度壊れた**（2026-08-08 実測）。

| 回 | 被害 | 復旧 |
|---|---|---|
| 1 | 決定記録インデックス 92 行が空ファイルになった | 追跡ファイルだったため `git checkout` で復旧。原因は特定できなかった |
| 2 | 配布物 1 ファイルに BOM が書き込まれた | 委譲先が検出・復旧し、原因を自己申告した |

原因は 2 回目の申告で判明した。**PowerShell の `Set-Location` は .NET の静的 API に効かない**。`[System.IO.File]::WriteAllText` などはプロセスの作業ディレクトリを基準にするため、複製ディレクトリへ移動しても相対パスでは元のファイルを書き換える。

委譲制約の常時適用項目には「既存ファイル・ディレクトリの削除は事前承認を要する」があるが、**隔離環境の作り方**（複製の手段・絶対パスの使用・作業前後の状態比較）を指定する項目がない。「複製で検証する」という指示だけでは、言語とランタイムの組み合わせによって成立しない。

## 影響

- git 管理下のファイルなら復旧できるが、未追跡ファイルや生成物であれば復旧手段がない
- 委譲先の自己申告と実態が食い違うため、事後の切り分けができない（1 回目は原因を特定できないまま終わった）
- 委譲側がコミット前に `git status` を全件確認しなければ、壊れた状態のままコミットしうる

## 対策の方向（採否は未定）

- B 群へ「破壊的検証を委譲するとき」の発火条件を足し、展開項目として (1) 複製の作り方を具体的に指定する（コピー元・コピー先・手段） (2) **絶対パスを使う**（`Set-Location` に頼らない） (3) 作業前後の `git status` を記録して比較し、比較結果を報告に含めさせる、を課す
- あるいは既存の「並列に委譲し、かつ委譲先がファイルを書き換えるとき」（worktree による隔離）の条件を、並列でない破壊的検証へ広げる
- 委譲側の受け取り時の確認（`git status` の全件確認）を、横断的ラッパーの Post へ足す案もある

## 検討状況

- 2026-08-08: 起票。delta 型だが同じ機構で 2 度発生しているため、worklog の横断走査を待たず起票した（worklog にも記録済み: `MakeAiInstructions-2026-08-08-06` / `-09`）
- 2026-08-15: 対策の方向 3 案を比較し、案 1（B 群への発火条件追加）を採用。案 2 は事故機構を塞げないため不採用、案 3 の受け取り時確認は `subagent-dispatch` の手順節へ実装先を移して採用した

## 結論

ADR-0093 で対策を決定し実装した（`subagent-dispatch` B 群へ発火条件「破壊的検証」を追加。隔離機構の第一選択・絶対パスと隔離ルートの突合・内容ハッシュの前後比較・委譲側の受け取り時独立確認）。「影響」に挙げた未追跡ファイル・生成物の破壊は、独立レビューの実験で `git status` 比較が原理的に検出できないことが判明したため、内容ハッシュ比較を主とする設計へ変更して塞いだ。既存の並列書き換え行にも同じ事故機構が残っていたため絶対パス項目を追記した。
