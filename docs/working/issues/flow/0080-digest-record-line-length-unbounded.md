# Issue-0080: Post ラッパー消化記録の「1 行」に長さ・内容の規範がなく、正本を名指ししながら詳細を重複記載して肥大する

- **Status**: closed
- **Opened**: 2026-08-13
- **Closed**: 2026-08-14
- **起票元**: feature/handoff-bloat-analysis サイクルのアドホック調査（LoopForAlpha のハンドオフ肥大化）
- **関連**: ADR-0057（消化記録の新設）、ADR-0080（`review=` の記録と保持）、`skills/session-handoff/SKILL.md`、Issue-0078 / Issue-0079 / Issue-0081（兄弟課題）

## 課題内容

消化記録は「マイルストーンごとに 1 行」という形式だけを定めており、**行の長さ・内容粒度の規範がない**。ADR-0057 の意図はチェックリスト証跡（ADR 番号 / worklog id / review 結果の外形記録）だが、実運用では 1 行にレビューの走査母数・指摘件数・Critical の中身・是正コミットまで書き込まれる。

LoopForAlpha での実測（2026-08-13、`docs/working/handoff/master.md`）:

- 消化記録節が 28KB（ファイル全体 99KB の 28%）。1 行平均 875 バイト、最大 2.5KB
- 多くの行が**同じ行内で「正本は計画の総括節 / Issue-0096」と正本を名指ししながら、その詳細を重複記載**している（参照だけで足りる情報が二重化）
- ADR-0080 により本サイクルの `review=` 行は finalize でも保持されるため、行が肥大したままサイクル終端（LoopForAlpha では数週間。Issue-0078）まで残る

## 影響

- 消化記録が証跡（1 行）でなく報告書（各行が段落）になり、read 時の要約コストが上がる
- 肥大した `review=` 行が保持規則で保護され、Issue-0078 のサイクル長と掛け算で節全体が数十 KB 化する

## 対策の方向（採否は未定）

- 行の内容を「判定結果＋安定識別子（ADR 番号 / worklog id / Issue 番号 / コミットハッシュ）＋正本への参照」に限定する規範を追加し、レビューの内訳・実測値は正本（計画・監査記録・Issue）側へ書くことを明示する
- 行の長さの目安（例: 200 字程度）を示す
- update 手順に「詳細を書きたくなったら正本へ書き、行には参照を書く」の分岐を明記する

## 検討状況

- 2026-08-13: 起票。対策の採否・設計は次サイクル（ユーザー判断）

## 結論

消化記録 1 行の内容を「判定結果＋安定識別子＋正本への参照」に限定し、1 行 200 字以内（デフォルト値）を規定した（ADR-0088）
