# Issue-0081: handoff の自由記述部の記載量を制御する規範がない（タイトル・次アクション・「要点のみ」抜粋・圧縮実施記録の残置）

- **関連**: ADR-0074（剪定の受け皿は git 履歴のみ）、ADR-0075（基準付き圧縮）、`skills/session-handoff/SKILL.md`、Issue-0078 / Issue-0079 / Issue-0080（兄弟課題）

## 課題内容

session-handoff のフォーマットは節構成を定めるが、各節の分量・記載形式の規範がないため、消化記録（Issue-0080）以外の自由記述部でも肥大の型が複数発生する。LoopForAlpha での実測（2026-08-13、`docs/working/handoff/master.md` 99KB）:

1. **タイトルへの状態詰め込み**: 見出し 1 行が 3.4KB（段階・フェーズの進捗・据え置き判断・ADR 参照まで太字混じりで記載）
2. **「次セッション開始時のアクション」の状態ダンプ化**: スキルの想定は 3 項目だが 11.5KB。確認ファイルの列挙が仕様・ADR・課題の全景説明になっている
3. **「要点のみ」抜粋の肥大**: 「正本は X。ここには要点のみ」と書きつつ、要点が数百バイト × 数十項目（正本参照の意味が薄れる）
4. **圧縮実施記録の残置**: finalize の圧縮で「何を削除したか」を 1.5KB の行として handoff 内に残している。ADR-0074 の「落とした情報の受け皿は git 履歴のみ」からの逸脱（削除の記録自体が肥大源になる）

## 影響

- 節ごとの規範がないため、finalize の圧縮対象基準（完了タスク・役目を終えた状態情報）に該当しない場所へ肥大が移る
- タイトル・次アクションは read 時に必ず要約対象になる場所であり、肥大がセッション開始コストへ直結する

## 対策の方向（採否は未定）

- フォーマット節に各節の分量目安と記載形式（タイトルは作業名のみ・状態は Status/Current Phase へ、次アクションは 3 項目・各 1〜2 行、など）を明記する
- 圧縮の実施記録は handoff に残さない（受け皿は git 履歴＝コミットメッセージ）ことを finalize 手順に明記する
- read 操作にサイズ実測を組み込み、閾値超過で警告する（Issue-0078 の対策と共用可能）

## 検討状況

## 結論

節別の字数規範（デフォルト 200 字）・列挙外の節への既定規則・圧縮記録の残置禁止を規定した（ADR-0088）
