# Issue-0082: 選択肢提示規範の spec が 3 世代前のツール選択規範のまま（スナップショット規約違反状態）

- **Status**: open
- **Opened**: 2026-08-13
- **起票元**: ADR-0085 の確定前レビュー（3 観点独立レビュー。実装整合性・仕様適合の両観点が独立に検出）
- **関連**: ADR-0024（元規範）、ADR-0036（環境確認ゲート）、ADR-0085（事象確認済みモデルでの不使用）、`docs/current/specs/2026-06-16-choice-with-recommendation-design.md`（対象ファイル）

## 課題内容

`docs/current/specs/2026-06-16-choice-with-recommendation-design.md` が、ADR-0024 時点（2026-06-16）の「構造化された質問ツールが利用できる場合はそれを使う」というツール選択規範のまま維持されており、現行規範（ADR-0036 の環境確認ゲート → ADR-0085 の事象確認済みモデル不使用、の 3 分岐）と矛盾している。CLAUDE.md「仕様書は、それを読むだけで現時点のシステム全容が分かるスナップショットとして維持すること」に反する状態。

具体箇所（2026-08-13 のレビュー実測）:

- L26-27「ツールの扱い」節: 「構造化された質問ツール（…）が利用できる場合はそれを使う。利用できない場合はテキストで選択肢を列挙する」
- L48: CLAUDE.md への反映文面の引用ブロックが同旨の旧文面
- L5 / L32 / L54 / L64 / L66: 存在しないパス `docs/principles.md` を参照（実体は `docs/overview/principles.md`。ADR-0025 のフォルダ再配置に追随していない）

乖離は ADR-0036（2026-07-05）の時点で始まっており、ADR-0085（2026-08-13）で反転幅が最大化した。旧型式の単一ファイル spec の維持方針が未定義である問題（Issue-0008）とも重なる。

## 影響

- 当該節の規範を記述する唯一の spec が、現行規範の反対を述べている（spec を信頼して読むと誤った規範を学習する）
- スナップショット規約（書き換えで更新）の実効性が、規範改定時の spec 追随漏れで崩れる型の実例になっている

## 対策の方向（採否は未定）

- 当該 spec の「ツールの扱い」節と引用ブロックを現行 3 分岐へ書き換え、パス参照を修正する
- または Issue-0008（旧型式 spec の維持方針未定義）の解決とあわせて、旧型式 spec の扱い（維持 or アーカイブ）を先に確定する

## 検討状況

- 2026-08-13: 起票。ADR-0085 サイクルのスコープ外（先行ドリフト）のため課題化
