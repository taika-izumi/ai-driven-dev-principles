# Issue-0085: 消化記録へフィールドを新設する拡張に、記録様式側の連動改定チェックリストが無い

- **Status**: open
- **Opened**: 2026-08-15
- **起票元**: `retrospectives/flow/2026-08-15-issue-0074-0065-cycle-check.md` 課題#1
- **関連**: `skills/session-handoff/SKILL.md`「Post ラッパー消化記録」、ADR-0092（`cyclecheck=` 新設サイクル）、ADR-0057 / ADR-0080（`review=` 導入の先行例）

## 課題内容

消化記録（handoff「Post ラッパー消化記録」）へ新フィールドを追加する拡張は、session-handoff の様式 8 箇所（形式行・書式例・記載条件/命名規約・節別記載規範・update・read・finalize 削除例外・「圧縮しないもの」保護リスト）への連動改定を要するが、この対応一覧が文書化されておらず、設計者が都度復元している。

ADR-0092 の `cyclecheck=` 新設では、復元漏れに起因する記録経路の穴（欠落検査の対象行識別・実装前昇格の偽陽性・後追い検査の記録先・形式行本体・保護リスト）が確定前レビュー 2 巡で計 7 指摘として検出された。レビューが無ければ「記録は増えるが誰も読まない・検査されない」状態で確定していた。詳細は起票元の振り返りファイルが正。

## 対策の方向（採否は未定）

- session-handoff スキルに「フィールド追加時の連動改定チェックリスト」を 1 節置く（今回の 8 箇所を初期値とする）
- あるいは、次のフィールド追加サイクルで ADR-0092「記録」「変更対象」節の実例を参照する運用に留める（頻度が低ければチェックリストの維持コストが上回る可能性）
