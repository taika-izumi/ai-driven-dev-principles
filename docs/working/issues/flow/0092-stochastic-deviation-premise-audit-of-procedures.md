# Issue-0092: 「確率的逸脱は残る」前提でのガイドライン全体棚卸し（過剰手順の検出実績ベース監査）が未実施

## 課題内容

本ガイドラインの直近の改修サイクルは、ほぼすべて「前サイクルのレビュー・振り返りで見つかった穴を、新しい検査・記録・規範で塞ぐ」型だった。「AI の出力は確率的に決定されるため、AI によるダブルチェックを重ねてもルールからの逸脱・矛盾は必ず残る」という前提（ADR-0099 Context で初めて明文化）を持たずに積まれた蓄積分には、期待検出量に見合わない過剰な手順が含まれている可能性がある。

構造的に過剰が疑われる領域（仮説。監査で実測検証する）:

- 検査の三層重複: 過剰適合点検（設計承認前）・サイクル全体整合検査（昇格前）・確定前レビュー（確定点ごと）が同じ成果物を別タイミングで読む
- 証跡・台帳系の増殖: 消化記録のフィールド 4 種・命名規約・欠落検査・圧縮例外規定など「プロセスについての記録」の管理コスト
- 毎マイルストーンの Post ラッパー 4 項目（worklog ゲート判定は棄却が多数）

## 対策の方向（採否は未定）

感覚で削らず、規範ごとの台帳を作って実測で判定する:

1. 常時・毎サイクル発火する工程・規範のインベントリを作る（発火頻度・1 回あたりのコスト）
2. 規範ごとに導入以来の検出実績を集計する（材料: `docs/records/retrospectives/README.md` の各サイクル要約、消化記録の git 履歴、worklog 中央ストア、各 ADR の検出実績記述）
3. keep / 簡素化 / 統合 / 退役候補に分類してユーザー判断を仰ぐ（各規範の退役規範条項の初回行使にあたる）
4. 削る・受容するだけでなく、今後の増設に対する歯止め（ADR-0099 の複雑化抑制制約の一般規範化・原則化）も同時に検討する

## 留意（監査を設計するときに参照すること）

- **「検出実績なし」は「規範が不要」と「発火機会がまだ無かった」を区別できない**（起票時のユーザー指摘）。直近追加された規範の多くは本リポジトリのガイドライン拡張作業でしか動いておらず、配布先プロジェクトの実運用に晒されていない。判定は検出実績の絶対数ではなく**発火機会数に対する比**で行い、発火機会が少ない規範（特に配布先での活用実績が無いもの）は退役判断を保留する側へ倒すこと
- 検出実績が実在する規範もある（確定前レビューは直近サイクルでも Critical 2 件を捕捉、サイクル全体整合検査は導入根拠に実測 7 件）。一律削減ではなく規範単位の判定とすること
- 監査自体が重い工程を新設しては本末転倒になる。監査は 1 回限りの調査として実施し、常設の工程を増やさないこと
