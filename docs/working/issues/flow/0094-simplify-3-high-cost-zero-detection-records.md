## 課題内容

監査で、記録・証跡型のうち欠落・不整合の検出が導入以来 0 件のまま高コストの様式を維持している 3 行が「簡素化」に分類された:

- **C-11**: `session-handoff` update 操作の本体（手順 1〜7・10 の 8 手順）
- **D-11**: `decision-log` 承認の昇格手順（5 ステップ）
- **I-17**: `retrospective` Phase 2（2 ファイル保存＋全件起票＋README 行追加）

## 対策の方向（採否は未定）

各様式の手順数・記載項目を削る簡素化案を作り、ユーザー判断で適用する。D-11 は Issue-0093 の K6（B-13 の統合先）と同時に扱うのが自然。簡素化の設計では、検出 0 が「様式が守られている」ことの結果である可能性（予防効果）に留意し、削る範囲は証跡の検出可能性を落とさない部分に限る。配布対象ソースに触れるため執行点 4 手順・version bump・過剰適合点検の対象。

## 検討状況

- 2026-08-16: 起票。実装は次サイクル以降（小規模）。
- 2026-08-17: 対策サイクル着手（ADR-0103 で Issue-0093 と同一サイクルに同梱、設計は ADR-0105）。なお対策の方向の「配布対象ソースに触れるため」の対象列挙のうち CONTRIBUTING.md は配布対象ソースに当たらない（ADR-0102 の実測。独立レビュー第 1 巡で検出）。

## 結論

ADR-0105 で対応。C-11 は手順の束ね直し（10→5 手順）、D-11 は昇格手順の束ね直し（5→3 ステップ）、I-17 は起票手順の参照化（正本を issue-management.md に一意化）。いずれも証跡の様式と義務は不変（削減は手順の記述構造のみ）。
