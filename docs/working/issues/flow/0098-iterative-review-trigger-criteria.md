# Issue-0098: 確定前レビューの反復（指摘反映後の再レビュー）の発動基準が未定義

- **Status**: open
- **Opened**: 2026-08-16
- **起票元**: Issue-0096 サイクルのユーザー指摘（レビュー指摘の反映後、再レビューの提示なしに確定まで進めた）

## 課題内容

確定前レビュー（pre-finalization-review）の指摘を反映して成果物を改訂したあと、改訂版へ再レビューをかけるか（重大指摘が無くなるまで反復するか）の基準が規範に無い。現行規範（start-work「確定前レビューの提示規則」但し書き）は「レビュー指摘を反映した改訂差分は未レビューに数えない。差分の再確認の要否はユーザー判断とし、選択肢として並記する」とだけ定めており、(1) 並記の実施が徹底されない（Issue-0096 サイクルで提示漏れが実測された）、(2) どういう条件なら反復を推奨側に置くべきかが書かれていない。

実測の分布: レビューを挟んだ過去セッションのほぼすべてで反復は未実施。反復が観測されたのは Issue-0092 監査セッションが初（重大指摘が無くなるまで反復し品質向上に寄与）。一方で反復は作業時間を明確に増やすため、常時反復は過剰の懸念がある（増設の歯止め ADR-0102 の評価可能性義務の観点でも、発動条件と期待検出量の定義が要る）。

## 対策の方向（採否は未定）

反復を推奨側に置く条件の候補（検討材料。決定は ADR で行う）:

- 初回レビューで Critical（またはそれ相当）の指摘が出た場合
- 改訂が指摘の機械的反映を超えて、新規の規範文・設計・配線を含む場合（Issue-0096 サイクルの実例: フック配線・執行点・退役規範小節が改訂で新規追加された）
- 成果物が規範・手順文書（実行による安全網が無い型）である場合

反復の停止条件（重大指摘ゼロ / 最大 N 巡 / ユーザー打ち切り）と、記録先（消化記録 `review=` の値に巡数を含めるか）も同時に設計する。
