# Issue-0109: 確定前レビューの反復規範が、状況の実測を無視した形式条件で推奨の向きを決めている

- **Status**: open
- **Opened**: 2026-08-22
- **起票元**: 利用者指示（第68回。第6段階フェーズ5 詳細化の確定前レビュー反復での実測を、将来の反復レビュー運用の改善材料として保存する）
- **関連**: `start-work`「指摘反映後の反復」（前置1・前置2・2段型・骨格安定）/ `pre-finalization-review`「反復の実施」/ worklog `LoopForAlpha-2026-08-22-05` / ADR-0154 / 計画 `docs/working/plans/2026-08-10-stage6-universe-expansion.md` フェーズ5 節（`3e39e43`）

## 課題内容

確定前レビューの反復で、**規範に基づく推奨と実際に妥当な選択が乖離する**。規範の推奨判定が、その時々の状況（増設の中身・収量曲線・下流の安全網）を判定材料にしない形式条件（増設回数・改訂の型・巡数）だけで向きを決めていることが原因とみられる。乖離のたびに利用者が「規範は置いて意見を」と確認する往復が発生する。

**乖離事例は検討ノート `0109-note-divergence-cases.md` に判断材料つきで蓄積する**（本課題の中核資産。規範ベースの推奨と実選択が乖離した事例を検出するたびに追記する）。

## 現在地の要約（2026-08-24 第77回時点）

- 事例8件 + 横断観測2組を記録済み（詳細・判断材料・抽象化した判定材料はノート参照）:
  - **事例1**（2026-08-22 フェーズ5 詳細化）: 前置1（増設2回連続 → 設計縮小推奨）が発火したが、増設はすべて写経実証済み欠陥への封鎖で、縮小は「実測済みの穴の再開放と等価」だった → フル巡を採択
  - **事例2**（同上）: 2段型 + 骨格安定未達で4巡目フル巡を推奨したが、収量曲線（Critical 2→0→骨格0）と残リスクの純化から機械検証で締めるのが妥当だった → 機械検証を採択（齟齬ゼロ・実質収束）
  - **事例3**（2026-08-23〜24 第7段階第1部 仕様レビュー）: 前置1 が再び「実証済みの穴の封鎖」局面で縮小を推奨 → フル巡を採択。新知見 = 「増設した機構そのものに欠陥が入る」型が2巡連続し、**増設中は縮小でも機械検証でもなくフル巡続行が正解**だった
  - **事例4**（同上）: 前置1（縮小）と2段型（フル巡）の両既定が外れ、**差分確認巡**が妥当 → 事後結果で裏づけ（新規設計欠陥ゼロ・所見は全て委譲側の反映ミス型 = 対応表方式が構造的に強い型）
  - **事例5**（同上）: 「迷えばフル巡」既定に対し**このまま確定**が妥当（残修正は全てレビュアー指定文の逐語適用 = 再巡は自己再検証）。終了状態語彙が実態（5巡で単調収束）を表せない問題も観測
  - **事例6**（2026-08-24 第77回 実装計画レビュー）: 「骨格への新規指摘1件でフル巡へ」の昇格規則が3回発火し、3回とも**差分確認巡の続行**が妥当だった。新知見 = **「検出器の欠落」は「迷えば骨格側」既定でほぼ必ず骨格に分類される**（骨格指摘5件全てが検証設計の欠陥・決定構造の欠陥は0件）ため、骨格指摘の有無は昇格条件として粗い。機能したのは実質収束の第1経路
  - **事例7**（同上）: **差分確認巡の構造的死角の初実測** — レビュー由来の例外追加（2→4種）が上流仕様の限定列挙「2種に限る」と衝突し、差分巡3回+機械検証が検出できず確定直前に委譲元が自力検出（→ ADR-0162）。「差分巡が常に正しい」への反証
  - **事例8**（同上）: 乖離解消の推奨自体に「本反復が確立した教訓（未レビューの是正14件中10件が機能しない）に反する未レビュー設計変更」が混入し、利用者の「懸念点は?」の1問で取り下げた。3-2 併記は推奨内容への教訓の自己適用を担わない
- **横断観測（事例3〜5）**: 実際に機能した収束指標は「指摘の対象年代」と「残指摘の型」の2つで、いずれも現行規範の判定材料に無い。縮小の語彙は「増設回数」でなく「規範の根拠が実測で反証されたとき」（第4巡の1%閾値廃止が実例）に個別発動するのが実態に合う
- **横断観測（事例6〜8）**: 「是正したつもりが機能していない」型が指摘反映後の新規指摘14件中**10件**で、捕捉できたのは対応表方式+写経実行のみ（定量的裏づけ）。差分巡主体の反復は spec 確定点のフル巡主体より1巡あたり安く実質収束へ到達したが、事例7 の死角があるため「常に優位」とは読まない
- 対策の設計は未着手（事例の蓄積段階）

## 原因（仮説）

推奨判定の入力が**改訂の形式的特徴**（機構の増設回数・新規規範文の有無・巡数）に限られており、次を判定材料にしていない:

1. **増設の中身の区別** — 本番の実行時挙動に条件・分岐を足す増設か、検証・記録・テストの固めか
2. **収量曲線** — 直近巡の Critical 数・設計骨格への新規指摘数の推移（規範は「骨格安定」の目安に使うが、迷ったら骨格側へ倒す既定と2巡連続条件の組み合わせで、実際に収束していても締めモードに入りにくい）
3. **下流の安全網** — 残リスク種別を実装時レビュー・TDD・機械検証が受け止められるか

## 対策候補（仮説。採否・設計は次サイクル以降。実装先はガイドライン配信元リポジトリ側）

1. 前置1 の計数対象を「本番の実行時挙動に条件・分岐を足す増設」に限定する（検証・記録・テストの追加を除外）
2. 推奨判定の材料に収量曲線（直近巡の Critical / 骨格新規指摘の推移）を明示的に採り入れる
3. 推奨が既定由来で内容判定と向きが割れる場合、**内容判定側の推奨と理由の並記**を 3-2 へ追加する（worklog `LoopForAlpha-2026-08-22-05` と同源）
4. 骨格安定の判定（迷ったら骨格側 × 2巡連続）の粒度を見直す — 「検証機構への指摘」と「決定構造への指摘」を別レイヤに分ける等（事例6 が定量で補強: 骨格指摘5件全てが検証設計の欠陥だった）
5. 差分確認巡の対象規定に「改訂が上流の限定列挙（『限る』『のみ』型）・件数固定・完了基準に触れる場合は当該上流文書を突合対象へ足す」を追加する（事例7。発火点はレビュー指摘で例外・逸脱を**採用した瞬間**）
6. 確定直前の提案・推奨に「本反復で確立した教訓・レビュアーの推奨と矛盾しないか」の自問を1行課す（事例8。3-2 は選択肢の比較材料の併記であり、推奨内容そのものへの教訓の自己適用は担っていない）
