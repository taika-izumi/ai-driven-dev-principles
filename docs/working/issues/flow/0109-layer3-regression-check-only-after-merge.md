# Issue-0109: Layer 3 の退行確認が、マージ・push 後にしか実行できない

- **Status**: open
- **Opened**: 2026-08-25
- **起票元**: Codex 対応サイクルの検証 6 の実施時に判明（実装計画 Task 11 Step 8 の引き継ぎ事項）
- **関連**: ADR-0112（Codex 向け配信の追加）、ADR-0016（プラグイン配信のみでスキルを届ける設計）、`docs/current/specs/2026-08-25-codex-support-design.md` の検証 6

## 課題内容

配布物（`dist/`）の変更が既存ツールのプラグイン認識を壊していないかを確かめる「Layer 3 の退行確認」は、**マージして push した後にしか実行できない**。

本開発機のマーケットプレイス登録は GitHub 経由である（2026-08-25 実測）:

```
"ai-driven-dev-principles": { "source": { "source": "github", "repo": "taika-izumi/ai-driven-dev-principles" } }
```

`/plugin marketplace update`（Claude Code）と `copilot plugin update`（Copilot CLI）はいずれも `origin/master` を fetch してスナップショットを更新する。feature ブランチのコミットは見に行かないため、push 前に実行しても旧版が降りてくるだけで、退行の有無を判定できない。

したがって退行確認は次の順序になる:

1. feature ブランチで実装・生成物の更新
2. master へマージ
3. push
4. **ここで初めて退行確認ができる**

**退行が見つかった時点で、それは既に master に載っている。** 「マージ前に既存の動作を壊していないか確認する」という退行確認の目的と、到達手段が矛盾している。

Layer 2（`AGENTS.md` / `CLAUDE.md`）は作業ツリーから直接読まれるためこの問題を持たない。プラグイン配信を経由する Layer 3 に固有の構造である。

## 対策の方向（採否は未定）

- **ローカルパス登録でのプレフライト**: マージ前に `/plugin marketplace add <リポジトリの絶対パス>` で一時登録して確認し、確認後に GitHub 登録へ戻す。README の方式 B が既に手順として存在する。登録形態の切り替え・復帰という手順が増え、切り替え忘れると以後の運用が変わる
- **検証用ブランチの push**: feature ブランチを push し、マーケットプレイスの参照先ブランチを一時的に切り替える。ツール側が参照ブランチの指定に対応しているかは未確認
- **退行確認の位置づけの変更**: 「マージ前のゲート」ではなく「マージ後の早期検出」と定義し直し、退行時は master 上で追加修正する運用を明示的に受容する。現状は暗黙にこの運用になっている
- 本サイクルでは 3 つ目（現状の追認）で進めた。spec の検証 6 へ実行タイミングの前提を追記済み
