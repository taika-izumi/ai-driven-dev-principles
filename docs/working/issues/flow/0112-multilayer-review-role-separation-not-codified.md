# Issue-0043: 多層レビュー（5層）の役割分担指針が明文化されておらず、レビュー設計の再現性がコンテキスト依存

- **Status**: open
- **Opened**: 2026-07-24
- **分類**: 開発フロー/ガイドライン関連
- **起票元**: retrospectives/flow/2026-07-24-stage3-open-strategy-search.md 課題#2

## 要約

第3段階のレビューは 5 層（仕様の独立レビュー 3 体 → 実装計画の独立レビュー 3 体 → タスクごとの 2 段階レビュー → 区切りの最終ブランチレビュー → マージ前のブランチ全体レビュー 2 体）で、いずれも有効打があった。しかし「どの層で何を検出するのが本命か」の指針が明文化されていない:

- 合成穴（複数機構の相互作用で成立する経路）はブランチ全体レビューでしか出ない
- fail-closed 契約の空振り（テストが実装を独立に固定できていない）は変異試験でしか出ない
- 「実測せよ」指示の有無が指摘の有効性を大きく左右する

これらの知見は handoff の「レビュー運用で効いた実践」節に時系列で蓄積されているだけで、層別の役割定義として整理されていない。handoff が消えると失われ、レビュー設計（各層のプロンプト・重さの調整）の再現性がメインエージェントのコンテキストに依存する。

対策の検討方向（次サイクルの責務。ここでは記録のみ）: レビュー層の役割分担・必須指示（実測・変異試験・削除テストの後継検証など）を恒久ドキュメントまたはスキル（requesting-code-review 拡張等）へ抽出する、など。
