## 課題内容

実装工程には 2 つの型がある: **タスク別独立レビュー往復型**（実装 → 仕様適合レビュー → コード品質レビューを毎タスクで回す）と、**確定前レビューへの前倒し型**（実コード全文を計画に載せ、確定前レビューで写経実行つきの重いレビューを行い、実装中の独立レビューは置かない）。LoopForAlpha の複数フェーズ実測で所要に大差が出たが、使い分けの判定基準が規範化されていない。

委譲元は判定 3 条件の仮説（前倒し型: 設計確定済み・実コード全文を計画に載せられる規模・実行による安全網が無い / 往復型: 既存コードとの衝突が主リスク・計画にコードを固定しきれない・残余リスク許容度が低い）と、複数フェーズ分の観測（型の選定理由・欠陥の件数と発見者・計画コードからの逸脱の有無）を蓄積している。**前倒し型の安全弁「実装が計画コードから機械的な適応を超えて逸脱したら、そのタスクはタスク別独立レビューへ格下げする」は、Issue-0110（確定済み計画からの逸脱判断の既定）の対策設計の直接材料である。**

一貫した実測（委譲時点）: (a) 2 観点独立レビューは並行委譲でも観点間の独立検出を保つ（12 タスク連続） (b) 計画の逐語コード・期待値には系統的に欠陥が入る（通算 24 件） (c) 使い分け仮説を覆す観測は出ていない。
