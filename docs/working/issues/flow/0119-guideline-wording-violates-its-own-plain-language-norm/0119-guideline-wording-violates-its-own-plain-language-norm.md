## 課題内容

`AGENTS.md`（Layer 2）は次を定めている:

> 対話・成果物ドキュメント（ハンドオフ/仕様書/ADR等）で用語を使うときは、文章だけを読んで意味が推測できる説明的な表現を用いること。「Aモード」「Primary/Secondary」のような、その場限りで定義のない略号・記号的呼称は使わないこと

ところが**配信スキル自身の文面**がこの条件を満たさない語を多用している。AI はスキル本文を読んで作業するため、その語彙がそのまま配布先の対話・成果物へ伝播する。**規約を持つ側が規約を守っていない**という構図である。

配布先が示した判定条件（2 つを同時に満たす語）は次のとおり:

1. 一般的に認知されていない、または一般的に認知されているが一般的な意味で使っていない
2. 同程度の文字数の一般的な語に置き換え可能

**実測**（2026-09-02。`ai-driven-dev-principles` 0.1.16 の `skills/` 配下を全数走査した出現回数）:

| 語 | 回数 | 種別 | 置き換え候補 |
|---|---|---|---|
| 正本 | 75 | 法律文書用語（「〜が正本である」を全スキルで多用） | 原典 / 基準 |
| 消化 | 33 | 経理用語。`session-handoff` の**正式なフィールド名**「Post ラッパー消化記録」 | 確認記録 |
| 突合 | 20 | 経理・金融のジャーガン | 照合（同じ 2 文字でより一般的） |
| 素の | 9 | 同一セッション内で「生の例外」と「率直な判断」の 2 義に使われた | 生の |
| 写経 | 8 | 仏教用語の転用（計画のコードをそのまま書き写すこと） | 書き写し |
| 配線 | 7 | 英語 wiring の直訳 | 接続 |
| 前置 | 6 | 一般には動詞化しない | 前に置く |
| 射程 / 射程外 | 5 / 5 | 比喩 | 範囲 / 範囲外 |
| 母数 | 4 | **統計用語の誤用**（本来は母集団のパラメータ。`subagent-dispatch` では「対象の件数」の意味） | 件数 |
| 消し込み | 3 | 経理用語。`start-work` の Post ラッパー「1つずつ明示的に消し込む」 | 一つずつ確認する |
| 裁定 | 2 | 硬い | 判断 |

「消化」と「消し込み」が同じ概念に 2 語当てられている点も読み手の負荷を上げている。

## 現在地の要約（委譲時点 = 2026-09-03。書き換える節。追記しない）

配布先で 8 セッション分の観測（第111〜116回・第118回は前半と後半で 2 本。第117回は未計測）を経て固まったのは次の 7 点である。各回の実測は本フォルダの資料が正本。

1. **問題の形は「語」だけではない**。読み手の負荷が最も高いのは記号的ラベル（`A 群` / `B 群` / `採用基準 (i)` / `観点1`〜`観点5` / `spec 確定点 (a)`）であり、これは `AGENTS.md` が名指しで禁じている当のものである
2. **記号的ラベルの供給源は増える**。第116回まで「2 系統から増えていない」と観測していたが、第118回に 3 系統目（`観点1`〜`観点5`。出所 = `decision-log` の `references/cycle-consistency-check.md`。セッション通算 22 件）と 4 系統目（`spec 確定点 (a)`。出所 = `pre-finalization-review` の提示規則）が出て、この観測は覆った
3. **語彙の供給源はサイクルの局面ごとに入れ替わる**。実装局面 = 写経・標本・母数・射程・A 群 / B 群（`subagent-dispatch`・逸脱判断の既定）／締め局面 = 突合・消し込み・観点1〜5（`decision-log` の整合検査・Post ラッパー）／サイクル末尾 = 移設・昇格・消化・確定点・現役性・剪定（`session-handoff` の cycle-reset・`retrospective`）。**局面固有の語は合計出現回数では軽く見えるが、その局面の報告では密度が高い** — 改名の優先度を合計回数だけで決めてはいけない
4. **`B群判定:` の書式が利用者の目に触れるのは、委譲を伴うセッションだけである**。第112〜115回は 4 連続で触れたが、委譲 0 件の第116回・第118回はいずれも 0 件（負の対照 2 回）
5. **改名の移行コストは配信物のフィールド名だけでは終わらない**。配布先が自分の成果物へ配信物由来語を**構造名**として定着させた例が 2 件出た（計画の完了条件表の列名「消し込み」／参照知識の索引の規則文「配置の軸は種別である」）。構造名は参照が張られるため文中の語より移行コストが高い
6. **利用者が語の意味を尋ねた例が 2 件ある**（`消し込み` = 配信物由来 / `lessons` = 既存ファイル名から持ち上げた名前）。2 件とも「大元の語を写した」経路であり、**出所を直せば頻度が下がる**という本課題の前提を支持する
7. **本課題の対象は配信物側の語に限る**。配布先の文書に定着した語の同型は LoopForAlpha#Issue-0131 が持ち、所有者と close 条件が異なるため分けて追跡する

**未計測のまま残っていること**: 置き換え候補語の実際の読みやすさ（利用者による評価）・改名の影響範囲（配布先の移行コスト）。

## 未解決の論点

- **規約の射程が曖昧**: `AGENTS.md` の当該条項は「`Aモード`」「`Primary/Secondary`」という**略号・記号的呼称**を例示しており、「一般語の非一般的用法」（母数・素の）や「業界ジャーガン」（消し込み・突合）を射程に含むかが文面から読めない。**まず規約側の射程を明確にする必要がある**（他の論点はこれに従属する）
- **英字フィールド名は規約の射程に入るか**: `cyclecheck=` / `ADR=` / `worklog=` / `review=` は `session-handoff` が定める消化記録の書式で、日本語の文中で記号として浮く
- **置き換えの粒度**: 全面改稿か、判定条件を満たす上位数語（正本・消化・消し込み・母数・突合）に絞るか
- **フィールド名の互換性**: 「Post ラッパー消化記録」は handoff の節見出しとして配布先の既存ファイルに実在するため、改名は配布先の移行を伴う。上の要点 5（構造名への定着）も同じ問題
- **規範文書としての簡潔さと平易さのトレードオフ**（「正本」1 語を「唯一の出所」へ置き換えると文が伸びる）

## トークン消費についての見立て（配布先の AI による未計測の判断。対策設計時に検証項目として扱う）

配布先の利用者が「一般語へ置き換えるとトークン消費が増えないか」を懸念したことへの回答として記録されたもの。**実測はされていない**。

- **語の置き換えそのものによる増分は小さい**（突合→照合は同じ 2 文字、正本→元の文書で +3 文字程度）。判定条件 (2) を守る限り出力全体で数％以内の見込み
- **トークンが目に見えて増えるのは指示の仕方が悪いとき**。「専門用語を避けよ」型の一般的な禁止指示は括弧説明や迂回表現を誘発し、1 か所あたり 10〜30 トークン増える。語の長さの差より 1 桁大きく毎回起きるため、**この型の指示は対策案から外す**
- **推奨経路はスキル本文そのものの書き換え**。AI は読み込んだ文書の語彙を写すため、追加指示なしで語彙が変わり、出力増分は語の長さの差だけになる
- **根拠となる観測**: 平易表現規約が既に存在するのに「突合」「正本」が出続けた。**指示より読み込んだ文書の語彙のほうが強い**
- **既存規約の文面は据え置きでよい見込み**。「専門用語を使うな」型ではなく「意味が推測できる名前を選べ」という命名基準であり、直すとしても射程の明確化の範囲に収まる
- 短い一般語がない語（母集合・恒等写像など）は置き換えず、**初出に 1 行説明**を添える

## 対象外とするもの（配布先の利用者が明示。2026-09-02）

**LLM の言語的な癖として出た語は是正の対象にしない。** 対象は、規範・スキル・文脈情報に出所を持ち、**大元の文章を直せば使用頻度が下がる**語に限る。配布先の走査では、AI が使ったジャーガンのほぼ全てが配信スキルかプロジェクト文書に出所を持つことが実測で確認された（出所ゼロの語は 2 件のみ）。
