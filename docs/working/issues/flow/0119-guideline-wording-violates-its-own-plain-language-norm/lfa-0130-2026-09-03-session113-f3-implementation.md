### (1) 🔴 配信ガイドライン由来の語が、計画への追加行の主要な中身になった

第112回は「コード内コメントが主経路」を測ったが、**配信物由来の語に限ると経路が違う**ことが本回で出た。

| 語（すべて配信ガイドライン由来） | 本回の計 | コード・テスト | 計画 | handoff |
|---|---|---|---|---|
| **逸脱記録** | 25 | **0** | 22 | 2 |
| **委譲元** | 18 | 4 | 13 | 0 |
| **機械的な適応** | 11 | 0 | 11 | 0 |
| 陳腐化 | 7 | 2 | 5 | 0 |

| 検出資産 / 採用基準 / 射程外の既存欠陥 / 設計の変更 | 各 1〜2 | 0 | 各 1〜2 | 0 |

**計画への追加 49 行のうち 17 行が行頭 `逸脱記録:` である**（`plan-deviation-defaults.md` が定める書式そのもの）。プロジェクト由来の語（`突合` 51・`標本` 47）はコードへ凍結されるのに対し、**配信物由来の語は計画ファイルへ凍結される**。凍結先が違うので、対策も別立てになる:

- プロジェクト由来 → コード内コメント（レビュアーと次の実装者が読む）
- **配信物由来 → 計画の逸脱記録・完了記録**（次サイクルの作業者と振り返りが読む）

⚠️ とくに `逸脱記録` は**書式で固定された行頭語**であり、`B群判定:` と同じく「本文の語を言い換えても消えない」型である。ただし `B群判定:` が対話にしか出ないのに対し、こちらは成果物へ 17 行残る。

### (2) 記号的ラベルの再演が 3 例目 — `採用基準 (i)`

`例外 c`（第111回）・`フェーズ2型`（第112回）に続く 3 例目として、`採用基準 (i)` が計画の逸脱記録 2 行へ**定義を添えずに**入った（丸括弧のローマ数字は `plan-deviation-defaults.md` の見出しを指す）。3 セッション連続で同じ型が出ており、**記録するだけでは止まっていない**ことが実測で示された。

### (3) 利用者向けの報告に出た語 — 表形式では説明が付かない

本セッションの利用者向けメッセージに、次の配信物由来の語が**説明なしで**出た: `Post ラッパー` / `消し込む` / `型分類` / `設計の変更` / `機械的な適応` / `逸脱記録` / `委譲元` / `確定点`。

一方、意思決定を求めた 2 回のメッセージでは、プロジェクト固有語（`校正物`）に初出の説明が付いている。**差は語の性質ではなく、その語が「説明の文の中にあるか」「進捗の要約表の中にあるか」である**（表・箇条書きは説明を添える場所が無い）。

→ 対策の候補として「語ごとの言い換え表」だけでなく、**「要約表・箇条書きでは配信物由来の呼称を使わず、平易な言い換えを使う」という書式側の規律**がありうる（未検証）。Issue-0131 の同名の観察と同じ結論に別経路で到達している。
