# Issue-0120: フォルダ昇格済みの課題ファイルに縮める手段が無く、4 役割の規律を守っても「現在地の要約」が単調増加する

- **Opened**: 2026-09-03
- **起票元**: LoopForAlpha#Issue-0130 の申し送り（Issue-0119）に随伴して検出。委譲元の検討経緯ログ末尾に、語彙の主題とは別の未解決点として記録されていたもの
- **関連**: Issue-0088（課題ファイルの肥大。closed。ADR-0094〜0098 で対処）/ ADR-0096（昇格条件・4 役割体系）/ ADR-0074/0075/0077（handoff 側の二段階剪定。本課題が指す非対称の相手方）/ Issue-0090（handoff 以外の成長型成果物）/ Issue-0119

## 課題内容

Issue-0088 の対策（ADR-0094〜0098）で、課題ファイルには次の 4 つの機構が入った:

1. フォルダ昇格（`NNNN-<slug>/`）と 4 役割体系（課題ファイル / 検討経緯ログ / 検討ノート / 時点資料）
2. 昇格後の課題ファイルは「検討状況」を**書き換え型**の「現在地の要約」に改める
3. 「現在地の要約」の 1 エントリは 200 字以内を目安とし、超過分は検討ノート・時点資料・検討経緯ログへ移す（課題管理定義 §7）
4. 追記のたびにサイズを実測し、目安値 10KB を超えていたらフォルダ昇格を提案する（同 §4）

**この 4 つを守っても、課題ファイルは縮まない。** 欠けているのは次の 2 点である:

- **機構 4 の打ち手が「フォルダ昇格の提案」しかない**。すでに昇格済みの課題では、サイズ超過を検出しても提案できる操作が無く、検出が空振りする
- **機構 3 はエントリ 1 件の長さを制御するが、エントリの件数に上限が無い**。観測が増えれば要約の点数が増えるため、時点資料へ切り出す規律を正しく守っても本体は単調増加する。切り出しは詳細を移すだけで、その資料を指す要約行は課題ファイルに残り、むしろ 1 行増える

handoff には二段階剪定と基準付き圧縮（ADR-0074/0075/0077）があるのに、**課題ファイルには剪定に相当する規定が無い**という非対称になっている。

**配布先での実測**（LoopForAlpha。2026-09-03 時点）:

- Issue-0130: 第116回に構成整理を行い、それまでの追加観測を時点資料 5 本へ切り出して **10.9KB** へ縮めた。以後も切り出しの規律を守り続けたが、2 セッション後には **13.2KB**（目安 10KB 超過）。「現在地の要約」の点数が 5 点 → 7 点へ増えたことが主因
- Issue-0131（同型・同時期）: **18.3KB**

つまり縮小操作を 1 回行っても、次の 2 セッションで元より大きくなる。

## 論点（対処を設計する前に判断すること）

- **縮小の契機をどこに置くか**: サイズ実測（§4）の打ち手を昇格済みの課題向けに拡張するか、要約のエントリ件数に上限を設けるか
- **何を落とすか**: 「確定した点」を要約から落として時点資料・検討経緯ログへ送る形が候補だが、確定した点こそ後から探しに来る対象でもある。handoff の剪定は「受け皿は git 履歴のみ」という割り切りを持つが、課題ファイルは open の間ずっと読まれるため同じ割り切りは使えない可能性がある
- **本当に抑制すべきか**: 長期観測型の課題では要約が育つこと自体が正常で、10KB という目安値のほうが観測型の課題に合っていない可能性もある。その場合は課題の型による目安値の層別が対策になる
