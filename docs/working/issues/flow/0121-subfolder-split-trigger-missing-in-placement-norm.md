# Issue-0121: 配置の正本に「種別サブフォルダをいつ作るか」の判定則が無く、同じ議論が分類フォルダごとに再演する

- **Status**: open
- **Opened**: 2026-09-03
- **起票元**: LoopForAlpha#Issue-0140 の申し送り（以後の正本は本ファイル）
- **関連**: `docs/overview/folder-structure.md` §5 運用規約（判定則が欠けている当の箇所）/ `skills/organize-inbox/SKILL.md`（判定則の欠落が効く経路）/ Issue-0089（指定席の命名・索引の規約が未定義。同じ「配置先の定義しか無い」型）/ Issue-0088（成長型成果物の抑制。closed）/ Issue-0120（フォルダ昇格済みの課題ファイルが縮まない）/ LoopForAlpha#ADR-0186（配布先が本課題の一般形をその場で決めた事例）

## 課題内容

`docs/overview/folder-structure.md` は配置判断の唯一の参照元であり、種別サブフォルダについて §5 の運用規約で 2 点を定めている（実体で確認。同ファイル 52〜53 行目）:

> - **種別サブフォルダはオンデマンド作成** — 使わない空フォルダを先行作成しない
> - **列挙されていない新種別** — 分類基準で判断し、該当する分類フォルダ直下または新しい種別サブフォルダに置く

しかし **「いつサブフォルダへ切り出すか」の判定則が無い**。「オンデマンド」は先行作成の禁止であって切り出しの契機を与えておらず、「直下または新しい種別サブフォルダ」は選択の余地を示すだけである。

そのため、分類フォルダのファイル数が増えて見通しが悪くなるたびに、**その場で軸と閾値を議論し直すことになる**。これは特定の分類フォルダに固有の問題ではなく、どの分類フォルダでも・どの配布先でも同じ形で起きる。

**経路の穴**: `organize-inbox` は分類基準を `folder-structure.md` に一元化しており（`skills/organize-inbox/SKILL.md` 17 行目「分類基準は `docs/overview/folder-structure.md` を唯一の参照元とする。本スキル内に基準を複製しない」）、手順は 40 行目で「移動・分割先に種別サブフォルダが必要でまだ無ければ作成する」と書く。**「必要」の判定則がどこにも無いため、このスキルはサブフォルダ化の契機を検出できない。**

## 配布先で実際に起きたこと（2026-09-03）

LoopForAlpha で `docs/reference/` のファイル数が増え、利用者から「reference フォルダが様々なファイルでいっぱいになって区別しづらくなる未来が見えます」との指摘が出た。同プロジェクトはその場で ADR-0186 として「配置の軸は**種別**」「同種別が 2 本以上になったらサブフォルダへまとめる」を決めたが、**判定則を `folder-structure.md` へ足すことはしていない**（配信物へ配布先固有ルールを増やさない方針。同 ADR-0181）。したがって一般形は未解決のまま本リポジトリへ回ってきている。

**あわせて申し送られた観測（軸の選び方の材料）**: 配置の軸の候補として「参照元（誰が参照するか）」が自然に出てくるが、**これは判別力を持たない**。配布先の実測では `docs/reference/` の 5 本への参照元数は 33 / 26 / 11 / 8 / 3 ファイルで、特定の参照元（handoff）はどのファイルにとっても多数の参照元のひとつだった。さらに参照元は時間で変わるため、参照元を軸にするとファイル移動が再発してパス参照が壊れ続ける。**軸は種別に固定すべきである**という根拠として使える。

## 対策の方向（採否は未定）

- `folder-structure.md` §5 の運用規約へ、切り出しの軸（種別）と契機（同種別が N 本以上、など）を 1〜2 行で足す。配布先の ADR-0186 が採った「軸 = 種別 / 契機 = 同種別 2 本以上」が一般形の候補
- 判定則を置いたら `organize-inbox` の手順 40 行目が自動的に判定できるようになるかを確認する（配線の追加が要るかどうか）
- 閾値を数値で固定するか、「見通しが悪いと感じたら」型の弱い契機にするかは論点。Issue-0089（指定席の命名・索引）と同じ「配置先の定義しか無い」型なので、両者をまとめて扱う余地がある
