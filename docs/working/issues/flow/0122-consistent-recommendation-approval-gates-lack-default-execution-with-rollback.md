# Issue-0122: 推奨が一致する承認ゲート（レビュー指摘の採否・反復提示・ADR 承認）に「事前宣言による既定実行 + 差し戻し窓」が無く、番号回答待ちが配布先の壁時計の最大費用になる

- **Status**: closed
- **Opened**: 2026-09-04
- **起票元**: LoopForAlpha#Issue-0168 の申し送り（以後の正本は本ファイル）。配布先の「開発の進め方の見直し」レビュー（`LoopForAlpha:docs/records/reviews/2026-09-04-dev-process-review/report.md` 所見 U1・U2・提案 A'）に由来する構造観察型の課題
- **関連**: ADR-0072（確定前レビューはユーザー指示時のみ発動）/ ADR-0080（確定点での提示は毎回行う）/ ADR-0005（セッション開始時の継続確認）/ ADR-0024（選択肢 + 推奨の提示）/ ADR-0107 決定 2（反復の停止は指摘の分類）/ Issue-0107（反復推奨規範の乖離。逆選択の実例が蓄積）/ Issue-0118（情報到達の体系設計）/ `skills/decision-log`（ADR 承認）/ `skills/pre-finalization-review/references/review-procedure.md` 手順 5（採否の裁定）/ `docs/overview/principles.md` 原則 4（適用強度はリスク・可逆性で調整）

## 課題内容

配布先 LoopForAlpha の会話履歴 121 セッション（2026-07-31〜09-04）の実測で、壁時計の 50.7% が人間待ちであり、人間ターン間隔 60 分以上の区間 115 件のうち 71 件（分数で 65%）が 15 字以下の回答（番号回答型）で閉じていた。深読み 6 本で最長の放置を生んだのは、AI が推奨つきの選択肢を提示して番号回答を待つゲートのうち **レビュー指摘の採否・反復提示・ADR 承認** の 3 型で、セッション継続確認・次手確認の直後の長時間放置はほぼ無かった。3 型は AI の推奨が「全件採用」「承認」「継続」で一致していても回答を待って停止する。原則 4 の「低リスク可逆 → 高い自律性」は、この 3 型には実装されていない。

一方、推奨と異なる選択（深読みで ≈ 5%）は価値を生んでおり（うち 2 回は規範側の不備として Issue-0107 に事例あり）、ゲートを廃止すると失う。

## 対策の方向（採否は未定）

1. セッション単位の事前宣言「AI の推奨が全件採用 / 承認 / 継続で一致する場合は既定実行して通知してよい」を `start-work` Phase 0〜1 で受け付ける機構。宣言下では 3 型のゲートは「提示 → 即実行 → 通知」（提示は残す = ADR-0080 と両立）
2. 推奨が分かれる場合（採否混在・縮小推奨・見送り推奨）は現行どおり停止
3. ハンドオフの消化記録に「自動採択」行を残し（原則 1）、次ターンで差し戻せる窓を置く
4. 撤退条件 = 差し戻し率（配布先の先行運用で実測する。深読みの逆選択 ≈ 5% を大きく上回れば無効化）
5. ADR-0072「発動はユーザー指示のみ」との整合は「宣言はユーザー指示の一形態」と読めるかの裁定が要る（規範改定型）

配布先は配信元の改定を待たず、セッション冒頭の宣言（ハンドオフ留意点）で 1 サイクル計測し、差し戻し率を本課題へ報告する予定。

- **起票元**: 開発の進め方の見直し（レビュー由来。詳細は記録が正）: `docs/records/reviews/2026-09-04-dev-process-review/report.md` 判定 2 (i)・所見 U1・U2・提案 A' / `cleanroom/03-reconciliation-report.md` Q1・課題 4 #8 / `cleanroom/05-refutation-report.md` T1〜T7・R1 / 深読み `measurement/deep-read/report-seq-025.md` L17-29・L134・`report-seq-050.md` L22・`report-seq-024.md` L24・`report-seq-072.md` L34

## 課題内容

実測（会話履歴 121 セッション。`measurement/01`・`human_wait.csv`・突合段 Q1）: 壁時計 29,981 分のうち人間待ちが 15,189 分（50.7%）。人間ターン間隔 60 分以上の区間 115 件のうち 71 件（分数で 65% = 12,941 分）は 15 字以下の回答で閉じている。深読み 6 本で最長の放置を生んだのは、**AI が推奨つきの選択肢を提示して番号回答を待つゲートのうち「レビュー指摘の採否」「反復提示」「ADR 承認」の 3 型**である（seq 25: レビュー指摘採否 407.5 分 + 323.7 分・ADR 承認 331.6 分 = 1,063 分で同セッションの 54% / seq 50: 反復提示 366 分 / seq 24: 確定前レビュー提示 255.5 分。深読みの番号回答直後の放置 1,927 分の 87%）。一方、セッション継続確認・次手確認の直後の長時間放置は 0〜1 件（≤ 100 分）で、費用はそこには無い（反証段 T3・R1）。

構造: 人間承認ゲート 36 行のうち不可逆性を根拠にするのは数行で、残りは確定点の承認と選択（棚卸し §4-1）。原則 4 は「低リスク可逆 → 高い自律性」を建前にするが、上の 3 型は AI の推奨が「全件採用」「承認」「継続」で一致していても回答を待って停止する。利用者は既にセッション単位で「次の質問も推奨案で」（seq 72 #5）と宣言する運用を取っており、深読み報告 `report-seq-025.md` L134 も「全件採用推奨なら進めてよい事前宣言」をガイドライン改定候補として挙げた。

なぜ問題か: 人間が 9 字（文字数の中央値）を返すために AI が平均 16 応答ぶん停止し、壁時計の費用は締切のある局面（10 月のイベント）で実費になる。逆に、推奨と異なる選択（深読みで ≈ 5%。うち 2 回は規範側の不備 = Issue-0109 として起票済み）は価値を生んでおり、ゲートを廃止すると失う。

対策の方向（採否・設計は配信元。本課題は申し送り単位）: (1) **セッション単位の事前宣言**「AI の推奨が全件採用 / 承認 / 継続で一致する場合は既定実行して通知してよい」を、start-work の Phase 0〜1 で受け付ける機構にする。宣言下では上の 3 型のゲートは「提示 → 即実行 → 通知」となり、提示自体は残す（ADR-0080 と両立）。(2) 推奨が分かれる場合（採否が混在・縮小推奨・見送り推奨）は現行どおり停止する（seq 24 #32 の「見送り推奨 → フル実施で重大 2 件」、seq 50 #27/#31 の反復提示の逆選択が正解だった実例を保存するため）。(3) ハンドオフの消化記録に「自動採択」行を残し（原則 1）、利用者が次ターンで差し戻せる窓を置く。(4) 撤退条件 = 差し戻し率（深読みの逆選択 ≈ 5% を大きく上回れば宣言を無効化）。(5) ADR-0072（発動はユーザー指示のみ）との整合は「宣言はユーザー指示の一形態」と読めるかの裁定が要る。

先行する利用者運用: 本プロジェクトでは配信元の改定を待たず、セッション冒頭の宣言（ハンドオフ留意点に記載）で 1 サイクル計測し、差し戻し率を実測してから機構化の採否を判断する。
