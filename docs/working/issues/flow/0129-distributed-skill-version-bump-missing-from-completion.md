# Issue-0129: 配布スキル変更時のバージョン更新が完了処理から抜ける

- **Status**: open
- **Opened**: 2026-09-07
- **起票元**: Issue-0126の終了後、ユーザーが配布スキルのバージョンアップ未実施を確認し、実施と認識差のIssue記録を指示した。
- **関連**: Issue-0128、CONTRIBUTING.mdの配布対象ソースの記法規約、scripts/build-dist.ps1

## 課題内容

配布スキルを変更した作業で、AIがソース更新・生成・検証・マージ・pushを完了させても、配布プラグインのバージョン更新を別作業として残した。ユーザーは、今回の配布スキル改定の完了処理としてバージョンアップも期待しており、追加指示が必要になった。

Issue-0126ではb0cb6f4で3スキルとdistを更新し、ffd5666でmasterへマージ、4a061aeまでpushしたが、定義は0.1.20のままだった。ユーザーの確認と「実施して」の指示を受けて、b1c4fbeで0.1.21へ更新・再生成・検証・pushした。

生成器はソースと生成物の同期、plugin.jsonとmarketplace.jsonのversion一致を検査するが、前の配布内容から変更があったときのversion更新を判定しない。このため、versionを据え置いても両方の-Checkは合格し、配布更新まで完了したという判断材料にはならない。現在確認したCONTRIBUTING.mdの生成手順にも、スキル変更時にversionを上げる実施条件・担当・タイミングが明記されていない。

## 影響

- 利用者が終了報告後に配布バージョンを確認し、追加の作業指示を出す必要がある。
- 更新されたスキル本文と同じversionの配布定義が存在し、利用側で今回の改定が届いたか判断しにくい。実際にキャッシュが更新されなかったことを今回測定したわけではない。
- 生成物の同期確認と、配布単位のバージョン更新を混同して完了を報告し得る。

## 検討状況

- 2026-09-07: [手順照合記録](../../../records/minutes/2026-09-07-session-workflow-gap-audit.md)のC10として、配布更新の欠落と会話上の追加指示を照合。pushは版更新とは別に毎回確認する要件を受領。

- 2026-09-07: ユーザー指示により起票。今回のバージョン不足は0.1.21への更新で解消済み。完了フローへの恒久的な接続は未実装。

## 対策検討時の確認事項

- 配布対象の変更がある場合に、バージョン更新の要否と完了状態を確認する経路を定める。記録文書だけの変更で毎回バージョンを上げる規則にはしない。
- 正本2定義と生成物の更新を同じ配布作業として扱い、生成チェック合格だけでバージョン更新済みとしない。
- マージ・push・配布バージョン更新の順序と、利用側キャッシュ更新との境界を明確にする。Gitタグ・GitHub Release・利用環境への再導入は、今回承認された必須作業と推定しない。
- **配布更新後のpushも毎回ユーザーに確認する**。以前のpush承認、バージョンアップの指示、完了処理の一般的な指示を、そのまま次のpushの承認として扱わない。

## 結論

未決。Issue-0128の完了工程への接続と関連するが、マージ済みでも発生する配布固有の問題として分離した。対策設計・スキル変更は未着手。
