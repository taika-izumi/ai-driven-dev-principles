### コマンド許可運用

対話モードのコマンド許可は、git 管理の `.claude/settings.json`（allowlist）と本規範のセットで運用する（ADR-0009。仕様: `docs/current/specs/2026-07-11-interactive-permission-allowlist.md`）。

- 許可ルールは**前方一致**で判定される。環境変数代入の前置（`$env:X=...; cmd`）、`cd &&` 連結、`;` による複数コマンド連結は許可を無効化するため、単純な単独コマンドに分割して書くこと
- 環境問題（PATH 未反映等）をコマンド前置で回避しないこと。検出したらユーザーへ報告し、環境側の恒久修正（またはセッション再起動）で解決すること
- git 操作は Bash ツールに統一すること（PowerShell と Bash の許可ルールは別扱いのため）
- ファイル操作はシェル経由ではなく専用ツール（Read/Grep/Glob/Edit/Write）を優先すること
- 未許可コマンドが繰り返し必要になったら、「常に許可」を場当たりに選ばず、可逆性基準（読み取り=許可 / リポジトリ内で可逆=許可 / 不可逆・外向き=ask）を満たす場合に限り `.claude/settings.json` への追加をユーザーに提案すること
- サブエージェントを起動するときは、起動プロンプトに本規範への参照（または要旨）を含めること

# Issue-0055: CLAUDE.md「コマンド許可運用」の連結・前置に関する説明が実挙動と違う（指示は妥当・理由が誤り）

- **Status**: open
- **Opened**: 2026-07-29
- **分類**: 開発フロー/ガイドライン
- **起票元**: 第23回（第4段階フェーズ5 クラスタ G）の Task 5.3。ゴール 0004 の Bash 許可の実効範囲を `claude -p` で実測した際に副次的に検出

## 要約

`CLAUDE.md`「コマンド許可運用」は次のように述べている:

> 許可ルールは**前方一致**で判定される。環境変数代入の前置（`$env:X=...; cmd`）、`cd &&` 連結、`;` による複数コマンド連結は**許可を無効化する**ため、単純な単独コマンドに分割して書くこと

このうち **`;` 連結について「許可を無効化する」は、claude CLI 2.1.220 の実挙動と違う。** 実測（記録: `docs/records/loop-learnings/2026-07-29-goal-0004-bash-allowlist-probe.md`）で判明した実挙動は:

> **連結された部分コマンドは1つずつ権限判定され、全部が許可された場合だけ複合コマンド全体が実行される。**

| 連結した部分コマンド | 結果 |
|---|---|
| `echo INJECTED`（副作用なし） | **実行された** |
| `git status --porcelain`（deny 済み） | 拒否 |
| `touch tests/...`（未許可の書き込み） | 拒否 |
| `echo ... > tests/...`（リダイレクト） | 拒否 |

つまり「連結すると許可が無効化されて全体が落ちる」のでも、「前方一致が文字列全体を飲み込んで何でも通る」のでもない。**独立に許可される部分コマンドだけが通る。**

## なぜ問題か

**運用上の指示そのもの（単独コマンドに分割して書く）は妥当なまま**である。連結の一部が許可されていなければ全体が落ちるため、分割して書くのが確実であることに変わりはない。問題は**理由の説明が事実と違うこと**にある:

1. **挙動が変わったときに判断を誤る。** 「無効化される」という理解のままだと、たとえば「許可済みコマンド同士なら連結してよいのか」「なぜ `echo` は通ったのか」を判断する材料が無い。今回は誤りが**実際より安全側**に外れていた（実際は一部が通る）ため実害が出ていないが、**外れる方向は事前には分からない**
2. **未測定の2項目が同じ文に混ざっている。** `$env:X=...` の前置と `cd &&` 連結は**測っていない**。今回の結果を根拠にこの2つまで正しい／誤りと判断してはならないが、同じ文に並んでいるため「まとめて実測済み」と読まれるおそれがある
3. **同型が本プロジェクトで繰り返し起きている。** [[Issue-0005]]（外部ツールの挙動前提が仕様確定時に未検証）と同根で、ここでも「ツールの挙動をこう理解している」が実測されないまま規範として定着していた

## 対策候補（着手はユーザー判断）

1. **未測定の2項目を実測してから、三者まとめて直す**（推奨に近い）。`$env:X=...; cmd` と `cd && cmd` を同じ形（`claude -p` + 対象設定）で測り、`;` 連結の結果と合わせて記述を書き直す。**三者を揃えて一度に直すほうが、部分的に直して残りが古いまま残る状態を作らない**
2. **`;` 連結の記述だけを先に直す**。安価だが、同じ文の未測定2項目が残るため 2 の問題が残る
3. **理由を書かず指示だけにする**（「単独コマンドに分割して書くこと」だけを残す）。誤った理由は消えるが、判断材料も消える
4. 現状維持

**変更対象は `CLAUDE.md` であり、ガイドライン文書の改定は `extend-guidelines` の手続きを要する。** また同じ記述はプラグイン `ai-driven-dev-principles` 側にも存在する可能性があるため、**修正先が本リポジトリだけで足りるかを確認すること**（[[Issue-0050]] と同型で、修正先がプラグイン側だった前例がある）。
