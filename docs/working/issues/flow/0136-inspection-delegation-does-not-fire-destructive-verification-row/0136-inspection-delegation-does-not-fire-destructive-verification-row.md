## 課題内容

**事象 1**（配布先 LoopForAlpha 第126回・2026-09-05）: 仕様適合レビューとコード品質レビューを委譲した際、委譲元は判定行を `検査=yes / ミューテーション=no / 破壊的検証=no` と書いたが、同じプロンプト本文で変異実験（対象を壊して検査が赤くなるかを測る）を指示していた。委譲先の変異台本の書き戻し先が `$PSCommandPath` 経由で Pester モジュール本体（`Pester.ps1`）へ解決され、同ファイルがゴール定義の本文で丸ごと上書きされた。委譲先は「実リポジトリは無変更（`git status --short`）」と正しく報告しており、破壊はリポジトリ外で起きたため原理的に検出できなかった。発見まで約 40 分。

**事象 2**（第127回）: 委譲元が「変異実験は範囲外」と明示して禁じた検査委譲でも、委譲先がスクラッチパッドへ複製を作って自発的に変異 8 件を実施した（本レビューで最も価値のある指摘を出した）。安全を担保したのは委譲先自身の規律であり、委譲元は `破壊的検証=no` と判定したため隔離の展開項目を一切注入していなかった。

**事象 3**（第127回）: 常時適用の「既存物の削除は事前承認」を明示した委譲で、委譲先が後片付けを「更新時刻が 50 分以内」で絞ったところ、同じ窓に入っていた既存 4 件（うち 1 件は課金して得た起動プローブの実セッション記録）も消した。書き込み先は隔離配下で正しかったが、**削除対象の選び方**が間接的だった。

**原因（配布先の分析）**:

1. **発火条件の重なりが読めない**: 判定表の「検査・監査・走査」「ミューテーション検査」「破壊的検証」は別行で排他的に読めるため、検査委譲の中で変異が起きる形が「検査」行だけの判定で通る。事象 2 は「指示していないのに変異が起きる」形なので、「変異を指示するなら併せて発火」という条件付けでも覆えない
2. **展開項目の射程**: 破壊的検証行の展開項目「検証対象範囲のファイル一覧と内容ハッシュを作業前後で比較」は、書き込み先が想定外の場所（検証対象範囲の外）へ解決した場合を覆わない。同項目の注記は「リポジトリ外の破壊は検出できない」と正しく警告しているが、検出手段は用意されていない
3. **ランタイム固有の落とし穴**: Pester の実行フェーズでは `$PSCommandPath` / `$MyInvocation.MyCommand.Path` がテストファイルでなくモジュール本体を指す

**配布先の暫定回避（実効性あり）**: 委譲プロンプトへ隔離プロトコルを注入する。`git archive HEAD` の短パス複製 / **固定文字列から組んだ絶対パス**での書き込み / 書き込み直前に隔離ルート配下であることを突合 / 実行文脈で解決先が変わる変数を書き込み先の算出に使わせない / Pester モジュールと実リポジトリのハッシュを前後で比較 / 後片付けは**自分が作ったパスを名指しで**消す（更新時刻・ワイルドカードで絞らない）。Issue-0135 / 0167 サイクルで変異委譲 5 回に適用し破壊 0（`lfa-0172-...md`「現在地の要約」・配布先の実装教訓 `docs/reference/implementation-lessons/issue-0135-0167-launch-resilience-checks.md` 項番 17）。

**対策の方向（採否・設計は本リポジトリ。配布先の提案）**:

1. 発火条件: (a) 「検査・監査・走査の委譲で変異・書き換えを伴う実験を指示するなら、ミューテーション行と破壊的検証行も併せて発火」を表または手順 2 に明記する。(b) 代替として、**検査・監査・走査の委譲では変異の指示の有無にかかわらず破壊的検証の展開項目を既定で発火させる**（事象 2 を覆う。費用は委譲プロンプトが数行伸びるのみ）
2. 破壊的検証行の展開項目に足す: 書き込み先は固定文字列の絶対パス + 隔離ルート配下の実行前突合 / 実行文脈依存の変数を書き込み先の算出に使わせない / 隔離ルート外への書き込みを試みたら停止して報告
3. 常時適用の 2（削除の事前承認）の展開項目に足す: 「後片付けでは自分が作ったパスを記録し、そのパスだけを消す。更新時刻・ワイルドカードなど間接的な条件で対象を選ばない」（費用は 1 行）
4. リポジトリ外の破壊を事後検出する軽量な手段（委譲先が触りうるツールチェーンのファイル一覧＋ハッシュを前後で記録する等）の要否。射程と費用の釣り合いは本リポジトリの判断（**難易度 中・ここだけ上位モデル＋確定前レビュー推奨**）
