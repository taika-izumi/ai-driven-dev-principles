# 検証担当本体を隔離する構成の再検討

状態: 2026-09-09、ADR-0153による設計検討。具体構成は未採用。旧v2計画のタスク1以降は保留する。実装・イメージ準備・モデル起動・認証情報の移送は行っていない。

## 維持する要求

主担当はClaude CodeとCodex、検証担当はCodex。スクリプトがファイルとGit履歴を独立コピーへ渡し、子が必要資料を探索して追加テストを作る。原本へ自動適用せず、指摘と再現テストを回収し、主担当の修正版を新runIdで再検証する。通常の受け渡しに利用者の本文転記を含めない。

ホストの原本・ホーム・機密・サービス・Docker制御権限を子へ渡さず、制御記録は子が書き換えられない場所に置く。ファイル保護と通信保護を別々に実証する。

## 配置の候補

| 候補 | 得られること | 残る課題・運用負担 |
|---|---|---|
| Codexとテストを同じコンテナへ置く | 構成が小さく、ホスト操作はマウントとネットワーク境界で制約できる | テストもモデル通信経路に触れ得る。認証を同居させる場合、追加テストが読めないという保証は別途必要。旧仕様のテスト実行環境の通信なしをそのまま維持できない |
| Codex用とテスト用のコンテナを分ける | テスト側は通信なしのまま、資料・編集・テストを専用接続へ集約できる。Codex側に内蔵操作が残ってもホストのファイルを直接渡さずに済む | 2環境の起動・停止と限定接続が必要。Codex側の認証情報を任意コード実行から守る方法と、モデル通信先以外への到達拒否を設計する必要がある |
| 上記分離に認証を保持する信頼側の中継を組み合わせる | 長期認証情報を子やテストへ渡さずに済む可能性がある | 認証方式に対応した中継が必要。任意URL転送を許さず、宛先・操作・期限・出力を制限する。ChatGPT認証との互換性は未確認で、実装済みの機能と扱わない |

現時点では候補2を中心に、認証の条件に応じて候補3の必要性を比較する。ただしこれは検討の見通しであり採用判断ではない。候補1への単純化によってテスト側の通信や認証情報への到達を無断で許可しない。

## 認証と通信の前提

OpenAIの[認証の公式資料](https://learn.chatgpt.com/docs/auth)では、ChatGPTログインによる契約枠の利用とAPIキーによる従量課金を区別している。ヘッドレス環境向けのデバイスコード認証も案内されている。認証キャッシュはアクセス用秘密情報を含むため、そのコピーを単なる設定ファイル移送と扱わない。

[セキュリティの公式資料](https://learn.chatgpt.com/docs/agent-approvals-security)では、コマンド用ネットワークプロキシはモデル・認証通信やMCP等のすべてを制御するものではない。したがって新構成では、Codex自体を含むコンテナ外向き通信を別の境界で制限し、環境変数にプロキシを設定しただけで迂回不能と認定しない。

以上は提供元の一次資料であり、このWindows/Docker環境での動作実証ではない。既存ChatGPT認証情報をホストから抜き出して転送する作業は行わない。

## 次の判断

認証・課金方針を確認する。ChatGPTの契約枠を維持するか、専用APIキーと別の従量課金を許容するかで、中継の互換性と利用者の準備作業が変わる。前者では初回のブラウザー認証等、後者ではキーと課金設定等の操作が必要となり得る。秘密値の提示は求めず、まず方式の希望だけを確認する。

回答後、認証の保持場所、モデル通信経路、テスト用通信なし環境への接続、記録の真正性、当該実行だけの停止を具体化する。保護条件の変更や新規必須依存が必要なら、その影響を示して相談する。詳細仕様確定前に既存仕様00〜03との対応と機能ブロック設計の適用要否を確認する。
