## Claude Codeの新規セッションで進める範囲

1. **実行環境と導入内容を確認する。** リポジトリmaster、Claude Codeの版、親セッションのAgent/Task等の実在、導入済みスキルの版を確認する。ローカル配布予定版は0.1.25、公開元は最後の確認時0.1.24。マージだけでプラグインの導入が更新されたと判断せず、必要なローカルソースを直接読む。新たな公開・更新操作は無断で行わない。
2. **標準サブエージェントの制限方法を確認する。** 実機ヘルプと公式文書から、子に渡るツール、権限、MCP、サンドボックス、再委譲の扱いを確認する。設定ファイルの値やモデルの自己申告だけで成立としない。まず書き込み操作のない子の起動で実ツール構成と結果回収を確認する。
3. **実行ありの構成を具体化してから子を起動する。** 既存Codexへの固定検査接続を標準サブエージェントにも限定公開できるか確認する。親が持つ汎用シェル・直接編集・他MCPが子へ残らないこと、子が制限解除や追加担当で保護対象へ変更できる道を持たないことを確認する。禁止文だけでは成立としない。
4. **新しい代用品だけで実経路を試す。** 子AIの実起動→許可処理成功→原本・共有ツール・既存記録の代用品への拒否→必要な子プロセスへの制限継承→結果回収→親の状態比較を確認する。固定MCPの試験は正常1成功・変異1失敗・復元1成功が基準。未実行・環境不一致・単なる起動エラーを成功に数えない。再委譲を許す構成ならその継承も確認し、許さない構成なら利用不可を確認する。
5. **結論を限定して更新する。** Claude標準サブエージェントで確認した構成と未確認をIssueのログ・参照知識・ハンドオフへ記録する。必要ならコード・配布参照を更新し、独立レビュー・生成検査を行う。成立しなければ、何が不足するかと追加作業を明示して相談する。既存の限定接続の成功を標準機能の成功へ読み替えない。

## 維持する制約と保全対象

- 重い検証は1件ずつ。OS・版・依存・起動方式を記録する。新しい必須依存、WSL移行、保護緩和、既存データを変更する実験は相談事項。今回は既存Codex併用の追加検証までを承認されている。
- 原本・共有Pester・実セッションログを変異対象にしない。新しい試験ルートに代用品を作り、既存 `.tmp/` の試験結果は再利用できる証拠として保全する。後片付けは作成物を名指しし、既存物を時刻でまとめて選ばない。
- 元の `.tmp/`、`docs/conversation_log.md`、inbox3件、別のissue-0122 worktreeとstashは触らない。inboxは手動整理予定。リモート操作・認証の状況は新セッションで確認し、以前の制約が解消したと推測しない。
- 0.1.25はローカルのみ。追加修正時は直前の公開状況を確認し、未公開なら同じ予定版、公開済みなら次の版とする。今回のマージ承認をpush・公開・導入の承認へ拡張しない。
