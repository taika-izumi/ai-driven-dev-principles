# 子がリポジトリとGit履歴を自分で探索できるようにする

問い: 親による資料本文の再出力を増やさず、独立したコピー内で子がGit履歴を参照できるか。

## 要求と実装

2026-09-09、ユーザーはスクリプトによるコピーと子からのGit履歴参照を条件に続行を指示した。要求と方式のドラフトはADR-0150。既存のコピー準備への追加であり、新しい役割・常設サービス・Docker方式・Linux先行は選択していない。

`RequestCopy.psm1`でbundle作成・検証・取り込みを行う。空のGit領域へ履歴と参照を移し、HEAD基準のインデックスを作る。作業ファイルはcheckoutせず既存のファイルコピーを保つ。管理領域・オブジェクトの共有、原本設定とフックのコピーは行わない。現用の仕様は`docs/current/specs/2026-09-09-isolated-verification/`と`scripts/verification/README.md`。

## 確認した事実

- Git 2.45.2.windows.1。公式の[git-bundle文書](https://git-scm.com/docs/git-bundle)でオフライン移送と参照の格納を確認（2026-09-09、Git公式の一次資料）。
- 使い捨て検証`.tmp/history-transfer-probe.ps1`の14項目が成功。証拠は`.tmp/history-transfer-a4048950-5e8f-458e-972a-8ebbbc8e1268/result.json`。本番モジュールの成功や権限制限の証拠とは区別する。
- 新規`History.Tests.ps1`が、実装前にコピー側HEAD不在で失敗することを確認。その後、実装とテストを追加。
- worktree入力の追加テストで、`--all`が`main-worktree/HEAD`もbundleへ含める事象を検出。出力参照を確認し、`--single-worktree`で入力worktreeのHEADと全参照に絞って解消。
- `Run-IndependentTests.ps1`を再実行し4群成功: コピー準備26件、履歴20項目＋fsck、プロセス管理7ケース、結果照合15ケース。
- テスト補助のGit実行ではユーザーのignore設定の読み取り拒否警告が出た。テスト自体は終了コード0。製品側のGit実行はユーザー全体・システム設定を継承しない。

## レビューの経緯と現在地

2026-09-09の続行指示で独立レビューを準備。Claude Code 2.1.265のヘルプでsafe-mode・tools許可リストを確認しRead限定で起動したが、初期出力が得られず今回起動したPIDと開始時刻を照合して停止した。送信成功は確認できていない。通常ユーザー権限での再試行は自動承認レビューが拒否。「レビュー自体は了承されているが、非公開リポジトリの具体的データをClaudeへ送ることと送信先の明示承認がない」が理由。再送信は行わず、ユーザーの明示承認待ち。

送信対象は`.tmp/history-review/send-manifest.json`の10ファイル（内容93,183バイト）に固定し、スクリプトで`.tmp/history-review/send-payload.txt`（指示込み97,414バイト）を作成した。承認後の候補はこの固定本文だけを渡すツールなしのClaudeレビュー。モデルによる追加ファイル参照を不要にし、対象以外のデータが増えない形とする。ファイル本文の連結はスクリプトが行い、親AIが生成し直していない。対象版を変更したら送信前に一覧と内容を照合する。

その後、ユーザーが「1で」と送信を明示承認し、固定資料によるツールなしのClaudeレビューを実施した。指摘2件のうちHEADのブランチ名喪失を再現・修正し、空junctionの指摘は保護境界の欠陥として不採用。履歴23項目を含む全4群が成功。ADR-0150を確定した。正本は`docs/records/reviews/2026-09-09-history-copy.md`。

SHA256形式・コピー中の参照更新も確認し、実リポジトリ749ファイルと履歴bundle約4.2MBのコピーは約40秒で成功した（F1修正前の実測）。証拠・条件・限界は上記レビュー記録を参照。浅い履歴・部分クローンは停止する。LFS外部実体やreflogだけに残る履歴を提供済みとは扱わない。

履歴のコピー成功は子の権限保護の証拠ではない。実エージェント起動・通信制限・共通CLI結合・両主担当からの往復実証は未完了。

初回コミット前のHEADと他ブランチの履歴が共存するケースも追加検証した。コピー側で偶然同名の初期ブランチがHEADになる問題を修正し、20項目と全4群を再実行して成功。深い試験ディレクトリではGitのpack書き込みがWindowsのパス長制限で失敗したため、試験名を短縮した。任意の長い出力先への対応は保証せず、準備失敗として返す。
