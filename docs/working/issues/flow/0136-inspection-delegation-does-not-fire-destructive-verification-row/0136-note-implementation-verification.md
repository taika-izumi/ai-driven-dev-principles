## 実行環境の確認

### Codex

試験用代用品を `.tmp/issue-0136-codex-agent/` に新規作成。書き込み先をrunへ限定し、run内のsession-log.jsonは読み取り専用、兄弟のprotected配下も読み取り専用とする一時プロファイルを使う。原本・共有ツールは実物を使わない。

初回は `-a` をexecサブコマンド後に置いたため引数解析で停止。`approval_policy` の一時設定へ修正した第2回は、担当が画像生成・副担当などを利用可能と報告し、指定した停止条件によりファイル操作前に停止した。ユーザー設定の読み込みを止める指定と、プラグイン等の機能無効化は同義ではなかった。

実機の `codex features list` で確認した `plugins`・`image_generation`・`multi_agent_v2` 等の無効化を追加し、第3回を実行。シェルと内蔵編集で許可先への書き込み成功、原本代用品への拒否を確認。共有ツール・同じrun内の既存記録の代用品へのシェル書き込みも拒否された。

子PowerShellは実行ファイルの誤指定で未確認となったため、実在する絶対パスを指定して該当部分だけ再試験。子からの正常書き込み・拒否と、run内の既存記録への内蔵編集拒否を確認。委譲元が保護対象3件の前後ハッシュ一致、許可側の内容、実際のコマンド出力を照合した。結果と制限指定は `docs/records/experiments/2026-09-08-codex-inspection-agent.json`。

副担当ツールは無効化指定後も担当が利用可能として一覧に挙げた。起動と制限継承を実行検証しておらず、この経路を禁止文だけで塞いだとは扱わない。今回確認したローカル操作の保護と、担当全体の保護成立は区別する。全ツール構成での対応完了や、Claude経由の成功は主張しない。

### Claude Code

WindowsネイティブCLIのRead限定起動は判断試験・独立レビューで利用できる。BashのサンドボックスはWindowsネイティブ非対応であり、内蔵編集の権限とコマンドのOS制限を別に扱う必要がある。[Anthropic公式サンドボックス仕様](https://code.claude.com/docs/en/sandboxing)、[権限仕様](https://code.claude.com/docs/en/permissions)。

UbuntuのWSL環境を読み取り照会した結果、`bwrap=/usr/bin/bwrap`、`claude`・`socat`・`node`・`pwsh`はPATHで未検出、`~/.local/bin/claude`も未検出。最初のインライン照会はWindowsからの引数受け渡しで変数名が落ちたため根拠から除外し、保存したシェルスクリプトで再確認した。結果は `docs/records/experiments/2026-09-08-wsl-inspection-inventory.json`。ディスク全体の不在証明とはしない。

Claudeの実行あり検査をWSLで確認する案には、少なくともLinux側のClaude・socat・認証確認が必要。Nodeの必須性は導入方法次第であり必須と断定しない。Windows用の検証との互換性、Windows相互運用経路の保護、seccompの可用性も未確認。現在のWindows検証をそのまま代替できるとは扱わない。

別案は、既にCodexがある環境に限り、ClaudeにReadと保護済みコマンドを呼ぶ限定操作だけを与える接続の実証。Codex単体の成功をこの経路の成功へ転用しない。利用条件に別ツールへの依存が加わるため、対応方針の相談後に具体化する。

追加インストール・認証移行・永続設定変更は実施していない。両ツールの実経路が成立するまでタスク3は未完、Issue-0136はopen、ADR-0141はProposedを維持し、対応済み配布版として公開しない。
