# v3起動条件とsbxの未確認機能

2026-09-09。実装前の読み取り確認により、clipboard文字列書込拒否とpids外側強制の機構を確認できなかった。実測はdocs/records/experiments/2026-09-09-v3-runtime-preflight.md。現仕様はb7941f3の02で、確認不能ならblockedとしているため後続実装を開始していない。

## 判断が必要な点

1. clipboard書込はホストのコピー内容を上書きする経路。画像読取無効化とは別で、原本ファイルの共有なしでも残る。今回ホストのclipboardを読んだり書いたりする試験はしていない。
2. pids128は同時プロセス数の上限。VM単位のCPU/メモリ隔離は別の制約であり、同じ保護と無断で読み替えない。上限の目的と、別の強制手段で代替できるかは設計判断になる。
3. SSH転送は全体設定がtrue。今回のVMに実際に転送されているとは断定しない。全体設定変更・daemon再起動を試験再開の指示だけで実行しない。

## 次手の候補（未採用）

- 保護目的と実在する機構を対応付け直す。原本・基準版・外側記録・認証の保全、通信なし採否用再実行は維持したまま、pids等の達成手段を検討する。clipboard書込を許容する案なら、例外として失う保護を明示して個別承認する。変更を決める前に仕様は書き換えない。
- 現行仕様を完全維持して、提供元に無効化・強制方法の有無を確認する。外部投稿は未承認であり、必要なら質問文だけ先に作る。回答待ちの所要時間は見積もれない。

いずれも未採用。独自基盤の導入・別OSへの移行・制約の撤去を自動で選ばない。検討を進める指示は設定変更・モデル起動の許可とは分ける。

### 資源制限の変更案

厳密なpids128を完了条件から外すだけで、何も制限しない構成にはしない。VM内プロセスはホストのプロセス一覧と同じ名前空間に直接作られるわけではないため、以前のコンテナの制御値をそのまま採用する必要性を見直す。ただしホストのVM管理・プロキシ・出力保存の負荷は残るので、CPU/メモリ割当だけでホスト無影響と主張しない。

同時稼働1VMは現行の直列実行を維持する。仕様の全体時間・各実行時間・停止猶予・出力容量上限は変更しない。負荷試験は合成題材・有限の負荷・中止条件を先に固定し、外側stopが成立しない場合はprofileをverifiedにしない。fork bombや実環境の枯渇を無承認で実行しない。試験の数値と操作承認は具体化後に別途提示する。

### クリップボード例外の変更案

画像読取は既定falseを維持し、文字列書込だけを限定例外として明記する。clipboardを安全な出力経路に使わず、回収結果は既存のファイル検査経路を使う。試験開始時の表示と完了結果に例外があることを残し、誤って「ホストへの作用なし」と表示しない。

利用者には貼り付けを避ける/コピーし直す作業が増える。これは本文資料の手動転記ではないが、普段の操作上の負担であり、採用判断に含める。clipboardの自動読取・退避・復元・消去は提案しない。機密のコピー内容を取得したり、利用者が途中でコピーした内容を上書きする別の問題を持ち込まないため。

VM内のclipboard用コマンドを消すだけでは、sudoを持つ子が別のクライアントで同じ経路を使える可能性が残る。コマンド削除を遮断の実証にはしない。書込を一切許容しない場合は、この例外案は使わず、提供元が支持する拒否方法または別の実行境界を検討する。

### 維持する条件と採否の区切り

原本・基準Git・control・認証の保全、共有workspace/skills/MCPなし、採否用再実行の通信拒否、対象VMの停止と他VMの保全は維持する。SSH転送拒否も維持する。今回の2条件の見直しにSSH許可を混ぜない。SSHの全体設定変更と通常ターミナルからの再起動が必要になれば、影響を示して別に承認を得る。

次に提示する選択肢は、(1) 資源制限の見直しとclipboard例外を小さな合成題材の試作に限定して採用、(2) 資源制限の見直しだけ採用しclipboard遮断は維持、(3) 両条件を維持して別の実現手段を検討。推奨は(1)だが、書込例外を許容できない利用者には(2)または(3)が必要。どの選択もモデル認証・実モデル実行・設定変更・新基盤導入をそのまま許可するものではない。

## 2026-09-10: 試作限定の変更を採用

ユーザーはclipboard遮断の目的と試作限定の意味を確認した後、「OKです。では推奨案で進めましょう」と回答。両変更を小さな合成題材に限って採用した（ADR-0160/0161）。上記の未採用表記は提示時の状態であり、現在の採否はこの節を正とする。

v3仕様の00〜03へ反映。実行profileにscope=synthetic-pilotとacceptedLimitations、結果にscope/limitationsを追加し、通常運用への自動拡張や制約の非表示を防ぐ。pids128は必須設定から外し、旧キーが残れば拒否する。画像読取・SSH転送拒否、原本等の保全は維持。今回の変更は元仕様のb7941f3からgit差分で復元可能。

実装コード、sbx設定、VM状態は変更していない。残る能力確認はSSH等の経路拒否、CPU/メモリ割当と有限負荷中の停止、切断・自動起動競合、認証・最小モデル試験。これらの実機操作の承認を今回の採用へ含めない。
