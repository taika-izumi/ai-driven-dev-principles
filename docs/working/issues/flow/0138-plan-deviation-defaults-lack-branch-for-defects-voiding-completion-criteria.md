# Issue-0138: 計画逸脱判断の既定に「射程外の既存欠陥がサイクルの完了基準・close 条件を満たせなくする」場合の分岐が無く、利用者が既定を覆した

## 課題内容

**事象**（配布先 LoopForAlpha・Issue-0135 / 0167 サイクル・2026-09-06）: 計画の最終タスク（Task 8）の再測で、master 側の既存回帰（コンテナ内 pytest の収集中断 = 検証チェックが全反復不合格）を検出した。既定の型「計画の範囲外の既存欠陥」に従えば不採用＋起票だが、放置するとサイクルの目的「ループのフロー C が起動できる」が成立しないため、利用者が 3 案から本サイクルでの最小修正の取り込みを選んだ（逸脱記録に `覆し:` 1 件。LoopForAlpha#ADR-0190）。

**原因**: 採用基準の 2 条件（検査の仕組みが無い型 / 自分で持ち込んだ後退）に、「当該欠陥が計画の完了基準または Issue の close 条件を満たせなくする」場合の分岐が無い。この型を不採用にすると Issue を close しても目的が達成されない。

**影響**: 利用者の判断を 1 回要した（費用は小）。ただし覆しは退役条件（直近 10 件で 3 件）の計数対象になるが、この覆しは既定の設計漏れであって当てはめの誤りではない。**設計漏れ由来の覆しが退役条件を早く満たすと、既定そのものの改良・廃止提案が誤って発火する**。

**本リポジトリで決めるべき問い**（配布先の提案）:

- 採用基準に「完了基準・close 条件を無効化する欠陥は、既定の不採用ではなく提示側（ユーザー判断）へ倒す」分岐を足すか。足す場合、**射程拡大の口実**に使われない条件設計（例: 完了基準の該当項目を名指しできること・最小修正に限ること・統合採用の記録形式）が要る
- 退役条件の計数で「既定の設計漏れ由来の覆し」を当てはめ誤りと区別するか
- **難易度 中〜高（規範の判定分岐の追加。誤用を防ぐ条件設計。上位モデル＋確定前レビュー推奨）**。毎サイクル使う規範なので早い方が効く
