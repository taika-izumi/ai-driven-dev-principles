# Issue-0143: 独立レビューで検出すべき欠陥と観点構成の対応が未検証

- **Status**: closed
- **Opened**: 2026-09-11
- **起票元**: 前提実在の原意照合を受けたユーザーの分析・起票判断依頼
- **関連**: ADR-0117・0185・0186・0187、Issue-0075（初見での利用可能性）、Issue-0112（レビュー層の役割分担）、Issue-0133（既存決定への係留）、Issue-0144（根拠探索の独立性）

## 課題内容

現在の4観点は、失敗を探す方法（敵対的）と、要求・実体・前提を比べる対象が混在している。名称・定義だけから担当が検査目的を安定して理解し、必要な欠陥を漏れなく探せることは確認できていない。

今回の改定は全体目的との整合と定義の明確化を追加したが、後続のADR照合で、前提実在の対象列挙、範囲外の明示、適用例への参照に弱化が見つかった。独立確認は新しい定義と例に依存し、導入ADRとの保持を網羅したものではなかった。6例の理解確認でも不要／前提誤りの判断と与件の扱いに不足が残った。

名称が理解を妨げた可能性はあるが、名称単独が原因だとは未検証。過去の全レビュアーが意図を誤解していたとも断定できない。対処は名前だけの変更や旧文の自動復元ではなく、プロジェクトの目的と現在防ぎたい欠陥からレビュー全体を再評価する必要がある。

## 検討する問い

- 目的・要求の取り違え、根拠のない対策、既存対策との重複、必要な保護の欠落、実体と接続の不一致、失敗経路、文書の利用不能を、どこで検出する必要があるか。
- 前提実在の旧意図のうち、今も必要なもの・他観点で扱えるもの・費用に見合わないものは何か。旧ADRは維持義務ではなく、採否判断の理由と失敗事例の情報源として読む。
- 観点と検査方法をどのように整理・命名すれば、会話履歴のない担当でも問い・根拠・限界を説明できるか。4観点維持・改名・統合・再編はいずれも候補で、先に数を固定しない。
- 規範・仕様・実装で必要な確認をどう変えるか。全場面へ同じ重さを課さず、初回設計と変更時の保持確認も区別する。
- 検査範囲・除外条件・原意を変えた場合、何を残す／変える／廃止するかを追跡できるか。現行の引用整合検査の適用漏れか、手順不足かも確認する。

## 完了条件

- 代表的な欠陥型と新しい観点・確認方法の対応を示し、原意の採用・変更・不採用理由を説明できる。
- 名称だけでなく定義・入力・根拠・未確認の扱いが文脈なしで理解できることを、定義の例をそのまま繰り返さない事例で確認する。観点ラベルの唯一一致を合格条件にしない。
- 新旧の要求・適用条件の対応と、意図的な変更を明示し、無意識の削減・拡大を検出できる。
- 観点・資料・レビュー量の増加を便益と比較し、既存工程との重複を抑える。効果未確認を一般的な保証にしない。
