# Issue-0144: 独立レビュアーが委譲元の選んだ資料の不足を自力で補えない

- **Status**: open
- **Opened**: 2026-09-11
- **起票元**: 独立レビューへ渡す情報と自由なプロジェクト閲覧についてのユーザーの分析・起票判断依頼
- **関連**: ADR-0185・0186・0187、Issue-0143（必要観点の再評価）、Issue-0133（全文を読んでも既存判断に係留）、Issue-0136（検査の操作経路の保護）、Issue-0141（静的確認の判定）

## 課題内容

今回のClaude独立担当は`--tools ""`で起動し、主担当が選んだ原文と抜粋だけを受け取った。初回の指定対象はソース5文書＋ADR2件、上位方針は2抜粋。導入意図を定めるADR-0117は含まず、担当は追加のファイル・履歴を検索・閲覧できなかった。差分回も同様で、未提供の参照先を確認不能として報告した。

書き込み可能な経路を持たせず静的確認を成立させた点と、根拠を独立に選べない点は別の性質である。担当が不足を報告できても、主担当がその重要性を理解していなければ資料が補われず、作成側の誤解がレビューへ持ち込まれる。

これは全レビュー環境で閲覧不能という意味ではない。現在のネイティブ担当はツール・作業場を継承する一方、利用できる起動APIには担当別の権限制限がない。既存のClaude読み取り専用構成はIssue-0136に記録があるが、今回の版・プロジェクト範囲・履歴検索でそのまま成立するかは未確認。

## 検討する問い

- 初期入力は目的・対象版・今回の範囲と入口に絞りつつ、担当が必要に応じてプロジェクト全体のファイル・索引・履歴を自力で検索・閲覧できるか。
- 「閲覧できる範囲」と「毎回読む範囲」をどう分けるか。全資料の一律読破や、主担当が選ぶ抜粋だけへの固定を既定にしない案を比較する。
- 読み取り・検索と、ファイル変更・任意コード実行・外部操作を分離できるか。作業中の差分を含む読み取り専用の複製、許可リストのファイル・検索ツール、要求された原文を機械的に返す経路など、既存機能から確認する。
- レビューする版・未コミット変更・履歴・他プロジェクトへの参照・機密情報や実行時ファイルを、どの範囲で扱うか。全プロジェクトへの読み取り許可と全ファイルの外部一括送信は区別する。
- 閲覧不能な箇所をどう開示し、主担当の解釈を経由しない形で補うか。ツールなしで限定確認する場合、その限界を総合的な独立レビューの保証へ読み替えない。

## 完了条件

- 既存機能の最小構成で、委譲元が初期入力から意図的に外した根拠を担当が発見・参照し、対象の不整合を指摘できることを確認する。
- 版・対象範囲・利用できる操作を示し、読み取り・検索の成立と書き込み拒否を区別して確認する。単なる「変更禁止」の指示を保護成立としない。
- 追加で読んだ資料・確認できなかった範囲を既存報告から追跡できる。資料量・読解費用・準備費用を比較し、無制限探索を解決策としない。
- プロジェクト全文を一律に読ませなくても、必要な根拠を発見できる条件と限界を説明できる。全文読解による既存判断への係留は0133の知見と照合する。
