# Issue-0008: 旧型式の単一ファイル spec の維持・アーカイブ方針が未定義

- **Status**: open
- **Opened**: 2026-07-05
- **起票元**: 2026-07-05 サイクル（振り返り課題×issue管理統合）の brainstorming 中に検出

## 課題内容

`docs/current/specs/` には旧型式の単一ファイル spec が8本残っている（2026-04-12〜2026-06-16）。「仕様書は現時点のシステム全容が分かるスナップショットとして維持する」規約に対し、これらは後続 ADR の改定が反映されず古びている（例: `2026-05-01-retrospective-design.md` は ADR-0021 のスコープ縮小・出力先2フォルダ化が未反映）。維持（書き換え更新）するのか、アーカイブ扱いにするのかの方針が未定義。

## 検討状況

- 2026-07-31: `2026-05-01-retrospective-design.md` を ADR-0056 反映で全面書き換えし、旧型式 spec 1本を「維持（書き換え更新）」で処理した（8本中1本が解消）。あわせて隣接する未定義事項が顕在化: **ファイル名の日付が初版作成日か最終更新日かが未規定**で、書き換え更新してもファイル名は初版日付のまま残るため、spec 一覧から現行性・鮮度が読めない。維持/アーカイブ方針の決定時に命名規約もあわせて決めること
- 2026-08-01: ADR-0057/0058 の反映で `2026-04-25-record-strengthening-design.md` を部分更新した際、旧パス表記（`docs/handoff/` 等、フォルダ構造再編前のもの）が同 spec 内に残存していることを確認。編集箇所のみ現行パスへ訂正し、全面訂正は本 issue の維持/アーカイブ方針の決定に委ねた
- 2026-08-04: ADR-0059/0060 の反映で同 spec に §7.4 を新設した際、§7.2「ADR作成手順への追記」が現行 `decision-log` 本文より古い記述（旧ドラフト承認フロー: 承認即 Accepted 化・却下即削除）を保持していることを確認。前回同様、変更箇所のみ追記し §7.2 の訂正は本 issue の方針決定に委ねた。**ドリフトが2サイクル連続で同一ファイルに顕在化**しており、部分更新のたびに現行実装と古い記述の併存が増える

- 2026-08-07: ユーザー指摘（「規約では仕様書を唯一の正とするはずだが実運用はそうなっていない」）を受けて実態を確認した。**ディレクトリ形式の spec は規約どおり書き換え更新されている**（`2026-07-17-worklog-skill-pipeline` は作成日より後の ADR-0048〜0053 / 0057 / 0058 / 0079 を反映、最終更新 2026-08-07。`2026-07-04-project-folder-structure` も同様）。**規約が執行されていないのは旧型式 8 本に限られる**ことが実測で切り分けられた。あわせて、配布物生成サイクル（Issue-0067 / ADR-0081〜0083）が `2026-04-13-template-folder-and-sync-design.md` の記述領域そのものを変更するため、同 spec を新 spec `docs/current/specs/2026-08-07-distributed-artifact-generation/` へ統合し、旧ファイルには「本 spec が正」を示す 1 行を残す方針をユーザーが選択した（削除という不可逆操作を避けるため）。旧型式の残り 6 本の方針は本 issue に残る
