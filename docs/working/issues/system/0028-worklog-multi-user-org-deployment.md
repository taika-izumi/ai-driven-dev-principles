# Issue-0028: worklog のマルチユーザー・組織展開対応が未設計（記録者・ストア間 id 一意性・組織スコープ）

- **Status**: open
- **Opened**: 2026-07-17
- **起票元**: 2026-07-17 セッションでのエントリフォーマットレビュー（設計意図ドキュメント `docs/inbox/2026-07-17-worklog-entry-format-rationale.md` 作成後の対話レビュー指摘 #4）
- **関連**: ADR-0044（中央集約・スコープ3分岐）、ADR-0045、spec `docs/current/specs/2026-07-17-worklog-skill-pipeline/`

## 課題内容

現行設計はユーザーのホームディレクトリ配下の個人ストア（`<home>/.ai-dev-worklog/`）前提であり、単独運用では問題ないが、職場展開後に「チームで delta を持ち寄って集約分析する」段階へ進むと以下が未設計:

- (a) **記録者の概念がない**: エントリに author 相当のフィールドがなく、集約後に誰の記録か判別できない
- (b) **ストア間で id が一意でない**: id は `<project>-<date>-<NN>` で、個人ストア内でのみ一意。複数人のストアをマージすると同一プロジェクト・同日・同連番の衝突が普通に起こる
- (c) **scope の中間層がない**: 現行は `project-specific` / `general-candidate` の 2 値。組織展開では「社内の複数プロジェクトでは汎用だが世間一般には固有（社内規約・社内インフラ依存）」という org-specific 中間層が必要になる見込み

いずれも v2 テーマ（職場での複数人運用が具体化した時点で着手）。v1 の個人運用には影響しない。
