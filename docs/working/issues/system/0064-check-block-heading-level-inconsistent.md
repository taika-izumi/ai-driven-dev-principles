# Issue-0064: 過剰適合点検ブロックの見出しレベルが記録先ごとに 2 通りで、存在確認を単一 grep で書けない

- **Status**: open
- **Opened**: 2026-08-07
- **起票元**: `retrospectives/system/2026-08-07-overfitting-check-for-extensions.md` 課題#1
- **関連**: ADR-0079（過剰適合点検・執行点の定義）、`CONTRIBUTING.md`「全シナリオ共通: 過剰適合の点検」、Issue-0047（規範のフック機械注入）

## 課題内容

ADR-0079 が定めた点検ブロックの見出しレベルが記録先ごとに揃っていない:

- `CONTRIBUTING.md` の雛形: `### 過剰適合点検（ADR-0079）`（インデントコードブロック内）
- 同ファイルの ADR 記録先の規定: `## 過剰適合点検（ADR-0079）`
- `docs/current/specs/2026-08-07-overfitting-check-for-extensions-design.md` のドッグフーディング実例: `##`

このため ADR-0079 自身が定めた執行点「拡張 spec / 拡張 ADR をコミットする直前に点検ブロックの存在を確認する」を、単一の grep パターンで機械化できない。将来フック等で自動化する際（Issue-0047 と同種）の直接の障害になる。

## 留意（対処を設計するときに参照すること）

- 見出しレベルを統一するか、レベルに依存しない検出方法（例: 見出しテキストのみを照合）を規定するかの二択
- `CONTRIBUTING.md` の雛形が `###` なのは、インデントコードブロック内で本文の見出しとして誤解釈されないための措置ではなく、単に spec の節名を写したもの。統一時に雛形側を変更しても表示上の問題は生じない
- 変更対象は `CONTRIBUTING.md`（雛形と ADR 記録先の規定）、ADR-0079 本文、既存の点検ブロック 1 件（2026-08-07 の spec）
