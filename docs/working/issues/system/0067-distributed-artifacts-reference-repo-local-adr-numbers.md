# Issue-0067: 配布先へ届く成果物が、本リポジトリ固有の ADR 番号を無修飾で参照している

- **Status**: closed（2026-08-08）
- **Opened**: 2026-08-07
- **起票元**: 議論由来（2026-08-07 セッション。ユーザーが template のリポジトリ固有情報依存として指摘し、調査でプラグイン配布側にも同型を確認）
- **関連**: ADR-0081（対象範囲）、ADR-0027（テンプレート初期セットの基準・「説明文は保持」）、ADR-0016（skills を template から除外しプラグイン配布へ）、ADR-0068（`<repo>#Issue-NNNN` によるクロスリポジトリの課題参照）、Issue-0001（template 同期の非対称性・closed）

## 課題内容

ガイドラインの配布先プロジェクトへ届く成果物が、本リポジトリ固有の ADR 番号を無修飾（`ADR-NNNN`）で参照している。配布先では同じ表記がその配布先自身の ADR を指すため、参照は無関係な決定を指す。配布先が ADR を書き進めれば番号は必ず重複する。

実測（2026-08-07）:

| 配布経路 | 対象 | ADR 参照 |
|---|---|---|
| `template/`（`sync-template.ps1` が生成） | 2 ファイル（`docs/records/retrospectives/README.md` 12 箇所 / `docs/overview/folder-structure.md` 7 箇所） | 19 箇所 |
| プラグイン `ai-driven-dev-principles`（`skills/`） | 16 ファイル | 159 箇所（ユニーク 46 本） |

残存の理由は経路ごとに異なる。`template/` は ADR-0027 が「インデックス行のみ除去し、説明文は保持」と定めたため、保持された説明文に埋まった ADR 番号が扱われなかった（Issue-0001 は行データの非対称性のみを解消して close された）。`skills/` は ADR-0016 で template から除外され、template 同期の検査対象にそもそも入っていない。

## 検討状況

- 2026-08-07: 起票。ADR-0081 で対象範囲を配布物全体（`template/` ＋ `skills/`）と決定（Proposed）。具体的な表記規則と ADR-0068 との関係（拡張か置換か）は未決定
- 隣接論点（本課題のスコープに含めるかは設計時に判断）: `docs/overview/folder-structure.md` 149/151/153 行に他リポジトリの実課題名（`LoopForAlpha#Issue-0069` 等）が例示として残っている。番号衝突ではないが配布先に無関係な固有名である
- 対象外と判断済み: `template/CLAUDE.md` のプラグイン名・インストール元リポジトリ名（配布先が環境準備に必要とする情報。ADR-0081）
- 2026-08-08: 実装・移行・文書化を完了し close。隣接論点として挙げた `folder-structure.md` の他リポジトリ名も本サイクルで解消した（149/151 行は中立名のプレースホルダへ、153 行は固有名を外して衝突の事実だけ残す形へ）

## 結論

**解決済み（2026-08-08）。** 4 つの決定と、それを実装する生成体制で対処した。

- ADR-0081: 除去対象は「配布先で解決できない参照」5 種（決定記録番号・課題番号・クロスリポジトリ修飾参照・worklog エントリ id・出所注記）。根拠の散文は残す
- ADR-0082: 注記を保持したソースから、注記を除去した生成物を配布する
- ADR-0083: ソースの書き方を位置で規約化（R1〜R5）し、生成器が規約適合の検査を兼ねる
- ADR-0084: 規約の適用範囲は機械判定の範囲より広く取り、差分は書き手が守る

実装: 共有ライブラリ `scripts/lib/strip-provenance.ps1`、生成器 `scripts/build-dist.ps1`（`skills/` → `dist/`）、`scripts/sync-template.ps1` の改修（判定・変換・`-Check`）。規約と執行点は `CONTRIBUTING.md`「全シナリオ共通: 配布対象ソースの記法規約」に置き、配布対象ソースを編集する 6 シナリオへ配線した。

結果（2026-08-08 実測）: 規約違反 36 件 → 0 件。`dist/` 19 ファイル・`template/` 7 ファイルとも出所識別子 0 件、実在の固有名・絶対パス・自己参照も 0 件。両生成器の `-Check` が `Up to date.` で通る。

**残課題**（本課題のスコープ外として分離。いずれも「原理と実装の隙」に属する）:

- Issue-0070: 機械判定がスクリプト内の散文（docstring・利用者向けメッセージ）に届かない
- Issue-0071: 配布されるスキルが配布されない文書を必須参照にしている
- Issue-0072: 括弧内判定が半角括弧を全角括弧と同一視する
