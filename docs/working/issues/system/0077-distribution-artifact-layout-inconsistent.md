# Issue-0077: 2 つの配布物の置き場が非対称で、`dist` の名前が実態（プラグインルート）と合っていない

- **Status**: open
- **Opened**: 2026-08-08
- **起票元**: 2026-08-08 のセッションでユーザーが指摘（「dist は配布物置き場のはずなのに、配布物である template の中身が入っていないのは違和感がある」）
- **関連**: ADR-0082（生成物を配布する体制）、ADR-0016（`skills/` を template から除外しプラグイン配布へ）、ADR-0003（テンプレートフォルダとマニフェスト同期）、`docs/current/specs/2026-08-07-distributed-artifact-generation/04-plugin-distribution-layout.md`

## 課題内容

配布経路は 2 つあり、どちらも「識別子を除去した生成物」という同じ性質を持ち、同じ共有ライブラリ `scripts/lib/strip-provenance.ps1` で作られる。しかし置き場が非対称である。

| 経路 | 中身 | 置き場 | 届き方 | 生成器 |
|---|---|---|---|---|
| プラグイン | スキル 13 本 | `dist/` | 自動（マーケットプレイス経由） | `build-dist.ps1` |
| テンプレート | 文書 7 ファイル | `template/` | 手動（人がコピー） | `sync-template.ps1` |

**`dist` は実際には「配布物置き場」ではなく「プラグインのルート」である。** `.claude-plugin/marketplace.json` の `source: "./dist"` がこのディレクトリを直接指し、`dist/.claude-plugin/plugin.json` が存在することでプラグインとして解釈される。したがって `dist` の中身は特定の構造に固定されており、任意の配布物を置ける場所ではない。名前がその制約を表していない。

この非対称は 2026-08-08 のサイクルで `dist/` を新設したときに生じた。`template/` は何サイクルも前から存在し、`dist/` を後から足す際に両者の関係を検討しなかった。仕様のブロック 04 でも配布構造の選択肢（構造 A / B）を比較したが、その軸は「スキルをどこに置くか」だけで、テンプレートとの関係は俎上に載せていない。

## 影響

- 配布物の全体像が、ディレクトリ構成から読み取れない。`dist` を見た人は「ここに配布物が集まる」と期待するが、実際には片方しか入っていない
- 新しい配布経路を足すとき、どこへ置くべきかの基準がない
- 現状は `dist/` 配下がまるごとプラグインキャッシュへ複製されるため、`template/` を安易に `dist/` 直下へ移すと、全利用者のキャッシュに文書 7 ファイルが複製される（利用者はキャッシュから取り出さないので無駄になる）

## 対策の方向（採否は未定）

**案 A: `dist/` を真の配布物置き場にし、中を分ける。**

```
dist/
  plugin/            ← marketplace の source: "./dist/plugin"
    .claude-plugin/plugin.json
    skills/
  template/          ← 手でコピーする文書一式
```

構造 A（マーケットプレイスの `source` にサブディレクトリを指定できる）は実機で確認済みなので成立する。副次的に、`template/` がプラグインの積荷から外れる利点もある。

コスト: `marketplace.json` の `source` 変更を伴う。**ここは 2026-08-08 のサイクルで 2 度事故が起きた領域**（インストール記録の消失）で、変更のたびにユーザー操作と記録確認が要る。あわせて両生成器の出力先・仕様・`CONTRIBUTING.md`・README の導入手順の書き換えが必要。

**案 B: `dist` を改名し、実態（プラグインルート）を名前で示す。** 例: `plugin/`。`template/` は現状のまま並列に置く。変更範囲は案 A より小さいが、「配布物が 2 箇所に分かれている」構図は残る。

**案 C: 現状維持とし、README と仕様に「2 経路がある」ことを明記する。** 構造は変えず、読み手の誤解だけを解く。

## 検討状況

- 2026-08-08: 起票。今サイクルでは機能そのものは正しく動いている（実機確認済み）ため、命名と配置の一貫性の問題として分離した。`dist` を「プラグインルート」の意味で使い続けるのか「配布物置き場」に改めるのか、という判断が対策設計の起点になる
