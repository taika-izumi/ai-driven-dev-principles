# Issue-0141: 検査委譲の実行準備の免除条項「書き込み可能な操作を持たない静的確認」に判定基準が無く、委譲元の誤判定で保護確認の経路ごと発火しない

- **Status**: open
- **Opened**: 2026-09-09
- **起票元**: ADR-0144 の Accepted 昇格時のサイクル全体整合検査（観点4「経路の閉じ」の (c) 発動条件が特定経路のみ偽にならないか）
- **関連**: `skills/subagent-dispatch/SKILL.md` 手順3の免除条項 / ADR-0141（免除条項の出所）/ ADR-0144（許可リスト方式に限る決定）/ `docs/records/experiments/2026-09-09-claude-native-subagent-interactive.json`（run i2・i3）

## 課題内容

`skills/subagent-dispatch/SKILL.md` 手順3は、実行を伴う検査・監査・走査または破壊的検証の委譲では起動前に保護条件の確認を課す一方、「書き込み可能な操作を持たない静的確認には、この実行準備を課さない」という免除条項を持つ。この免除の成否は「その担当が書き込み可能な操作を持たないか」という委譲元の判定に依存するが、その判定をどう行えば成立とみなせるかの基準が書かれていない。

判定を誤ると保護確認の経路そのものが偽になり、確認が一度も走らない。2026-09-09 の実測がこの誤判定の実例にあたる。拒否リストで書き込み系5ツールを外した担当は「書き込み可能な操作を持たない静的確認」と読める構成だったが、実際には列挙外の書き込み可能ツールが残っており、そのうち NotebookEdit が保護対象の代用品を承認要求なしで上書きした（run i2・i3）。

ADR-0144 は保護の成立方法を許可リスト方式に限ったため、免除の判定を「許可リストの明示列挙で書き込み可能な操作が無いことを示せた場合」に寄せる余地はある。ただし免除条項自体は ADR-0141 に由来し、Claude Code 以外のツールにも適用される一般規範である。判定基準をツール非依存の形でどう書くか、免除条項を残すか撤去するかは本サイクルでは決めていない。
