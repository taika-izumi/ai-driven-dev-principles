# Issue-0148: 子プロセスの打ち切り条件が全体期限と出力量上限だけで、出力が止まっても全体期限まで停滞を検出できない

- **Status**: open
- **Opened**: 2026-09-16
- **起票元**: タスク9の着手前に利用者から提起された懸念（「上限設定が厳しいと作業が終了しきらず、逆に緩すぎると過大な待ち時間が発生する」）。実装を確認したうえで、本サイクルは現行のまま進め課題として残す判断（2026-09-16 の利用者選択）
- **関連**: `scripts/verification/Execution.psm1` の `Invoke-VerificationProcessV3`（打ち切り判定 `:253` 出力量・`:267` 全体期限）/ 仕様02（実行の上限）/ ADR-0193（実行中のセッション保持）

## 課題内容

`Invoke-VerificationProcessV3` が実行を打ち切る条件は次の2つだけである。

- 出力の合算量が `maxOutputBytes` を超えたとき（`:253`）
- 当該コマンドの残時間（単調時計）が尽きたとき（`:267`）

正常終了は子プロセスの終了で即座に検出されるため（`:263`）、**上限は固定の待ち時間ではなく異常時の打ち切り点である**。したがって上限を緩めても通常の所要時間は伸びない。しかし出力が完全に止まった状態（停滞・ハング）を判定する条件が無いため、停滞しても全体期限に達するまで気づけない。

結果として、上限値の設定が次の交換を強いる。厳しくすると正常な長時間作業を途中で切ってしまい、緩くすると停滞時に無駄な待ち時間が発生する。実作業を長時間任せる段階ではこの交換が実害になる。

なお進捗の可視化自体は現状でも可能である。標準出力・標準エラーは逐次ファイルへ書き出され、`FileShare::Read` で開かれているため（`:232-233`）、実行中に別プロセスから追尾して読める。共通CLIにその表示機能は無い。

## 対策候補（未採用）

- 最終出力時刻を汲み出しループで保持し、無音が一定時間続いたら停滞として打ち切る（結果に停滞を示す理由を持たせる。上限値は実行設定の限度へ追加する）
- 共通CLIに実行中の標準出力の末尾を定期表示する診断を足す（打ち切りは変えず可視性だけ上げる）
- 現状維持とし、README に「全体上限は停滞時の待ち時間でもある」ことと追尾の手順を既知の制約として書く
