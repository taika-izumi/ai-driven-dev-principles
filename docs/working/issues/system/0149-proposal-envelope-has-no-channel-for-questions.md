# Issue-0149: 提案の受け渡し契約に未解決の前提・質問を表す欄が無く、隔離環境の中の担当が主担当へ問い返せない

- **Status**: open
- **Opened**: 2026-09-16
- **起票元**: タスク9の着手前に利用者から提起された確認（「サブエージェントがメインエージェントに『設計はこれでよいか』と質問を投げていた気がするが、今の環境ではできないのか」）。実体を確認したうえで、本サイクルは現状のまま進め課題として残す判断（2026-09-16 の利用者選択）
- **関連**: `scripts/verification/proposal.schema.json` / `scripts/verification/Proposal.psm1` の `Invoke-VerificationProposal`（受信後・検査前の停止）/ ADR-0157（提案と採否用再実行の分離）/ Issue-0148（停滞の検出）

## 課題内容

提案の受け渡し契約 `proposal.schema.json` の項目は `schemaVersion` / `runId` / `summary` / `findings[{description, sourcePaths}]` / `files[{kind, path, contentBase64}]` / `truncated` に限られ、**未解決の前提・質問を表す欄が無い**。実行も1往復に固定されており、依頼を標準入力で渡して提案を回収した後、検査の前にVMを停止する（`Proposal.psm1` の停止手順）。

このため、隔離環境の中の担当が「この前提でよいか」と判断を仰ぎたい場合、書ける場所は `summary` または `findings[].description` の自由記述しかなく、それを質問として扱う経路も、答えて続きを再開する経路も無い。運用上は「不明点を findings に書かせ、主担当が依頼文を直して次の往復を回す」で代替できるが、文脈は引き継がれず毎回新しいVMからやり直しになる。

ADR-0157 が提案と採否用再実行を分離した結果として意図された構造であり、欠陥ではない。ただし実作業を任せる段階では、前提の食い違いに気づくのが1往復分遅れる。

## 対策候補（未採用）

- 提案契約へ「未解決の前提」欄を追加し、質問を構造化して受け取る（答えは次の往復で渡す。対話の継続はしない）
- 同一VMで中の担当の会話を再開できるかを実測し、問い返しを含む複数往復を設計する（VM保持中の時間上限は Issue-0148 と直結する）
- 現状維持とし、依頼文の雛形に「前提が不明なら findings へ書く」ことを明記する

## 検討状況

- 2026-09-16: 起票。質問欄の追加には「誰が答えるのか（利用者か主担当か）」「質問文も未信頼データとしてどう検査するか」「待機中の時間上限をどう扱うか」の決定が伴い、タスク9の承認区切りを作り直すことになるため、本サイクルでは契約を変更しない。対策の採否・設計は次サイクル以降のユーザー判断
