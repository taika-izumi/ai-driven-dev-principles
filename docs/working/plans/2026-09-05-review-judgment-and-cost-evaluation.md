# レビュー推奨と追加物の費用評価の実装計画

> **実行担当者へ:** `superpowers:executing-plans` を用いてタスク順に実行する。サブエージェント方式を選ぶ場合は `superpowers:subagent-driven-development` を用いる。チェックボックスは実施後に更新する。

**目的:** レビュー方式・人数の推奨を状況判断へ移し、追加する仕組みの費用を既存の採否手順で比較できるようにする。

**構成:** `pre-finalization-review` の既存4文書とCONTRIBUTING.mdを改定する。初回の強い推奨、実施のユーザー判断、停止・記録・独立性の既存条件を維持する。別の検査スクリプトや台帳は作らない。

**使用技術:** Markdown、JSON、既存のPowerShell配布生成器。製品コードの新設・変更はない。

**設計:** `docs/current/specs/2026-08-05-dispatch-and-pre-review-skills-design.md` の「スキル2」以降。ADR-0124・0125。設計レビューはフル実施1回＋差分再確認1回で実質的な収束。

**状態:** 確定（2026-09-05）。計画レビュー第1回の指摘2件を反映し、ユーザー判断で追加レビューをせず確定した。実装は未着手で、次セッションから開始する。

## 全体の制約

- 初回の未レビュー規範内容には4観点の独立レビューを強く推奨するが、実施・見送りはユーザー判断。誤記等の除外、レビュー済み上流の扱い、記録不明時の扱いを維持する。
- フル実施4観点・担当1〜4体、差分再確認1体、機械検証はレビュアーなし。方式・人数を状況から判断する。
- レビュー通算回数の通常型4回・規範改定型8回の注意喚起と復元規定を維持する。回数上限にはしない。
- 停止2経路、骨格安定の停止・継続利用上の条件、退避・独立性・記録形式を維持する。方式の推奨を固定する用途からは外す。
- 原則・AGENTS.md、委譲制約の全般、実装時の逸脱判断・レビュー深度を変更しない。既存仕様書のスキル1の責務も変更しない。
- 配布対象ソースの記法と語彙はCONTRIBUTING.mdと `docs/overview/wording-replacements.md` に従う。出所の参照番号は全角括弧内または出所リストへ置く。
- 既存の未追跡 `.claude/`、`docs/conversation_log.md`、inbox3件を編集・ステージしない。生成物は生成器から作り、手修正しない。
