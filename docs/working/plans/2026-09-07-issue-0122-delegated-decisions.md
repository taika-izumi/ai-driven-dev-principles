# Issue-0122 判断の分担に基づく自動進行の実装計画

> 実行担当向け: `superpowers:executing-plans` または `superpowers:subagent-driven-development` を用いてタスク単位で実行する。実行方式はユーザー指示と利用可能な環境に従う。

**目的:** 初期設計で合意した相談事項・委任範囲・限度を、後続の計画・レビュー・実装・ADR・再開へ適用する。

**構成:** start-workの新規参照ファイルを判断権限の正本とする。既存の各工程から参照し、妥当性・検証・操作権限の正本を維持する。記録は既存の設計・計画・課題・ADRへまとめる。

**技術:** Markdown、PowerShell、既存のbuild-dist/sync-template。新しいランタイム・承認台帳・検査基盤は追加しない。

**仕様:** `docs/current/specs/2026-09-07-delegated-decision-workflow/00-overview.md`と01〜03。ADR-0133。仕様レビューはフル1回＋新規担当の差分再確認1回で新規指摘なし。

## 共通制約と検証方針

- 許可は内容を提示した上で得る。単なる継続指示から包括許可を作らない。
- 判断権限と変更の妥当性を分ける。委任を理由に検証・レビュー・操作承認を省かない。
- 対象作業完了まで有効。中断・撤回・別作業を区別し、AIの局所変更で境界を広げない。
- 累積比較基準は承認時点を識別し、履歴なしでは承認直後・AI変更前に既存文書へ保存する。
- 初期分担を後続工程へ適用し、工程ごとの追加許可や数値予算を必須にしない。
- スキルの意味上の実装を先に行い、必要なレビューと検証が済んだ時点で配布版を更新する。
- `.claude/`、`docs/conversation_log.md`、inbox3件は既存未追跡の手動整理対象で、編集・ステージしない。Issue-0130は別の起票成果物で本実装の差分へ混ぜない。
- 配布対象ソースの記法・語彙はCONTRIBUTING.mdと置き換え表に従う。

検証は、シナリオに対する規範の読み取り比較、独立した実装レビュー、既存生成検査を組み合わせる。文字列があるだけの検査を、自動進行が動いた証拠としない。実際の利用セッションでの効果は導入後の評価と区別する。
