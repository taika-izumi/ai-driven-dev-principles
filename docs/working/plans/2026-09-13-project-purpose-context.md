# プロジェクトの目的・方針の参照 実装計画

> 実装担当は `superpowers:executing-plans` でタスク順に実行する。委譲方式を選ぶ場合は `superpowers:subagent-driven-development` とsubagent-dispatchを適用する。

**目的:** 各プロジェクトの現在の目的・方針を、開始・再開・委譲時に取得し、局所依頼だけで判断する経路を減らす。

**構成:** 目的の特定・変更の正本をstart-workの参照文書へ置き、AGENTS・開始・handoff・委譲から接続する。目的本文は各プロジェクトで維持し、プラグインには含めない。

**技術:** Markdownの指示・スキル、既存PowerShell生成器、既存Codex CLIの読み取り専用Sol実行。新しい実行基盤は作らない。

**仕様:** `docs/current/specs/2026-09-12-project-purpose-context/00-overview.md` と01〜03。判断理由はADR-0190。確定前レビューはR1〜R3（フル1回＋差分2回、実質的な収束）。

## 全体の制約・判断の分担

- 全体目的の現行根拠はロードマップ冒頭・4.0節とADR-0130・0183。要求・必要品質・権限・継続情報を保ち、AI費用・時間・将来負担を抑える。目的を再定義しない。
- 正本指定を優先し、標準入口は `docs/overview/project-purpose.md`。既存の適切な文書・節を再利用し、本文を二重管理しない。
- 全体start-workは主担当の責務。子は目的・範囲の確認を行い、不足は必要な読取りか親への報告へ限定する。読み取り専用作業へ永続化を強制しない。
- 目的・方針を含む固有指示を配布更新で上書きしない。ユーザーが明示した変更を既存の正本・決定記録へ反映し、未完なら確定内容と未反映を保持する。
- 新しい台帳・全件ハッシュ管理・自動注入基盤・全履歴読破は追加しない。初期比較、Claude/sbx、Issue-0136、ADR-0184は再開しない。
- 今回の承認は目的の参照機能の設計・改修と、選択されたレビュー。公開・利用側への実導入・別の継続判断規範の採用は含めない。既存の広い判断委任があるとは扱わない。
- **逸脱判断の既定:** ai-driven-dev-principles 0.1.28の `skills/start-work/references/plan-deviation-defaults.md` を適用する。設計変更・範囲拡大は同既定と既存の承認に従う。不採用のまま実装時レビューへ送る指摘は0件。
- 文書規範の改修には `superpowers:writing-skills` を適用する。行動比較で現行版が合格しても、期待値を変えて失敗を作らず、観測と限界を記録する。

## 共通検査と実行条件

ソース編集の節目で必要な生成を行い、以下を実行する。

```powershell
pwsh -NoProfile -File scripts/build-dist.ps1 -Check
pwsh -NoProfile -File scripts/sync-template.ps1 -Check
pwsh -NoProfile -File scripts/check-claude-md-size.ps1
git diff --check
```

期待値は両CheckがUp to date・記法違反0、差分検査が成功。AGENTSは既存目安12,000バイト・45箇条との関係を確認する。スキル参照文書はソース・distの両方に存在し、固有目的本文はtemplate.manifest・dist・templateへ混入しない。見出し・リンクだけの確認で意味の検査を代替しない。

この計画で提案するモデル実行は判断比較2回＋実装レビュー1回の計3回、いずれも新規Sol/high。各実行は既存runnerと同じ20分の停止設定を用い、実行合計の停止上限は60分。実作業の時間予測や費用保証ではない。途中の読取り失敗や環境不一致を無条件で再試行しない。追加のモデル起動・試験方式変更が必要なら理由と影響を示す。

送信するのは当該ソース・仕様・参照資料、人工の8ケース、レビューに必要な差分であり、認証情報・個人設定・会話ログ・他プロジェクトの実体を含めない。実行計画の選択でこの範囲を確認する。既存の資料送信承認を無関係なデータへ広げない。
