# extend-guidelines

AI駆動開発ガイドラインの拡張作業を自動的にガイドするゲートウェイスキル。

## 手順

### 1. CONTRIBUTING.md を読み込む

まず、リポジトリルートの `CONTRIBUTING.md` を読み込み、設計思想と拡張ルールを把握すること。

このファイルが見つからない場合は、ユーザーに以下を報告して作業を中断する:
「`CONTRIBUTING.md` が見つかりません。拡張ルールの参照元が存在しないため、作業を開始できません。」

### 2. 拡張内容をヒアリングする

ユーザーに「何を拡張したいか」を確認する。以下の選択肢を提示すること:

- 原則を追加・変更したい
- CLAUDE.md を更新したい
- 新しいSkillを作成したい
- 既存のSkillを改定したい

### 3. 該当シナリオを確認する

CONTRIBUTING.md の該当シナリオセクションを読み、判定基準・手順・チェックリストを確認する。
ユーザーの要望が判定基準に合致するか検証し、合致しない場合はその旨を伝える。

### 4. brainstorming を開始する

ユーザーの要望と CONTRIBUTING.md の拡張ルールをコンテキストとして保持したまま、brainstorming スキルを呼び出す。brainstorming では以下を念頭に置く:

- CONTRIBUTING.md の判定基準とチェックリストを設計の制約として扱う
- 既存の原則・指示・スキルとの整合性を確認する
- ADRの作成が必要かどうかを判断する（CONTRIBUTING.md「ADRを記録するとき」セクション参照）

### 5. 確定前の過剰適合点検

設計承認の前に、CONTRIBUTING.md「全シナリオ共通: 過剰適合の点検」を実施し、点検結果の定型ブロックを spec（spec を作らない場合は ADR 末尾の独立節「## 過剰適合点検（ADR-0079）」）へ記録する。点検ブロックの無い拡張 spec / 拡張 ADR はコミットしないこと（ADR-0079）。新設（規範・手順・観点）を含む拡張では、CONTRIBUTING.md「全シナリオ共通: 新設の評価可能性」の記載要件もあわせて確認すること（ADR-0102）。

### 6. 配布物の生成を案内する

**本手順はガイドライン本体のリポジトリで拡張作業を行う場合のみ該当する**（配布先プロジェクトには生成器も配布対象ソースも存在しない）。

拡張作業の完了後、配布対象ソース（`template.manifest` 記載ファイル／`skills/` 配下／空インデックス生成対象 3 ファイル）を変更した場合は、コミット前に次が必要であることをユーザーに案内する。

1. 変更した側の生成器を実行する。`scripts/build-dist.ps1`（`skills/` を変更した場合）、`scripts/sync-template.ps1`（それ以外を変更した場合）
2. 両者を `-Check` で実行する（それぞれ自分の出力先しか見ないため、変更範囲によらず両方を回す）
3. 生成された `dist/` と `template/` を同じコミットに含める

出所識別子の記法規約（ADR-0083）に違反があれば生成器が非ゼロ終了する。違反は修正してから再実行する。規約の詳細と、機械判定が届かず目視が要る 3 点は `CONTRIBUTING.md`「全シナリオ共通: 配布対象ソースの記法規約」にある。
