# update — マイルストーン更新

`session-handoff` の update 操作の正本。

呼ばれるタイミング: 各スキル完了後、plan の 1 タスク完了時、その他マイルストーン到達時

手順:
1. 既存ファイルを読み込む
2. 各節を最新化する。更新対象: ヘッダ（Last Updated を現在時刻（Asia/Tokyo）へ、Current Phase を最新の状態へ）/ 完了したタスクの「完了済みタスク」への移動 / 進行中のタスクの「状態」「残り」の最新化 / 重要な意思決定があれば「重要な意思決定の履歴」へ ADR 番号を追記 / 既知のブロッカーがあれば追記。確定前レビューの反復が継続中の場合は、対象確定点の型・成果物の型（値は「規範改定型／通常型／規範改定型（迷い判定・閾値は通常型の値）」の 3 値。定義は `pre-finalization-review` 提示規則の 2 型分類。「対象確定点の型」とは別項目）・実施済みの方式と巡数・レビュアーのモデル・保留中の選択（次に実施する方式または回答待ちの提示）・改訂前退避ファイルのパス・骨格安定と判断していたか（Yes/No と根拠 1 行。判断材料であり規範的判定には使わない）・Accepted 済み ADR 本文の改訂の有無（改訂記録の未記入がある場合）を「進行中のタスク」の状態・残りへ書く。反復終了時は当該記載を除去または最新化する。
3. 「Post ラッパー消化記録」へ当該マイルストーンの1行を追記する（ADR-0057）。ADR 候補検出の結果（番号 or なし＋理由）と worklog-record の結果（エントリ id or 棄却＋理由）を書く。棄却を明示しない限り未発火と区別できないため、棄却時も必ず書く。当該マイルストーンが確定点（spec 確定点 / plan 確定点）だった場合は、確定前レビューの結果（`review=`）も併記する。確定点の型（`spec 確定点 (a)〜(c)` / `plan 確定点`）の定義は pre-finalization-review スキルの「確定点での提示（提示規則）」節を参照（ADR-0080）。この記録は次の確定点での推奨判定の判定材料になるため、欠けると判定は「未レビュー」側へ倒れる（ADR-0080）。当該マイルストーンに Accepted 昇格処理が含まれる場合（名称に `Accepted 昇格` を含める）と、サイクル全体整合検査のみを実施した場合は、検査の結果（`cyclecheck=`）も併記する（値の定義は `decision-log` の `references/cycle-consistency-check.md` を参照。ADR-0092）。1 行は 200 字以内とし、各フィールド値は「判定結果＋安定識別子＋正本への参照」に限定する（ADR-0088）。詳細は正本側へ書く。反復の途中経過が独立のマイルストーンになる場合、その行には review= を書かず確定点行へ集約する（行そのものは ADR= / worklog=〈および該当時 cyclecheck=〉を伴って通常どおり追記する）。確定点行が未作成なら当該確定点の通過時に作成して反復記録を 1 回でまとめて書き、既にある場合は既存の方式要素を残したまま末尾追記・終了状態更新で最新化する（置換しない。日付は当該確定点の通過日を維持し、update のたびに書き換えない。ただし 1 行 200 字を超える場合は `review-field-values.md` の縮退規定に従い、中間の方式要素を正本側へ移す）。終了状態を記入する更新で、当該確定点の反復が Accepted 済み ADR 本文の改訂を含んでいた場合は decision-log の `references/status-updates.md` の改訂記録規定を適用する（ADR-0108）。
4. 各節への追記で詳細を書きたくなったら、正本（対応する ADR / issue / worklog / 参照知識ドキュメント）へ書き、handoff の行には参照を書く（独立手順「移設」の対応表〈`relocation-map.md`〉に従う。正本へ書いた場合は `relocation-procedure.md` の手順 3〜6 に従い、手順 6 のとおり次のコミット時に handoff と同時に add する。ADR-0088）
5. ファイルを上書き保存する（コミットはセッション終了時、または明示的なコミットタイミングで実施）
