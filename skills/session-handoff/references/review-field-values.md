# `review=` の値定義（ADR-0107）

確定点（spec 確定点 / plan 確定点）を通過したマイルストーンの消化記録行を書くときに読む。

`review=` の実施記録は 1 個以上の方式要素を `＋` で連結する（実施順に全要素を残す。同一方式の連続は既存要素の巡数を加算し、方式の切替、または同一方式でもレビュアーのモデルが変わったときは新要素を足す——モデルは方式要素の識別子に含まれるため。`機械検証` はレビュアーを立てずモデル欄を持たないため本規則の対象外。1 巡が複数体で構成されモデルが混在する場合はモデルを `/` で併記する（併記は当該方式要素の全巡で登場したモデルの和集合を `/` で並べる）——併記内容の変化は新要素の契機に数えず、体数・指摘件数などの内訳は正本側へ書く）。方式要素は `フル実施（モデル・N 巡）` / `差分再確認（モデル・N 巡）` / `機械検証（N 回）`（値語彙「フル実施」「差分再確認」は歴史的語彙で、それぞれフル巡・差分確認巡〈定義は pre-finalization-review の `references/iteration-norms.md`「反復の実施」節〉に対応する）。N は当該方式要素が表す連続区間の巡数とし、確定点の初回レビュー巡はその方式に対応する最初の方式要素に含める。確定点全体の通算はすべての方式要素の N の和として読み、反復の深さを読むときは初回の 1 巡を差し引く。設計そのものを変える修正（設計縮小を含む）を挟んだ場合も巡数は通算し、転換の経緯は値に書かず正本（plan・ADR・課題ログ）側へ書く。`見送り` / `非発火` は反復局面（実施後の改訂発生時）では使わないが、推奨判定が偽のままユーザー指示で実施した場合は方式要素の括弧内に「推奨判定は偽」を併記してよい（任意）。

末尾の方式要素の括弧内の最後に**終了状態**を反復の終了時に書く（記録全体の帰結を表す。反復継続中の行は方式要素のみの記載でよく、継続中である事実・再開手順・セッション跨ぎの申し送りは handoff「進行中のタスク」節が正本として担う）。終了状態は次の 4 値とし、複数が成立する場合は 実質的な収束 ＞ ユーザー打ち切り ＞ 提示後確定 ＞ 改訂なし確定 の順で採る:

- `実質的な収束` — 実質的な収束（pre-finalization-review の `references/iteration-norms.md`「指摘反映後の反復」の停止判定。いずれかの経路）の判定が真のまま確定した場合（改訂が 1 度以上発生した場合に限る。改訂が 1 度も発生しなかった場合は `改訂なし確定` または `提示後確定` を採る）
- `提示後確定` — 反復提示への回答としてユーザーが「このまま確定」を選んだ場合、または回答として選ばれた方式を実施した結果さらなる改訂が生じなかった場合（実質的な収束の判定が否の場合は `提示後確定（実質的な収束に至らず）` と併記する。真の場合は優先順位により `実質的な収束` を採る）
- `ユーザー打ち切り` — 反復提示の選択肢への回答としてではなく、ユーザーが反復の終了を明示的に指示した場合
- `改訂なし確定` — 改訂が 1 度も発生せず、反復提示も行われなかった場合（＝指摘が無かった場合。指摘があったが全て不採用の場合は提示を経由するため `提示後確定` 側になる）

1 行 200 字に収まらない場合は、最初と最後の方式要素を `＋…＋` で省略を示して連結し、末尾要素の後へ `＝通算 N 巡`（巡を立てる方式の和。機械検証がある場合は `・機械検証 N 回` を併記）を添え、完全な連鎖は正本（plan・ADR・課題ログ）側へ書く。例: `review=フル実施（claude-opus-5・4 巡）＋…＋差分再確認（claude-opus-5・1 巡・提示後確定（実質的な収束に至らず））＝通算 8 巡・機械検証 2 回`（終了状態が入れ子括弧になる場合は例のとおり閉じ括弧を重ねる）。反復継続中の縮退では終了状態の枠は空のままでよい（終了状態は反復の終了時に記入する）。巡数・終了状態は消化記録の値限定（`section-volume-norms.md`）の「判定結果」に含まれる。
